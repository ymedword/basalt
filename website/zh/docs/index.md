# 文档

先了解 Basalt 管理什么，再按快速开始运行一个 Agent，或继续阅读项目架构。

## Basalt 是什么 {#what-is-basalt}

**Basalt 是面向企业自托管的 Agent OS，为多个独立业务 Agent 提供统一的运行与管理平台。**

每个 Agent 通过独立目录和 AGENT.md 定义身份、模型、工具、技能与任务，使用底座的执行循环、模型接入、定时调度、持久化和审计能力。创建新的业务 Agent 时，主要配置它的职责与资源，复用同一套公共基础设施。

例如，日报 Agent 可以定时整理简报，文件检查 Agent 可以读取授权工作区并列出问题。它们分别管理定义、会话与作用域记忆，共享底层服务。这是配置用途示例，需要按实际业务接入资源。

## 为什么称为 Agent OS {#agent-os}

这里的 OS 指运行在企业基础设施上的 Agent 应用运行平台。可以从三个层次理解它的职责：

| 层次 | 负责什么 |
| --- | --- |
| 模型 | 根据上下文返回内容，或提出工具调用 |
| Agent 运行底座 | 组装上下文，执行有界的模型与工具循环，保存状态并记录调用 |
| Agent OS | 将运行底座提供给多个 Agent，统一管理生命周期、共享资源、调度、访问策略与运维 |

Basalt 用一个 Go 应用承接后两个层次。模型提出动作，运行时校验声明的工具、执行对应策略并记录调用；使用者通过管理台和 API 配置 Agent、查看执行情况。

**每个 Agent 独立管理：** 身份、配置、允许使用的资源、会话和作用域业务状态。**平台统一提供：** 执行、模型与工具适配、调度、存储、审计和管理服务。逻辑作用域不等同于进程或容器故障隔离。

## 当前代码提供什么 {#current-capabilities}

- 基于目录的 Agent 定义、配置、显式启停与归档。
- 显式模型连接、资源发布版本、内置工具、MCP 与可复用技能。
- 有界 ReAct 执行、上下文组装、会话和 Agent 作用域内的持久记忆。
- 按 Agent 管理定时任务，并向配置的通知渠道投递结果。
- 内嵌管理台、HTTP API、执行记录，以及模型与工具调用审计。
- 单节点 Go 运行时、内嵌 SQLite 与本地文件；内置工具分别执行文件、命令和网络访问策略。

长期记忆在 save_memory 成功时保存。会话历史是另一类记录，普通对话不会自动晋升为长期记忆。模型与外部工具会按所配置的服务接收相应请求数据。

当前管理 token 提供基础管理认证；个人账户、SSO 与完整租户治理属于下文的规划方向。

## 核心概念 {#concepts}

| 概念 | 含义 |
| --- | --- |
| Agent | 具备独立定义、资源声明与作用域状态的业务执行者 |
| Run | 一次请求或定时任务的有界执行，有独立的结果记录 |
| Session（会话） | 持久保存的对话，可以包含多次 Run |
| Workspace（工作区） | 实例的数据目录，默认是 .basalt/，保存数据库、Agent 定义与配套文件 |
| Resource（资源） | 可复用的模型连接、MCP 服务、技能或通知渠道；符合资格的发布版本绑定到 Agent，在执行时解析使用 |

## 未来方向 {#roadmap}

目标是形成面向企业自托管的 Agent OS，让任务能够被执行、验证、追踪和持续改进。**以下内容属于规划，尚未成为当前能力，也没有交付日期承诺。**

| 方向 | 希望解决什么 | 状态 |
| --- | --- | --- |
| 知识与记忆 | 按权限使用私有资料，提供可追溯引用、语义检索和完整的更新／删除生命周期 | 规划；能力建设第一优先 |
| 诊断与任务编排 | 解释任务失败，持久保存长任务进度，支持有界委托与修订 | 规划 |
| 执行隔离与受控学习 | 先建立隔离、评测与准入，再生成可复用技能候选；批准的改动有版本且能回滚 | 规划 |
| 分布式执行 | 将状态外置，在多个节点之间协调任务归属、预算与恢复 | 规划 |
| 企业治理与接入 | 补齐企业身份、角色、租户／项目范围、审计查询、配额、审批和更多渠道接入 | 规划 |
| 目标到产物的任务交付 | 围绕业务目标组织专业 Agent，以可追溯产物和有界复核完成交付 | 长期方向 |

知识与记忆优先推进，诊断为后续编排提供基础；隔离与学习准入先于受控能力更新，分布式和完整企业治理在这些基础上继续建设。每个方向都需要独立设计评审和可复现验证，不能在当前版本中通过打开一个配置开关直接获得。
