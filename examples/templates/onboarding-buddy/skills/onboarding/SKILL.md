# 入职导读技能（L2 正文）

这份技能规定「怎么排顺序、怎么判变化、怎么写报告」。取数由 `AGENT.md` 的步骤完成，
本技能**不负责**调用 MCP、不负责概括资料内容。

## 一、分桶与排序

按**路径形态**分三桶，规则按顺序判断，**先命中者定桶**：

| 顺序 | 桶 | 判定 | 阅读定位 |
| --- | --- | --- | --- |
| 1 | 参考 | 路径以 `archive/` 开头 | 需要时再查，不进第一周 |
| 2 | 按角色 | 路径含 `/`（在子目录里，且不是 `archive/`） | 按岗位 / 场景选读 |
| 3 | 必读 | 其余（根目录下的文档） | 入职第一周读完 |

桶内顺序：按 `path` 升序（ASCII），不按修改时间、不按篇幅。

为什么要按路径而不是按标题：路径是资料库的稳定事实，标题是编辑随时会改的一句话；
按标题分桶意味着同一天换个标题，阅读顺序就变了，跨天不可比。

**不得**做的事：

- 不得按你对内容的理解把根目录文档降级成「参考」——分桶只看路径；
- 不得新增桶（新增桶 = 改判据，要改这张固定表并重跑夹具）；
- 不得把同一篇文档放进两个桶。

## 二、变更判定

基线是本技能的唯一依据，存在记忆条目 `onboarding-buddy 上次运行` 里
（`path → sha256` 表 + 观测时间）：

| 集合 | 判定 | 证据 |
| --- | --- | --- |
| 新增 | 本轮有、基线没有的 `path` | 路径本身 |
| 内容变更 | 两边都有，`sha256` 不同 | 新旧哈希并列写出 |
| 移除（待核实） | 基线有、本轮清单没有 | 旧路径；**必须**标「待核实」 |
| 未变 | 两边都有且 `sha256` 相同 | — |

**「没列出来」不是「被删除」**：清单截断（服务端有数量上限）、单篇元信息失败、
MCP 只拿到部分结果——都不构成删除证据。移除只有一种证据：`list_documents` 本轮
成功返回，且清单里确实没有这个 `path`。

**「改过」不是「变了内容」**：`modified_at` 只用于展示，判定变更**只**看
`sha256`。复制文件、重排版但内容不变时 `modified_at` 会变、`sha256` 不变，
这种变化不进「内容变更」集合。

## 三、报告固定模板

```markdown
# 入职导读 · <观测日期>

## 来源
| 项 | 值 |
| --- | --- |
| 资料库 | `docs-readonly`（只读；根目录由部署方指定） |
| 文档数 | <n> |
| 基线 | <上次运行时间 / 首跑，无基线> |
| 观测时间 | <ISO 时间或「夹具复跑」> |

## 阅读顺序
### 必读（第一周）
1. <path> —— <主题一句话；未读正文写「未读正文」>

### 按角色
1. <path> —— <主题一句话>

### 参考
1. <path> —— <主题一句话>

## 本次变化
- 新增：<path> …（没有写「无」）
- 内容变更：<path> `<old>` → `<new>`
- 移除（待核实）：<path>
- 未变：<n> 篇

## 待确认
- <path>：<原因>

## 失败
<错误原文；没有写「无」>
```

规则：

- 三个桶没有内容时写「无」，不省略小节；
- 「主题一句话」只能来自本轮真正读过的正文；没读正文的写「未读正文」，**不得**
  按文件名编一句；
- 「内容变更」必须同时写旧哈希与新哈希，只写「有更新」不算；
- 不写「学习建议」「考核重点」——资料库里没有这类内容，属于臆测。

## 四、失败与降级

- MCP 不可用：只写失败段，不写阅读顺序、不更新基线；
- 单篇元信息失败：该篇进「待确认」，其它文档照常排顺序；基线**不更新**；
- 基线损坏（不是 JSON 或缺 `path` 字段）：退回首跑语义，保留原记忆条目，报告写明；
- 清单为空：写「资料库为空」，不写阅读顺序，基线更新为空表（这是真实状态）。
