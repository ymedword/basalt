# policy-watch —— 每日政策追踪模板

读取指定官方来源的公告列表，按 `id` 与内容哈希与上次快照对比，输出新增 / 修订 /
下线三集合。判定口径与报告模板由 `policy-watch` 技能规定，**无凭据、无 MCP、无脚本**。

档位：A（全量）

## 领域

政策信息——每天固定时间告诉你「官方来源上多了什么、改了什么、少了什么」。

## 能力

- 两个来源的公告列表逐条读取（`id` / 标题 / 链接 / 发布日期 / 正文哈希）；
- 按 `id` 与 `content_sha256` 判定新增 / 修订 / 下线；
- 读不到不等于下线：来源级失败整体记「不可用」，不参与下线判定；
- 首跑只记快照，三集合全空；
- 任一来源不可用时保留旧快照，下一轮重读同一段。

## 工具与域名

| 项 | 值 |
| --- | --- |
| `tools:` 声明 | `http_get`、`read_file`、`write_file` |
| `skills:` 声明 | `policy-watch`（实体在本目录 `skills/policy-watch/SKILL.md`） |
| MCP | 无（`mcp_servers: []`） |
| 出网域名 | `notices.example.gov`、`standards.example.org`（**占位**，导入时换成你的官方来源） |
| 内置域名白名单 | **无**——`http_get` 本身不带域名清单 |

**出网边界**：导入后必须把你要用的**真实**官方来源域名加进管理台「执行环境」的域名
白名单，否则每次运行都是 `sandbox_denied`。换来源时同时改 `AGENT.md` 第 1 步的表格、
本 README 的域名行与白名单，三处保持一致。白名单不因导入模板自动放宽。

## 文件范围

## 凭据

无。模板里不出现任何 `${...}` 占位。需要登录才能看的官方来源不在本模板范围
（`http_get` 不带认证头）。

## 已知限制

- 只有两个来源、单页列表：来源分页时**必须**补齐分页，否则「下线」会把下一页的
  条目误判成下线条目（技能已把这类情况限定为「待核实」）；
- 只认列表页给出的哈希或你自己抓到的正文哈希，不抓附件（PDF / 附件正文不在范围）；
- 不解读政策、不做影响分析——这是有意限制，避免没有来源的结论；
- 占位域名 `example.gov` / `example.org` 不是真实站点，未替换前复跑只能走夹具。

## 夹具与期望结果

`fixtures/announcements.json`：`previous` 4 条、`current` 4 条，两个来源本轮都读取
成功。复跑（`previous` 当快照、`current` 当本轮）期望：

| 集合 | 条目 | 依据 |
| --- | --- | --- |
| 新增 | `STD-2026-019` 模型调用留痕最小字段集 | 本轮有、快照没有 |
| 修订 | `REG-2026-042` 关键信息基础设施运维外包备案指引 | 哈希 `fdcafcd6…` → `d620b73c…` |
| 下线（待核实） | `STD-2026-017` 日志留存格式规范（草案） | 快照有、本轮列表没有，且该来源读取成功 |
| 未变 | `REG-2026-041`、`STD-2026-018` | 哈希一致 |

合计：新增 1、修订 1、下线 1、未变 2；「来源」表两行都是「读取成功」。若把第二个
来源在复跑时标记为不可用，则 `STD-2026-017` **不得**再出现在下线集合——这条用于
人工核对「读不到 ≠ 下线」。

## 通知路径

基线 `notify_mode: none`（零通知）。要每日推送：管理台把 `notify_mode` 改成
`allowlist` 并勾选渠道，再给 `daily-policy-watch` 配 `deliver_to`；由系统在 Run
成功后发送，模型不调用 `notify`、失败不自动补发。

## 生效方式

复制目录后：技能复制到 `.basalt/skills/policy-watch/`，域名加白名单，绑定模型连接，
重启 Basalt（或走既有受控发布流程）。技能与 `AGENT.md` 的变更都要重启后生效。
