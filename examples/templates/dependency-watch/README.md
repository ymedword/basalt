# dependency-watch —— 每日依赖漏洞观察模板

读一份依赖清单，向 OSV 批量查询已知漏洞，与上次基线对比，输出新增 / 仍然存在 /
已修复三集合。判定口径写在 `AGENT.md`（本模板没有技能），**无凭据、无 MCP、无脚本**。

档位：A（全量）

## 领域

供应链安全——每天固定时间回答「我们的依赖上这次新冒出来哪些已知漏洞」。

## 能力

- 解析固定格式的依赖清单（生态 / 包名 / 版本），格式不合法的行单列「待确认」；
- 一次 `querybatch` 查询全部包，响应按位置与查询顺序对应；
- 对新增漏洞有界抓详情（最多 10 条），其余只写编号；
- 以 Agent 根目录的 `history.json` 为基线，判定新增 / 仍然存在 / 已修复（待核实）；
- 批量查询整体成功才更新基线，任何一行失败都保留旧基线；
- 清单里已经没有的包，其编号进「已修复（待核实）」，不静默丢。

## 工具与域名

| 项 | 值 |
| --- | --- |
| `tools:` 声明 | `http_post`、`http_get`、`read_file`、`write_file` |
| MCP | 无（`mcp_servers: []`） |
| 出网域名 | `api.osv.dev`（HTTPS 443） |
| 内置域名白名单 | **无**——`http_post` / `http_get` 本身不带域名清单 |

**出网边界**：导入后必须在管理台「执行环境」把 `api.osv.dev` 加进域名白名单
（`basalt.yaml` 的 `http.allowed_domains` 只是首次种子），否则每次运行都是
`sandbox_denied`。白名单不因导入模板自动放宽。出网只是**查询**：漏洞编号、包名与
版本会发给 OSV；依赖清单本身不涉及业务数据，但清单里若写进内部包名，请先确认可以
外发。

## 文件范围

| 路径 | 读 / 写 |
| --- | --- |
| `dependencies.txt`（Agent 根目录） | 读（你的输入，模板不自带；示例见 `fixtures/`） |
| `history.json`（Agent 根目录） | 读基线、查询整体成功时写新基线 |
| `dependency-watch.md`（Agent 根目录） | 写（整文件覆盖） |
| `fixtures/dependencies.txt`、`fixtures/osv.json` | 只读（仅离线复跑用） |

基线放 Agent 根目录而不是子目录：`write_file` **不建父目录**，写到 `state/` 之类
的子目录会直接失败。

## 凭据

无。OSV 是公开接口，不需要 key；模板里不出现任何 `${...}` 占位。

## 已知限制

- 只查清单里列出的**精确版本**：不解析 `package-lock.json` / `requirements.txt`，
  也不做传递依赖展开——清单要你自己生成；
- 一个版本一条查询：包多时请求体变大（`http_post` 的 body 上限 256 KiB），几千个包
  要分批，本模板不分批；
- 只报编号与摘要，不报 CVSS 分数、不给升级建议——OSV 批量接口不返回打分；
- 「已修复」永远标「待核实」：查不到也可能是接口抖动或包名写错；
- `history.json` 是 Agent 根目录的单个文件：**手动改坏它会退回首跑语义**（全部漏洞
  按首跑列出、不标新增）。

## 夹具与期望结果

`fixtures/dependencies.txt` 共 9 行：2 行注释 + 6 行有效 + 1 行格式非法（第 9 行
`npm dotenv`，只有两个字段）。`fixtures/osv.json` 的 `querybatch` 按这 6 个包的
**清单顺序**给出结果，`vulns` 是详情，`previous_history` 是复跑基线。复跑期望：

| 集合 | 条目 | 依据 |
| --- | --- | --- |
| 新增 | `OSV-2026-1002`（`npm:lodash@4.17.20`）、`OSV-2026-1003`（`PyPI:requests@2.31.0`） | 本轮有、基线没有 |
| 仍然存在 | `OSV-2026-1001`（`npm:lodash@4.17.20`） | 基线里也有 |
| 已修复（待核实） | `OSV-2026-0999`（`npm:axios@1.6.0`） | 基线有、本轮该包没有返回任何编号 |
| 干净 | `npm:axios@1.6.0`、`PyPI:pyyaml@6.0.1`、`npm:express@4.18.2`、`PyPI:flask@3.0.0` | 本轮查询没有返回漏洞 |

读数合计：有效 6 行、待确认 1 行（第 9 行）；当前漏洞 3 条；新增 2、仍然存在 1、
已修复 1；干净 4 个包。`OSV-2026-1002` 的详情带别名 `CVE-2026-78901`（虚构），
其他两条无别名——报告里无别名写「无别名」，不要留空括号。

## 通知路径

基线 `notify_mode: none`（零通知）。要每日推送：管理台把 `notify_mode` 改成
`allowlist` 并勾选渠道，再给 `daily-dependency-watch` 配 `deliver_to`；由系统在 Run
成功后发送，模型不调用 `notify`、失败不自动补发。

## 生效方式

复制目录后：把 `dependencies.txt` 放到 Agent 根目录（模板不自带你的清单），域名加
白名单，绑定模型连接，重启 Basalt（或走既有受控发布流程）。`AGENT.md` 的变更要重启
后生效；域名白名单在管理台保存即生效。
