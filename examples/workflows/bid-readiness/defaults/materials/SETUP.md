# 企业采购响应准备 · 默认工作流示例

随 Basalt 二进制交付，4 类 Agent、17 个顺序节点、R01–R48 共48条需求。
这是内部准备包的合成示例，不是真实招标；不承诺资质、报价或真实客户业绩。
产品材料固定于 `ca9a0d29f185a548b14b595e6068c52df1c3cdf4`，不能当成未来版本的能力证明。
来源和哈希见 `source-manifest.json`，后续产品更新不静默修改本次示例来源。

## 安装和升级

新实例首次启动自动准备四个禁用角色和本目录。由开箱安装器管理的既有实例升级时准备一次。
原先声明不接管 Agent 的旧实例不自动加角色，可停止服务后在工作区执行：

```sh
basalt demo workflow install
```

四个目录为 `agents/bid-requirements`、`agents/bid-technical`、`agents/bid-delivery`、
`agents/bid-reviewer`；每个角色只得到其职责需要的只读文件副本。
已有目录或生命周期记录保留，不覆盖用户文件、不恢复归档。安装标记生效后，删除的示例不自动复活。
新版本继续携带模板；已发布定义和已安装资料由用户维护，不自动升版或重置。

## 首次配置（管理台）

1. 在“模型与连接”配置可用的对话模型；若要体验知识库，另配向量模型。
   凭据经原管理入口录入，不写入示例文件。示例不限定供应商，不附带测试额度。
2. 在“Agents”分别为四个角色绑定已配置模型。默认模型为空且无定时计划；安装不会产生费用。
3. 在“知识库”显式创建并摄取：`bid-request` 放 `sources/request-01.md` 至 `request-08.md`；
   `bid-product` 放 `sources/product-main.md`。摄取可能调用向量模型并产生费用。
   为需求调查员添加 `bid-request` 只读绑定；技术核查员添加 `bid-product` 和 `bid-request` 只读绑定。
   默认不预填不存在的集合引用。商务与复核节点直接获得冻结原文，不需要自动检索；
   它们仍保留受限 `read_file` 权限。安装不摄取、不检索，不确认新记忆。
4. 阅读 `memory-suggestions.json`，逐条通过原记忆管理入口为对应 Agent 提交并确认；
   只作该 Agent 的核心经验提醒，不写入全局事实。全部明确标为合成经验，当前文件优先。
5. 发布配置并启用四个角色。开启配置中的 `flows.enabled` 后启动服务（启用 Worker 本身不创建任务）。
6. 在“工作流 → 工作流定义”点“载入采购准备模板”。它按当前目录绑定 UID、版本和资源哈希；
   缺少就绪角色会点名提示。若角色已被用户修改，必须核对它仍适合这个职责。
7. 检查顺序、输入输出和预算，点“只读在线校验 → 核对发布 → 确认发布”。已有同名定义会形成新版本；
   在途任务仍固定原版本。上述操作不会调用模型。

## 手动运行和验收

在“执行任务 → 新建任务”选 `bid-readiness-matrix-v1`，输入：

> 完成 SYN-AI-2026 内部采购响应准备包，覆盖 R01–R48；各专业分别核对后再最终复核。
> 保留所有证据缺口，不对外提交。

只提交一次，记下任务 ID。离开页面后可回到原任务查看；不要用重复新建代替恢复。
此时才会调用所选模型并计费。默认单任务最长30分钟、200000总 token、70次工具调用；
这不是金额预算或免费额度，发布前可调低。实际时长和费用取决于配置模型与调用结果。

顺序为需求四组 → 技术四组 → 商务四组 → 复核四组 → 最终摘要。
四组 `review_1`–`review_4` 各核对12条，最终 `final_pack` 汇总，不另行核验所有原文。
节点成功只证明执行及结构验收通过；人工仍需检查48条依据、缺口、责任、行动，不能把模型自评当业务验收。
重点检查维护期18个月的起算点、20/40/30/10付款条件、480000元是预算而非报价、
人员要求不等于 Agent 数量、缺资质与压测材料不被写成满足。

任务被阻断时先查看原因和原 Run；未知副作用不自动重放。历史失败任务保留。
CI、基础和回归测试使用本地模型协议夹具，禁止对真实模型发请求；本例只由用户手动启动。
