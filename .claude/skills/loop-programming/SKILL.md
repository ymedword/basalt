# Loop Programming

由当前 Agent 驱动“取任务 → 实现 → 验收 → 修复 → 保存 → 下一任务”。
Harness 提供正确性判据，本 skill 决定下一步。使用现有编辑和执行工具，不另启动
Coding Agent CLI，不用循环脚本或自身递归调用来承载开发流程。

## 读取输入与恢复

1. 读取用户目标、项目规则、工作区状态、任务卡及批准记录；保留已有改动。
2. 读取项目适配，默认路径为 `harness/project.md`。从中取得公共检查、专属检查、
   状态路径、预算及收口要求。缺少适配时先建立最小真实映射，不复制别的项目技术栈。
3. 读取过程记录，恢复任务位置、输入版本、失败历史和累计预算。存在旧机器 checkpoint
   时仅用作历史证据，由项目规则完成迁移；不伪造或继续写旧执行器的状态。
4. 核对任务卡人工 review ① 的实际决定与所审版本。随后 spec / plan / tasks / analyze
   由 AI 按项目流程推进，无需重复请求 tasks 或实现前确认；一致性门禁仍须通过。
   缺少批准时完成可审阅的任务卡，交给第一处 review，不能自行宣布人审通过。

固定人工 review 为任务卡生成后与 US 收口时。目标、权限、公共契约或验收语义发生
实质变化时修订第一处 review 的输入；这不是增设中间的常规确认关卡。

## 先接 Harness，再实现

公共 Harness 集中维护，当前任务的行为、边界、失败模式与反例随任务卡走。
复用项目已有公共 Harness；需要设计或复核判据时使用项目声明的 Harness 方法，
本仓为相邻的 [agent-harness](../agent-harness/SKILL.md)。

控制侧先建立专属断言、冻结判据并记录有效红态。实现者只能在允许范围内实现或修复，
不能为转绿删除测试、放宽断言、扩大跳过范围或缩减故障条件。新增测试与不改变语义的
接口适配按项目规定推进。角色分离和哈希留证不代表已经形成操作系统权限隔离。

## 逐任务执行

1. 选取依赖满足且可判定的一组任务，记录原任务 ID、允许范围、输入指纹及检查映射。
2. 先验收可能已完成的实现；恢复时不能因聊天记录说失败就重复执行外部副作用。
3. 需要修复时，先在过程记录追加任务 / 问题 ID、累计次数、修复假设和下一步，
   再修改实现。计数跨会话及输入修订保留，不能靠换任务名清零。
4. 运行快速公共检查、任务专属断言与受影响回归；读取原始退出码、逐项结果、
   具名测试 PASS / SKIP 和报告，不能仅凭命令退出 0 或实现者自述判断完成。
5. 失败先归因：实现错误修实现；派生工件错误在已审范围内修订并复跑分析；
   环境问题修前置再重跑；需要改变已审语义时保留反例，返回第一处 review。
6. 有新证据且预算允许则继续。通过后保存证据，由控制侧据此更新任务勾选并取下一任务。
   不把前序未验任务或尚未实现的能力算成通过。
7. 全部任务已验后，运行完整公共门禁、全部专属检查及适用的整链路 / 外部验收。
   最终验收失败反馈到相关任务，按原预算修复，不能用局部绿态替代。

源码或输入变化后，核对旧证据适用范围并重跑受影响检查；最终证据必须对应当前
工作区 / 制品。执行验收时保持源码稳定，报告为 running、缺失或中断都不算通过。

## 状态、预算与停止

每次尝试前、每次验收后、任务切换前将以下事实写入项目过程记录：

- 输入 / 源码版本、真实批准依据、当前任务与依赖；
- 失败命令、退出码、断言读数、修复假设和累计次数；
- 报告与日志位置、已验与未验范围、下一条可执行动作；
- 本轮临时资源归属与清理、外部等待或缺少的权限。

预算优先采用用户与项目规则；未规定时同题最多三次无效修复后停止盲试。
项目规定的调试 / 设计升级流程继续适用，但不能借升级重置预算。
相邻尝试没有新读数、新假设或新定位时，不继续重复执行。同一任务尚有有效修复路径
且在授权与预算内，继续推进，不在每个步骤询问是否继续。

预算耗尽、缺少必验环境 / 权限、输入冲突或无法判定正确性时保存现场、阻断原因、
已做调查及具体下一步。普通实现失败仍在循环内修复，不一律交人裁决。
超时与进程清理由实际命令执行工具负责；skill 的记录和重试纪律依赖 Agent 执行，
不声称具有独立守护进程、不可篡改账本或崩溃自动续跑能力。只恢复已持久化的事实。

## 收口与交接

按项目要求执行独立 AI 复核，修复范围内发现并重验。独立上下文不可用时明确记录限制，
不能把作者自检冒充独立 review。收口提交当前版本、交付范围、逐项验收证据、
发现处置、允许跳过及未验证项，交人工 review ②。

人工尚未接受时标记待收口。自动化通过不授权 commit / push / 部署，按会话既有授权处理。
本 skill 与项目适配可迁移到其他项目；项目命令、阈值与契约保持在各项目事实源中。
