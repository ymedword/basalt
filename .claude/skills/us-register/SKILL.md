# us-register — US 登记器

把「新 US 登记」从两个编排 skill 的六处手工表里收敛成**一次台账追加**：事实源是颗粒度文档，
派生方向单向（文档 → 台账），两个编排 skill 只留取数规则句。

## User Input

```text
$ARGUMENTS
```

## 用途与触发

- 新 US 立项：`/module-doc-gen N` 写完颗粒度文档后、`/module-dev N` 之前跑一次
- 触发词：登记 US、新 US 立项、us-register、把 US 登记进台账

## 不做什么（边界）

- **不写颗粒度文档**——那是 `/module-doc-gen` 的活；本 skill 只读它、不改它
- **不改两个编排 skill 的取数表**——它们已改为规则句（见配置区「引用方」），不含 US 清单
- **不判断「要不要加技术栈 / 门禁 / 不变量」**——三项一律作为问题问用户（宪法级条目 6）
- **不 commit / push**

## 输入加载（完整读取，不得凭记忆）

1. 该 US 的颗粒度文档 `docs/us/us{N}-*.md`（glob）——**唯一事实源**；
2. 台账 `docs/us/REGISTRY.md` 现有全部行（幂等判据 + 追加位置）；
3. 按需读文档头部「事实主源顺位」段与 §3「交付物清单 / 改造点」两节（派生用）。

## 执行流程

### 步骤 1：输入校验（文档缺 → 报错退出）

输入**必须**是整数 N。glob `docs/us/us{N}-*.md`：

- 零命中 → 报错退出：`US-N 颗粒度文档不存在——先跑 /module-doc-gen N`
- 多命中 → 报错退出（歧义，让用户指定）
- 恰一个 → 记下相对路径，继续

**不得**在文档缺失时凭记忆或前序 US 的事实造登记行。

### 步骤 2：幂等检查（重跑不追加第二行）

台账里已有 `| N |` 行 → 报告 `US-N 已登记（文档入库：<值>），跳过` 并退出。
用户显式要求「重新登记」时，**不得**直接改行——走步骤 4 的 diff 停点，让用户看着改。

### 步骤 3：从文档派生行（逐列，取不到就标 `待补`）

| 列 | 派生方式 |
| --- | --- |
| US | 用户输入 |
| 类型 | 缺省 `开发类`；用户另有说明才改 |
| 颗粒度文档 | 步骤 1 glob 到的相对路径（反引号包裹） |
| 技术方案章节 | 文档头部「事实主源顺位」段里点名的技术方案章节；写「无对应章节」时，连同它列出的对照段一起抄 |
| 需求文档章节 | 同上段里点名的需求文档章节 |
| 模块落位（摘要） | 文档 §3.1 交付物清单 + §3.2 改造点**摘到内部包粒度**（不是抄全文）；`→ 包名`（如 `→ internal/storage`）的写法与既有行一致 |
| 文档入库 | `git log --diff-filter=A --format=%ad --date=short -- <文档路径>`；输出为空（未跟踪 / 仓库尚未 `git init`）→ 写 `未入库` |

任何一列**取不到** → 写 `待补` 并在步骤 4 作为问题提出，**不得**编。

### 步骤 4：diff 预览 + 固定停点

打印：①拟追加的整行；②台账行数 `前 → 后`；③列出所有 `待补` 列与建议值。**停下等用户确认**，未确认**不得**落盘。

### 步骤 5：三项「能力追加」判断题（逐项问，缺省跳过）

按顺序问用户，**不得**预填、**不得**代答：

1. **新工具链 / 新依赖坐标？** 是 → 问清坐标与版本，**必须**先核实（Go 侧
   `GOPROXY=https://goproxy.cn go list -m -versions <module>`；npm 侧 npm registry），
   再追加到 `module-dev` 的固定技术栈句。**例外**：宪法架构约束技术栈表与
   `module-dev` 固定技术栈句里**已有的坐标直接落地**（不重复询问）；**版本变更**
   按新增处理
2. **新构建步骤 / 新 profile？** 是 → 追加到 `module-dev` 的门禁命令段
3. **新机器可判不变式？** 是 → 要求给出**可复制执行的 grep 复核命令**，追加到
   `module-dev` 的全局不变量清单

三项都否 → 只写台账一行，两个 skill 零改动。

### 步骤 6：落盘

- 台账追加行（表格末行之后；**不得**改动任何历史行）
- 步骤 5 答「是」的项，同步追加到 `module-dev` 配置区对应段
- **不得**动 `module-doc-gen`（它只留取数规则句）

### 步骤 7：自检（逐项证据写进报告）

1. 台账与两个 skill 逐文件跑 markdownlint：零诊断，且返回 `linesInFile`（证明文件真被解析过，不是"没检查"）
2. `git diff --stat` 只落在预期文件；台账 diff **只有 `+` 行、无 `-` 行**
3. 台账登记表数据行数 = 登记前行数 + 1
4. 报告：改了哪些文件、每处 diff 摘要、幂等状态、三项判断题的答案、**未验证项**（如版本坐标仅在模块代理层核实、未真跑构建）

报告完停止——commit / push 由用户决定。

## 宪法级条目（不得违反）

| # | 约束（不得 / 必须） | 违反时的症状 | 复核方式（可验证） |
| --- | --- | --- | --- |
| 1 | **必须**先读颗粒度文档再登记；文档不存在 → **必须**报错退出 | 凭记忆造登记行，编排层拿到错事实 | `/us-register 99`（无文档）→ 非零退出且零写入 |
| 2 | **必须**写前打 diff、停下等确认；未确认**不得**落盘 | 编排层被静默改，模块开发时取到错章节 | 未确认时 `git diff` 为空即退出 |
| 3 | **必须**幂等：同一 US 重跑不追加第二行 | 表里出现两行同一 US，取数取到先出现的那行 | 对已登记的 US 连跑两次，第二次 no-op |
| 4 | **不得**改动历史行（只许追加） | 历史裁决被"顺手优化"，与已交付事实不符 | 跑完 `git diff` 无 `-` 行 |
| 5 | 派生方向**必须**单向（文档 → 台账）；**不得**反向改文档 | 事实源被登记器污染，文档与代码事实脱钩 | `git status` 里颗粒度文档不发生变更 |
| 6 | **不得**自行判断"要不要加技术栈 / 门禁 / 不变量"——**必须**列为问题等用户答 | 无关不变量被塞进全局清单，收尾自查出现空转项 | 运行输出必须含这三个问句 |
| 7 | 列取不到**不得**编——**必须**标 `待补` 并提问 | 台账里出现看似合理的假事实 | 台账 grep `待补` 命中数 = 报告里列出的待补项数 |

## 产出后自检（写回前执行）

- 每列都能指回文档的具体段落（章节 / §3.1 / §3.2 / git），无凭空值
- 新增行的写法与既有行同构（反引号包裹路径与包名、`→ 包名`、`| --- |` 分隔行不动）
- 版本类内容一律先核实（Go 侧 `GOPROXY=https://goproxy.cn go list -m -versions <module>`；
  npm 侧 npm registry），不凭记忆

## 项目配置区（复制本 skill 到新项目时，只改写本节）

> 本节与 `module-dev` / `module-doc-gen` 的「项目配置区」保持同一份事实，复制到新项目时同步修改。

### 台账

- 路径：`docs/us/REGISTRY.md`；列顺序固定：`US | 类型 | 模块执行颗粒度文档 | 技术方案章节 | 需求文档章节 | 模块落位（摘要） | 文档入库`
- 台账是**唯一登记处**；本 skill 是它的唯一写入方
- 「模块落位（摘要）」列记的是**内部包**（单 Go module + `internal/` 分包，不是构建模块）；
  包结构纪律见 `docs/TechnicalSolution.md` §10.1
- 「文档入库」列在仓库尚未 `git init` / 文档未跟踪时记 `未入库`

### 引用方（只留规则句，不内嵌 US 表）

| 位置 | 引用方式 |
| --- | --- |
| `module-dev` 配置区「输入与模块类型分流」 | 输入整数 N → 查台账；无行 → 报错退出提示 `/us-register N` |
| `module-dev` 配置区「颗粒度文档与技术方案」 | 文档路径与章节对照从台账取；「无对应章节」行按差异裁决注执行 |
| `module-doc-gen` 配置区「输入与文档路径 / 章节来源」 | 台账已有该 US → 按台账列取数；查无 → 自定位章节并写进文档头部，供本 skill 派生；**查无且 N > 14 时按 `docs/Roadmap.md` §4.2 取对应方向节为事实源** |

### 能力追加三个落点（步骤 5 的写入目标）

1. 新工具链 / 依赖坐标 → `module-dev` 固定技术栈句（含追加段形态）
2. 新构建步骤 / profile → `module-dev` 门禁命令段
3. 新机器可判不变式 → `module-dev` 全局不变量清单（每条必须带可复制的复核命令）

### 设计沿革（防漂移记录）

登记曾分散在两个 skill 的六处（`module-dev`：分流表 / 章节映射表 / 模块落位表 /
颗粒度文档段；`module-doc-gen`：输入范围 / 章节映射表），每加一个 US 要手改六处、
三处同源（文档 + 两个 skill）易漂移。现收敛为：台账一处写入 + 两个 skill 规则句。
