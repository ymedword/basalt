# module-doc-gen — 生成模块执行颗粒度文档

## User Input

```text
$ARGUMENTS
```

## 职责与边界

- **产出**：`docs/us/us{N}-<slug>.md` 一份（六节结构，见下）；写入前先说明
  结构与来源，写后报告验证了什么。
- **不产出**：spec / plan / tasks（speckit 命令的活）、代码（`module-dev` 的活）。
- **与 module-dev 的衔接**：本文档是 `/module-dev` 的输入；module-dev 的
  步骤 5 用"交付物清单"做任务比对，步骤 7 用 harness 做对号——因此本 skill
  产出的清单必须**逐项可核**。

## 输入加载（完整读取，不得凭记忆）

1. 技术方案对应章节（按配置区「章节来源」取数规则）——**事实主源，最权威**；
2. 需求文档对应章节（WHAT / 验收 Demo）；
3. 宪法 `.specify/memory/constitution.md`（条款并入"设计要点与约束"）；
4. `specs/{NNN}-*/spec.md` 若已存在——文档不得与其冲突，锚点直接引用；
5. 可选参考文件（如其他项目的参考文档/讲义 PDF）——**只借结构与讲法，不借事实**。

## 文档结构（六节，固定，不增不减）

```text
1. 模块概述        —— 定位（一句话）+ 价值（WHAT/WHY，不带类名和技术栈）
2. 设计要点与约束  —— 职责边界表（本模块职责/非本模块职责）+ 关键约束清单
                      （每条对应宪法条款或版本纪律）；有核心逻辑的模块必须附
                      「核心逻辑」小节：流程图（ASCII 或 mermaid）+ 伪代码
3. 交付物清单      —— 代码/测试/配置/表四类；类级粒度 + 关键方法签名；不写方法体
4. 验收测试（Harness）—— 测试分层标准（是否访问真实网络）+ 测试类→验收点映射表 +
                         关键回归测试写出代码
5. 范围边界        —— 核心阶段不做项，逐项标注依据（需求文档 §6 /
                      技术方案"核心阶段不做"）
6. 验证与验收      —— 剩余人工项（真模型/真 webhook/冒烟/安全扫描/装配确认/
                      验收 Demo 锚点）
```

## 易漏维度核对表（生成时逐项核对，防遗漏）

历史遗漏教训（对照参考文档逐点比对时发现），每次生成文档必须逐项检查：

| 维度 | 处理要求 |
| --- | --- |
| 审计关联标识传导 | 每个写审计的组件签名必须写明关联标识（如 sessionId / runId）参数与来源；跨模块签名扩展必须进「前序改造点」 |
| 上下文对象传递机制 | Profile/Session/工具执行环境的取用路径必须写明（显式类型化参数 vs `context.WithValue`——后者只允许追踪标识），与权威文档裁决一致；与参考文档不同时写「差异裁决注」 |
| 前序改造点清单 | 触及前序交付契约（接口签名/字段扩展）的必须单列一节并标注软门禁 |
| 后续模块能力占位 | 下游模块接入的能力（如 Memory）必须显式写占位点与接入模块 |
| 缓存语义 | 文件加载类交付物必须写明"每次重读 vs 缓存"及修改后生效时机 |
| 边界行为返回语义 | 强制结束/超限等边界的技术方案未规定项 → 进文末「待决事项」，给出默认建议 |
| 并发泄漏类回归 | goroutine 泄漏 / context 未传播 / 共享状态竞态等"单请求测试测不出、并发才暴露"的 bug → 必须进 harness 关键回归（写出代码），并由 `go test -race` 覆盖 |
| 留痕顺序 | 循环/执行类伪代码必须体现"先留痕（写 `pending`）再判断/返回"的顺序（审计两阶段写，见宪法第 5 条与 `docs/contracts/run-and-errors.md` §7.2） |
| 配置占位符解析语义 | `${ENV_VAR}` 在加载/装配层的解析责任必须写明（未解析残留即拒、不静默取默认；明文检查按原始配置值判断） |
| LLM 响应字段可空性 | 带工具调用的响应 content 可能为空、usage 可空——循环/回填/历史组装逻辑必须写明兜底 |
| 失败信息回填闭环 | 工具/调用失败时错误信息必须回填进对话上下文——模型看不到结果就不会收敛（回填 content，空时用 errorMessage） |
| 依赖初始化副作用 | 新增第三方坐标先问用户、先核实（`GOPROXY=https://goproxy.cn go list -m -versions <module>`）；`import _` 副作用注册（如 SQLite 驱动）与 `init()` 行为必须在交付物清单写明 |
| 可观测性双轨 | 审计落库 ≠ 运行日志：失败路径两者都要（错误路径落审计 + WARN 日志），文档交付物清单必须点名日志职责 |
| 关键不变量负向用例 | 安全 / 并发 / 审计 / fail-closed 类不变量**必须**有拒绝路径用例（越权 / 越界 / 凭证回显 / 判定在发送前）；harness 条目须写明"**实现错时它怎么红**"（逆改点 / 变异口径），写不出逆改点的用例 = 无判别力，重新设计 |

## 强制规则

1. **事实只从项目文档取**：参考文件与项目文档冲突 → 以项目技术方案为准，并在
   文档对应位置写「差异裁决注」明示，不悄改。
2. **不发明概念**：交付物只到类级 + 关键方法签名；任何技术方案之外的新类型 /
   配置键 / 表 / 端点 → 不写进正文，列到文末「待决事项」交用户裁决。
3. **harness 先行**：测试函数名英文（中文验收点以注释保留，便于对号）；关键回归
   测试写出代码、断言逐条对应 FR；框架确切断言写法标注「以实测为准（写前核实）」。
4. **所有 FR 可测试**：每条 FR 必须被"设计要点与约束"里的验收点或 harness
   映射表覆盖。
5. **头部固定裁决句**：与最新技术方案冲突以技术方案为准；配套工件（spec/plan）
   已锁定的引用而不冲突。
6. **拿不准的不自定**：模型名、未决参数、验收口径、边界行为返回语义 → 文末
   「待决事项」清单，交用户裁决。
7. **核心逻辑必须有流程图 + 伪代码**：循环/状态机/关键链路类模块，第 2 节必须
   附「核心逻辑」小节——流程图（ASCII 或 mermaid）+ 伪代码；伪代码中的方法名/
   签名与交付物清单**逐字一致**，不得在伪代码里发明签名。
8. **harness 判别力**：**不得**以测试数量 / 覆盖率替代行为正确性；写出代码的
   关键回归必须能指出"实现改了它会不会红"（逆改点 / 变异口径）——写不出逆改点
   的用例按"对号入座但无判别力"处理，重新设计（红态判据见 `module-dev` 写后
   DoD：必须看到逐字的预期失败文案，不得只看退出码）。

## 产出后自检（写回前执行）

- 交付物清单 ↔ 技术方案章节逐项比对：无多、无缺；
- 测试类 ↔ FR 映射全覆盖；
- **harness 判别力抽查**：关键回归逐条能指出逆改点（实现怎么改它会红）；安全 /
  并发 / 审计 / fail-closed 类均有拒绝路径用例（负向用例）；
- 无外部概念、无凭空版本号（版本先核实纪律：写依赖坐标前查
  `GOPROXY=https://goproxy.cn go list -m -versions <module>`；npm 侧查 npm registry）。

### 输入与文档路径

- 输入：US 编号（整数 N）；可选参考文件路径
- 产出路径：`docs/us/us{N}-<slug>.md`（slug 取英文短名，如 `us1-foundation`）
- **不在本 skill 内维护 US 清单或章节映射表**——登记处是 `docs/us/REGISTRY.md`
  （US 台账，由 `/us-register N` 维护）
- US 是**开放序列**（US-15 起顺延，编号只增不改），见 `docs/Roadmap.md` §4.1

### 章节来源（取数规则）

- 台账**已有**该 US → 以台账「技术方案章节 / 需求文档章节」列为取数依据
- 台账**查无**（新 US 首次生成）→ 由本 skill 自行定位技术方案与需求文档的对应
  章节，写进文档头部「事实主源顺位」段，供随后 `/us-register N` 派生登记
- 技术方案**无对应章节**时 → 按上一条定位对照段，并在文档 §2.4 写全差异裁决注
  （module-dev 以该裁决链为主源，**不得**跳过冲突检查）
- US 触及 NivroOS 兼容承诺时（`docs/Compatibility.md` §2 对照矩阵行 / §5 共享验收
  样例）→ 对应节追加为**附加事实源**，写进文档头部「事实主源顺位」段；§5 样例
  同时作为该 US 的验收判据（逐条比对）；无涉及不读
- 台账由 `/us-register N` 写，**本 skill 不写台账**；登记完交棒 `/module-dev N`

逐字取自 `docs/Roadmap.md` §4.2 的**唯一取数规则增补**（仅"本 Roadmap"路径化）：

> 台账查无且 N > 14 时，「章节来源」**必须**取 `docs/Roadmap.md` 的对应方向节为事实源，写进颗粒度文档头部，供 `/us-register` 派生；方向节与四份权威文档冲突时，**以技术方案为准**（不变）。
