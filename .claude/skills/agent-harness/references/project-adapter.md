# 项目适配：把公共方法绑定到真实仓库

复制本 skill 到新项目后，复用已有配置；只有缺少映射时才建立 `harness/project.md`。
这是语义映射模板，不是可直接执行的配置；未填写项不能当默认批准或默认通过。

| 映射 | 项目应给出的事实 |
| --- | --- |
| 规则与契约 | 项目规则、需求 / 设计、接口与数据契约的路径及优先级 |
| 任务卡 | 模块卡路径、六类输入、专属验收所在位置；批准决定与所审版本如何记录 |
| 两处人工 review | 任务卡生成后与交付收口时；已有明确例外和权限边界 |
| 控制与实现 | 谁派生规格 / 计划 / 任务，谁持有外部断言，谁实现，谁独立复核 |
| 公共检查 | 唯一配置源、现有命令、超时、必跑与允许跳过规则 |
| 专属检查 | 失败模式、测试 / 数据 / 故障步骤、实际 task / check 映射与保护路径 |
| 执行节奏 | 快速本地、完整本地、独立 CI / 重型环境的范围与必验时机 |
| 结果读取 | 原始退出码、逐项状态、具名测试命中、报告与日志的真实读取方式 |
| 状态与恢复 | 过程记录的路径与所有者、输入指纹、累计预算；验收命令的并发锁 |
| 系统整合 | 链路、部署模式、实际依赖、对账与可观测 / 管理面的证据 |
| 隔离与清理 | 本轮资源的标识、清理规则、不能触碰的环境与凭证边界 |

先填本项目现有的工具和事实，不从其他项目复制数据库、语言版本、集群节点数、
覆盖率阈值或“十秒接管”等指标。指标来自任务需求，能力来自实际实现与运行证据。

由当前 Agent 使用 loop-programming skill 驱动，列出真实验收命令、结果与退出码，
在过程记录中持久化任务位置与预算；没有写出的状态不能声称已跨会话恢复。
验收程序不负责启动编码 Agent，不因命令叫 `test` 或返回 0 就推定覆盖完整。

迁移现有项目时保留既有批准、已完成任务和失败历史。先给工作区快照，再追加映射，
不重新初始化、不批量改历史输入，也不强制迁移到本 skill 的示例路径。
