# US 台账

每个 US 一行：类型、颗粒度文档、技术方案 / 需求文档对照章节、模块落位。**唯一登记处**——`module-dev` 与 `module-doc-gen` 只留取数规则句、不再内嵌 US 表（登记曾分散在两个 skill 的六处，现收敛为：台账一处写入 + 两个 skill 规则句）。

**维护方**：`/us-register N`。手工编辑本表时，**不得**改动已登记的历史行，只许追加。

**事实源顺位**：颗粒度文档（`docs/us/us{N}-*.md`）是本表的事实源，派生方向**单向**（文档 → 台账）；两者冲突时**以文档为准**，改台账不改文档。

**US 是开放序列（US-15 起顺延，编号只增不改）**，见 `docs/Roadmap.md` §4.1。本表**不预登记**——行随各 US 颗粒度文档产出逐行追加，不从文档倒推、不预留空行。

## 列定义

| 列 | 含义与取数 |
| --- | --- |
| US | US 编号（整数） |
| 类型 | `开发类` / `评审类` / `串联类` / `Demo 类`；缺省 `开发类`。处理方式见 `module-dev` 配置区的分流表 |
| 模块执行颗粒度文档 | `docs/us/us{N}-<slug>.md`（glob 匹配） |
| 技术方案章节 | `docs/TechnicalSolution.md` 的对应章节；技术方案无对应章节时写「**无对应章节**」+ 对照段。台账查无且 N > 14 时按 `docs/Roadmap.md` §4.2 取对应方向节为事实源 |
| 需求文档章节 | `docs/DemandAnalysis.md` 的对应章节 |
| 模块落位（摘要） | 交付物落到哪几个**内部包**（单 Go module + `internal/` 分包，不是构建模块）；细节以该 US 颗粒度文档 §3（交付物清单 + 改造点）为准 |
| 文档入库 | 颗粒度文档首次提交日（`git log --diff-filter=A --format=%ad --date=short`）；仓库尚未 `git init` / 文档未跟踪 → `未入库` |
