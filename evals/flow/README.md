# US19 固定控制样例与单 Agent 对照

输入、资料版本、路线和预期见 [固定语料](../../testdata/flow/workloads.json)，共12项，包含正常流程及必须停止的情形。资料正文由仓库文件固定，不下载外部内容。生产实例的Agent UID、生命周期版本和资源hash只能在隔离夹具装配后绑定，不能手写成发布证据。

[单Agent基线](baseline.json) 固定为同一原同步Run入口，使用相同资料、资源权限与根预算上限，由同一验收规则判定结果；不能把Run的`completed`当作任务验收成功。Flow额外节点的实际模型／工具调用与累计预算必须计入对照，不通过重置会话获得额外额度。

本地脚本模型只证明流程、拒绝、查证和账本控制，不能证明业务质量优势。所有12项必须分别命中预期；空证据、冲突、撤权、取消、预算和unknown样例的正确结果是停止／阻断。报告区分预期正确率、业务验收率、错误成功、非法调用、调用数、累计token与耗时。真实模型每策略至少3轮的对照仍须用户单独授权；当前不执行、不记通过。

## 对照边界补充

两臂使用相同冻结资料、完整输出 Schema、来源值验收器和后验根预算阈值。普通 Run 沿用既有配额与执行预算，不具备 Flow 的祖先预算预扣；单 token 案例在 Flow 侧发出前拒绝，普通侧仍可能调用一次并由同一后验判据拒绝，报告分别给出实际消耗，不能宣称机制完全相同。token 报告区分已知小计与未知用量调用数，未知不等于零成本。分支核对实际节点身份，工具逐条核对原审计名称、规范参数与次数。
