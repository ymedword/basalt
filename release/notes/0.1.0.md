# Basalt 0.1.0 发布说明

## 摘要

Basalt 0.1.0 是首个正式版本：面向企业自托管的 Agent OS，单 Go 二进制承载多个独立业务 Agent，共享渠道接入、模型路由、工具调用、记忆、知识与调度底座。本版本提供 windows/amd64、linux/amd64 两个**含随包运行时**的完整归档，以及 linux/arm64、darwin/arm64 两个仅产品二进制的归档；首发部署支持档为 Compose 多 Worker（一个控制面 `serve` + 至少一个 Worker `gateway` + 共享 PostgreSQL）与本机 `LocalRunner` 执行档。

## 变更

- 单二进制 Agent OS：一个进程托管多个业务 Agent，Agent 定义、配置与业务状态按目录隔离，执行、接入、调度、存储与审计底座共享。
- 自实现 ReAct 循环与工具调度；模型客户端只做协议调用，不接管循环。默认 `LocalRunner` 执行档，容器隔离（OCI / gVisor）为实例级 opt-in。
- 渠道接入、模型路由、记忆（含语义召回与确认）、知识库（PostgreSQL + pgvector）、会话历史与滚动压缩。
- 定时调度、可视化 Flow 协作与任务验证、可观测与执行诊断、学习准入与受控演进。
- 分布式执行：数据库租约、fencing 写保护、调度去重、回收与内容寻址资产 bundle；Compose 双角色多 Worker 交付（`docker/compose.multiworker.yaml`）。
- 首次安装链路：`basalt init`、首次 `serve` 自动初始化、`basalt demo workflow prepare` 幂等预演与安装；SQLite v6 → PostgreSQL v12 迁移工具。
- 发布工程：四平台归档、`basalt-verify` 下载侧独立校验、SBOM、provenance 与 Ed25519 签名。

## 升级步骤

1. 停止全部旧进程（多 Worker 拓扑必须整组停），备份 PostgreSQL、每个工作区、`master.key` 与管理凭据、旧镜像与旧二进制。
2. 解压对应平台归档，替换 `basalt` 二进制（含随包运行时的归档请整目录替换，不要只换二进制）。
3. 由新控制面执行 `basalt db migrate`，确认 schema 版本后启动服务，检查 `/api/v1/health`。
4. 多 Worker 拓扑先启控制面、再启 Worker；跨 schema 升级必须停全部旧进程，不允许新旧混跑。
5. 失败时按「回滚」整组恢复；只恢复数据库不足以回滚。

## 部署支持矩阵

| 形态 | 状态 | 说明 |
| --- | --- | --- |
| Compose 多 Worker（`docker/compose.multiworker.yaml`） | 已支持 | 一个控制面 `serve` + 至少一个 Worker `gateway` + 共享 PostgreSQL；单宿主编排按 Operations §8.3 |
| `LocalRunner` 执行档 | 已支持 | 默认执行档，本版本唯一验证过的工具执行方式 |
| K8s 单实例 / 多 Worker | 未验证 | 规划项，不得用本版本证据冒充 |
| 数据库 HA（主备 / 自动故障转移） | 未验证 | 不在本版本范围；PostgreSQL 单实例是唯一受支持形态 |
| 真实双宿主（A + B 云服务器） | 未验证 | 编排与自动化按单宿主验证；两宿主实测在首发后补充 |

容器隔离（OCI / gVisor）是实例级 opt-in，不在首发支持矩阵内；开启后 5 个 daily 脚本受影响，4 个 Flow 角色只读不受影响，可回退 local。

多 Worker 拓扑升级：先停全部旧进程，备份数据库、每个工作区、密钥与旧镜像，新控制面先迁移，再启动新 Worker；同 schema 的两个版本之间不宣称制品版本门禁，"不得新旧混跑"是部署纪律。回滚是整组恢复（数据库 + 每个工作区 + 主密钥 + 旧镜像），只恢复数据库不足以回滚。

## 已知问题

- linux/arm64 与 darwin/arm64 归档为产品二进制档（binary），不含随包 Node / Python / dbhub / github-mcp-server / fetch 运行时；依赖随包运行时的 MCP 工具需自行提供运行时，或改用 windows/amd64、linux/amd64 完整归档。
- darwin/arm64 与 linux/arm64 只做了宿主上的二进制启动验证（`basalt --version`），未跑完整 smoke 与管理台验收。
- 自动化验收不调用真实模型：模型相关行为用本地协议桩与冻结夹具验证，真实模型效果需部署后自行配置验证。
- 容器隔离、K8s、数据库 HA 与真实双宿主均未验证，见上方支持矩阵。
- 自动升级入口按受限方式交付：升级与回滚按本说明手动执行，不以工具输出冒充升级完成。

## 校验与签名

只使用下载目录中的 `basalt-verify`，但公钥与校验器哈希必须从发布页 / 运维记录等「带外」渠道核对，下载目录里的同名文件不能当作信任根：

```text
basalt-verify --release-dir <下载目录> --public-key <带外取得的公钥>
```

`SHA256SUMS` 覆盖发布目录中的全部文件，签名在 `SHA256SUMS.sig` 与 `release-record.json.sig`。

## 回滚

停止新服务，恢复升级前的 PostgreSQL、workspace、配置、主密钥与 `basalt.old`，再启动旧版。
