# Basalt 0.2.1 发布说明

## 摘要

Basalt 0.2.1 在 0.1.0 的 Compose 多 Worker 交付之上补齐「数据库权威」的一致性闭环：控制台管理的 Agent 定义与配置、技能正文，以及四类运行期策略（允许域、拒绝域、网络例外、执行档位）在所有 Worker 上按数据库权威自动生效，不再依赖手工重导种子或重启碰运气。发布仍提供 windows/amd64、linux/amd64 两个**含随包运行时**的完整归档，以及 linux/arm64、darwin/arm64 两个仅产品二进制的归档；部署支持档不变，仍为 Compose 多 Worker（一个控制面 `serve` + 至少一个 Worker `gateway` + 共享 PostgreSQL）与本机 `LocalRunner` 执行档。

本版本取代**从未正式发布**的 0.2.0 候选：0.2.0 的 tag 已推送到源码仓库，但对应提交的自动化验收（CI）未通过、其 Release 始终保持草稿未发布，因此不存在 0.2.0 的正式制品。0.2.1 在 0.2.0 的功能内容之上修复自动化验收暴露的问题，并以修复后的提交重新构建全部制品；`v0.2.0` tag 未被移动。

## 变更

- 已发布资产跨 Worker 分发：发布先写确定性的内容寻址载荷、再移动资源指针；Worker 以四态同步机（pending / installed / ready / blocked）有界拉取并逐文件校验，失败项按轮次公平重试，恢复后自动补齐，旧版本在同步失败期间继续服务。
- 技能发布联动：技能新版本发布后，直接依赖它的 Agent 被联动重发；技能正文物化到各 Worker 的本机发布版本目录并按文件校验；晚到的旧版本不覆盖新版本，转为 blocked 的失败项在后续全量扫描轮复位，运行期无需重启。
- 运行期固定版本：Run 领取事务内钉住 bundle 哈希，并与执行租约在同一事务复核；Entry、定义与技能取自同一固定 bundle，在途 Run 不因同步切版本。
- 四类运行期策略（允许域 / 拒绝域 / 网络例外 / 执行档位）一致快照刷新；过期判定取最近一次成功核对时间，只有读失败才在准入返回 `POLICY_STALE`（503）。
- 注册表与调度集合同轮、固定顺序刷新：运行期新增 Agent 不重启即可被下一轮扫描领取；到期扫描使用两段键集轮转与冻结圈界，持续高频到期仍能结束一圈并重新发现新增任务。
- 概览「分布式执行」按进程实例给出服务端计算的三态读数（心跳正常 / 心跳超时待确认 / 已停止）与全库计数，读取失败显示「状态不可用」而不是 0；状态只作显示，不参与准入、调度或租约接管。
- 修复复核发现的缺陷：Worker 的 MCP 准备链缺少换入前复核接线并在不可重入的资源锁上自死锁；技能重发转 blocked 后运行期不再自愈；发布失败的审计收尾没有时间上限（现为显式 5 秒预算）。
- 发布门修复（相对 0.2.0 候选）：启动失败停机路径会取消资产同步与策略刷新两个后台循环，停机在预算内完成并保留「停机完成」标记；Worker 启动时以只读方式准备已 applied 的 MCP server（不写 applied、不补凭据来源），一次性命令与同步轮之前依赖 MCP 的 Agent 均可注册；自动化验收夹具改由短命控制面进程完成共享初始化预热。产品行为只在上述修复面变化。
- 同步更新管理台构建产物、契约与 OpenAPI、运维与部署文档；无新增 Go / npm 依赖。

## 升级步骤

1. 停止全部旧进程（多 Worker 拓扑必须整组停），备份 PostgreSQL、每个工作区、`master.key` 与管理凭据、旧镜像与旧二进制。
2. 解压对应平台归档，替换 `basalt` 二进制（含随包运行时的归档请整目录替换，不要只换二进制）；由新控制面执行 `basalt db migrate`，schema 版本从 12 前向推进到 13。
3. **先启动新控制面**：启动链为存量已发布指针回填数据库载荷（幂等、可重复）。回填只接受与本机目录逐字自洽的来源，缺失或损坏逐条记为 `payload_missing` / `corrupt`，不伪造、不写空载荷、不移动指针。
4. 用 `basalt assets status` 与启动日志核对回填结果；确认 `/api/v1/health` 正常后再启动各 Worker。Worker 只校验 schema 版本，不建库、不迁移。
5. 全部 Worker 就绪后，在概览「分布式执行」确认各进程实例状态；跨 schema 升级必须停全部旧进程，不允许新旧混跑。
6. 失败时按「回滚」整组恢复；只恢复数据库不足以回滚。

## 部署支持矩阵

| 形态 | 状态 | 说明 |
| --- | --- | --- |
| Compose 多 Worker（`docker/compose.multiworker.yaml`） | 已支持 | 一个控制面 `serve` + 至少一个 Worker `gateway` + 共享 PostgreSQL；单宿主编排按 Operations §8.3 |
| `LocalRunner` 执行档 | 已支持 | 默认执行档，本版本唯一验证过的工具执行方式 |
| K8s 单实例 / 多 Worker | 未验证 | 规划项，不得用本版本证据冒充 |
| 数据库 HA（主备 / 自动故障转移） | 未验证 | 不在本版本范围；PostgreSQL 单实例是唯一受支持形态 |
| 真实双宿主（A + B 云服务器） | 未验证 | 发布证据按单宿主采集；两宿主实测在首发后补充 |

容器隔离（OCI / gVisor）是实例级 opt-in，不在首发支持矩阵内；开启后 5 个 daily 脚本受影响，4 个 Flow 角色只读不受影响，可回退 local。

多 Worker 拓扑升级：先停全部旧进程，备份数据库、每个工作区、密钥与旧镜像，新控制面先迁移并完成载荷回填，再启动新 Worker；同 schema 的两个版本之间不宣称制品版本门禁，"不得新旧混跑"是部署纪律。回滚是整组恢复（数据库 + 每个工作区 + 主密钥 + 旧镜像），只恢复数据库不足以回滚。

## 已知问题

- 0.2.0 的 tag（`v0.2.0`）指向的提交未通过自动化验收，该候选从未发布正式制品；请使用本页的 0.2.1 制品，不要用 `v0.2.0` tag 的源码自行构建发布。
- 载荷按内容寻址去重，但本版本**不交付自动清理（GC）**，也不提供保留期配置键；数据库存储不宣称有界。
- `worker_nodes` 历史登记行不自动清理，保留期与清理策略另立模块。
- linux/arm64 与 darwin/arm64 归档为产品二进制档（binary），不含随包 Node / Python / dbhub / github-mcp-server / fetch 运行时；依赖随包运行时的 MCP 工具需自行提供运行时，或改用 windows/amd64、linux/amd64 完整归档。
- darwin/arm64 与 linux/arm64 只做了宿主上的二进制启动验证（`basalt --version`），未跑完整 smoke 与管理台验收。
- 自动化验收不调用真实模型：模型相关行为用本地协议桩与冻结夹具验证，真实模型效果需部署后自行配置验证；真实 webhook 与通知渠道同样未由发布流程验证。
- A+B 两宿主真实链路（控制台发布 → 两端执行 → 核对版本哈希与实际配置值）不在本发布的自动化证据内，部署后单独登记。
- 容器隔离、K8s 与数据库 HA 均未验证，见上方支持矩阵。
- 自动升级入口按受限方式交付：升级与回滚按本说明手动执行，不以工具输出冒充升级完成。

## 校验与签名

只使用下载目录中的 `basalt-verify`，但公钥与校验器哈希必须从发布页 / 运维记录等「带外」渠道核对，下载目录里的同名文件不能当作信任根：

```text
basalt-verify --release-dir <下载目录> --public-key <带外取得的公钥>
```

`SHA256SUMS` 覆盖发布目录中的全部文件，签名在 `SHA256SUMS.sig` 与 `release-record.json.sig`。

本发布页另附**不计入** `SHA256SUMS` 的补充资产，按发布页公开的 SHA-256 单独核对：

| 补充资产 | 内容 | 校验方式 |
| --- | --- | --- |
| `basalt-0.2.1-deploy.tar.gz` | 两角色 Compose、环境模板、部署脚本、安装说明与运维手册 | 摘要见本 Release 页面 |
| `basalt-0.2.1-image-linux-amd64.tar` | `docker load` 镜像包 | 摘要见本 Release 页面；加载步骤见部署包内 `IMAGE-LOAD.md` |

`basalt-verify` 只对「发布目录」运行：该目录只放本页列出的签名制品，补充资产放在其他目录，不要混入校验目录。镜像以 `docker save` 包交付、未推送注册表；加载后按 `IMAGE-LOAD.md` 用本地镜像 ID 组成 `版本@sha256:` 写入 `BASALT_IMAGE`。

## 回滚

停止新服务，恢复升级前的 PostgreSQL、workspace、配置、主密钥与 `basalt.old`，再启动旧版。
