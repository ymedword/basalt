## User Scenarios & Testing *(mandatory)*

### User Story 1 - 业务系统以 HTTP 完成多轮会话 (Priority: P1)

工单系统运维在已启动的服务实例上，为一位业务用户创建（或复用）一个 Agent 会话，发送一条消息并拿到本轮运行结果，随后读取该会话最近的历史，最后把会话归档。每一步都由统一信封承载，成功与失败可用同一套解析逻辑处理。

**Why this priority**: 这是本模块存在的核心理由——没有这条有状态会话链路，外部系统无法把 Agent 接入业务流程；其余端点都围绕它展开。

**Independent Test**: 启动服务后，用任意 HTTP 客户端依次调用建会话、发消息、取历史、归档四个端点，校验每步响应信封与业务数据；全过程不依赖 CLI 交互。

**Acceptance Scenarios**:

1. **Given** 服务已启动且配置了可用 Agent，**When** 以同一（渠道、用户、Agent）元组两次创建会话，**Then** 两次都返回同一会话标识，第二次不新建会话、不改写创建时间。
2. **Given** 一个 active 会话，**When** 发送一条不超过 32 KiB 的消息，**Then** 返回统一信封，`data` 含运行状态、最终文本、运行标识与触发来源 `api`。
3. **Given** 一个已有超过 100 条消息的会话，**When** 读取会话详情，**Then** 只返回最近 100 条且按发生顺序升序排列。
4. **Given** 一个 active 会话，**When** 归档该会话，**Then** 返回无载荷成功信封（不含 `data`），会话状态变为已归档；再次归档返回同样的无载荷成功且首次归档时间不变。
5. **Given** 一个已归档会话，**When** 读取详情，**Then** 历史照常返回；**When** 向其发送消息，**Then** 返回 400 且提示会话已归档。

### User Story 2 - 一次性任务的无状态调用 (Priority: P2)

第三方巡检平台只需对某个 Agent 执行一次任务并拿到结果，不希望在系统里留下会话历史。它调用无状态调用端点，得到本轮运行结果，响应中的会话标识为空；运行记录与审计仍然照写，便于事后追溯。

**Why this priority**: 无状态调用让 HTTP 接入覆盖「一次性任务」这一半场景，且与有状态链路共享同一执行入口；缺少它，外部系统只能为一次性任务制造垃圾会话。

**Independent Test**: 对一个已存在的会话先取历史并记录消息数，再调用无状态端点，最后再次取该会话历史——消息数不变；同时确认本次运行的运行记录存在。

**Acceptance Scenarios**:

1. **Given** 服务运行中，**When** 调用 `POST /api/v1/agents/{name}/invoke`，**Then** 返回信封的 `data` 中会话标识为空字符串，且系统未创建任何会话。
2. **Given** 一次无状态调用完成，**When** 查看该既有会话的历史，**Then** 消息数与本轮运行前一致。
3. **Given** 一次无状态调用完成，**When** 检查运行记录与审计，**Then** 本轮运行已入库（无会话关联）。

### User Story 3 - 并发准入与运行边界 (Priority: P3)

业务方在高峰期可能对同一会话重复提交，或同时提交超过实例承载能力的任务。系统必须立刻给出确定性的拒绝语义（不排队）：同一会话已有在途运行时返回「会话忙」，实例并发超限返回「实例过载」并点名当前上限。运行自身还有迭代 / 工具次数上限与 60 秒时限，触发时以 200 + 明确状态或 504 表达。

**Why this priority**: 没有准入，HTTP 面会绕过既有的执行约束，出现重复追加或资源失控；它决定系统在并发下是否可信。

**Independent Test**: 构造一个阻塞中的运行，向同一会话再发一条消息，确认返回 409 与冻结文案；构造第二个并发运行超过配置上限，确认 429 且文案含上限值；把预算调到 1 轮迭代，确认返回 200 + `limit_reached` 且文案点名可调配置键。

**Acceptance Scenarios**:

1. **Given** 同一会话有一个在途运行，**When** 再发送消息，**Then** 返回 409 `SESSION_BUSY`，文案逐字为「该会话有正在执行的任务，请等待完成或稍后重试」。
2. **Given** 实例并发上限为 1 且已有一个在途运行，**When** 在另一会话发起运行，**Then** 返回 429 `TOO_MANY_RUNS`，文案含数字 1。
3. **Given** 运行达到迭代上限，**When** 本轮返回，**Then** HTTP 状态为 200、错误码为 `LIMIT_REACHED`、状态为 `limit_reached`，文案点名 `budget.max_iterations`。
4. **Given** 运行超过 60 秒，**When** 时限到达，**Then** 返回 504 `TIMEOUT`，且该运行记录为已取消。
5. **Given** 配置把迭代预算设为 2，**When** 发起一次 HTTP 运行，**Then** 运行实际使用该预算（而非硬编码缺省值）。

### User Story 4 - 运维探活与只读清单 (Priority: P4)

运维与集成方在接入前需要确认服务健康、进程能力、已注册 Agent、可用工具与全局记忆内容。五个只读端点给出这些信息，且不产生任何副作用、不回显凭证。

**Why this priority**: 只读面是接入期的排障入口；它不承担业务写入，但决定了外部系统能否自助完成配置校验。

**Independent Test**: 对五个只读端点各发一次 GET，确认信封结构与字段；在有一个未注册 Agent 的配置下，确认 `/profiles` 返回该条目且 `problems` 非空，而 `/info` 的 Agent 计数只算已注册项；扫描响应确认无凭证字段。

**Acceptance Scenarios**:

1. **Given** 服务运行中，**When** 调用 `GET /api/v1/health`，**Then** 返回 200 与健康状态。
2. **Given** 已连接 2 个 MCP 服务器、装载 1 个已注册与 1 个未注册 Agent，**When** 调用 `GET /api/v1/info`，**Then** `mcp_servers` 为 2、`agents` 为 1，且响应不含任何 API key 或 base URL。
3. **Given** 工具注册池含内置与 MCP 工具，**When** 调用 `GET /api/v1/tools`，**Then** 顺序与注册顺序一致，来源分别标注为 `builtin` / `mcp` / `code`。
4. **Given** 全局记忆有核心区与归档区内容，**When** 调用 `GET /api/v1/memory`，**Then** 两分区均带标题返回；空分区返回空字符串而非仅标题。
5. **Given** 任一未注册 Agent，**When** 调用 `GET /api/v1/profiles`，**Then** 该条目 `registered` 为 false 且 `problems` 恰含一条拒绝原因。

### User Story 5 - 进程模式与安全默认 (Priority: P5)

运维通过 `basalt serve` 启动 HTTP 服务，通过 `basalt gateway` 启动占位进程（调度能力归后续阶段），`basalt chat` 保持纯 CLI。默认只监听本机回环；跨源写请求默认被拒绝；服务端超时覆盖「慢请求体 + 长运行 + 写响应」全段；收到中断信号后按五阶段优雅停机，在途运行先收尾、超时才取消，最后才释放共享资源。

**Why this priority**: 进程模式决定服务能否被安全地部署与运维；它不改变业务语义，但没有它，前四个故事无法以真实进程形态交付。

**Independent Test**: 启动 `serve` 并用真实连接验证监听地址、默认回环、跨源写拒绝与优雅停机事件序；启动 `gateway` 确认只打占位日志、不占端口；启动 `chat` 确认不占端口。

**Acceptance Scenarios**:

1. **Given** 未配置监听地址，**When** 启动服务，**Then** 只监听 `127.0.0.1:8080`。
2. **Given** 服务运行中，**When** 浏览器从恶意来源发起跨站 POST，**Then** 返回 403 信封且运行未被触发；**When** 同一来源发起 GET，**Then** 正常返回且响应不包含任何跨域允许头。
3. **Given** 客户端慢速上传请求体，**When** 运行耗时接近上限，**Then** 响应完整返回而非被写超时截断。
4. **Given** 有在途运行，**When** 进程收到中断信号，**Then** 监听先停止、运行在宽限期内继续并可完成；宽限到期才取消运行并关闭连接；运行返回后进程才释放共享资源。
5. **Given** `basalt gateway` 启动，**When** 查看日志，**Then** 明示调度器 / 通道族归后续阶段，且未监听 HTTP 端口。

### Edge Cases

- 单条消息恰为 32768 字节时接受；32769 字节时在运行开始前拒绝为 400。
- 请求体超过配置上限（缺省 1 MiB）时返回 400（不是 413），且不进入解析与运行。
- 消息字段缺失或为 `null` → 400；空字符串是合法消息，照常运行。
- JSON 对象之后跟有尾随内容 → 400；未知字段被忽略。
- 未知路径或未定义方法 → 统一 404 信封（不区分 405）。
- 同一元组创建会话时，目标行已被归档 → 返回既有归档行，不复活、不改写。
- 创建会话时 `agent` 缺失 / `null` → 400「agent 必填」且零写入；未知或未注册 Agent → 404。
- 既有会话绑定的 Agent 已不存在或未注册 → 追加消息 404（回显 Agent 名），不启动运行。
- 运行以失败结束 → HTTP 200、状态 `failed`，但对外原因只给固定公开文案，绝不出现路径、SQL、堆栈或内部哨兵值。
- 归档请求到达时该会话有在途运行 → 409，归档不生效，运行继续到底。
- 运行请求到达时该会话恰被归档 → 400（线性化结果），不残留在途计数。
- 中间件内发生 panic → 500 信封 + 错误日志（堆栈只进日志）；已写响应头则不再写第二份信封。
- 无 `Origin` 的非浏览器客户端调用写端点 → 放行；`Sec-Fetch-Site: cross-site` → 403。
- 无状态调用只可能遇到 429，不存在 409（没有会话可锁）。
- 服务端连接在宽限期结束后仍未收尾 → 取消运行、关闭活动连接；5 秒有界等待到期仍有请求在执行时记录错误日志并继续等待在途请求全部退出（等待超时不等于已退出）。
- 监听器异常退出（`Serve` 返回错误）→ 执行与中断信号相同的收尾路径（取消在途、关闭连接、等待在途归零）后才返回，调用方随后才释放共享资源。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 恰好提供 10 个核心端点：`GET /api/v1/health`、`GET /api/v1/info`、`GET /api/v1/profiles`、`GET /api/v1/tools`、`GET /api/v1/memory`、`POST /api/v1/sessions`、`GET /api/v1/sessions/{id}`、`DELETE /api/v1/sessions/{id}`、`POST /api/v1/sessions/{id}/messages`、`POST /api/v1/agents/{name}/invoke`；MUST NOT 提供会话列表端点（归后续管理台阶段）。
- **FR-002**: 未匹配的路径或方法 MUST 返回统一信封的 404，而不是默认纯文本响应。
- **FR-003**: 所有响应 MUST 使用统一信封：成功包含 `data`，失败省略 `data`；时间戳 MUST 为 UTC 的 RFC3339 表示；内容类型 MUST 声明 JSON 与 UTF-8。
- **FR-004**: 归档成功是唯一无载荷成功例外：MUST 省略 `data`，`message` 固定为 `success`。
- **FR-005**: HTTP 层 MUST 只产生八个错误码：`OK`、`BAD_REQUEST`、`NOT_FOUND`、`SESSION_BUSY`、`TOO_MANY_RUNS`、`LIMIT_REACHED`、`TIMEOUT`、`INTERNAL`；`UNSUPPORTED_TYPE` 与 `NOT_CONFIGURED` 为契约保留码，本阶段 MUST NOT 产生。
- **FR-006**: 错误到 HTTP 状态与错误码的映射 MUST 依据错误类型而非错误文本。
- **FR-007**: 同一会话已有在途运行时，新运行请求 MUST 返回 409 `SESSION_BUSY`，文案逐字为「该会话有正在执行的任务，请等待完成或稍后重试」。
- **FR-008**: 实例并发运行数达到上限时 MUST 返回 429 `TOO_MANY_RUNS`，文案 MUST 含当前生效上限值；准入 MUST NOT 排队或等待。
- **FR-009**: 运行达到迭代或工具调用上限时 MUST 返回 HTTP 200、错误码 `LIMIT_REACHED`、`data.status = "limit_reached"`，文案 MUST 点名对应的可调配置键。
- **FR-010**: 每个 HTTP 运行的预算 MUST 取自配置文件中的预算段，MUST NOT 回落到与配置无关的硬编码缺省。
- **FR-011**: 每个请求的运行 MUST 有 60 秒时限；到期 MUST 返回 504 `TIMEOUT`，且运行记录为已取消。
- **FR-012**: 归档 MUST 只改写会话状态与首次归档时间；MUST NOT 删除消息、会话、运行记录或审计；重复归档 MUST 幂等。
- **FR-013**: 当会话有在途运行时，归档请求 MUST 被拒绝为 409（复用冻结文案），归档 MUST 不生效，会话状态与消息 MUST 保持不变。
- **FR-014**: 已归档会话 MUST 仍可读取历史；向其发送消息 MUST 返回 400 `BAD_REQUEST`，文案固定「会话已归档，不可追加消息」。
- **FR-015**: 会话详情 MUST 返回最近 100 条消息并按发生顺序升序；系统 MUST NOT 接受请求派生的排序或分页参数。
- **FR-016**: 创建会话 MUST 以（渠道、用户标识、Agent 名）元组确定性派生会话标识；请求未提供时 MUST 取缺省 `channel = web`、`user_id = anonymous`；同元组重复创建 MUST 返回既有行，MUST NOT 改写创建时间或复活已归档行。
- **FR-017**: 会话标识派生 MUST 对 CLI 与 HTTP 共用同一实现；派生结果 MUST 仅含安全字符（小写字母、数字、连字符），对不合规渠道名 MUST 使用固定安全前缀，且既有 CLI 固定向量 MUST 保持不变。
- **FR-018**: 无状态调用 MUST 使用空会话标识，MUST NOT 创建会话或追加消息；运行记录与审计 MUST 照常写入；运行 MUST 记 `UserID = anonymous`、`Channel = web`。
- **FR-019**: 所有 HTTP 运行的渠道 MUST 记为 `web`，视图触发来源 MUST 记为 `api`。
- **FR-020**: 单条消息 MUST 按 UTF-8 字节计不超过 32 KiB（32768 字节允许，32769 拒绝），判定 MUST 发生在运行开始之前；有状态与无状态入口 MUST 同受此限。
- **FR-021**: 请求体总量 MUST 受配置上限约束（缺省 1 MiB），超限 MUST 返回 400（不是 413）。
- **FR-022**: 请求解码 MUST 忽略未知字段；对象解析后 MUST 读到输入结尾（尾随内容 → 400）；必填字段 MUST 区分缺失 / `null` 与空字符串。
- **FR-023**: 服务端超时 MUST 为：读头 5 秒、读 60 秒、空闲 120 秒、写超时 = 读超时 + 运行时限 + 10 秒余量（缺省 130 秒）；写超时 MUST NOT 写成与运行时限同量级的常数。
- **FR-024**: 未显式配置监听地址时 MUST 只监听 `127.0.0.1:8080`；远程暴露 MUST 要求运维显式修改配置。
- **FR-025**: 收到中断信号后 MUST 按五阶段停机：停止接入 → 宽限等待（缺省 70 秒）→ 超时取消并断开 → 有界等待收尾（5 秒）→ 释放共享资源；基上下文 MUST 与信号解耦，宽限期 MUST NOT 被信号直接取消。监听异常退出（`Serve` 返回错误）MUST 走同一收尾路径；有界等待到期 MUST 记录错误并继续等待在途请求全部退出，等待超时 MUST NOT 被视为已退出，共享资源 MUST 在全部在途请求退出后才释放。
- **FR-026**: 中间件链顺序 MUST 为：panic 恢复 → 请求日志 → 跨源保护。
- **FR-027**: 跨源保护 MUST 放行安全方法；对非安全方法依据来源信息拒绝跨站请求，拒绝响应 MUST 为 403 信封（错误码 `BAD_REQUEST`、固定文案）且零副作用；系统 MUST NOT 输出任何跨域允许头。
- **FR-028**: panic MUST 记错误日志（含请求标识与堆栈，堆栈只进日志）；响应未开始时 MUST 返回 500 信封。请求标识 MUST 在中间件链首生成并注入请求上下文，panic 日志与请求完成日志 MUST 共享同一标识；请求完成日志 MUST 以延迟方式记录，panic 且未写响应头时 MUST 记录状态 500。
- **FR-029**: 对外响应 MUST NOT 出现底层错误串、文件路径、堆栈、SQL 片段或凭证；500 文案 MUST 固定为「服务器内部错误」；运行以失败正常返回时 `data.reason` MUST 只取固定公开文案（失败 / 已取消 / 达到上限）。运行以失败结束时 MUST 另记一条经脱敏的内部诊断日志（含运行标识、请求标识、会话标识与 Agent 名）；客户端在运行返回前断开时同样 MUST 记录该诊断；原始原因 MUST NOT 直接写入日志。脱敏 MUST 覆盖 Authorization 头连同 scheme 与凭证、Bearer 令牌、凭证键值（带引号值 MUST 整体识别，支持空格与反斜杠转义；未闭合引号 MUST 遮蔽到串尾）、引号字面量（含反斜杠转义）、URL、绝对 / UNC 路径与 SQL 正文（含多行语句）。
- **FR-030**: 元数据端点 MUST 只读，MUST NOT 产生副作用；`/memory` MUST 只读全局层且不接受 Agent 参数。
- **FR-031**: `/profiles` MUST 按装载顺序返回；未注册条目 MUST 在 `problems` 恰含一条拒绝原因；空数组字段 MUST 输出 `[]`。
- **FR-032**: `/tools` MUST 按注册顺序返回，并正确标注来源为 `builtin` / `mcp` / `code`。
- **FR-033**: `/memory` MUST 返回带标题的核心区与归档区；空分区 MUST 为空字符串；`backend` MUST 取归一化配置（空 → `markdown`）。
- **FR-034**: `/info` MUST NOT 回显任何凭证或端点地址；`mcp_servers` MUST 为真实已连接数；`agents` MUST 为已注册 Agent 数（不含未注册项）。
- **FR-035**: `serve` MUST 在全量装配前幂等自动初始化工作区；`gateway` 与 `chat` MUST NOT 自动初始化。
- **FR-036**: `serve` MUST 启动 HTTP 并阻塞至信号；`gateway` MUST 全量装配后打印占位信息并阻塞至信号，MUST NOT 启动 HTTP；`chat` MUST NOT 启动 HTTP；三种模式 MUST 共享同一装配顺序与同一把实例锁。
- **FR-037**: 配置键 `server.max_concurrent_runs` MUST 落位：缺省或 0 表示 32，负数 MUST 在配置装载阶段拒绝，取值 MUST 接线到运行入口的并发上限。
- **FR-038**: 会话状态复核与在途运行登记 MUST 在同一把服务级准入锁内完成；在途计数归零后 MUST 清除对应表项。
- **FR-039**: 创建会话时 `agent` 缺失或为 `null` MUST 返回 400 `BAD_REQUEST`「agent 必填」；未知或未注册 Agent MUST 返回 404；两条失败路径 MUST NOT 创建或修改任何会话。
- **FR-040**: 既有会话绑定的 Agent 已不存在或未注册时，追加消息 MUST 返回 404 `NOT_FOUND`（回显请求的 Agent 名），且 MUST NOT 启动运行。

### Key Entities *(include if feature involves data)*

- **会话（Session）**：一次持续对话的身份；由渠道、用户标识与 Agent 名派生唯一标识；含状态（active / archived）、创建时间、首次归档时间、渠道与消息计数。
- **消息（Message）**：会话内的一次输入或输出（用户、助手、工具结果）；按会话内序号排序；是历史窗口与运行回填的事实源。
- **运行（Run）**：一次执行记录；含运行标识、会话标识（无状态时为空）、Agent、渠道、状态、原始原因与时间；HTTP 视图从中投影状态与最终文本。
- **Agent 条目（Agent Entry）**：一个 Agent 目录的装载结果；含是否注册、拒绝原因与配置摘要（供应商、模型、调度数、工具与技能声明）。
- **工具清单项（Tool Entry）**：注册池中的一个工具；含名称、描述、输入模式与来源分类（内置 / MCP / 代码注册）。
- **记忆分区（Memory Sections）**：全局层的核心区与归档区；只读展示，带标题，空分区为空字符串。
- **信封（Envelope）**：所有响应的统一外层；含错误码、消息、可选数据与 UTC 时间戳。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 外部系统可在不接触命令行的情况下，通过 HTTP 完成「建会话 → 发消息 → 取历史 → 归档」全流程，四个步骤的响应均符合同一信封结构。
- **SC-002**: 同一会话的并发第二个运行请求在 1 秒内得到 409 与冻结文案；实例并发超限的请求在 1 秒内得到 429 且文案包含当前上限值。
- **SC-003**: 会话历史读取在一次响应内返回最近 100 条消息，顺序 100% 与发生顺序一致。
- **SC-004**: 对全部错误路径与失败运行响应的检查中，0 次出现凭证、绝对路径、堆栈或内部哨兵值。
- **SC-005**: 默认配置下，监听端口只绑定本机回环地址；未显式修改配置时远程无法直连。
- **SC-006**: 收到中断信号后，在途运行在宽限期内可正常完成；宽限到期后运行被取消。5 秒有界等待到期时若仍有在途请求，进程 MUST 记录错误并继续等待，只有在途请求全部退出后进程才返回并释放共享资源；监听异常退出时同样满足上述顺序。
- **SC-007**: 10 个核心端点全部返回统一信封；未知路径与方法返回 404 信封，0 次返回纯文本。
- **SC-008**: 配置迭代预算为 2 时，HTTP 运行在第 2 轮触达上限并返回 `limit_reached`；预算配置对运行实际生效（非硬编码缺省）。
- **SC-009**: 32 KiB 边界行为可判定：32768 字节接受、32769 字节在运行前拒绝；请求体超限返回 400。
- **SC-010**: 跨站写请求 100% 被拒绝且未触发运行；跨域响应中 0 个跨域允许头。

## Assumptions

- 运行入口、会话 / 消息 / 运行仓储、工具注册池、记忆门面、MCP 连接池、工作区初始化与配置装载均已由前序模块交付并可直接复用；本模块不重建任何执行能力。
- 核心阶段无认证与多租户；安全边界依赖默认回环监听与跨源写保护，远程暴露由运维显式配置并自担边界。
- 契约（`docs/contracts/openapi.yaml` 与 `run-and-errors.md`）是本模块固定字面量的事实源；错误码、冻结文案与视图字段以其为准。
- 本模块零新增第三方依赖、零数据库迁移、零新增配置键（`server.max_concurrent_runs` 为既有契约键的落位）。
- 调度器、管理台与会话列表、热重载、Agent 动态管理、鉴权与多租户归后续阶段；本模块只在装配线上预留挂载点。
- 会话历史的可见范围固定为最近 100 条；分页、搜索与排序参数不在本阶段定义。
