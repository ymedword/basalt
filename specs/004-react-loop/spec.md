### User Story 1 - 唯一运行入口与循环闭环（Priority: P1）

运行面看到一个 Agent **真的转起来了**：一次运行请求进来（Agent 名 / 会话标识 / 用户消息 / 渠道 / 用户标识 / 预算），系统先把这次运行的配置**冻结成快照落库**（失败就拒绝启动，不留半截），再进循环——每轮"组装完整请求 → 调用模型 → **先把助手消息落库**（含它请求的工具调用）→ 有工具就**串行**执行 → 工具结果回填 → 下一轮"，直到模型不再请求工具、或迭代 / 工具预算耗尽、或调用方取消。三类终止在返回结果里语义分明（完成 / 达上限 / 已取消），**达上限不是错误**；循环留痕顺序可判卷：**执行工具之前助手消息必须已经落库**——否则崩溃恢复会误判"半截工具组"。提示词每次请求都重新组装四段（系统提示词取**本次运行快照冻结的正文**、记忆段留空占位、对话历史、工具列表），历史超预算时先按**轮数**、再按**完整工具交互组**从最老处裁，不可裁部分超限则**拒绝启动**（零模型调用）。

**Why this priority**: 这是"Agent OS 能跑 Agent"的第一次落地——没有它，`AGENT.md` 契约、provider 接入、Profile 加载都只是静态资产；它同时是后续所有 US（记忆 / 调度 / REST / 管理台）的唯一执行入口。

**Independent Test**: 以进程内**假模型客户端**（脚本化响应，含"先请求工具、再给最终回答"两轮）与**假工具面**驱动运行入口，断言：留痕顺序（执行前助手消息已在库）、一次运行恰 2 条助手消息、三类终止状态与计数（迭代数 / 工具调用数）、轮内重组装（第二轮请求含上一轮工具结果）、第一段取自快照正文而非重读、裁剪按轮数且不拆组、不可裁超限即拒绝且模型零调用、快照先落库后开跑、运行账本从 `running` 到终态。全程不开网络、不开真实模型。

**Acceptance Scenarios**:

1. **Given** 一只已注册 Agent 与一份合法请求，**When** 假模型首轮就给出纯文本回答，**Then** 运行完成（`completed`）、迭代数 = 1、轮号从 1 起、恰 1 条助手消息落库、最终回答只落一次且只出现在返回结果与助手消息里。
2. **Given** 假模型首轮请求一次工具调用、次轮给出用上工具结果的最终回答，**When** 运行，**Then** 恰 2 条助手消息 + N 条工具结果消息、工具**串行**执行、第二轮的请求体里带着第一轮的工具结果（轮内重组装）、工具调用计数 = 1。
3. **Given** 假模型每轮都请求工具，**When** 迭代达到上限，**Then** 运行状态为 `limit_reached`（**不是**失败）、返回已得的部分结果与计数；达上限由配置覆盖项驱动（缺省上限见 FR-020）。
4. **Given** 一次正常运行进行到中途，**When** 调用方取消上下文，**Then** 运行状态为 `cancelled`、组内未执行的调用回填"已取消"合成文本（**不是**预算文本）、**取消优先于预算**判定。
5. **Given** 一段历史远超上下文预算，**When** 组装请求，**Then** 先按轮数保留最近若干轮、仍超则按完整工具交互组从最老处继续丢弃（**不拆散任何一组**）；若不可裁部分（系统提示词 / 工具定义 / 当前消息）本身超限，**Then** 运行**拒绝启动**（点名上下文预算键）且模型**零调用**。
6. **Given** 一次运行的配置快照写入失败，**When** 请求开跑，**Then** 运行拒绝启动、**零模型调用**、返回失败状态并点名原因。

### User Story 2 - 沙箱、工具调度与内置文件工具（Priority: P2）

模型（或诱导它的用户）尝试用工具碰工作区外的东西：`read_file` 收到 `../../etc/passwd` 这类目标 → 得到**四段式拒绝文案**（违规说明 / 具体目标 / 规则出处 / 放行指引），审计落 `failed` + `sandbox_denied`，**运行本身照常继续**（工具失败不判运行失败，失败信息回填给模型让它自己收敛）。合法路径则真的读到文件内容并喂回模型。工具面本身有唯一调度归属：解析工具名 → **运行时归属校验**（全局注册但不在本 Agent 的 `tools:` 声明内 → 不执行、不写审计、回填放行指引并点名声明处）→ 审计 `pending` **预写**（写失败即**拒绝执行**，回填"审计不可用"，运行继续）→ 执行 → 终态回填（回填失败记 ERROR、行留 `pending`、**不覆盖**真实结果）。受控执行侧：环境变量白名单（不继承代理与凭证类变量）、超时**杀整棵进程树**、输出**读取中**限流且尊重更小的配置上限、截断标记只写生效上限。

**Why this priority**: 它是本产品对严监管客户的**核心承诺**——"审计 day-one 且 fail-closed"与"授权与执行分离"两条宪法原则第一次有可执行判卷；也是"首个工具闭环"里"工具"那一半。

**Independent Test**: 以临时工作区夹具直接调用工具面与沙箱面：越界路径（含软连接逃逸）逐例四段式拒绝 + 审计七类分类逐例对号；`pending` 预写失败时工具一次都不执行；进程树强杀后父子进程都消失；管道输出超限时内存不随输出膨胀且截断标记不含原始长度；三件文件工具的参数 / 失败类别逐字对齐契约。全程不触真实网络。

**Acceptance Scenarios**:

1. **Given** 一个不在本 Agent `tools:` 声明内的工具名（全局已注册），**When** 模型请求它，**Then** **不执行**、**无审计行**、回填四段式放行指引并点名声明处，运行继续到完成。
2. **Given** 审计 `pending` 预写失败（夹具注入），**When** 请求执行工具，**Then** 工具**一次都不执行**、回填"审计不可用"、运行继续；审计行**零**新增。
3. **Given** 模型请求读工作区外路径（或经工作区内软连接指向外部），**When** 执行，**Then** 拒绝文案四段齐备且逐字对齐标准形态、审计落 `failed` + `sandbox_denied`、运行继续。
4. **Given** 一个长时间运行且派生子进程的任务，**When** 单工具超时触发，**Then** 整棵进程树被回收（父子都不残留）、审计 `failed` + `timeout`、运行继续下一轮。
5. **Given** 输出远超上限的任务，**When** 执行，**Then** 读取过程中限流（内存不随输出增长）、截断标记只写**生效上限**（**不承诺**原始长度）、截断标记与结果包装可被下游识别。
6. **Given** 一次对 `AGENT.md` / 技能库 / `memory/` 的**写**请求，**When** 判定，**Then** 保护规则**先于**一般放行生效、拒绝且点名规则出处；命令行面**硬拒** `bash` / `sh`（含 `-c` 与脚本形态）。

### User Story 3 - 会话持久化、命令面与崩溃恢复（Priority: P3）

运维在真控制台里 `basalt chat`：AGENT.md 身份生效（自称与正文一致），多轮问答，问"读一下工作区里的 notes.txt 并总结"时界面出现一行"正在调用工具"提示（**不打印入参与结果全文**），随后给出用上文件内容的回答；`Ctrl-C` → 该次运行标记"已取消"、打印提示、**进程退出码 0**（取消是预期动作而非错误）；`--message` 单条即退、标准输入结束正常退出。会话历史**跨重启可续**：进程被强杀后重启，再次进入同一会话，历史仍在、可继续。若上次死于工具执行中途，被中断的那次调用在历史里显示"结果未知（进程中断，无法确定是否已产生外部副作用）"或"未执行（进程中断）"，且半截工具组被**补齐**、陈旧运行被收尾——补齐**只进消息、不进审计**（审计只记真实发生的事），且**幂等**（重启两次不重复插入）。`session list` 只读可用（不取实例锁、不做恢复）。

**Why this priority**: 它让"会话"从内存对象变成可续资产、让"崩溃"从数据损坏变成可解释状态；命令面则是用户可见的验收面。放在 P3 是因为它建立在 P1 的运行留痕与 P2 的审计链之上（恢复按位置判组、按审计行分类）。

**Independent Test**: 临时工作区内以假模型驱动运行并落库，**新建仓储实例**（模拟重启）读回断言历史 / `seq` 单调 / `tool_call_id` 与供应商扩展字段往返保真；构造三类恢复场景（只有旧运行的审计行 / 当前运行有 `pending` 行 / 组已完整）逐条断言合成文本与幂等；命令面用管道输入输出判卷（渲染模板、退出码、`Ctrl-C` 语义以可注入的中断信号判卷）。

**Acceptance Scenarios**:

1. **Given** 一次已完成的运行，**When** 新建仓储实例读回该会话，**Then** 用户消息 / 助手消息（含工具调用）/ 工具结果三条全在、`tool_call_id` 与供应商扩展字段**往返零丢失**、`seq` 单调自增。
2. **Given** 上次进程死于工具执行中途（审计行停在 `pending`），**When** 重启后对该运行做恢复，**Then** 该行的合成文本为"结果未知（进程中断，无法确定是否已产生外部副作用）" + WARN，`pending` 审计行归一化为 `unknown`，运行被收尾为失败；**重启两次零变化**（幂等）。
3. **Given** 只有**旧运行**的审计行、当前运行的调用没有对应审计行，**When** 恢复，**Then** 合成文本为"未执行（进程中断）"（**不是**"结果未知"）——分类按组归属，不按调用 id 猜。
4. **Given** 已结束（`completed` / `failed`）的运行与工具行，**When** 恢复扫描，**Then** 已结束状态**不被覆盖**；组修复与运行收尾在**同一短事务**内完成。
5. **Given** 真控制台会话进行中，**When** 用户按 `Ctrl-C`，**Then** 该次运行"已取消"、打印取消提示、**进程退出码 0**；`--message` 单条模式跑完即退、标准输入 `EOF` 正常退出。
6. **Given** 同一渠道 + 用户 + Agent 画像的三个属性，**When** 派生会话标识，**Then** 结果由**规范元组编码 + 稳定哈希**得出（`user=a-b, profile=c` 与 `user=a, profile=b-c` **不得**撞成同一标识）；`session list` 在实例被持锁时仍可用（只读命令不取锁、不做恢复、零写入）。

### User Story 4 - 行为评测基座与资源用量（Priority: P4）

开发用**固定用例集**回答"这次改动有没有让 Agent 变笨"：用例以 YAML 承载（输入 / 夹具 / 预算 / **可执行断言**），默认跑**进程内假模型后端**（可重复、进日常回归），只在**显式门控**（命令行指定 + 环境变量凭证）时才打真模型；逐例断言 PASS / FAIL，结果文件含每例**运行标识**与**审计关联**。资源用量按 **token 用量 + 调用次数**读（**称资源用量、不换算金额**）；用量缺失 / 悬空 / 未知时标"**计量不完整**"，**不得**把库中默认零解释为零成本。**不新增评测表**。

**Why this priority**: 它是"提示词改动 / 模型更换有没有退化"的判卷基座，也是验收 Demo 的读数来源；放在 P4 是因为它复用 P1~P3 的运行入口、审计链与落库面，不能先于它们成立。

**Independent Test**: 在临时工作区跑一批 YAML 用例（含"应调用某工具"与"应拒绝越权"两类），默认 fake 后端下逐例断言通过且两次运行读数一致（可重复）；把某例断言改成坏值，断言判 FAIL；真模型档未门控时明确跳过且**不**计入通过。

**Acceptance Scenarios**:

1. **Given** 一批 YAML 用例，**When** 执行评测（默认档），**Then** 逐例跑通、可执行断言逐条判定并输出 PASS / FAIL、两次运行读数一致（可重复）、全程不访问真实模型与真实网络。
2. **Given** 未显式门控真模型，**When** 执行评测，**Then** 真模型档**明确跳过**（不算通过）；门控条件齐备（命令行指定 + 环境变量凭证）时才发出真实调用。
3. **Given** 一次评测运行，**When** 读结果文件，**Then** 每例带运行标识与审计关联、资源用量以"token 用量 + 调用次数"呈现、**不含金额换算**；用量缺失或不完整时该例标"计量不完整"。
4. **Given** 一次评测端到端跑完，**When** 检查数据面，**Then** **零新增表**（只看既有表的读写）。

### Edge Cases

- 模型响应带工具调用但 `content` 为空 → 循环**容忍**（助手消息照落、工具照执行）；`usage` 缺失 → 计 0 并如实标注，**不得**当成"零成本"或"零用量"事实。
- 模型请求了工具但**本轮助手消息落库失败** → 该轮不得进入执行（宁可整次运行失败，也不产生"执行了但历史里没有"的调用）。
- 工具执行成功但**终态回填失败** → 审计行留 `pending`（不得写成功）、保留真实结果供下游取用；该行在下次恢复时归一化为 `unknown`，**不得**被写成"未执行"。
- `write_file` 的目标父目录不存在、或校验与写入之间父目录被换成指向工作区外的软连接 → 拒绝（不跟随越界软连接），**不得**先在界外落盘再补救。
- 工具名解析不出 / 参数不是合法 JSON 对象 → 审计 `failed` + `invalid_input`（**仍写审计行**，因为"模型请求了"这件事本身要留痕）；名字不在注册池 → 无审计行 + 四段式回填。
- 上下文预算刚好卡在边界（不可裁部分**等于**上限）→ 按"超限才拒"判定，等于上限放行。
- 同一会话并发两次请求 / 实例数超限 → **不排队**，直接拒绝（返回调用方错误，不是运行状态）。
- 恢复扫描遇到"组完整但运行仍 `running`" → 只收尾运行，**不**动消息；遇到"审计行仍 `pending` 但组已完整" → 归一化审计行，**不**补消息。
- 截断标记写入后下游再做拼接 → 标记形态必须能被人与程序同时识别（**不承诺**原始长度，不得据标记推算）。
- 真控制台被重定向 / 管道 → 两侧按 UTF-8 显式处理（不猜环境变量、不靠终端属性）；`Ctrl-C` 只影响当前运行，不影响已落库的历史。

## Requirements *(mandatory)*

### Functional Requirements

#### 运行入口与循环

- **FR-001**: 系统 MUST 提供**唯一运行入口**：接受一次运行请求（Agent 名 / 会话标识 / 用户消息 / 渠道 / 用户标识 / 预算；配置哈希由运行时填充）并返回运行结果（运行标识 / 状态 / 最终文本 / 迭代数 / 工具调用数 / 配置哈希 / 原因）。**运行期失败**（模型错、工具错、快照失败、上下文超限）MUST 一律体现在返回**状态**里；函数级错误 MUST 只用于**调用方问题**（请求非法 / Agent 不存在 / 同会话忙 / 实例数超限）——四类一律**不排队**、立即拒绝。
- **FR-002**: 循环 MUST 为**本仓自实现**（`go.mod` MUST NOT 出现任何 Agent 框架坐标；协议 SDK MUST NOT 接管循环或自动执行工具）。每轮次序 MUST 为：组装完整请求 → 调用模型 → **先落助手消息**（含工具调用）→ 有工具则**串行**执行 → 工具结果回填 → 下一轮；工具 MUST NOT 并行。无工具调用即完成，最终回答 MUST 只落一次。
- **FR-003**: 迭代轮号 MUST 从 1 起；首次即纯文本完成时迭代数 MUST 为 1。三类终止 MUST 语义分明：完成 / 达上限（`limit_reached`，**不是错误**）/ 已取消（`cancelled`）。每条**提前返回路径**（取消 / 预算 / 上限 / 追加失败）MUST 都经同一"补齐半截工具组"入口，MUST NOT 有旁路。
- **FR-004**: 终止与取消判定 MUST 在**每次执行工具之前**进行：先查取消、再查工具预算；**取消优先于预算**；工具预算耗尽 MUST NOT 禁止"不使用工具的模型响应"（下一轮纯文本完成照常完成）；轮首取消 MUST NOT 计入当前轮（那次的模型调用并未发出）。
- **FR-005**: 模型客户端的调用 MUST 经**既有唯一入口**（路由查表 + 两阶段审计，US-2 已交付）；循环 MUST NOT 自建第二套审计。预写失败 ⇒ **拒绝发出**（该错误上抛即运行失败）；调用发生后的终态回填失败 ⇒ 记 ERROR、审计行留 `pending`、**不覆盖**结果（与既有语义一致）。
- **FR-006**: 模型响应 MUST 容忍两处可空：带工具调用时 `content` 可为空；`usage` 可缺失 ⇒ 计 0 并如实标注。响应的工具调用标识与思考内容 MUST 原样透传到后续链路（落库 + 出站编码，见 FR-014）。

#### 提示词组装与上下文预算

- **FR-007**: 请求 MUST 每轮**重新组装**四段：①系统提示词 = **本次运行快照冻结**的段一正文（MUST NOT 重读文件）；②记忆注入（**留空占位**，接入归记忆 US）；③对话历史；④工具列表。上一轮的工具结果 MUST 出现在下一轮的历史里。
- **FR-008**: 工具池为空时请求体 MUST NOT 携带工具定义键（既有行为的空池形态逐字不变）；非空时按供应商形态编解码。
- **FR-009**: 上下文裁剪 MUST 两级：先按**轮数**保留最近若干轮（MUST NOT 按消息条数），仍超预算则按**完整工具交互组**从最老处继续丢弃（MUST NOT 拆散任何一组）。系统提示词、工具定义、当前消息 MUST NOT 被裁。
- **FR-010**: 不可裁部分（系统提示词 + 工具定义 + 当前消息）估算超限 ⇒ 运行 MUST **拒绝启动**（失败状态、点名上下文预算键）、模型调用次数 = **0**。
- **FR-011**: token 估算 MUST 由**版本明确**的估算器完成，估算面 MUST 覆盖**完整出站字段**（消息文本、角色、工具定义 schema、工具调用参数、供应商扩展字段），且 MUST 对同输入确定性（两次估算同值）；估算器版本 MUST 可被结果或日志读出。上下文准入 MUST 另保留固定**余量**以吸收协议包装开销（估算器版本常量与余量缺省值逐字冻结在颗粒度文档 §6.2 第 9 条，两者一并写进评测结果文件与快照日志）。MUST NOT 宣称其为"保守上界"（无此结论）。

#### 运行级配置快照与运行账本

- **FR-012**: 每次运行开始前 MUST 冻结并落库一份**运行级配置快照**：Agent 名 / 内容哈希 / `AGENT.md` **全文** / 文件清单（段一素材与附属文件）；落库失败 ⇒ **拒绝启动**（零模型调用）。MUST NOT 只存哈希。
- **FR-013**: 快照的 Profile 与段一正文 MUST 解析自**同一次读取**（MUST NOT 先读一遍解析 Profile、运行中再读一遍取正文——两次读取之间文件可能已变）；哈希 MUST 由文件清单的**规整序列化**得出，当前时间 MUST NOT 混入（同一内容、不同时刻 MUST 得同哈希）；同一 `(agent_name, hash)` MUST 幂等（重复落库不产生第二行、不覆盖既有行）。
- **FR-014**: 工具调用标识（`tool_call_id`）与思考内容（推理字段）MUST 全链保真：入站解析 → 会话落库 → 出站编码三处逐字不丢；供应商扩展字段 MUST 保持原始 JSON 形态往返（大数不精度丢失）。
- **FR-015**: 运行账本 MUST 自本 feature 起写入：起始 `running`、终态更新全部列（状态 / 迭代数 / 工具调用数 / 起止时间 / 原因）；**运行账本 MUST NOT 有"最终文本"列**（最终回答只存在返回结果与会话的助手消息里）；时间戳 MUST 存毫秒；触发源 MUST 由渠道映射（命令行 → 用户手动 / web → API / 定时 → cron / 管理台 → 手动）。
- **FR-016**: 运行标识 MUST 为 `<渠道>-<毫秒时间戳>-<随机 6 位>` 形态，且随机部分 MUST 取密码学随机源（字母表与形态逐字口径见颗粒度文档 §6.2 第 2 条）。

#### 工具调度与审计两阶段

- **FR-017**: 工具调度 MUST 有**唯一归属**（循环只经它调度）。次序 MUST 为：解析工具名 → **运行时归属校验** → 审计两阶段 → 执行 → 结果包装。工具调度 MUST **只返回结果、不写消息**（消息写入归循环，见 FR-021）。
- **FR-018**: 归属校验 MUST 在**运行时**执行：工具全局已注册但**不在本 Agent 的 `tools:` 声明内** ⇒ 不执行、**不写审计行**、回填四段式拒绝（点名声明处）；名字不在全局注册池 ⇒ 同样不执行、不写审计行、回填四段式拒绝。声明面校验（装载期）MUST NOT 取代运行时校验。
- **FR-019**: 工具执行 MUST 审计 fail-closed：执行**前**先写 `pending` 行（写失败 ⇒ **拒绝执行**，回填"审计不可用"，**运行继续**）；执行后更新终态。终态回填失败 ⇒ 记 ERROR、行留 `pending`、**不覆盖**真实结果。执行入参、结果、耗时、错误信息 MUST 如实落库（失败原文超长时截断，截断口径见 FR-020）。工具执行失败 MUST NOT 判运行失败——失败信息 MUST 回填给模型。
- **FR-020**: 审计**状态字面量** MUST 冻结为四值 `pending` / `success` / `failed` / `unknown`（**无** `cancelled`）；**失败分类** MUST 冻结为七值（沙箱拒绝 / 超时 / 目标不存在 / 入参非法 / 外部错误 / 运行时错误 / 未知）逐字对齐契约；**运行状态**是**另一套**五值，两套 MUST NOT 混用——运行可以"已取消"而审计仍按既有口径记失败及分类。工具表 MUST NOT 有轮次列与截断列（截断标记写在结果 JSON 值内）。
- **FR-021**: 会话消息追加 MUST 有**唯一路径**：正常运行的模型响应与工具结果由**循环**统一追加、用户输入由**运行入口**写入、崩溃 / 取消后的半截组由**补齐路径**写入——三者 MUST 经同一会话写透接口（显式承载运行标识）；MUST NOT 出现第二个出口。**任一消息写入失败 ⇒ 运行 MUST 失败**（fail-closed——MUST NOT 出现"执行了但历史里没有"的调用；审计终态回填失败**不在**此列：记 ERROR、行留 `pending`、不覆盖真实结果）。

#### 沙箱授权判定

- **FR-022**: 授权判定输入 MUST 只含"**谁、要碰什么**"，MUST NOT 含"打算怎么做"（动作类型 MUST NOT 带命令行参数）；判定与执行 MUST 分离（判定接口与执行接口两个，调用方 MUST NOT 依赖具体实现）。
- **FR-023**: 读白名单 MUST 含工作区与**技能库**；**跨 Agent 读取 MUST 显式授权**（配置键未开 ⇒ 拒绝且点名该键名）；所有路径 MUST 经工作区根约束（**不跟随越界软连接**）、不可解析的目标 MUST **失败关闭**（默认拒）。
- **FR-024**: **保护规则 MUST 先于**一般放行判定：配置文件写入 / 技能库写入 / 记忆目录写入 / 脚本目录写入 MUST 被拒并点名规则出处。`AGENT.md` 写入 MUST 被拒（Agent 定义只经管理面变更）。
- **FR-025**: 命令行放行 MUST 为**整串逐字**匹配（多词串与部分匹配 MUST 被拒）；`bash` / `sh` MUST **硬拒**（含 `-c` 形态与"解释器 + 脚本文件"形态）。
- **FR-026**: 网络目标判定（本 feature 只落判定面，工具本体归 US-5）：域名 MUST 大小写不敏感；**纯 IP 字面量 MUST 被拒**；scheme MUST 限 http / https；跳转 MUST NOT 放宽超过 **5 跳**。
- **FR-027**: 拒绝文案 MUST 为**四段式**（违规说明 / 具体目标 / 规则出处 / 放行指引），四段齐备且形态固定（供下游逐字判卷）。
- **FR-028**: 沙箱判定 MUST 可被审计分类使用：拒绝 ⇒ 审计 `failed` + 沙箱拒绝分类（**不是**运行失败）。

#### 受控执行与内置文件工具

- **FR-029**: 子进程执行 MUST：环境变量走**白名单**（MUST NOT 继承代理变量与凭证类变量）；超时 MUST 杀**整棵进程树**（父子一并回收）；输出 MUST 在**读取中**限流（内存 MUST NOT 随输出膨胀）且 MUST 尊重**更小**的配置上限；MUST 捕获退出码与 stderr。
- **FR-030**: 输出截断 MUST 只写**生效上限**（MUST NOT 承诺或推算原始长度）；截断标记 MUST 落在结果 JSON 值内（不新增列）；失败原文入库前 MUST 截断到固定上限。截断标记的逐字形态冻结在颗粒度文档 §6.2 第 7 条。
- **FR-031**: 解释器 argv 形态校验 MUST 属**执行侧**（负号形态拒绝 / 脚本真实路径越界拒绝）——判定侧只看"谁、要碰什么"。
- **FR-032**: 内置文件工具 MUST 恰三件（`read_file` / `write_file` / `list_dir`），入参、出参与失败类别 MUST 逐字对齐契约；`read_file` MUST 真的读工作区文件并回填内容（"首个工具闭环"的实证点）。
- **FR-033**: 文件工具的路径操作 MUST 经工作区根约束：读 MUST NOT 跟随越界软连接；`list_dir` MUST 不递归、不跟随软连接；`write_file` 目标**父目录不存在 ⇒ 拒绝**，且实际写入 MUST 经**相对根句柄**完成（防"校验与写入之间被换成越界软连接"的竞争窗口）。
- **FR-034**: 工具注册 MUST 显式（无隐式发现）：重名 MUST 拒绝；名字集 MUST 排序稳定；规格取用 MUST 保序；未命中 MUST 明确返回"未找到"。归属校验所依据的"本 Agent 声明名集" MUST 由装配期从注册表导出并注入装载器（装载器 MUST NOT 反向依赖工具注册表）。

#### 会话、消息与崩溃恢复

- **FR-035**: 消息追加接口 MUST 显式承载**运行标识**（消息对象本身没有该字段，恢复却依赖落库列）；会话可跨重启读回（用户消息 / 助手消息含工具调用 / 工具结果三类保真，`seq` 单调）；**无状态会话**（空会话标识）MUST 只在内存、MUST NOT 落会话历史，但仍 MUST 落运行与审计。
- **FR-036**: 半截工具组补齐 MUST **先判缺失**（判据落在**消息**上：哪些工具调用没有对应的结果消息）**再**按审计行分类——次序 MUST NOT 颠倒。五分支逐字：①有终态审计行 ⇒ 还原真实结果；②执行过但终态回填失败（行仍 `pending`）或 `unknown` ⇒ "结果未知（进程中断，无法确定是否已产生外部副作用）" + WARN；③无行 + 取消 ⇒ "已取消（运行被取消，该调用未执行）"；④无行 + 预算耗尽 ⇒ "未执行（工具调用次数超限）"；⑤无行 + 崩溃 ⇒ "未执行（进程中断）"。
- **FR-037**: 补齐 MUST **只进消息、不进审计**（审计只记真实发生的事）；补齐 MUST 幂等（重复调用不重复插入、组已完整为 no-op）；补齐失败 MUST 有**错误返回**（调用方记 ERROR，运行照常收场）；补齐收尾 MUST 用**独立有限时长**的上下文（父上下文已取消时仍必须写得进去）。
- **FR-038**: 崩溃恢复扫描 MUST 在启动时（**取锁后、开跑前**）执行六步：把 `pending` 审计行归一化为 `unknown`、按**位置**（MUST NOT 按调用 id）判定半截组并补齐、把**仍为** `running` 的运行标 `failed`；组修复与运行收尾 MUST 在**同一短事务**内；MUST 只覆盖**仍未结束**的行（已结束状态 MUST NOT 被覆盖）；MUST 幂等（连跑两次零变化）；`pending → unknown` 与运行收尾两处 MUST 留痕可查。
- **FR-039**: 会话标识 MUST 由"渠道 + 用户 + Agent 画像"经**规范元组编码 + 稳定哈希**派生（长度前缀消歧——直接按分隔符拼接 MUST NOT 被采用）；派生 MUST 由命令面在**准入之前**完成；用户取不到时回落固定值（形如 `<渠道>-<哈希前 16 位十六进制>`、回落值逐字冻结在颗粒度文档 §6.2 第 1 条）；**空会话标识 MUST 保留"无状态"语义**（运行入口 MUST NOT 代为派生）。

#### 命令行通道与命令面

- **FR-040**: 命令行通道 MUST 在真控制台上经**控制台 API** 读写（MUST NOT 依赖标准输入输出的字节流假设）；管道 / 重定向两侧 MUST 显式按 UTF-8；"是否终端"的判定 MUST NOT 靠猜环境变量；平台差异 MUST 分平台分支适配（Windows 控制台 API / Linux 与 Darwin 各自的终端属性调用）。
- **FR-041**: `chat` 命令 MUST：交互多轮（`--message` 单条即退、标准输入结束正常退出）；渲染口径固定（工具调用期间一行提示、**不打印入参与结果全文**、失败一行、达上限 / 取消的醒目提示 + 已得部分结果）。渲染模板的逐字形态冻结在颗粒度文档 §6.2 第 4 条。
- **FR-042**: `Ctrl-C` MUST 只取消**当前运行**：该次运行状态为"已取消"、打印取消提示、**进程退出码 0**（取消是预期动作而非错误）；已落库历史 MUST NOT 受影响。运行 MUST 另有**资源时限**（命令面 60 秒、调用方已有更早截止时取更早者——`Ctrl-C` MUST NOT 替代资源时限）。三条交互终止语义与时间限逐字冻结在颗粒度文档 §6.2 第 3 条。
- **FR-043**: `session list` MUST 为**只读**：不取实例锁、不做恢复、不清理锁文件（打开库前 MUST 校验结构版本，不匹配即拒绝）；输出为一行一会话 + 末尾汇总 + 空库文案（渲染模板逐字冻结在颗粒度文档 §6.2 第 5 条）。

#### 装配与依赖方向

- **FR-044**: 运行引擎包 MUST 只依赖标准库（MUST NOT import 任何内部包或第三方）——本 feature 起该包首次有可执行语句，其依赖面 MUST 由机器判据复核（`go list`）。
- **FR-045**: 模型客户端实例 MUST 在装配处**一次构建**为"名称 → 客户端"映射表，运行时**只查表**（MUST NOT 遍历推断——映射遍历顺序不确定）。
- **FR-046**: 重路径的装配次序 MUST 固定：取实例锁 → 写模式打开 → 显式迁移 → 崩溃恢复 → 开跑；轻路径（只读命令）MUST NOT 取锁、MUST NOT 开数据库写入。
- **FR-047**: 服务层的运行准入 MUST 与实例锁 / 会话忙 / 实例数上限共同生效：同会话忙与实例满 MUST 直接拒绝（不排队）；准入失败 MUST NOT 产生半截落库。

#### 评测基座与资源用量

- **FR-048**: 评测用例 MUST 以 YAML 承载（输入 / 夹具 / 预算 / **可执行断言**）；默认后端 MUST 为**进程内假模型**（可重复、进日常回归）；真模型 MUST **显式门控**（命令行指定 + 环境变量凭证缺一不可）。
- **FR-049**: 评测 MUST 复用唯一运行入口与审计链（MUST NOT 自建第二套执行路径）；结果文件 MUST 含每例运行标识与审计关联；**MUST NOT 新增评测表**。
- **FR-050**: 资源用量 MUST 按"**token 用量 + 调用次数**"读取并呈现，MUST **称资源用量**、MUST NOT 换算金额；用量缺失 / 悬空（无对应审计行）/ 未知时 MUST 标"**计量不完整**"，MUST NOT 把库中默认零解释为零成本。

#### 工程纪律

- **FR-051**: 全 feature MUST NOT 新增第三方坐标（`go.mod` 零新增）；复用既有直接依赖的能力（Windows 控制台与作业对象、Unix 终端属性与进程组）MUST 经既有坐标完成；MUST NOT 引入未被固定技术栈句覆盖的新坐标。
- **FR-052**: 可观测性 MUST 双轨：失败路径**既落审计又记 WARN 日志**（固定键：运行标识 / 会话标识 / 工具名 / 原因 / 细节）；审计写失败记 ERROR（固定键：运行标识 / 存储名 / 操作）；恢复结果记 INFO（归一化数 / 修复组数 / 收尾运行数）；快照记 INFO（Agent 名 / 哈希 / 清单条数）。键名集逐字冻结在颗粒度文档 §6.2 第 6 条。日志与错误文案 MUST NOT 回显文件全文或配置原文。
- **FR-053**: 业务状态（会话 / 声明面 / 工具环境 / 预算）MUST 一律**显式类型化参数**传递；`context.WithValue` MUST NOT 出现在业务代码里（本 feature 零使用）；MUST NOT 用包级变量模拟作用域传递。
- **FR-054**: MUST NOT 引入异步编排；工具执行 MUST 串行（一轮内多工具逐个执行）。时间 MUST 一律显式传入（MUST NOT 在函数内取真实当前时间）。
- **FR-055**: 覆盖面纪律：所有文件读写（含目录扫描）MUST 经工作区根约束；已发布的迁移脚本 MUST NOT 被改写（本 feature **零新增迁移**——六表 US-1 已建齐）。

### Key Entities

- **运行请求（RunRequest）**：Agent 名 + 会话标识 + 用户消息 + 渠道 + 用户标识 + 预算 + 配置哈希。
- **运行结果（RunResult）**：运行标识 + 状态（五值）+ 最终文本 + 迭代数 + 工具调用数 + 配置哈希 + 原因。
- **运行环境（RunEnv）**：请求 + 配置快照 + 会话 + 预算 + 工具池——循环的输入面（**不含**运行标识字段，标识显式传递）。
- **工具执行环境（ToolEnv）**：运行标识 / 会话标识 / Agent 名 / Agent 目录 + 时限 + 输出上限。
- **配置快照**：Agent 名 + 内容哈希 + `AGENT.md` 全文 + 文件清单（规整序列化）+ 段一正文；同一 `(agent, hash)` 幂等。
- **工具调用（ToolCall）**：调用标识 + 工具名 + 参数（原始 JSON）+ 推理内容。
- **工具结果（Result）**：状态（成功 / 失败）+ 内容或错误信息 + 失败分类（七值）+ 截断标记 + 耗时。
- **审计行（工具调用）**：两阶段一行——`pending` 预写、终态回填（状态 / 分类 / 入参 / 结果 / 错误原文截断）。
- **消息**：用户消息 / 助手消息（含工具调用与扩展字段）/ 工具结果消息（含 `tool_call_id`）；落库带 `seq` 与 `run_id`。
- **会话**：会话标识（渠道 + 用户 + 画像派生）+ 历史消息序列；跨重启可续；无状态会话只在内存。
- **沙箱动作（Action）**：主体（Agent 名）+ 动作类型 + 目标（路径 / 命令串 / 网络目标）——**不含** argv。
- **评测用例**：输入 + 夹具 + 预算 + 可执行断言；结果含运行标识、审计关联与资源用量。
- **资源用量**：token 用量 + 调用次数（不换算金额；不完整时标注）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 循环判卷零例外：留痕顺序（执行前助手消息已落库）在含工具调用的用例中 100% 成立；一次运行助手消息数**恰等于**模型响应数（丢最终回答 = 0 例）；三类终止状态与计数 100% 对号；轮内重组装（第二轮请求含上一轮工具结果）100% 成立。
- **SC-002**: 审计 fail-closed 零例外：`pending` 预写失败场景中工具执行次数 = **0**、审计行新增 = **0**、运行仍完成 100%；归属校验场景中未授权工具执行次数 = 0、审计行 = 0、四段式放行指引出现率 100%；七类失败分类逐例对号率 100%。
- **SC-003**: 沙箱判卷：越界路径（含软连接逃逸 / 未授权跨 Agent / 保护规则目标 / 多词命令 / `bash` 与 `sh` 形态 / IP 字面量与非法 scheme）逐例拒绝率 100%、四段式文案齐备率 100%；合法路径 100% 放行。
- **SC-004**: 恢复保真：五分支合成文本逐字对号率 100%；恢复扫描幂等（第二次运行零变化）100%；已结束状态被覆盖 = **0** 次；半截组补齐后"无结果消息的工具调用"数 = 0。
- **SC-005**: 会话资产：跨重启读回的三类消息保真率 100%（`tool_call_id` 与扩展字段往返丢失 = 0）；会话标识派生碰撞 = **0**（构造消歧用例对拍）；`Ctrl-C` 后进程退出码 = 0 且该次运行状态为已取消。
- **SC-006**: 上下文预算：按轮数裁剪与按组裁剪的用例 100% 通过（拆散组 = 0、按条数裁剪 = 0）；不可裁超限场景拒绝启动率 100% 且模型调用次数 = 0；token 估算对同输入两次调用同值率 100%。
- **SC-007**: 评测基座：默认档两次运行读数一致率 100%、真实模型调用 = **0** 次；真模型未门控时 100% 明确跳过；结果文件含运行标识与审计关联率 100%；金额换算出现 = **0** 次。
- **SC-008**: 工程纪律：`go.mod` 新增坐标 = **0**；运行引擎包 import 面 100% 为标准库；业务代码 `context.WithValue` 命中 = 0；Agent 框架坐标命中 = 0；本轮覆盖率按可执行判据达标（运行引擎 / 工具 / 存储 ≥70%，通道 ≥50%，无豁免）；默认测试层真实网络访问 = 0 例、真实模型调用 = 0 次。

- 准入**排队**（同会话忙、实例满都不排队，直接拒绝）。

- `shell` / `http_get` / `http_post` 工具本体与工具清单命令（归 US-5）；网络目标判定只落判定面。

- 定时触发器与定时模式的更长运行时限。
