## User Scenarios & Testing *(mandatory)*

**标签口径（`[US1]` / `[US2]` / `[US3]` 不混淆）**：下面三个用户故事在 [tasks.md](./tasks.md) 中以 Spec-Kit 的工具标签 `[US1]` / `[US2]` / `[US3]` 出现——那是**本 feature 内部**用户故事的编号，**不是**项目台账（[docs/us/REGISTRY.md](../../docs/us/REGISTRY.md)）里的 US-1 / US-2 / US-3。本 feature 的三个故事同属项目 **US-2（Provider 对接）** 一个模块，是它的三个独立可验场景；标签按工具产出保留。

### User Story 1 - 一次调用，成败都留痕（Priority: P1）

审计员视角的完整旅程：配置里声明了若干供应商，系统对其中某一家的调用**发出之前**，审计库里已经先落下一行该次调用的记录（进行中形态）；调用成功 → 该行补上用量与耗时；调用失败 → 该行补上失败类别与（截断后的）失败原文。审计本身不可写时，调用**不发出**——「查不到记录」必须意味着「确定没执行」，而不是「执行了却没留痕」。调用被取消（或截止时间到）时同样先留痕后发出，且审计写入的任何失败都**不得**改写调用本身的返回语义。供应商返回的消息里带有思考内容或本系统未知的扩展字段时，这些字段在往返两跳中**一个都不丢**。

**Why this priority**: 可审计是本产品的差异化承诺，两阶段写是它的实现方式（宪法 V 自本 US 起有写入面）；这一条同时是后续所有会真实调用模型的 US（循环 / 工具 / 记忆）的地基——没有它，之后的每一次调用都无从解释。

**Independent Test**: 用进程内假供应商 + 真审计库覆盖「成功 / 供应商报错 / 取消 / 审计不可写」四条路径，查库行与返回错误即可判卷；协议面用回环假 OpenAI 服务验证出站请求体与入站解析，全程不访问真实网络。

**Acceptance Scenarios**:

1. **Given** 显式映射表里有供应商 A、审计库可写，**When** 发起一次调用并成功返回，**Then** 在调用发出的一刻库里已有该次调用的进行中记录，返回后该记录为成功并带用量三列（供应商未返回用量 → 三列为 0 且仍记成功）、失败类别为空。
2. **Given** 审计库不可写，**When** 发起调用，**Then** 返回错误、该供应商的客户端**零次**被调用、日志落 ERROR。
3. **Given** 调用被取消（或截止时间到），**When** 调用返回，**Then** 记录为失败 + 类别「超时」，返回的错误仍可判定出具体的取消 / 截止原因。
4. **Given** 供应商名不在映射表 / 关联标识缺失 / 模型无法解析，**When** 发起调用，**Then** 立即点名拒绝、**零调用、零审计行**（「无行 = 确定没执行」）。
5. **Given** 调用已发出但审计终态补写失败，**When** 调用返回，**Then** 记录保留在进行中形态（**不得**伪造终态）、日志落 ERROR、**调用结果的返回语义不被改写**（取消路径亦然——返回的仍是取消错误）。
6. **Given** 消息含思考内容与一个本系统未知的供应商扩展字段，**When** 把该消息交回发起第二次调用，**Then** 第二次请求体里这些字段仍在（原名、原值）；出站请求体里消息数组只出现一次（已知字段基座不得顶掉消息本身）。

### User Story 2 - 一眼看清配了哪些供应商（Priority: P2）

运维在已初始化的工作区运行 `basalt provider list`：逐条看到供应商名、地址（按「只留 scheme://host/path」收窄渲染）、缺省模型与凭证状态文案——**不含任何凭证值**。该命令只读配置文件：不开库、不取实例锁、不做恢复、不构造客户端。缺配置文件或供应商段为空即判失败并点名路径 / 段名（「列出已配置的供应商」在无配置时目的未达成，与诊断命令的容忍语义**刻意不同**）；配置无效则把已点名键路径与变量名的原错误上抛。

**Why this priority**: 首日排障与配置核对的主入口；它同时是「地址面只支持 scheme + host + path」在**展示侧**的纵深防御点——即使上一层被绕过，输出也不得带出地址里的敏感成分。

**Independent Test**: 在临时目录写各形态配置（正常两家 / 缺文件 / 空段 / 无效 / 直接注入含 userinfo / query / fragment 的条目），跑命令比对输出、退出码与三路（标准输出 / 标准错误 / 日志缓冲）的凭证断言。

**Acceptance Scenarios**:

1. **Given** 配了两家供应商（凭证为占位形态、经环境变量解析），**When** 运行命令，**Then** 两家各自的名称 / 收窄地址 / 缺省模型 + 凭证状态文案齐备、有汇总行、退出码 0，且输出不含凭证值。
2. **Given** 配置文件不存在，**When** 运行命令，**Then** 失败并点名配置文件路径（**不**沿用诊断命令「无配置不计失败」的容忍语义）、退出码 1。
3. **Given** 配置文件存在但供应商段为空，**When** 运行命令，**Then** 失败并点名段名、退出码 1。
4. **Given** 配置本身无效（含凭证约定违规），**When** 运行命令，**Then** 原错误上抛（点名键路径与变量名）、退出码 1、输出不含凭证值。
5. **Given** 直接注入一条地址含 userinfo / query / fragment 的供应商条目（绕过装载期），**When** 运行命令，**Then** 渲染结果只保留 scheme://host/path，三类敏感成分**都不出现**在输出里。

### User Story 3 - 配置防线与真实供应商的一次调用（Priority: P3）

验收人视角的端到端一跑：配置里某家的地址含不支持的成分（userinfo / query / fragment）→ **装载期即拒绝**，文案只点名键路径与不支持的成分名，**不回显原 URL、也不回显其中的值**（userinfo 里可能正是一份凭证），一切启动路径同判；配置合法时，用经环境变量注入的真实凭证 + 显式执行开关跑一次真实调用 → 审计库出现成功行；把地址换成不可达端点重跑（**不需要凭证**）→ 失败同样落审计。凭证值不出现在标准输出 / 标准错误 / 日志 / 审计行 / 对话里。

**Why this priority**: 这是「真实调用验收 Demo」与「凭证红线」的合体——模块的对外承诺最终由它兑现；地址面选择「装载期明确拒绝」而非「静默裁剪」，正是为了不让配置在运行时被改写成另一个含义。

**Independent Test**: 装载期三条新规则（供应商重名 / 地址必填 / 地址含不支持成分）用默认层用例逐条判卷，**不需要凭证**；真实调用正例与不可达反例走集成层（显式执行开关 + 凭证环境变量**双门控**，缺一即跳过并写明理由），环境守卫在 CI 上跳过。

**Acceptance Scenarios**:

1. **Given** 配置里两家供应商同名，**When** 装载配置，**Then** 拒绝并点名两条目的下标（否则映射表静默缺条目、无人发现）。
2. **Given** 某供应商条目缺地址 / 地址缺 scheme / 地址含 userinfo / query / fragment，**When** 装载配置，**Then** 逐例拒绝、点名键路径与不支持的成分名，且文案**不含原 URL、不含其中的值**（地址不代补 scheme——不做隐式推断）。
3. **Given** 显式执行开关打开、真实凭证经环境变量注入、两家供应商配置就绪，**When** 执行一次真实调用（入口显式设截止时间），**Then** 调用成功、库中出现成功行，用量三列与响应一致（供应商未返回用量 → 三列为 0 且仍判成功）。
4. **Given** 把地址指向不可达端点（不需要凭证），**When** 执行调用，**Then** 失败同样落审计（失败态 + 非空的失败类别），用例**不因缺凭证跳过**。
5. **Given** 真实凭证已注入，**When** 检查全部输出面，**Then** 凭证值在标准输出 / 标准错误 / 日志 / 审计行的失败原文 / 对话里**零出现**。
6. **Given** 缺凭证或未打开执行开关，**When** 执行集成用例，**Then** 用例跳过并写明理由——**跳过不算通过**，收口报告必须区分「通过」与「跳过」。

### Edge Cases

- 被路由不到的供应商名、缺少关联标识（运行标识为空 / 轮次小于 1）、模型无法解析（请求与供应商缺省都空）——三道拒绝都发生在预写**之前**：零调用、零审计行，且点名原因。
- 供应商条目未过装载期校验（缺地址 / 重名 / 地址含不支持成分）——客户端**从未被构造**，调用面不可达：失败点在使用之前，不产生审计行。
- 供应商返回 3xx：**不跟随**重定向（凭证不得随重定向跨主机转发），按外部错误记审计。
- 响应是畸形 JSON / 供应商 4xx / 5xx / 网络不可达 / DNS / TLS 失败：一律归「外部错误」，**不 panic**、不吞错。
- 供应商错误正文**回显了凭证**（现实里确有其事）：返回错误、日志、审计失败原文三路都不得含凭证值。
- 调用**之前**上下文已取消：预写与取消解耦，行照落（先留痕）再发出（客户端立刻以取消失败），终态为失败 + 超时——取消**不得**伪装成「审计不可用」的拒发。
- 终端用户在终态补写失败的窗口里崩溃 / 被强杀：库里留下的是进行中形态的行（无半写、无伪造终态），可被后续恢复流程识别（恢复本体归 US-4）。
- 失败无法归类（第三方客户端实现抛回的异常错误）：兜底为「未知」类别——该值**不是**恢复流程专属。
- 供应商未返回用量 / 带工具调用的响应正文为空 / 思考内容为空：三者都**不判失败**，其中思考内容与扩展字段**不得丢**。
- 并发调用（含取消路径）与并发预写：竞态检测下零告警、同一进程内行为可复现（映射表装配时一次构建、之后只读）。

## Requirements *(mandatory)*

### Functional Requirements

#### 显式映射与调用面

- **FR-001**: 供应商名 → 客户端实例的映射 MUST 在装配处**逐条**由配置构造、路由**只查表**；**不得**遍历推断、**不得**「取第一个」、**不得**把「唯一的那个」当默认（Go 映射遍历顺序随机 → 同一进程不同请求指到不同供应商）。配置里供应商名重复 MUST 在装载期拒绝并点名两条目下标——否则映射静默保留最后一条、缺条目无人发现。
- **FR-002**: 新增的第三方依赖 MUST 只有一个（LLM 供应商 SDK），且其角色 MUST 收窄为**协议类型与已知字段的编解码**：HTTP 往返由本仓库自建（**一次** POST、**不重试**、**不 fallback**、**不跟随重定向**）。**不得**启用任何自动工具循环、**不得**让 SDK 接管会话历史或工具调度、**不得**在应用层加隐式重试；响应中的工具调用只**透传**给调用方，执行权归后续 US 的工具执行器。

#### 调用与审计（fail-closed 两阶段写）

- **FR-003**: 每次调用 MUST 两阶段写审计：**先**插「进行中」记录（插入失败 → **拒绝发出**该次调用并落 ERROR 日志——审计不可用比调用不可用更严重），调用返回后更新为终态（成功 / 失败 + 失败类别）。「进行中」状态 MUST 由仓储在插入时**固定写入**（不由调用方传入——从源头消除传错状态的可能）；终态更新 MUST 只对**仍处在进行中**的行生效（已终态的行 → 报错并点名该行、**不得覆盖**，即终态只写一次）；终态更新失败 MUST 只落 ERROR 日志、把行**留在进行中形态**（**不得**伪造终态），由后续 US 的恢复流程收口。
- **FR-004**: 两处审计写入 MUST 与调用取消**解耦**（在剥除取消信号、独立短超时——缺省 5 秒——的上下文里执行）：被取消的调用同样要留下「这次调用存在过」的证据；预写解耦的另一个后果是——预写失败必须真的意味着「审计不可用」，而不是「上下文恰好已取消」。
- **FR-005**: 运行标识 / 会话标识 / 轮次 MUST 随请求**显式**传入并落审计行；运行标识为空或轮次小于 1 → **拒绝发出且不写审计行**（用法错误，非调用失败）。只要调用被发出过，MUST 先有进行中记录；反之，凡未发出的调用 MUST NOT 合成审计行（合成会污染后续恢复判据）。
- **FR-006**: 生效模型 MUST 按「请求模型 > 供应商缺省模型」解析；两者都空 → 点名供应商拒绝、零调用、零审计行；生效模型 MUST 落审计行。
- **FR-007**: 每次**失败**的调用 MUST 落失败类别（七类字面量之一，**不得**只留自由文本）。本 feature 的取值面三类：**外部错误**（供应商 4xx / 5xx、网络不可达 / DNS / TLS、响应不可解析、3xx 未跟随）、**超时**（调用被取消或截止——两个上下文错误**归并**为「超时」，但错误链的区分保留，调用方可判定具体原因）、**未知**（兜底：既非客户端产出的安全错误、错误链上也无上下文错误的异常错误——如第三方客户端实现抛回的裸错误）。
- **FR-008**: 协议往返 MUST 两端保真：出站把已知字段与扩展透传位**平铺**进消息、入站把已知键映射到模型字段、未知键收进扩展透传位；消息模型的字段与 JSON 名 MUST 逐字保真（工具调用 / 工具调用标识 / 思考内容 / 扩展透传位）。验收 MUST 走**两跳**（假服务返回未知字段 → 解析进透传位 → 下一次请求体仍含该字段）——只做一次本系统类型的序列化往返检不出「依赖库把未知字段丢了」，不构成该条验收。
- **FR-009**: 响应字段可空性 MUST 全部兜底：用量可空（三列 0、**不判失败**）、带工具调用的响应正文可空（只透传、不判失败）、思考内容可空但**不得丢**。
- **FR-010**: 可观测性 MUST 双轨（审计轨 + 日志轨 **都**要，级别口径见 FR-011 的字段纪律）：预写失败 = ERROR（服务降级，需人介入）、终态更新失败 = ERROR（残余窗口）、调用失败与路由拒绝 = WARN；日志字段 MUST 用固定键（供应商 / 模型 / 运行标识 / 错误 / 失败类别），**不得**把错误文本拼进消息主体、**不得**记凭证、**不得**记全量地址。

#### 凭证与地址面

- **FR-011**: 脱敏责任 MUST 落在**客户端边界**（它是唯一持有凭证的地方）：错误文案离开客户端前 MUST 抹除凭证回显、按 4 KB 截断（**UTF-8 安全**，不得切断半个字符）、**不得**携带请求地址与响应正文全文；服务侧照原样记录它拿到的错误（服务不持有凭证，无从脱敏）。截断 MUST 在**落库前**再做一次（审计列的家——对任何写入方都成立、单点可单测，同样 UTF-8 安全）：两处各自独立成立，**不得**只留一处。审计行 MUST NOT 存凭证。判据可执行：假服务回显合成凭证 → 返回错误 / 日志缓冲 / 审计失败原文三路均无该值；超长失败原文落库后长度不超过 4 KB 且为合法 UTF-8。
- **FR-012**: 供应商地址的支持面 MUST 收窄为 scheme + host + path 三部分并**原样保留**（路径可为空；缺 scheme **不代补**——不做隐式推断）；含 userinfo / query / fragment 的取值 MUST 在**装载期拒绝**（**不采用**「接受后静默裁剪」——静默删改会改写用户配置的含义，把认证 / 路由错误推迟成难定位的运行时故障），地址缺失 MUST 提为必填。拒绝文案 MUST 只点名键路径与不支持的成分名，**不回显原 URL、也不回显其中的值**（解析库的原始错误自带 URL，**不得**直传）。构造期 MUST 按同一口径**再判一次**（客户端可被直接构造，不依赖装载层已拦）；展示层 MUST 按收窄规则渲染（纵深防御，不依赖上一层已拦干净）。

#### 命令面

- **FR-013**: `basalt provider list` MUST 走**轻路径**：只读配置文件，**不开库、不取实例锁、不做恢复、不构造客户端**；缺配置文件或供应商段为空 → 失败（退出码 1）并点名路径 / 段名；配置无效 → 原错误上抛（已点名键路径与变量名、不含凭证值）；正常 → 逐条列出名称 / 收窄地址 / 缺省模型 / 凭证状态文案 + 汇总行，退出码 0，输出**零凭证值**。退出码口径沿用 US-1（成功 0 / 失败 1，原因由文案区分）。

#### 工程纪律

- **FR-014**: 上下文 MUST 只承载取消 / 截止 / 追踪标识；映射表、模型表、审计仓储、日志器与关联字段一律**显式类型化参数**传递，业务代码中 `context.WithValue` **零使用**。客户端 MUST NOT 设自有超时（截止时间由调用方上下文承载）。
- **FR-015**: 客户端与映射表 MUST 在装配时一次构建、之后只读（并发安全的前提）；配置改动**重启生效**（热加载归后续 US）；本 feature 的调用面 MUST NOT 引入响应缓存。并发调用（含取消路径）在竞态检测下 MUST 零告警、零 goroutine 泄漏。
- **FR-016**: 依赖方向 MUST 遵守：契约层（类型 / 接口 / 常量 / 哨兵）只依赖标准库、**不 import** 其他内部包与第三方；实现落实现包；审计 SQL MUST 只出现在存储包且写入路径**唯一**；仓储接口声明在消费方、实现放实现包、装配在唯一装配层；依赖无环由 CI 复核。
- **FR-017**: 测试基础设施 MUST 交付：假供应商（按脚本回放响应 / 错误、记录收到的请求、可阻塞到上下文取消、以「调用已进入」的同步信号替代时间等待）与回环假 OpenAI 服务（回放 HTTP 状态与响应体、记录收到的请求体）；默认测试层 MUST 无一例访问真实网络。

### Key Entities

- **供应商配置条目**：名称（映射表的键，重复即拒绝）、地址（只支持 scheme + host + path）、凭证（环境变量占位，解析后只进客户端）、缺省模型。
- **显式映射表**：装配时逐条构建的「供应商名 → 客户端实例」对照，加一份「供应商名 → 缺省模型」的对照；之后只读，路由只查表。
- **调用请求**：路由与审计关联组（供应商名 / 运行标识 / 会话标识 / 轮次 / 配置快照标识——本 feature 恒空）+ 协议内容组（模型 / 消息序列）。
- **调用响应**：正文 / 工具调用 / 思考内容 / 扩展透传位 / 用量（可空）。
- **审计行（`llm_calls`）**：调用前可知字段（关联键、供应商、生效模型、创建时间，形态为「进行中」）+ 终态回填字段（状态、用量三列、耗时、失败原文[截断 4 KB]、失败类别）。列与状态字面量的唯一事实源是 `docs/contracts/schema.sql`（本规格不另抄列清单）。
- **失败类别**：七类字面量（本 feature 实际产生三类：外部错误 / 超时 / 未知）。

### Out of Scope（本 feature 明确不做）

- ReAct 循环、工具执行器、工具注册与执行（工具调用只透传）。
- 调用重试、fallback 链、流式输出、embedding / 图片 / 语音（只做 Chat Completions）。
- Anthropic 原生协议适配（扩展阶段）。
- Agent 加载与 Profile（供应商 / 模型 / 温度的来源）、`profile` 四条命令（US-3）。
- 运行级预算 / 并发准入 / 取消判定（运行标识的生成）/ 会话历史写入（US-4）。
- 配置快照与配置快照标识的填充（本 feature 写空）、启动恢复扫描（进行中 → 未知等）、实例锁与写模式命令准入（US-4 / US-11）。
- HTTP 端点与错误码映射（本 feature 的「未配置」哨兵只是对外映射位）、`chat` / `serve` / `gateway` 命令（12 条命令中的其余 9 条）。
- 监控指标实装（仍为空实现）、审计查询面与审计导出（`llm_calls` 只写不查）、企业级治理（认证 / 多租户 / Tool Policy / SSO）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 审计留痕零例外：已发出的调用 100% 先有进行中记录（在供应商客户端内部当场查库验证）；审计不可写场景下发出调用次数 = **0**；终态补写失败场景下伪造终态 = 0（行留在进行中形态）。
- **SC-002**: 失败可解释：失败调用 100% 带七类之一的类别；未注册供应商 / 关联缺失 / 模型不可解析三类拒绝的审计行数 = 0（「无行 = 确定没执行」双向成立）。
- **SC-003**: 凭证红线：供应商回显合成凭证的场景下，返回错误 / 日志缓冲 / 审计失败原文三路命中 = 0；`provider list` 与一切失败文案的标准输出 / 标准错误命中 = 0。
- **SC-004**: 地址面 100% 拒绝：三类不支持成分（userinfo / query / fragment）各一例在装载期被拒，构造期防御校验同样全拒；拒绝文案对本 URL 与其中值的回显 = 0。
- **SC-005**: 协议保真：未知扩展字段与思考内容在两跳往返后 100% 保留（第二次请求体逐字比对）；出站请求体中消息数组出现次数 = 1。
- **SC-006**: 命令面：`provider list` 在缺配置文件 / 空段两种形态下 100% 判红并点名；正常形态 100% 列出全部条目且凭证值命中 = 0；退出码口径与 US-1 一致（成功 0 / 失败 1）。
- **SC-007**: 环境独立性：默认测试层访问真实网络 = 0 例；真实调用验收由人执行、凭证经环境变量注入、明文落盘 = 0；集成用例在缺凭证 / 未开执行开关时以「跳过」呈现——**跳过不构成验收通过**（收口报告区分通过与跳过）。
- **SC-008**: 工程纪律：业务代码 `context.WithValue` 命中 = 0；审计 SQL 出现在存储包之外 = 0；依赖无环（CI 复核）；覆盖率按可执行判据达标（契约层与实现包自本 feature 起纳入判卷，无豁免）。
