## User Scenarios & Testing *(mandatory)*

**标签口径（`[US1]` / `[US2]` / `[US3]` / `[US4]` 不混淆）**：下面四个用户故事在 `tasks.md` 中以 Spec-Kit 的工具标签 `[US1]`~`[US4]` 出现——那是**本 feature 内部**用户故事的编号，**不是**项目台账（[docs/us/REGISTRY.md](../../docs/us/REGISTRY.md)）里的 US-1 / US-2 / US-3 / US-4。本 feature 的四个故事同属项目 **US-5（Shell 与 HTTP 工具）** 一个模块，是它的四个独立可验场景；标签按工具产出保留。

### User Story 1 - 出网取数：两件 HTTP 工具与逐跳判定（Priority: P1）

用户配置好域名白名单后，在真控制台问「今天天气怎么样」：模型请求 `http_get` 取外部数据，工具**每一跳在发送之前**都判定一次（scheme / 主机 / 端口 / 域名白名单——**判定只此一处**），HTTP 客户端**不得自行跟随重定向**；`3xx` 由工具按状态码决定怎么跳（只有 301 / 302 / 303 / 307 / 308 判跳转，301/302/303 转 `GET` 且丢正文、307/308 保持方法与正文；304 之类按普通响应返回），跳数上限 **5**（初始请求不计，超限归沙箱拒绝而非外部错误），**跨源跳转不携带模型给的请求头**。取回的响应按生效预算读取（多读 1 字节让下游截断判据必定命中，标记恰一次），内容首行是响应状态行；4xx / 5xx 与 DNS / 连接 / TLS / 响应读取失败一律判**外部系统错误**（文案只出自产类别与主机名，**不回显** URL 原文 / query / 响应体 / Location），取消与截止**保留自身身份**并优先归超时。**不读环境代理变量**；出站请求体超上限（256 KiB，按 UTF-8 字节计）判**入参非法**、**零发送**。模型据此给出穿衣建议（验收 Demo 的读数来自这条链路）。

**Why this priority**: 它是本模块的旗舰与验收 Demo 一的直达路径，也是**出网档的首个真实消费方**——US-4 交付了域名判定与逐跳契约却没有驱动者；2026-10-17 用户终裁的**端口冻结组合**（只允许协议默认端口、初始与每一跳同判、拒绝先于发送）也整体落在这一条链路上。

**Independent Test**: 以进程内**假网络执行器**（记录每次请求与返回脚本化响应）× **真白名单策略** 驱动两件工具，逐例断言：每跳判定次数与发送次数对齐、越界的那一跳**零发送**、跳数上限计到 6 次请求、五种状态码各自的重定向语义与跨源头规则、端口冻结组合逐格对号（默认放行 / 非默认拒 / 交叉档拒）、4xx / 5xx 与网络失败的类别与文案（零 query / 零响应体 / 零 Location 原文）、取消传播（等「请求已发出」信号再取消、限时返回）；另以**真客户端**跑本地回环测试服务判三条真链路行为（跳转由工具驱动 / 环境代理不可达仍直连 / 取消限时返回）。全程不出进程。

**Acceptance Scenarios**:

1. **Given** 白名单域名内的合法 URL 与返回 200 的假网络执行器，**When** 执行 `http_get`，**Then** 结果内容首行为响应状态行、换行后接响应体，且本次只有一次判定与一次发送。
2. **Given** 第一跳返回 302 且 `Location` 指向白名单外的域名，**When** 执行，**Then** 得到四段式沙箱拒绝（点名越界目标）、分类为沙箱拒绝，**假执行器记录的请求次数恰为 1**（被拒的那一跳未发出）。
3. **Given** 服务器连续返回重定向，**When** 执行，**Then** 假执行器恰收到 6 次请求（初始 + 5 跳），第 6 个重定向被拒且**归沙箱拒绝**（不是外部系统错误）。
4. **Given** 白名单域名内的重定向指向**同一主机的非默认端口**（如 `:8080`），**When** 执行，**Then** 被拒、归沙箱拒绝、四段式第 2 段点名主机与端口、第 4 段指引固定写「当前版本不支持非默认端口」且**不指向**域名白名单，**目标请求零发送**（假执行器只收到初始请求 1 次）。
5. **Given** 响应为 405 / 500，**When** 执行，**Then** 判外部系统错误、文案形态为「状态码：主机名」、**不含** query 与响应体；**Given** 连接被拒 / 响应体读取失败，**Then** 同样归外部系统错误且文案不含 URL 原文。
6. **Given** 请求已发出后调用方取消上下文，**When** 读取响应体途中取消，**Then** 在限时内返回、错误链保留取消身份（分类据此归超时），**不得**把取消读成「读完了」、**不得**留后台读取。
7. **Given** 出站请求体超过 256 KiB，**When** 执行 `http_post`，**Then** 判入参非法、**零发送**（假执行器零次请求）。

### User Story 2 - 命令执行：`shell` 工具与输出预算到读取端（Priority: P2）

Agent 在自己的目录下跑白名单内的命令：可执行名与逐项参数**分开**承载、**argv 直执**（不经任何 shell、工具**不得**在本地拆分可执行名——把 `bash -c "curl …"` 拆开正是绕开命令档的标准姿势）；`bash` / `sh` 在策略侧**硬拒**（判定先于白名单查询）；请求里的超时**只能缩短**（生效值取执行侧上限与请求值的更小者；非正值按缺省、不报错）；有 Agent 上下文且目录存在时子进程工作目录即该 Agent 目录（**不得**引入全局目录切换）；子进程环境变量由受控执行侧按白名单过滤（工具**不读**进程环境与代理变量）。**非零退出码不是错误**——结果首行写退出码、换行后接输出（stderr 已合流），把非零码判成失败会让「没匹配到」一类正常结果全变失败。输出**原样透传**（限流点标记归执行侧，工具**不得**自行截断或加标记）。运维配置里的输出预算**真正到达读取端**：装配值取既有预算键，逐运行更小的上限随命令下传到读取端并夹到 256 KiB 硬上限——配置收紧了预算，子进程**不得**照旧读满。

**Why this priority**: 这是「首个真正动手的通道」的命令半场，也是**命令档的首个真实消费方**（受控执行器自 US-4 交付以来零生产调用点）；没有它，「三档授权全部有真实消费方」这句承诺只完成一半。放在 P2 是因为它复用 US-4 已交付的受控执行与进程树回收，判定面（命令档）也已就位，交付面比出网链路窄。

**Independent Test**: 以**假命令执行器**（记录收到的上下文截止时刻与命令结构，零进程）× **真白名单策略** 驱动工具，逐例断言：参数逐项原样、可执行名整串传入判定、工作目录随 Agent 上下文、环境恒空、超时四态（缺省 / 更短 / 更长不生效 / 非正值）、非零退出码的呈现形态、输出零改动透传、逐运行预算随命令下传；`bash -c "…"` 整串被拒且**假执行器零调用**；另以**真执行器链路**（真实调度器 × 假审计仓储）判截断标记恰一次与预算口径。全程不起真实子进程。

**Acceptance Scenarios**:

1. **Given** 白名单内的命令与逐项参数，**When** 执行，**Then** 传给执行侧的命令结构里可执行名与参数**逐项原样**（无拼接、无拆分）、工作目录为 Agent 目录、环境为空。
2. **Given** 模型请求 `bash -c "curl …"`，**When** 执行，**Then** 得到四段式拒绝（可执行名整串比对失败 / 硬拒）、**假执行器零调用**、错误归沙箱拒绝。
3. **Given** 执行侧上限 30 秒，**When** 请求 `timeout_seconds` 分别为缺省 / 5 / 3600 / 0，**Then** 生效截止时刻分别为 30 / 5 / 30 / 30 秒——只有更短才收窄，更长不生效，非正值不报错。
4. **Given** 命令以非零码退出且输出非空，**When** 执行，**Then** 结果**无错误**、首行为「退出码：N」、其后为原始输出（含执行侧已追加的截断标记，若发生）。
5. **Given** 逐运行生效预算小于装配值，**When** 执行，**Then** 下传到读取端的上限为该更小值（读取侧取装配值、逐命令值与 256 KiB 硬上限的最小者）。
6. **Given** 输出远超上限，**When** 走真实调度链路，**Then** 落库结果中截断标记**恰出现一次**、标记中的上限为**生效上限**、截断后的内容不超过上限（中文按字符边界回退）。

### User Story 3 - 越权与失败的可判卷：端口冻结、文案脱敏与分类补齐（Priority: P3）

模型（或诱导它的用户）在各种边界上试探：命令档的 `bash -c`、域名档的非默认端口与白名单外域名、字段类型给错的入参。系统的回应必须是**可判卷**的：出网判定的**端口档**按冻结组合逐格成立——`http` 配省略端口或显式 `:80`、`https` 配省略端口或显式 `:443` **放行**；`http:443`、`https:80` 交叉档与 `8080` / `8443` 等非默认档**一律拒**、归沙箱拒绝，**初始请求与每一次重定向同判、拒绝先于发送**；拒绝文案四段齐备且**脱敏**——目标值只出主机（与端口），**不得**回显 URL 原文 / userinfo / query。失败分类补齐两档承载：**外部系统错误**（4xx / 5xx 与出网失败）与**入参非法**（参数类型 / 取值不合法——模型给错类型不是本仓缺陷），判序为沙箱 → 入参非法 → 取消/截止 → 外部系统 → 文件不存在 → 兜底；既有三件文件工具的解码与取值错误**同批改载体**（文案不变、只换类型）。敏感面纪律：日志、模型可见文案与错误文案**不得**含 userinfo / query / 请求头 / 响应体内容；**不得**笼统承诺「凭证不落库」——本模块不注入运维凭证，模型参数按契约原样进审计。所有拒绝照常落审计（预写先于执行）、**运行照常继续**。

**Why this priority**: 这是本产品对严监管客户的承诺面（三档授权「全部有真实消费方」的判卷口 + 审计分类可读 + 不扩撒秘密）。放在 P3 是因为它横跨前两个故事的产物（分类承载与端口规则被它们使用），单独交付不产生新通道，但缺了它前两个故事的失败面就不可判卷。

**Independent Test**: 策略面以真策略逐格断言端口组合（放行两格 / 交叉档两格 / 非默认档）、四段式文案与脱敏（第 2 段含主机与端口、**不含** userinfo 与 query；第 4 段含固定指引且**不含**域名白名单键名）；分类面以真实调度器 × 假审计仓储逐类断言七值与判序（外部系统错误包着截止错误仍归超时、入参非法先于外部系统）；既有文件工具的载体断言文案不变。全程零网络、零进程。

**Acceptance Scenarios**:

1. **Given** 出网目标为 `http://example.com`（省略端口）或显式 `http://example.com:80`，**When** 判定，**Then** 两格**等价放行**（`https` 与 `:443` 同理）；**Given** `http://example.com:443` / `https://example.com:80` 交叉档或 `:8080` / `:8443`，**Then** 一律拒、归沙箱拒绝。
2. **Given** 目标 URL 形如 `https://user:secret@example.com:8443/x?token=…`，**When** 判定被拒，**Then** 文案与日志**不含** `secret` / `token` / query 原文，第 2 段点名主机与端口；第 4 段含「当前版本不支持非默认端口」且**不指向**域名白名单。
3. **Given** 外部系统错误（含包着截止错误的错误链），**When** 分类，**Then** 包着取消 / 截止归**超时**、其余归**外部系统错误**；**Given** 参数类型不符，**Then** 归**入参非法**；七值分类各一条夹具逐字对号（兜底分支**不得**吞掉新分支）。
4. **Given** 既有三件文件工具的解码 / 取值失败（注入类型错误 / 空值），**When** 断言，**Then** 载体已是**入参非法**类别、**文案与既有断言逐字不变**。
5. **Given** 任一拒绝路径（沙箱 / 入参非法 / 超限），**When** 执行，**Then** 审计**仍落行**（预写先于执行、终态记失败与分类）、失败信息**原样回填**模型、运行**照常继续**。

### User Story 4 - 工具清单：`basalt tool list` 与装配六件（Priority: P4）

运维执行 `basalt tool list`：逐行「名称：描述」、末尾空行 + 汇总行「共 6 件工具」——这是**运维恢复演练判据 4** 的读数来源（工具注册表非空），与判据 5 走同一条路径。顺序由实现侧给出（排序稳定），命令面**不得**重排；空池有专门文案。命令属**重路径**（答案来自装配期构建的内存注册表——启动即走取锁 → 迁移 → 恢复 → 开跑四步、各记既有日志），准确含义是「**清单读取本身不修改状态**」；**不得**为它写轻路径第二套装配。命令面**不得**直接依赖工具实现包——清单经**消费方定义的端口**取值、由装配层注入适配器；装配池至此**六件**（三件文件工具 + 本模块三件）。

**Why this priority**: 它让「注册了什么」可现场核对、是恢复演练判据的读数面，并收口本模块的装配接线（注册池 +3、受控执行器首次接线之外的最后一块）。放在 P4 是因为它建立在 P1~P3 的工具与装配之上，且本身不产生新通道。

**Independent Test**: 以**假端口**（实现清单接口，记录调用）判渲染（顺序稳定 / 汇总行 / 空池文案 / 装配缺件报错）；以**真注册表**判端口转调保序与装配池六件（三件新工具可解析）；判命令名归属重路径（与既有命令同路）；判依赖方向（命令面包**不得** import 工具实现包——判据扩面）。全程零网络、零进程。

**Acceptance Scenarios**:

1. **Given** 装配完整的重路径，**When** 执行 `tool list`，**Then** 输出逐行「名称：描述」+ 末尾空行 + 「共 6 件工具」，顺序与注册表给出的顺序**逐项一致**（命令面零重排）。
2. **Given** 注册表为空（防御分支），**When** 渲染，**Then** 输出空池文案。
3. **Given** 装配缺件（端口未注入），**When** 执行，**Then** 返回**带点名的错误**（不是空输出、不是静默成功）。
4. **Given** 命令名解析，**When** 判归属，**Then** `tool` 与 `chat` 同走重路径、`session` 仍走轻路径。
5. **Given** 依赖方向判据，**When** 扫描命令面导入面，**Then** 工具实现包零命中（判据**扩面**——覆盖新面，不是放宽阈值）。

### Edge Cases

- 重定向响应的 `Location` 缺失或无法解析 → 判**外部系统错误**（外部系统给不出目标），且**不回显** `Location` 原文（可能带 userinfo / 凭证）；相对 `Location` 按**当前** URL 解析后再判。
- 3xx 中**未被列为跳转**的状态码（如 304）→ 按**普通响应**返回（内容 + 状态行），**不**跳转、**不**计入跳数。
- 跳数刚好用满（已跟随 5 次）后服务器再给重定向 → 拒；判据是「已跟随次数 > 5」，**初始请求不计**，执行侧因此恰收到 6 次请求。
- 请求体恰好等于上限 → 放行（按「超限才拒」判定）；多字节字符横跨上限边界 → 按 UTF-8 **字节**计，不得劈出半个字符。
- 响应体恰好等于生效上限 → **不判截断**（工具多读的 1 字节是给下游判据用的，不进入结果内容）；等于上限 + 1 字节 → 截断且标记恰一次。
- 空响应体 → 内容只有状态行（无换行后的正文段）。
- 出站请求头：模型提供的头**逐项**设置、不加白名单；`Host` / `Content-Length` 由 HTTP 客户端自管（模型给的同名头不生效也不报错）；跨源跳转**一律不带**模型头；`POST` 转 `GET` 时同时清 `Content-Type` / `Content-Length` / `Content-Encoding`。
- shell 的 `arguments[0]` 以 `-` 开头（仅解释器名单内的可执行名）→ 执行侧形态校验拒绝（内联代码形态）；普通命令的 `-c` 参数（如 `git -c color.ui=false status`）是**正常参数**，不判红。
- `timeout_seconds` 给负值 / 零 → 按缺省处理，**不**产生新的错误路径（与「入参非法」的既有口径分层：执行器判结构与必填、工具判类型与取值）。
- 出网失败包着取消 / 截止错误（未来某处经 `%w` 包装）→ 分类仍穿透判出超时（`Unwrap` 是第二道防线）。
- 响应体读取错误 → **不得**丢弃（EOF 与取消读成同一种「读完了」会把失败读成成功）。
- 执行侧传回非零退出码且输出为空 → 结果**无错误**、只有退出码首行。
- 传输层对幂等请求的连接复用重发（标准库行为）→ 如实登记为例外：**不得**把「代码里没有重试循环」写成「只发送一次」；应用层零重试、重发收敛在同一次调用（同一审计行）内。

## Requirements *(mandatory)*

### Functional Requirements

#### 出网工具与判定面

- **FR-001**: `http_get` / `http_post` MUST 逐字对齐契约参数面：`http_get` 只有目标地址；`http_post` 加请求体（**必填**，空串是合法值——在场即算，工具 MUST NOT 二次判空）与内容类型（缺省 JSON）；两件 MUST NOT 出现任何超时参数（超时由执行侧上下文一体承担）。
- **FR-002**: 出网 MUST **逐跳校验**：**每一跳在发送之前**判定一次（协议 / 主机 / 端口 / 域名白名单），HTTP 客户端 MUST NOT 自行跟随重定向（把重定向交回工具）；判定 MUST 只此一处——工具 MUST NOT 本地预判或改写目标串（两份判定必然漂移）。
- **FR-003**: 端口档 MUST 按冻结组合判定（2026-10-17 用户裁决）：`http` + 省略端口或 `:80`、`https` + 省略端口或 `:443` → **放行**；交叉档（`http:443` / `https:80`）与其余非默认档 → **一律拒**、归沙箱拒绝；**初始请求与每一次重定向同判、拒绝发生在发送之前**；拒绝指引 MUST 固定写「当前版本不支持非默认端口」，MUST NOT 提示「加入域名白名单即可解决」（域名白名单管主机、不管端口）；边界 MUST 如实登记：本地 `8080` 类服务在当前版本不可达（放行通道须新增配置键，归扩展阶段）。
- **FR-004**: 重定向 MUST 只对 301 / 302 / 303 / 307 / 308 执行（共五种）；301 / 302 / 303 → 转 `GET` 并丢弃请求体（同时清正文相关头）；307 / 308 → 保持原方法与请求体；**其余 3xx（如 304）MUST 按普通响应返回**、不跳转、不计跳数。方法 / 请求体 / 请求头的跨跳语义 MUST 集中在一处实现。
- **FR-005**: 跳数上限 MUST 为 **5**，以「已跟随的重定向次数」计、**初始请求不计**；超限 MUST 判沙箱拒绝（**不是**外部系统错误）。
- **FR-006**: 跨跳请求头 MUST 按同源规则：模型提供的请求头只随首跳；仅当目标与**当前跳同源**（协议 + 主机 + 端口三者全同）才转发；**跨源一律不转发任何**模型提供的头；`POST` 转 `GET` 时清除正文相关头。单跳内 MUST 逐项设置、MUST NOT 引入头部白名单概念（`Host` / `Content-Length` 由客户端自管）。
- **FR-007**: 出站请求体 MUST 有上限 **256 KiB**（按 UTF-8 字节计）；超限 MUST 判**入参非法**且**零发送**。该上限是本模块的**新增裁决**（契约与技术方案均无此规定）——文档 MUST 如实标注、MUST NOT 冒称契约已有；保护范围与局限（不发出，但审计预写先于工具执行 ⇒ 该行仍留痕并记失败）MUST 如实登记。
- **FR-008**: 非重定向且状态码 < 400 的响应 MUST 按「首行状态行 + 换行 + 响应体」呈现内容；响应体 MUST 按生效上限 **+1 字节**读取（让下游截断判据必定命中）；空体 MUST 只有状态行；**工具 MUST NOT 自行追加截断标记**（标记由执行侧追加、恰一次、值 = 生效上限）。
- **FR-009**: 4xx / 5xx MUST 判**外部系统错误**（MUST NOT 把 5xx 当「成功带回内容」——模型会把错误页当数据用）；失败文案形态 MUST 为「状态码：主机名」，MUST NOT 含 query / 响应体 / `Location` 原文。
- **FR-010**: DNS 解析失败 / 连接失败 / TLS 握手失败 / 响应读取失败 MUST 判**外部系统错误**——文案只出自产类别与主机名（协议错误的原文里带整条 URL，MUST NOT 直接透传）；**取消与截止 MUST 保留自身身份、只上抛该身份哨兵**（分类据此归超时；MUST NOT 上抛携带 URL 原文的传输层包装错误——两个错误点都如此）——两个错误点（发送与读取）MUST **先判上下文再包装**；响应读取错误 MUST NOT 被丢弃。
- **FR-011**: 出网 MUST **不读环境代理变量**：HTTP 传输件的代理配置恒为空；客户端 MUST 显式关闭自行跟随重定向。
- **FR-012**: 两件出网工具的结果 MUST 一律标记「不可重试建议」为假，语义 = 「当前不给出可重试建议」；MUST NOT 把该字段读成「运行时会不会自动重试」（应用层零重试是契约独立承诺）；传输层对幂等请求的连接复用重发 MUST 如实登记为例外（同一审计行内，MUST NOT 写成「只发送一次」）。

#### 命令工具与受控执行

- **FR-013**: `shell` 参数 MUST 逐字对齐契约：可执行名**必填**、参数数组**逐项原样**；执行 MUST 为 **argv 直执**——可执行名与参数**分开**承载，MUST NOT 拼接命令串、MUST NOT 经任何 shell 转发；工具 MUST NOT 在本地拆分可执行名（拆分正是绕开命令档的标准姿势）。
- **FR-014**: 命令档判定 MUST 归策略层：`bash` / `sh` **不得放行**（含内联代码形态；硬拒 MUST 先于白名单查询——先查白名单会让「白名单里写了 bash」这个配置错误变成放行）；解释器名单内的可执行名只接受「脚本路径 + 参数…」形态（首个参数 MUST NOT 以 `-` 开头）、脚本真实路径 MUST 落在该 Agent 的脚本目录或技能库内——这两条属**执行侧**形态校验；工具侧 MUST NOT 存在任何 shell 调用点。
- **FR-015**: 超时 MUST **只缩短**：生效值 = min(执行侧上限, 正请求值)；请求值非正 MUST 按缺省处理、不报错、MUST NOT 新增错误路径（契约的「入参非法」由执行器的入参校验产出）。
- **FR-016**: 工作目录 MUST 为：有 Agent 上下文且目录存在 → 该 Agent 目录；否则进程默认；MUST NOT 引入全局目录切换。
- **FR-017**: 子进程环境变量 MUST 只透传配置白名单（由受控执行侧统一过滤）；`shell` 契约**没有**环境参数 ⇒ 传给执行侧的环境 MUST 恒为空；工具 MUST NOT 读进程环境、MUST NOT 读代理变量。
- **FR-018**: **非零退出码 MUST NOT 判错误**：结果首行「退出码：N」、换行后接输出（标准错误已合流）；只有**执行失败**才是错误；工具 MUST NOT 追加任何其他装饰。
- **FR-019**: 截断责任分工（命令侧）：限流点标记由执行侧在读取中追加，执行侧按生效预算必要时再截一次；工具 MUST **原样透传**输出、MUST NOT 自行截断或追加标记（会出现两个标记）。
- **FR-020**: 逐运行输出预算 MUST 到达**读取端**：装配值 MUST 接**既有**运维配置键（MUST NOT 传零让读取侧恒用缺省）；逐运行更小的上限随命令结构下传到读取端，读取侧取「装配值、逐命令值、256 KiB 硬上限」三者更小者；MUST NOT 新增配置键（Profile 无该覆盖权）。配置白名单在装配期一次构建 ⇒ 配置生效时机 = **重启**。

#### 失败分类与错误承载

- **FR-021**: 失败分类 MUST 新增两条分支：**外部系统错误** → `external_error`（插在取消 / 截止判定**之后**——身份优先）与**入参非法** → `invalid_input`（插在沙箱判定**之后**、取消 / 截止判定**之前**）；判序 MUST 为：沙箱 → 入参非法 → 取消/截止 → 外部系统 → 文件不存在 → 兜底。七值字面量本身**冻结不变**（本模块只新增**产出方**与承载，不改取值集），全表逐字为：`sandbox_denied`（沙箱拒绝）、`invalid_input`（入参非法）、`timeout`（取消 / 截止——MUST NOT 被外部系统分支截胡）、`external_error`（外部系统错误）、`not_found`（目标不存在）、`runtime_error`（兜底）、`unknown`（崩溃恢复的 pending 行）。
- **FR-022**: 入参非法的**分层 MUST 不重复**：执行器判「合法 JSON 对象 + 必填键」（入口）、工具判「字段类型与取值」（解码点），两处产出**同一类别**；错误承载 MUST 为专门类型（判定只认类型、不比文本），既有三件文件工具的解码 / 取值错误 MUST **同批改载体**（文案不变、只换类型；本模块是对既有分类兜底行的**细化**，不是改判——本仓缺陷仍归运行时错误）。
- **FR-023**: 审计链路 MUST **零改动**：工具 MUST NOT 写审计、MUST NOT 写消息；两阶段写（先预写、后回填）与结果消息追加的唯一归属不变 ⇒ 本模块的拒绝 / 超限路径**仍留有审计行**（预写先于工具执行）且终态记失败与分类；失败信息 MUST **原样回填**模型（四段式文案 MUST NOT 被吞掉、替换或泛化）。

#### 工具清单命令与命令面

- **FR-024**: `tool list` MUST 逐行「名称：描述」、末尾空行 + 「共 N 件工具」；空池 MUST 有专门文案；顺序 MUST 由实现侧给出（排序稳定），命令面 MUST NOT 重排、MUST NOT 依赖 map 遍历；MUST NOT 打印参数详情（那是管理域的能力）。
- **FR-025**: 命令面 MUST 经**消费方定义的端口**取工具清单，MUST NOT 直接 import 工具实现包（依赖方向判据 MUST 扩面覆盖新面）；端口实现 MUST 由装配层注入（顺序与渲染同源）；注入位缺失 MUST 报**带点名的错误**。
- **FR-026**: `tool list` MUST 属**重路径**（答案来自装配期构建的内存注册表）：启动即走取锁 → 迁移 → 恢复 → 开跑四步、各记既有日志；「只读」的准确含义 MUST 是「**清单读取本身不修改状态**」，MUST NOT 写成「整个命令零写、零日志」；MUST NOT 为同一语义写轻路径第二套装配。

#### 装配、可观测性与工程纪律

- **FR-027**: 装配 MUST：注册池三件 → **六件**；受控执行器**首次生产接线**（输出预算接既有配置键，`int64`→`int` 转换照既有先例、非正值留给包内缺省）；新增工具清单端口的适配器与注入位；重路径命令集增补工具组名；过期占位注释同步更新（注释是事实登记面）。
- **FR-028**: 可观测性 MUST 双轨不变：工具本体**不记日志**（失败路径的 WARN 固定键由调度器承载，键集逐字不变）；`tool list` 与既有的轻路径只读命令**不同档**（前者含重路径启动日志）；MUST NOT 以「消灭日志」换取「只读」的表面一致。
- **FR-029**: 敏感面纪律：日志、模型可见文案与错误文案 MUST NOT 含 userinfo / query / 请求头 / 响应体内容；策略拒绝分支的目标值 MUST 脱敏（解析失败分支与主机 / IP 分支均不得回显完整 URL）；文档 MUST NOT 笼统承诺「凭证不落库」——本模块**不注入**运维凭证，模型参数按契约**原样**进审计（如实边界）。
- **FR-030**: 依赖与纪律红线：工具包 MUST 只 import 核心抽象与标准库；核心抽象包 MUST 只依赖标准库（机器判据）；`context` MUST 只承载取消 / 截止 / 追踪（MUST NOT 用 `context.WithValue` 传业务状态）；工具执行 MUST 同步、MUST NOT 异步编排或起后台读取；时间 MUST 显式传入；MUST NOT 引入抑制静态检查的注释。
- **FR-031**: 零变更面：第三方依赖坐标**零新增**（只用标准库网络能力与本地回环测试服务）；配置键**零新增**（既有键名逐字沿用）；表结构与迁移**零改动**；MUST NOT 触碰四份权威文档与契约（既有工具实现与用例的改造点除外——逐条属软门禁，开工前报告）。

### Key Entities

- **工具输入（两件出网工具）**：目标地址 + （POST）请求体与内容类型 + 请求头集合。
- **工具输入（命令工具）**：可执行名（必填，整串）+ 参数数组（逐项原样）+ 可选超时（只缩短）。
- **逐跳请求描述**：方法 + 目标地址 + 请求体 + 内容类型 + 请求头集合——跨跳语义（方法 / 请求体 / 请求头）在跳转时由**一处**规则产出下一跳描述。
- **外部系统错误**：外部目标（状态码与主机的组合）+ **自产类别摘要** + 原因链（只经解包供分类与排障，**不进文案**）。
- **入参非法错误**：工具名 + 可读原因（模型给的参数不合法，非本仓缺陷）。
- **命令**：可执行名 + 参数 + 工作目录 + 环境 + **本次执行的读取侧上限**（只许比装配值更短）。
- **命令结果**：输出 + 退出码 + 是否已被限流点截断（既有结构，本模块只消费）。
- **工具清单项**：名称 + 描述（顺序由注册侧给出）。

## Assumptions

- 硬依赖 US-4 已交付物：工具调度器（两阶段审计 + 分类）、白名单策略（路径 / 命令 / 域名三档判定与四段式拒绝）、受控本地执行器（环境白名单 / 整树终止 / 读取上限流）、工具注册表（显式注册 / 排序稳定）、端口注入范式。本模块**不消费**其他未交付能力（记忆工具归后续 US，MCP / 通知 / 定时管理同）。
- 三档授权的**判定**归 US-4（本模块零复写、零预判）；本模块交付的是**驱动**——命令档与域名档的首个真实消费方；路径档消费方 US-4 已交付。域名档本模块只补**端口规则与拒绝文案脱敏**（既有判定缺端口一项——如实登记为前序改造点，MUST NOT 继续声称"判定零改动、端口已被覆盖"）。
- 前序改造点（逐条属**软门禁**，开工前报告）：核心抽象包新增两类错误承载与分类两条分支；受控执行器首次生产接线与逐命令收窄（命令结构增读取侧上限字段）；域名判定增端口规则与脱敏；既有三件文件工具的解码 / 取值错误改载体（文案不变）；命令面新增工具组与端口注入位、依赖方向判据扩面；装配池 +3 与过期占位注释同步。
- 契约状态：本模块触及的运行时契约（`agent-md.md` §5.2 / §5.3、`run-and-errors.md` §7.3 七值与 §6 预算表、`schema.sql` 列级口径）在对应链路验证通过前为"待验证设计草案"——不构成本模块开工阻断（与既有安排一致）。
- 出站请求体上限（256 KiB）与端口冻结组合是本模块的**新增裁决**（不冒称契约已有）；前者范围与局限、后者边界（本地非默认端口服务不可达）均已如实登记。
- 传输层对幂等请求的连接复用重发是既有标准库行为，登记为例外（收敛于同一审计行内）；应用层零重试 / 零重放。
- 平台分支：本模块**无新平台分片文件**；本地回环测试服务允许进默认层（既有限回环口径），真实外网与真实子进程只在人工项。
- 评测基座本模块**不改**（用例集扩面归收尾 US；Demo 一按人工项手工执行并留读数）。

### Out of Scope（本 feature 明确不做）

- 工具的**并行**调用（一轮内多工具并发执行）。
- 幂等键 / 重试 / 重放（`http_post` 有外部副作用：不自动重试、崩溃恢复不自动重放，重传即新运行）。
- 流式响应（SSE / 假流式）。
- 容器化沙箱与命名空间隔离（唯一实现仍是白名单授权 + 受控子进程）。
- 按 Agent 的权限矩阵（当前粒度 = 每个 Agent 的工具声明清单）与出网凭证托管（OAuth / 密钥管理 / 轮换）。
- `tool show`、工具启停与权限编辑、以及工具清单的 REST 端点（归后续 US）。
- 记忆工具、MCP 客户端与工具接入、通知与定时管理工具（归后续 US）。
- 热加载装配；评测用例集扩面（本模块只手工跑 Demo 一）。
- `use_skill` 工具（**永久禁止**——技能沿用声明式绑定 + 渐进披露）。
- **非默认端口的放行通道**（须新增配置键）——归扩展阶段；边界如实登记：本地 `8080` 类服务在当前版本**不可达**。
