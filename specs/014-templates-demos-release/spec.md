## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员通过 MCP 目录与诊断把一条 server 配置配到可用 (Priority: P1)

管理员不知道某个 MCP server 的正确启动方式与所需环境变量，也不想翻外部教程。他在管理台打开 MCP 目录，看到六条已整理好的配方（GitHub、Brave Search、Fetch、Playwright、Filesystem 只读、DBHub），每条标明传输方式、命令与参数、需要的环境变量、依赖、来源地址与"是否经过实测"。他选一条"添加到配置"，表单被预填但**不会自动保存**。保存时若引用的环境变量未设置或为空，系统在写入前拒绝，页面显示"未配置环境变量"并给出对应操作记录入口；文件、发布版本与指针都不变。配置发布后，他点"诊断"查看命令能否定位、环境变量是否就绪、是否需要重启、有哪些已知边界；点"测试"则真实发起一次连接并记录被测版本、阶段、失败分类与发现的工具。他还能看到某个 server 的工具里哪些被内置工具抢占了名字、哪些被跳过。

**Why this priority**: 这是本 US 唯一的**产品代码**切片；没有它，目录只是文档，模板与 Demo 也只能靠猜配置。它同时保护"凭证不落盘、失败不在写入后才发现"这条安全底线。

**Independent Test**: 在临时实例上打开管理台目录页、预填一条配方、制造一次缺环境变量保存、对一条已发布 server 做诊断与测试，核对页面与操作记录的四类状态（配置 / 连接 / 测试 / 诊断）互不混淆；全部可在无真实外部服务时用假连接完成。

**Acceptance Scenarios**:

1. **Given** 一份只有内置工具、没有 MCP 配置的工作区，**When** 管理员读取目录，**Then** 返回六条按 id 升序的条目，字段完整、`verified` 全为 false 且验证说明非空；读取前后 `mcp_servers.yaml` 哈希与操作记录条数不变，且没有任何子进程被启动。
2. **Given** 目录中的一条配方，**When** 管理员点"添加到配置"，**Then** 表单得到预填值但系统不发送保存请求；管理员不点保存即离开时配置不变。
3. **Given** 一条引用了未设置环境变量的 MCP 配置，**When** 管理员保存或发布，**Then** 系统拒绝（503）并返回操作标识，错误只点名 server、键与变量名而不含值；定义文件、发布版本与发布指针均不变，操作记录为失败态。
4. **Given** 一条已发布且无变更的配置，**When** 管理员再次发布，**Then** 系统幂等成功、不新建版本、不重复做环境校验，也不宣称"环境已满足"。
5. **Given** 一条已发布但未重启的 server，**When** 管理员打开诊断，**Then** 页面显示待重启为真，且诊断结论与连接状态、测试结论分开展示；诊断不启动进程、不写操作记录。
6. **Given** 一条测试连接成功但服务端没有暴露任何工具，**When** 管理员查看测试结果，**Then** 结果为成功、工具列表为空，页面另提示"服务端未暴露工具"，不被记为工具列表失败。
7. **Given** 一条 server 提供与内置工具同名的工具，**When** 查看该 server 视图，**Then** 工具来源显示"已提供 2 / 已注册 1 / 跳过 1（赢家：内置）"，而工具列表仍是服务端提供的原始名单。

### User Story 2 - 使用者复制五个每日 Demo 与八个模板，跑出可核对的业务结果 (Priority: P2)

使用者想验证 Basalt 能不能跑真实业务。他从 `examples/daily/` 复制一个 Demo（例如"GitHub 星标雷达"）到隔离工作区，按 SETUP 绑定模型连接与通知渠道、登记 MCP server 与环境变量，然后到点自动运行。运行结果可核对：首跑明确"没有历史基线"，第二次运行会去重并算出星标差值；日报整理类 Demo 通过技能按需读取正文与参考文件，并把结果直接投递给配置的渠道；数据库统计 Demo 用只读 SQLite 连接统计缺失 / 重复 / 非法值三类问题且不发通知；文档变更 Demo 通过自研只读 MCP 对比目录，给出新增 / 修改 / 删除三集合与内容哈希；行业简报 Demo 同时调用 Brave 与 Fetch，并把未取得正文的链接只当线索。另有八个领域模板可直接改造，其中六个为可运行档、一个依赖浏览器、一个明确标注未验证。

**Why this priority**: 这是"底座能跑真实业务"的证据面；它依赖 14A 的目录与诊断才可能被正确配置，但可以与 14A 并行准备素材。

**Independent Test**: 在临时实例上按 SETUP 装载任一 Demo，用固定输入与假模型（或未授权时的夹具）核对业务断言与六段证据；模板可装载、工具可解析、档位与依赖标注一致；不依赖真实外部服务即可判定素材质量。

**Acceptance Scenarios**:

1. **Given** 首次运行的 GitHub 雷达 Demo，**When** 运行结束，**Then** 结果含 `baseline_missing=true` 且不含星标差值字段；第二次运行去掉已见仓库并给出正确差值。
2. **Given** 数据库统计 Demo，**When** 样例库含缺失 / 重复 / 非法值三类问题，**Then** 脚本给出逐类计数，模型只解释不重算，且该 Demo 不产生任何通知。
3. **Given** 文档变更 Demo 的第二次运行，**When** 对比基线，**Then** 输出新增 / 修改 / 删除三集合，修改集合每项带内容哈希，且只读 MCP 的三件工具均被实际调用。
4. **Given** 八个模板，**When** 逐个装载校验，**Then** 每个声明的内置工具都能解析到已注册内置工具，每个声明的 MCP 工具都在目标 server 的工具清单内（允许子集）；档位固定为六 A、一 A\*、一 B，且 B 模板明写"未验证"。
5. **Given** 任一 Demo 的六段证据，**When** 人工与自动各跑一次，**Then** 输入哈希、时区与计划、产物哈希、运行标识、业务断言、通知次数与故障读数均可核对，且自动触发与人工补跑分开留证。
6. **Given** 空的示例脚本目录或缺失 Python 3 的环境，**When** 运行示例测试入口，**Then** 命令失败并点名，不因"零发现"而误报通过。

### User Story 3 - 维护者在干净检出上用候选二进制验收七场景并完成发布锚点 (Priority: P3)

维护者拿到一个干净的候选提交。他先确认工作区无未提交改动，用干净检出跑完整门禁；再用本次构建出的同一份候选二进制跑七条运行可靠性场景（工具闭环、越权、取消 + 工具超时、崩溃恢复、版本冲突、热加载、Web / 调度 / 通知），其中取消后不得有子进程残留且会话可继续、工具超时不得终止 Run、运行中改写配置只影响下一次运行。随后在 Windows 与 Linux 两个平台按同一组命令走查，整理依赖与许可表，按既有运维流程演练一次升级与恢复，固化发布证据（版本、提交、实际执行的候选路径与哈希）。最后由用户手动打 `v0.1.0` 标签。

**Why this priority**: 它不产出新业务能力，但决定"这次交付能不能被信任地发布"；依赖前两片与全部前序 US。

**Independent Test**: 在干净检出上执行构建、门禁、示例测试与七场景 e2e，逐项核对退出码与证据文件；平台走查与 tag 由人工完成并留证。

**Acceptance Scenarios**:

1. **Given** 一个干净候选提交，**When** 执行干净检出流程，**Then** 归档到临时目录后门禁全绿，且脚本在脏工作区或缺少候选制品时直接失败。
2. **Given** 候选二进制，**When** 执行发布 e2e，**Then** 输出标记 `binary_source=candidate`、被测路径与 SHA-256，且该文件与准备分发的文件是同一份；七场景全部通过，缺前置即失败而非跳过。
3. **Given** 一个阻塞中的工具调用，**When** 取消 Run，**Then** 运行落 `cancelled`、无子进程残留、同一会话可继续；**Given** 工具自身超时，**When** 等待，**Then** 工具审计记失败 + 超时、Run 继续并以完成收尾、失败结果回填下一轮请求。
4. **Given** 一个正在运行的 Run，**When** 管理员改写该 Agent 的指令文件，**Then** 本次 Run 仍用旧正文，下一次 Run 使用新正文。
5. **Given** 两个平台的走查记录，**When** 汇总发布证据，**Then** Windows 与 Linux 证据都在，依赖与许可可溯源，`v0.1.0` 标签由用户创建且记录中无 AI 代打。

### Edge Cases

- 目录读取发生在 MCP 运行时尚未装配的进程里：目录是静态集合，仍应可读；不得因为"没有运行时"而报错或返回空。
- 诊断遇到无法静态确认的入口（`.cmd`、含分隔符的相对路径）：只能给"未确认"，不得启动进程去"确认"；随后测试仍须真实尝试。
- 测试期间服务端进程中途退出或协议握手失败：按真实错误给出阶段与分类，不得一律归为"依赖未确认"或误记为超时。
- 环境变量"已设置但为空串"与"未设置"同档拒绝；错误不得回显值，也不得把占位符字面量写进配置文件。
- 旧测试记录缺少新字段：页面显示"历史记录字段不全，需重新测试"，不得据此推断通过。
- 目录条目 `verified=false` 时验证时间与平台必须为空；若实现填了值，视为把未验证写成已验证。
- 示例与模板中出现真实用户标识或明文凭据：视为可移植性失败，必须改为占位与 SETUP 覆盖。
- 模板声明的 MCP 工具多于服务端实际提供：视为空壳，必须修复；不得自动降档或删除声明。
- 重复运行、跨触发点重叠、停机错过：按既有调度契约处理（跳过而非排队、不自动补跑）；Demo 结果不得编造缺失数据。
- 通知发送失败或回执未知：Demo 不得标记为"已送达"；成功 Run 只是获得代投资格。
- `make e2e` 缺少 Python 3、候选二进制或 stage 配置：直接失败，不得跳过计入通过。
- 站点 / README 增量遇到 US-13 未收口：不修改其交付物，切片保持未完成。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供一份只读的 MCP server 目录（六条），经管理认证可读；读取 MUST NOT 启动进程、安装软件、写配置或写管理操作记录，且 MUST NOT 改变 MCP 定义文件内容。
- **FR-002**: 目录条目 MUST 含固定字段：标识、显示名、摘要、分类、传输方式、命令、参数、地址、环境变量占位（键 / 占位符 / 是否必需 / 说明）、依赖、来源地址、验证状态四字段（`verified` / `verification_note` / `verified_at` / `verified_platforms`，取值规则见 Clarifications）与固定 code 的提示集合；条目 MUST 按标识升序；未验证条目 MUST 有验证说明且验证时间与平台为空。
- **FR-003**: 目录提示集合 MUST 只允许目录固定 code（`read_only_tool_face_required` / `server_write_capability` / `write_tool_name_collision` / `browser_required` / `sqlite_sample_only` / `package_entry_unverified` / `stdio_child_egress_unconstrained`），MUST NOT 返回自由文本。
- **FR-004**: 管理台 MUST 提供目录视图：可筛选、可看详情、可"添加到配置"预填表单但 MUST NOT 自动保存；未验证条目 MUST 显示"配方未实测"，MUST NOT 出现"已验证"徽章。
- **FR-005**: 保存、发布或回滚 MCP 配置时，若环境变量占位引用的变量缺失或为空，系统 MUST fail-closed：先写 pending 操作记录再拒绝（503 + 操作标识），定义文件、发布版本与指针 MUST 不变；错误 MUST 只点名 server / 键 / 变量名，MUST NOT 含值；幂等发布 MUST 跳过重复校验且 MUST NOT 宣称环境已满足。
- **FR-006**: 系统 MUST 提供管理认证的 MCP 诊断读取能力，返回传输方式、已发布版本、已应用版本、是否待重启、命令定位状态（located / not_found / unconfirmed）与原因、环境变量键是否就绪（只回布尔）、诊断固定 code 提示集合与检查时间；诊断 MUST NOT 启动进程、连接服务、写操作记录或改变版本状态。
- **FR-007**: 诊断提示集合 MUST 只允许诊断固定 code（`stdio_child_egress_unconstrained` / `remote_mcp_downstream_unconstrained` / `args_placeholders_not_resolved` / `package_entry_unverified` / `http_auth_header_unsupported` / `env_gate_process_local`）；两套提示集合 MUST 各自固定、MUST NOT 合并枚举。
- **FR-008**: MCP 测试结果 MUST 追加字段：操作标识、被测版本标识（0 = 无法确定）、阶段（preflight / spawn / initialize / tools_list / complete）、失败分类（command_not_found / permission_denied / policy_denied / timeout / http_unauthorized / http_unreachable / handshake_failed / tools_list_failed / env_missing / dependency_unconfirmed；成功为空）、工具名单（字段 MUST 始终存在）；旧字段语义 MUST 不变。
- **FR-009**: 测试端点契约 MUST 补充 503（环境缺失）与 504（超时），二者 MUST 带操作标识且 MUST NOT 返回测试结果对象；页面 MUST 通过操作标识读取操作详情中的阶段与分类。
- **FR-010**: 测试的操作状态语义 MUST 为：连接失败 / 策略拒绝记 success + 结果失败；超时记 failed + 504；环境缺失记 failed + 503；预写失败 MUST NOT 执行、MUST NOT 留操作行、MUST NOT 启动子进程。
- **FR-011**: 服务端工具清单为空（协议成功但无工具）时 MUST 记测试成功、工具列表为空、无失败分类；页面 MUST 另提示"服务端未暴露工具"；MUST NOT 改写为工具列表失败。
- **FR-012**: 诊断与测试 MUST 互不预判：诊断未确认时测试 MUST 仍真实尝试；失败阶段与分类 MUST 来自结构化失败结果，MUST NOT 解析标准错误输出或日志。
- **FR-013**: MCP server 视图 MUST 追加工具来源（已提供 / 已注册 / 跳过，跳过项带赢家来源与原因），工具名单 MUST 保持"服务端提供的工具"语义，未连接时工具来源 MUST 为空；注册池重名语义 MUST 不变（内置赢家、只告警不改变）。
- **FR-014**: 系统 MUST 交付五个每日业务 Demo（GitHub 星标雷达、仓库日报、业务数据体检、文档变更、行业简报），每个含独立 Agent 目录、固定输入、期望业务结果、运行说明、业务脚本单测与失败样例；业务断言 MUST 覆盖：首跑无基线不得编造增长率、去重与差值、技能三级按需读取、只读数据库三类问题逐类计数、零通知、记忆对照三集合与内容哈希、双 MCP 来源表与"未取正文只作线索"。
- **FR-015**: 每个 Demo 的证据 MUST 覆盖六段：输入快照哈希、时区与计划、候选产物哈希、运行标识、业务断言（字段 / 计数 / 集合）、通知次数与故障读数；自动触发与人工补跑 MUST 分别留证；空输入 / 无变化 / 依赖失败 MUST NOT 编造结果。
- **FR-016**: 系统 MUST 交付八个领域模板，档位 MUST 固定为六 A（weather-brief / arxiv-tracker / policy-watch / ticket-insights / onboarding-buddy / dependency-watch）、一 A\*（web-watch）、一 B（funding-watch）；模板 MUST 可装载，声明的内置工具 MUST 可解析，声明的 MCP 工具 MUST 是目标 server 工具清单的子集；A 档不通过时 MUST 只能修复或保持未完成，MUST NOT 自动降为 B；B 模板 MUST 明写"未验证"。
- **FR-017**: 示例与模板 MUST NOT 含真实用户标识或明文凭据，MUST 可复制为便携基线；系统 MUST NOT 自动导入示例或自动放宽白名单。
- **FR-018**: 系统 MUST 交付自研最小只读 MCP server 素材（主 module 内 `package main`、纯标准库、零第三方依赖、只读、拒绝越界 / 绝对路径 / 软链接）及其单测；该素材 MUST NOT 被产品二进制导入；安装器 MUST 把源码实际导出到工作区并生成最小 `go.mod`，使导出目录可独立构建，仓库 MUST NOT 维护第二份源码副本；样例数据库 MUST 由脚本生成且 MUST NOT 提交二进制；示例总览 MUST 公开可读且 MUST NOT 链接私有路径。
- **FR-019**: 示例脚本测试 MUST 按固定目录清单逐目录执行并断言每目录用例数不低于下限（零发现即失败）；`docs-readonly` 的 Go 测试 MUST 单列命令执行；两者 MUST 并入统一的示例测试入口，且缺 Python 3 MUST 失败而非跳过。
- **FR-020**: 发布 e2e MUST 使用与分发同一份的候选二进制（同构建参数、关闭 CGO），MUST 导出绝对路径并重算哈希、标记候选来源；MUST 覆盖七场景（工具闭环 / 越权 / 取消 + 工具超时 / 崩溃恢复 / 版本冲突 / 热加载 / Web·调度·通知）；缺前置 MUST 失败，MUST NOT 跳过。
- **FR-021**: 取消 Run MUST 落 `cancelled` 且无子进程残留、同一会话可继续；工具自身超时 MUST 记工具审计失败 + 超时、Run MUST 继续并以完成收尾、失败结果 MUST 回填下一轮请求；运行中改写 Agent 指令 MUST 不影响本次 Run，下一次 Run MUST 使用新正文。
- **FR-022**: 发布收尾 MUST 交付：干净检出流程（要求工作区干净、从提交归档到临时目录、构建与门禁）、依赖与许可表（Go / Node / Python / MCP 包，版本与许可可溯源）、升级与恢复演练记录、发布证据（版本 + 提交 + 实际执行的候选路径与哈希，且与分发产物同一文件）、Windows 与 Linux 两平台走查证据；`v0.1.0` 标签 MUST 由用户手动创建，AI MUST NOT 代打。
- **FR-023**: 公开材料 MUST 只做增量：README（英文单语）与官网 MUST 增加模板与 Demo、MCP 目录、运行示例、验证状态区块，MUST NOT 新增一级路由或链接私有路径；US-13 收口前 MUST NOT 修改其交付物。
- **FR-024**: 四份权威正文与公开运维手册的相关小节 MUST 与实现同步（新五场景、目录 / 诊断 / 测试记录 / 工具来源、示例依赖与出网边界、文件量重估），且 MUST NOT 借此改写历史 US 的已验收证据。
- **FR-025**: 本 US MUST 保持零 schema 迁移、零新增 Go 依赖坐标、零新增 npm 生产依赖；MUST NOT 把发布 e2e 加入既有门禁或 CI，MUST NOT 修改既有 stage。
- **FR-026**: 发行包 MUST 内嵌五个 Demo 的素材，并 MUST 提供独立安装命令（`basalt demo install`）按需在目标工作区准备 Agent、技能、脚本、样例数据与固定版本的 MCP 依赖；两个 GitHub Demo MUST 共用同一份 GitHub MCP。安装器 MUST 保留 `basalt init` 的既有职责不变，MUST NOT 写模型配置或凭据，Demo MUST 保持停用、安装后逐项列出待配置项；MUST NOT 自动改动权限；权限变更 MUST 要求用户显式确认。安装器 MUST 交付按官方流程编写的凭据获取指引（GitHub PAT 与 Brave Search API key：最小只读权限、有效期、套餐或费用要求、本机配置与验证方式），且凭据 MUST 只由用户在本机输入、安装器 MUST NOT 接收、回显或落盘任何凭据值。目录与 Demo 中的 MCP 配方 MUST 与实测版本一致（DBHub 1.5.0 只读经 `dbhub.toml` 的 `[[tools]]` 表达、`--readonly` 不再使用），只读 MUST 由服务端实际拒绝写操作来验证，MUST NOT 只靠提示词限制。

### Key Entities

- **MCP 目录条目（Catalog Entry）**：一条推荐配方，含标识、显示名、摘要、分类、传输、命令与参数、地址、环境变量占位、依赖、来源、验证状态四件套与提示 code 集合；只读、不安装、不写配置。
- **MCP 诊断（Diagnosis）**：一条 server 的只读检查结果，含已发布 / 已应用版本、待重启、命令定位三态与原因、环境变量就绪布尔、诊断提示集合、检查时间；与连接、测试、配置四轴独立。
- **MCP 测试记录（Test Record）**：一次真实连接尝试的结论，含操作标识、被测版本、阶段、失败分类、工具名单、延迟；成功 / 失败 / 超时 / 环境缺失各有固定落法。
- **工具来源（Tool Disposition）**：服务端提供的工具数与实际注册数、跳过项（赢家来源与原因）。
- **每日 Demo（Daily Demo）**：一个独立 Agent 目录 + 固定输入 + 期望业务结果 + 运行说明 + 业务脚本单测 + 证据模板；五条。
- **模板（Template）**：一个领域 Agent 目录，档位 A / A\* / B 固定，含依赖、证据状态与已知限制；八条。
- **示例证据（Demo Evidence）**：输入哈希、计划与时区、产物哈希、运行标识、业务断言、通知与故障读数的六段记录。
- **候选制品（Release Candidate）**：一次构建产出的单二进制，按路径与哈希绑定发布证据；被测与分发必须是同一份。
- **发布证据包（Release Evidence）**：版本、提交、候选路径与哈希、依赖与许可表、双平台走查、升级与恢复演练记录。
