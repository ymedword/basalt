## 任务阶段口径：测试准备 / 实现 / 验证（R3 裁决 P1-a，**不得**混记）

每个任务**只承担一个阶段**，DoD 只登记本阶段的读数——**不得**把「准备好测试」记成「测试已通过」：

| 阶段 | 承担者 | 本阶段交付与 DoD 读数 |
| --- | --- | --- |
| **测试准备** | 测试类任务（T005~T011 / T016~T019 / T024~T032 / T038~T045 / T053） | 测试**落地** + **登记红态读数**（**逐字失败文案**与原因；若编译前提未落地则记**逐字构建错误**）+ **写明转绿前提 = T0xx**；**不得**写「转绿 / PASS / 通过」 |
| **实现** | 实现类任务（T012~T014 / T020~T022 / T033~T036 / T046） | **由红转绿**——绿态读数登记在实现任务的 DoD 里，并点名它让哪几条测试任务由红转绿 |
| **验证** | 故事收尾任务（T015 / T023 / T037 / T047） | 本故事**全绿** + 关键回归逐条**绿态**读数 + **逆改点红态复现**读数（每条关键回归 1 条；`go test -overlay` 逆改，探针建在**仓库外**、用毕即删） |

**编译前提 vs 转绿前提**：**编译前提**只允许是「提供符号」的任务（新文件 / 类型面字段 / 注入位——**纯类型面声明（只增字段或注入位、零行为）不算实现先行**）；**行为面**任务一律记作**转绿前提**，**不得**成为测试任务的编译条件（T042 的 WARN 半轨 T046 是现成的正例）。同一任务既提供符号又提供行为（新文件类）时，两个前提相同，写一次即可。

**Goal**: 记忆在**每次运行开始读一次**、运行内冻结，读成文本注入系统提示词的段 2——`Prompt.System = 段一正文 + "\n\n" + 核心区文本`（核心区为空则**不产生任何字符**、与 US-4 逐字节相同）；记忆文本经 `RunEnv` 的**第三个非导出注入位** `memory string` 传入（沿 `llmClient` / `agentDir` 先例，**不得**走 `context.WithValue`）；读取失败 → 拒绝启动（`StatusFailed`、零 LLM）；注入后超上下文预算 → 同样拒绝启动且 `Reason` 点名 `budget.context_tokens`；`ConfigSnapshot` **零记忆字段**（快照是配置级事实、记忆是运行级输入）
