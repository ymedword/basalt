### User Story 1 - 跨对话记偏好：段 2 注入与运行级冻结（Priority: P1）

用户在 CLI 会话 A 里说「以后回答简洁点」：模型调 `save_memory` 写入**核心区**，确认文案含作用域与分区（不回显内容）；进程重启后开新会话 B，Agent **无需重新交代**就按该偏好输出——这条链路是**验收 Demo 二**。链路的技术骨架是**段 2 注入**：每次运行**开始读一次**记忆（运行内冻结），把生效层的**核心区文本**拼在段一正文之后（`段一正文 + "\n\n" + 核心区文本`），段一遇到的核心区文本**完整**进系统提示词（**永不截断**——「核心记忆区永不裁剪」是契约逐字）；没有记忆时 `Prompt.System` 与 US-4 时期**逐字节相同**（空记忆**不得**留下任何痕迹：不加换行、不加标题）。记忆文本经运行环境的**显式注入位**传入，**不得**走上下文携带或包级变量。

**Why this priority**: 它是本模块的验收 Demo 与旗舰路径——没有段 2，`save_memory` 写下去的东西无人读，Demo 二不成立；它同时是「运行级快照」这条与基线**有意不同**的语义（记忆不进配置快照、每次运行重建）的落点。放 P1 还因为它是**唯一的注入面**：这条不对，其余全部白做。

**Independent Test**: 以**脚本化记忆读取替身**（记录读取次数、按次返回不同文本）驱动真 `AgentService` 与真 `PromptBuilder`，逐例断言：①有记忆时入站 system = 基线 + 两换行 + 核心区文本（逐字节）；②空记忆时入站 system 与基线**逐字节相同**；③整次运行只读一次——多轮运行的第 2 轮入站 system **不得**出现「改后」文本；④注入后超上下文预算 → `failed` + `Reason` 点名预算键 + **零模型调用**，且有**同预算无记忆必须放行**的对照组。全程不打真实模型。

**Acceptance Scenarios**:

1. **Given** 生效层核心区文本非空，**When** 组装并观察一次模型调用的入站消息，**Then** system 内容 = 段一正文 + `"\n\n"` + 核心区文本（**逐字节**相等）。
2. **Given** 无记忆（空层），**When** 观察入站 system，**Then** 与无记忆端口时的基线**逐字节相同**（不产生任何字符）。
3. **Given** 一次运行内工具调用产生第 2 轮，**When** 第 2 轮组装提示词，**Then** 读取次数恒为 1、两轮入站 system 都是**同一份**旧文本（运行内冻结）。
4. **Given** 同一上下文预算 8192（可裁面 7168），**When** 对照组不接记忆、实验组接 90 KB 记忆，**Then** 对照组 `completed` 且模型被调用一次；实验组 `failed`、`Reason` 含 `budget.context_tokens`、模型调用**恰好 0** 次。

### User Story 2 - 两层作用域与回退：Agent 层优先、不叠加、缺失即回退（Priority: P2）

同一份 Agent 资产被多个 Agent 复用时，各写各的：Agent 层记住该 Agent 的专有事实，全局层承载跨 Agent 共享的偏好。解析规则三句话：**有 Agent 上下文且该层有内容 → Agent 层；否则 → 全局层；两层**不叠加**（Agent 层命中时全局层**一个字都不进**系统提示词）**。边界语义按契约字面「层有内容」= **任一分区正文非空**（分区标题与模板说明**不算内容**）——故某 Agent 的层里**只写了归档**时，生效层仍是它自己、段 2 得**空文本**，**不得**因此回退去注全局层核心区。**无 Agent 上下文 = 全局层**是正常取值（不是异常、更不是错误）：运维直连会话、CLI 顶层调用都落全局层。

**Why this priority**: 它是「一个目录 = 一个 Agent」在多 Agent 共用资产下的落点，也是本模块最容易写错的一处——把两层内容拼起来「更全」但**违背契约**（同一句话在提示词里出现两遍、总量不受配额约束）。放 P2 是因为它不阻塞 Demo 二（Demo 二只走 Agent 层或全局层其一），但它是本模块**唯一**在作用域面的判别力来源。

**Independent Test**: 以**两档载体**（markdown 的临时工作区根 / sqlite 的临时真库）跑**同一组断言**（跨档契约测试表）：①全局层有内容、Agent 层空 → 生效层 = 全局层；②Agent 层有核心条目 → 只注 Agent 层、全局层内容**不出现**；③另一 Agent 的层**只有归档条目** → 生效层仍是它、段 2 **为空**（不得回退全局层核心区）；④归档条目**不进**注入面；⑤空串 Agent（无上下文）→ 全局层，**不报错**。

**Acceptance Scenarios**:

1. **Given** 全局层核心区有「- 全局偏好」且 Agent 层为空，**When** 读取生效层，**Then** 结果含「- 全局偏好」。
2. **Given** Agent 层随后写入核心条目，**When** 再读生效层，**Then** 含 Agent 层条目且**不含**全局层条目（两层不叠加）。
3. **Given** 某 Agent 的层里**只有归档条目**，**When** 读取该 Agent 的生效层，**Then** 结果**为空**且**不报错**（层非空即生效层，不回退全局层核心区）。
4. **Given** 空串 Agent 上下文，**When** 读取生效层，**Then** 得全局层内容且无错误（正常取值）。

### User Story 3 - 载体两档与载体隔离：换档只改一行、记忆只能经记忆工具进出（Priority: P3）

`memory.backend` 一行配置决定载体：**markdown**（缺省；工作区里的 `MEMORY.md`，人可读可手改）与 **sqlite**（`memory_entries` 表，可并发可查询）。两档**同一套语义**——同一组 `Append` / `Load` / `Recall` 场景在每档上跑**同一张断言表**（`Load` 文本**不承诺逐字节相同**，只承诺同一解析器可切出同一分区结构）；换档 = 改一行 + 重启（配置生效时机 = 重启）。`mem0` 与一切未知取值 **fail-closed**：拒绝启动并点名键与取值（**不得**静默降级到 markdown——那会让「我配了 mem0」变成「记忆写进了文件」）。同时，**载体隔离**是审计可信度的前提：`memory/` 目录对**文件工具不可写**（规则与指引 US-4 已交付、本 US **零改动**，只新增负向用例守住它），记忆写入**只能**经记忆工具——`save_memory` 是**唯一**写入面。

**Why this priority**: 「三档同语义」的可验证口径（同场景表换档重跑）是本模块的架构承诺；载体隔离则是安全面——它没做出真实消费方之前，`memory/` 不可写只是策略里的一条静默规则。放 P3 是因为两档载体共用同一门面与解析器（sqlite 档只是把读写换成 SQL），交付面比注入面窄。

**Independent Test**: ①两档跑同一张跨档契约表（写入 / 读取 / 检索 / 配额边界全对号）；②负向隔离：文件工具写 `memory/` 被拒、**规则名与指引逐字**、被拒后原文件**逐字节不变**，且**正向对照**（同一根、同一 Agent 上下文下记忆工具写成功）；③`memory.backend` 取 `mem0` 与未知值 → 装配期拒绝启动、点名字面量；④两档各写一条记忆后重启进程，内容可见（持久化真落盘）。

**Acceptance Scenarios**:

1. **Given** 两档载体，**When** 跑同一张场景表（Append / Load / Recall / 配额边界），**Then** 每格断言在**两档都成立**。
2. **Given** 文件工具与 `memory/MEMORY.md` 目标，**When** 执行写工具，**Then** 拒绝、规则名 = 「记忆目录不在可写范围」、指引逐字、目标形状为工作区相对路径（不回显绝对路径），**且原文件逐字节不变**。
3. **Given** 同一工作区根与 Agent 上下文，**When** 记忆工具写入，**Then** 成功且内容真的落进 `memory/agents/<name>/MEMORY.md`（隔离是「通道分离」不是「记忆不可写」）。
4. **Given** `memory.backend: mem0` 或未取值，**When** 启动，**Then** 拒绝启动并点名键与取值（含「当前版本不支持」的语义），**零静默降级**。

### User Story 4 - 记忆治理可判卷：配额判在原子域内、读取面三档不塌陷、检索语义两态（Priority: P4）

三件容易被「一个 `_`」写坏的治理面：①**配额**——核心区单条 ≤ 4096、每层核心区总量 ≤ 32768（按 **UTF-8 字节**），超限返回**可读拒绝**（点名上限 + 给「改写归档区 / 压缩内容」的下一步），归类 `invalid_input`；**判定与追加必须原子**（sqlite 档同事务、markdown 档门面锁内）——否则两笔并发各查各的都在限内，双双落盘即穿透上限；②**读取面三档不得塌成一档**——文件不存在 / 合法空层 = **空层**（回退照常、首次写入即创建）、其他 I/O 错误 = **上抛**（注入面拒绝启动、零 LLM）、**非空但结构损坏** = **拒绝使用、拒绝覆盖、原文件逐字节不变**，三者**不得**被 `text, _ := ReadFile(rel)` 抹平；③**检索语义**——归档区条目级**整串子串**匹配、**区分大小写**、按写入顺序：**连续短语能命中、分散词不自动组合**（不分词 / 不扩词 / 不向量化），未命中是**成功** + `(无匹配条目)`（不是错误），空 `query` 在工具层即拒（零检索——sqlite 的 `instr(content,'')` 空针会**匹配全部**）。

**Why this priority**: 这三件都是「实现错了也不会立刻显形」的面——配额穿透要并发才暴露、读取面塌陷要在权限或人来手改后才暴露、检索语义错要模型拿着碎片词乱召才暴露。它们是本模块**判别力**最集中的地方，也因此放在最后（前三件故事不过关时它们无从谈起）。

**Independent Test**: ①并发写（16 笔）两档**一条不丢**（多重集比较，`-race`）；②sqlite 档并发 12 笔恰 **8 笔**通过（恰在上限 == 放行，第 9 笔被拒）、到顶后 1 字节都进不去；③手工编辑超配额 → 注入**完整** + WARN 日志（**逐字节**等于完整期望文本 + 尾部哨兵；日志**不得**打印记忆正文）；④读取面三档（缺失 / I/O 失败 / 非空损坏）逐档断言，含「损坏文件被拒后原文件逐字节不变」；⑤检索两态（连续短语命中 / 分散词不命中）逐档对号；⑥空输入零写入零检索（以记录调用次数的替身证明）。

**Acceptance Scenarios**:

1. **Given** 16 笔并发追加同一作用域，**When** 全部返回，**Then** 逐个 `nil error`、条目**逐字齐全且两两不同**（多重集比较——丢条、重复、半条都红）。
2. **Given** 核心区总量上限 32768 与恰 4096 字节的条目，**When** 并发 12 笔追加，**Then** **恰好 8 笔**成功、其余 4 笔为总量类配额拒绝；随后再追加 1 字节仍被拒。
3. **Given** 人手把核心区写到 ≈72 KB，**When** 读取生效层，**Then** 返回**完整**核心区文本（含末尾哨兵，逐字节相等）且日志含 WARN、不含记忆正文。
4. **Given** 缺 `## 归档记忆` 的非空文件，**When** 读取与追加，**Then** 两者都报错、错误点名缺失的标题、文件**逐字节不变**；**Given** 文件不存在，**When** 读取，**Then** 空文本 + 无错误且照常回退。
5. **Given** 归档条目「SQLite 方案 评估」，**When** 用连续短语查询与用分散词查询，**Then** 前者**命中**、后者**不命中**；大小写不同**不命中**；未命中返回 `(无匹配条目)` 且无错误。

---

### Edge Cases

- **空记忆**：文件不存在 / 零字节 / 只有文件标题 + 两分区标题（无条目）→ 均为**空层**：段 2 不产生任何文本、`Prompt.System` 与 US-4 逐字节相同；**首次写入即创建**骨架。
- **合法扩展不算损坏**：人手加的 `### 小节`、裸段落、条目正文里长得像标题的行 → 不是损坏（判据只看三条结构事实：两个分区标题各出现**恰一次**且**核心在归档之前**）。
- **条目正文里的结构样子**：条目正文里的 `## 归档记忆`、`"- "`、代码围栏**只是字符**——条目边界由「零缩进结构行 + 零缩进 `"- "` 首行 + 两空格缩进续行」决定，多行条目**不得**被拆条，写入与重建**无损可逆**。
- **Agent 层只写归档**：层非空 → 生效层是它自己、段 2 得空文本（**不得**回退全局层核心区）。
- **无 Agent 上下文**（`AgentName == ""`）：正常取值 → 全局层；工具侧作用域**只**从执行环境取，模型传不了 Agent 名、路径反推也**不算数**。
- **手工编辑超配额**：注入期 WARN + **完整**注入（不静默截断）；若因此超上下文预算 → 拒绝启动该次运行（`failed` + 点名预算键 + 零 LLM）。
- **配额恰在上限**：恰 4096 字节的条目、恰 32768 字节的总量**放行**（边界含等号）；两档算法一致（排除载体添加物）。
- **原子替换失败**：**旧文件逐字节不变**（「临时文件已清理」**不足以**作为判据）+ 零临时文件残留。
- **空输入**：空 `content` / 空 `query` → `invalid_input`、**零写入 / 零检索**（sqlite 空针会匹配全部）。
- **未命中**：不是错误——`RecallByKeyword` 返回空切片 + nil error，工具渲染 `(无匹配条目)`。
- **委派与并发**：并发写同一作用域**一条不丢**、总量不穿透；跨进程不承诺（单实例由实例锁兜底）。
- **敏感面**：确认文案与错误文案**不回显**内容；日志**不打印**记忆正文（只打长度与作用域）。

## Requirements *(mandatory)*

### Functional Requirements

#### 记忆接口与作用域

- **FR-001**: 长期记忆 MUST 有**唯一**统一接口（三方法，签名逐字）：追加一条到指定层的指定分区、读取指定层的完整记忆、在归档区做关键词检索；MUST NOT 增删方法名或参数，MUST NOT 在门面与载体之间另立第二套读写接口。
- **FR-002**: 记忆接口与端口 MUST 落在核心抽象包（纯类型与纯逻辑）；该包 MUST 只依赖标准库——记忆接口面 MUST NOT 出现文件操作或 SQL。
- **FR-003**: 作用域 MUST 是一等值（含 Agent 名的结构体 + 全局层零值），MUST NOT 用 `nil` 或空串顶替；「无 Agent 上下文」MUST 是正常取值（→ 全局层），MUST NOT 当异常或错误。
- **FR-004**: 生效层解析 MUST 为「有 Agent 上下文且该层有内容 → Agent 层；否则 → 全局层」；**两层 MUST NOT 叠加**——Agent 层命中时全局层内容**一个字都不得**进系统提示词。
- **FR-005**: 「层有内容」的判据 MUST 是**任一分区正文非空**；分区标题与模板说明 MUST NOT 算作内容；Agent 层只有归档条目时生效层 MUST 仍是它自己（段 2 得空文本），MUST NOT 回退去注全局层核心区。

#### 段 2 注入与运行级冻结

- **FR-006**: 记忆文本 MUST 在**每次运行开始时读一次**、运行内冻结；同一次运行内的每一轮组装 MUST NOT 重读载体。
- **FR-007**: 配置快照 MUST NOT 新增记忆字段（快照清单逐字不含 memory）；记忆文本 MUST 经运行环境的**显式**注入位传入，MUST NOT 用 `context.WithValue` 或包级变量承载。
- **FR-008**: 段 2 拼接形态 MUST 固定为「段一正文 + 换行 + 换行 + 核心区文本」；核心区为空时 MUST NOT 产生任何文本（与无记忆时的系统提示词**逐字节相同**）。
- **FR-009**: 段 2 注入的核心区文本 MUST **完整**进系统提示词（含分区标题行、不含文件标题）；MUST NOT 静默截断、MUST NOT 按条丢弃；归档区 MUST NOT 进注入面（它只经检索工具取回）。
- **FR-010**: 注入后不可裁部分超上下文预算 → 该次运行 MUST **拒绝启动**（`failed` + `Reason` 点名预算键 + **零模型调用**）；MUST NOT 截断后继续跑、MUST NOT 静默超发。
- **FR-011**: 记忆读取失败 → MUST 与段一读取失败同口径（拒绝启动、零模型调用、`Reason` 点名载体）；MUST NOT 吞错继续——但该处置**只限** I/O 错误与非空损坏两档（见 FR-018）。

#### 载体（markdown / sqlite）与两档同语义

- **FR-012**: 载体 MUST 有两档：markdown（缺省）与 sqlite；两档 MUST 跑**同一张场景断言表**（同语义可验证口径）；`Load` 文本 MUST NOT 承诺逐字节相同，只承诺同一解析器可切出同一分区结构。
- **FR-013**: markdown 载体的**全部**读写 MUST 经工作区根的相对句柄（MUST NOT 拼绝对路径、MUST NOT `..` 逃逸）；Agent 层文件与目录 MUST **按需创建**（MUST NOT 预建 `memory/agents/`）。
- **FR-014**: markdown 写入 MUST 是**原子替换**（同目录唯一名临时文件 + 改名）；替换失败时**目标文件 MUST 逐字节不变**且零临时文件残留——「临时文件已清理」MUST NOT 充当判据。
- **FR-015**: markdown 条目形态 MUST 为：结构行只认**零缩进**（文件标题恒为第 1 行 + 两个分区标题）；条目 = 零缩进 `"- "` 首行 + **两空格缩进**的后续行（含空行）；写入与重建 MUST **无损可逆**；人手写的裸段落 MUST 也按条目收集并原样重建；注入面读的是**重建结果**（文件本身不被改写）。
- **FR-016**: sqlite 载体的**配额求和与追加** MUST 在**同一事务**内完成（复用既有的写锁原语），MUST NOT 把求和放到事务之外。
- **FR-017**: 同作用域写入 MUST 串行化，粒度为**完整作用域**（`Scope` 的每个不同取值一把锁——每个 Agent 一把 + 全局层一把）、归门面持有；MUST NOT 用全仓一把大锁，也 MUST NOT 按「层」只建两把（Agent 层一把会被**所有** Agent 共用，同样把无关 Agent 串成一队）；**同 Scope 串行、不同 Agent MUST NOT 互相阻塞**（MUST 有对应验证）；跨进程 / 多实例 MUST NOT 承诺（单实例由实例锁兜底——如实边界）。
- **FR-018**: 读取面错误 MUST 分**三档**且 MUST NOT 被「一个 `ok` / 一个 `_`」抹平：①文件不存在 / 合法空层 → 空层（空文本 + nil error，回退照常，首次写入即创建）；②其他读取错误（权限 / I/O）→ 返回错误（注入面拒绝启动；写入面不触碰原文件、原样上抛）；③非空但结构损坏 → 拒绝使用、拒绝覆盖、**原文件逐字节不变**且错误点名症状（缺哪个 / 重复哪个 / 次序错）。合法扩展（多余的 `### 小节`、裸段落、条目正文里的任何行）MUST NOT 判为损坏。
- **FR-019**: 结构损坏的判据 MUST 只看三条结构事实：缺分区标题、同一分区标题出现两次、归档标题早于核心标题。
- **FR-020**: 后端取值 MUST fail-closed：取值域 = markdown（缺省）/ sqlite；`mem0` 与未知取值 MUST 拒绝启动并点名键与取值；MUST NOT 静默降级；MUST NOT 新增配置键。

#### 配额与可读拒绝

- **FR-021**: 核心区写配额（按 **UTF-8 字节**）：单条 ≤ 4096（**仅核心区写**受此限）、每层核心区总量 ≤ 32768；恰在上限 MUST 放行（边界含等号）；归档区 MUST NOT 有配额。
- **FR-022**: 条目正文 MUST 有**唯一的规范化表示**（`TrimSpace(原文)`），且 MUST 在**写入入口规范化一次**（两档各自入口、同一规范化语义）；**写入、单条检查、总量求和、存储、重建渲染、召回（含查询词）MUST 作用于同一表示**——MUST NOT 出现「检查用原始入参、存储用另一份」的错位。配额的求和单位 MUST 是**规范化后条目正文自身的字节**——含用户内容内部的空白与换行（首尾空白已由规范化去掉、不计入），只排除载体添加物（文件标题 / 分区标题 / `"- "` 前缀 / 续行缩进 / 条目间空行）；两档 MUST 同一算法（8 条恰 4096 字节的条目在两档都恰好达到 32768 并放行、第 9 笔被拒；**首尾空白边界处两档读数与判定 MUST 一致**——MUST 有对应用例，含首尾各带空白且原长贴上限的一组）。
- **FR-023**: 超配额 MUST 返回**可读拒绝**：点名触发的上限 + 给出可执行的下一步（改写归档区 / 压缩内容）；MUST NOT 只说「失败」。
- **FR-024**: 配额拒绝的失败归类 MUST 为**入参非法**（`invalid_input`）——与「入参不合法」同类，判序先于运行时错误，模型看到的是**可自我纠正**的指令。
- **FR-025**: 手工编辑导致的超配额 MUST **不按写拒绝**处理：注入期记 **WARN** 并**完整**注入（MUST NOT 静默截断——静默截断会让排障者误判为模型失忆）；若因此超上下文预算 MUST 走拒绝启动路径（FR-010）。

#### 记忆工具

- **FR-026**: MUST 有两件记忆工具：`save_memory`（必填 `content`；可选参数名 **`scope`**，取值 `CORE` / `ARCHIVAL`，省略或 `null` → `ARCHIVAL`，严格区分大小写，其余取值 → 入参非法）与 `recall_memory`（必填 `query`，**单个关键词**）；参数名 MUST NOT 改成 `section`（会与 `memory_entries.scope` 列——**分层** `agent` / `global`——撞名；契约 §5.4 注「**两个 `scope`**」：工具参数 `scope` = **分区**，表列 `scope` = **分层**，两处语义 MUST NOT 混淆）。
- **FR-027**: 作用域 MUST 只在工具层解析，**唯一来源**是执行环境里的 Agent 名（非空 → 该 Agent 层；空 → 全局层）；MUST NOT 让模型传 Agent 名、MUST NOT 从路径反推。
- **FR-028**: 检索 MUST 只查归档区、**整串子串**匹配、**区分大小写**、按写入顺序；**连续子串命中**、**分散词 MUST NOT 自动组合**；MUST NOT 分词、MUST NOT 同义词扩展、MUST NOT 向量检索。
- **FR-029**: 空 `content` / 空 `query` MUST 在工具层即拒（入参非法）、**零写入 / 零检索**；判据 MUST 是**规范化（`TrimSpace`）后为空**——纯空白与空串同档（MUST 有四态用例）。
- **FR-030**: 未命中 MUST NOT 是错误：返回空结果 + nil error，工具渲染为 `(无匹配条目)`；MUST NOT 映射成「未找到」或「运行时错误」。
- **FR-031**: 工具文案 MUST 固定（字面量权威面 = 颗粒度文档 §6.2 口径 11，非 §2.3 伪代码的占位形态）：`save_memory` 确认含**作用域与分区**（`已记住（作用域：全局层 或 Agent 层 <name>；分区：核心记忆 或 归档记忆）`）且**不回显内容**；`recall_memory` 命中条目按写入顺序以**空行**分隔。
- **FR-032**: 记忆工具 MUST NOT 落审计、MUST NOT 写消息、MUST NOT 记日志；失败分类 MUST 沿用执行器的既有判序；自产错误 MUST 只有两类——入参非法（含取值与配额）与载体 I/O 错误（原样上抛 → 运行时错误）。
- **FR-033**: 记忆工具 MUST NOT 持有沙箱面（策略 / 受控执行器）——其目标不是「工作区外的资源」，而是**固定路径上的记忆载体**；写入面由「路径约定 + 配额 + 载体隔离」三件封闭。
- **FR-034**: 载体隔离 MUST 保持：`memory/` 目录对文件工具**不可写**（规则与指引为 US-4 已交付面，本 feature MUST 零改动，只新增负向用例守住它）；记忆写入 MUST 只能经记忆工具。

#### 装配、配置与工程纪律

### Key Entities

- **作用域**：分层一等值——含 Agent 名（非空 = 该 Agent 的层）或零值（= 全局层）。
- **分区**：核心区（进注入面、有写配额、不可检索）与归档区（不进注入面、无配额、可检索）——**两档载体的分区语义完全一致**。
- **记忆条目**：正文（UTF-8 字节口径的配额单位）+ 分区归属 + 创建时间（显式传入的时钟）。
- **生效层文本**：门面读出的核心区文本（含分区标题行、不含文件标题）——段 2 注入的唯一素材。
- **配额错误**：类别（单条 / 总量）+ 可读拒绝文案（点名上限 + 下一步）。
- **记忆工具输入**：`save_memory` = 内容（必填）+ 分区参数（`CORE` / `ARCHIVAL`，缺省归档）；`recall_memory` = 单个关键词（必填）。
- **工具环境**：run 标识 / Agent 名（作用域唯一来源）/ Agent 目录——作用域与路径由它显式给出。

- **已知边界（本 feature 不解决，只登记成有读数的已知量）**：归档区**无配额**（只有核心区有 32 KB 上限）+ **每次运行整层读一次**——单次运行的记忆读取开销与归档区体量同阶（markdown 档整文件读、sqlite 档整层查询）；本 feature **不**设上限、**不**做索引优化、**不**做分页，边界写进运维可见的口径并在人工项留实测读数；MUST NOT 在报告里写成「性能已验证达标」（无 SLO 即无「达标」一说）。
- 平台与并发：进程内 per-scope 锁即可满足（跨进程 / 多实例不承诺，单实例由实例锁兜底）；markdown 档的原子替换在三平台（linux / darwin / windows）行为一致——判据按四目标编译矩阵给，MUST NOT 用单档抽查代替。

### Out of Scope（本 feature 明确不做）

- 向量检索 / 语义召回 / 知识库（召回是关键词检索；另一档能力归扩展阶段）。
- `mem0` 载体档（本 feature 的取值域外**即拒绝启动**；实现与真服务联调放扩展阶段）。
- 多租户记忆隔离（企业级治理归扩展阶段）。
- 记忆写入审核 / 策略引擎 / 敏感信息过滤（扩展阶段；本 feature 的写入面**只有配额一道**）。
- 记忆管理端点与界面（`GET /api/v1/memory` 归 US-9，管理台归 US-12）。
- 归档区裁剪 / 压缩 / 迁移（扩展阶段；承诺是**只追加、删除留缺口**）。
- 归档区的容量边界与检索性能保证（本 feature 只把已知边界变成有读数的已知量）。
- Agent 删除时清理记忆（存量不迁移不删除，本 feature 不改）。
- 记忆配额做成配置键（本 feature **零新增配置键**——配额是代码常量）。
- `USER.md` 注入面调整（US-4 已定，本 feature 不移动）。
- `notify` / `manage_schedule` 工具（归 US-8 / US-10）、MCP 工具与技能加载（归 US-7）。
