# US25 实施研究

- Decision：`basalt init` 在 `Workspace.Init` 之后、`Store.Bootstrap` 之前调用 `deps.FirstInstall.Prepare(workDir)`；`FirstInstall` 是 `cli` 侧消费方端口，`app` 用无状态 `firstInstallAdapter` 调既有 `ensureNewInstanceConfig(workDir, programRuntimeRoot())` 并映射报告。Rationale：`init` 的既有契约是“不取实例锁、不做恢复”，首次准备只写 `O_EXCL` 文件；若先建 SQLite 库，`detectNewInstance` 会把全新目录判成存量实例，导致主密钥、管理面密码与开箱 Agent 全部跳过——这是 D-25-02 的根因。Alternative：把首次准备放进 `Store.Bootstrap` 之后（判据直接红）或让 `init` 直接依赖 `app`（`cli` 反向依赖装配层）拒绝。
- Decision：首次准备顺序固定为“配置 → `provisioning.pending` → 内置安装意图 → 名册”，第二次调用 `detectNewInstance=false` 零写入；并发首次启动只允许一个写成功（`O_EXCL` + 既有名册判定）。Rationale：半截状态必须在下次启动失败关闭并提示人工处理，而不是被当成“未创建”继续铸钥；并发双写会产生两个实例身份。Alternative：把 `init` 与 `serve` 的首次准备合并成一次取锁操作拒绝（`init` 契约明确不取锁）。
- Decision：自动建钥资格在既有“无记录、无密钥、零托管密文”之外再加两条：`AutoInit` 且（`FreshInstance` 或 `ProvisioningPending`），且 `HasRuntimeHistory=false`；读历史失败写 `RuntimeHistoryErr` 让判定落 `await_init`，不吞成 false。Rationale：首次 `serve` 因缺入口限流退出后，`pending` 记录与名册都在，`FreshInstance=false`；没有 `pending` 续做会把用户永久挡在门外。Alternative：只看 `FreshInstance`（重试死局）或把查询错误当“无历史”（可能给有业务数据的库铸新钥）拒绝。
- Decision：`HasRuntimeHistory` 只查 `runs` / `task_executions` / `agent_lifecycle` / `kb_documents` 四表，`management_operations` 不计入；单条只读 `EXISTS` 查询，不把整表读进内存。Rationale：管理操作不代表业务历史，把管理操作算进去会让每个跑过管理动作的库永久失去自动建钥能力；四表是 Q-25-07 冻结的本次资格判据。Alternative：全表扫描或把所有表都算历史拒绝（前者性能风险，后者与 Q-25-07 冲突）；该判据不得表述为“证明整个共享库从未使用”。
- Decision：Worker 复用既有 `gateway` 子命令与全量装配（调度、租约续约、回收、心跳都在运行），只去掉 HTTP 监听、管理面密码与首次安装；`needsServeInit` / `needsServer` 保持只匹配 `serve`，不为 Worker 扩大。Rationale：Q-25-04 明确 Worker 运行 scheduler，复用 US-24 同一套去重；新增 `basalt worker` 子命令会形成第二套装配与第二套执行路径。Alternative：Worker 只执行不调度（接管语义会不同）或新增进程模式拒绝。
- Decision：`entrypoint.sh` 以 `BASALT_ROLE=worker` 分支：预检种子工作区、主密钥文件与其**直接父目录**权限（`basalt secrets check-key`），通过后停写并 `exec /opt/basalt/basalt gateway`；缺种子 / 缺密钥 / 不可读 / 权限过宽一律退出 78。Rationale：预检必须在进程内用 Go 解析器做（镜像无 JSON 工具），且父目录权限与文件权限同等重要（`LoadMasterKey` 同时校验两者）。Alternative：shell 内解析密钥（无法复现 Go 解析器语义）或把预检推迟到运行期（会在写业务表后才失败）拒绝。
- Decision：种子归档为 `tar` + `seed-manifest.json`（`format_version=1`，`files[]` 含 `path` / `size` / `sha256`）；导入前逐项校验清单，篡改、截断、越界路径、符号链接一律拒绝且目标工作区零落盘；只支持人工传输，不做热同步或跨机自动分发。Rationale：Q-25-03 冻结格式；热同步会引入第二套分发路径与一致性谜题。Alternative：rsync / S3 自动分发（明确不做）或只校验文件存在（无法拒绝篡改）拒绝。
- Decision：Demo 准备拆 `Plan` / `Apply` 两段：无 `--yes` 只发 GET；`Apply` 创建集合（409 时重读复用）、摄取九个文档（同步）、给两个 Agent 用**基础集合 ETag** 作 `If-Match` 只提交 `AGENT.md`；412 视为计划过期、停止该 Agent 并重新计划，不得用新 ETag 重提旧正文。Rationale：TOCTOU 是“读取正文到提交之间他人改动”的唯一正确判据；用新 ETag 重提会把他人改动覆盖掉。Alternative：直接 PUT 整份正文或以 200 判成功拒绝（后者无法发现逐项失败）。
- Decision：Demo 准备复用 `flow` CLI 的 HTTP 纪律（`--server` 无凭据 / 查询 / 路径，明文 HTTP 只允许回环，token 文件 ≤ 4096 字节，响应 ≤ 2 MiB，禁重定向），但另写新客户端、不重构 `flow_cli.go`。Rationale：复用纪律、避免改动已交付模块；两套客户端各自有独立测试。Alternative：重构 `flow_cli.go` 抽公共客户端（超出本 US 范围，且会动 US-19 冻结判据）。
- Decision：Demo 部分成功退出码 3（区别于 1 硬失败），输出逐项结果与可续提示；第二次运行幂等（集合复用、文档去重、绑定不变、无新模型调用）。Rationale：Q-25-05 冻结；脚本 / CI 需要区分“部分成功可续”与“硬失败”。Alternative：统一退出 1（丢失可续语义）或退出 0（把部分失败当成功）拒绝。
- Decision：双角色 Compose 用单文件 `docker/compose.multiworker.yaml` + `profiles: control|worker`，两角色共享私有网络、同一 PostgreSQL 与同一把主密钥；数据库端口单宿主不发布或只绑回环、双宿主只绑私网；不改 `docker/compose.yaml`。Rationale：Q-25-02 冻结单文件 profiles；改写 US-18 单实例文件会破坏其锁测试与已交付判据。Alternative：两文件双 Compose（用户已裁）或数据库发布到 `0.0.0.0`（安全不变量不允许）拒绝。
- Decision：Worker 健康检查自行解析 DSN 后运行只读命令判定数据库可达，只表示可达、不表示注册或心跳健康；不配置自动重启。Rationale：自动重启会掩盖崩溃并伪造可用性；健康检查若报“Worker 已注册”会越过数据库状态判断。Alternative：curl 控制面健康端点（Worker 无 HTTP）或直接 `pg_isready`（镜像不含客户端）拒绝。
- Decision：定时执行接管拆两段：① 旧执行由回收器 `ClaimExpired → RecoverExecution → fenced FinishExecution` 只收尾（零新 Run、零消息、零模型 / 工具调用、零重放、调用与工具计数不变，旧持有者回写被 fencing 拒绝）；② 后续新的 `planned_at` 才正常领取执行。Flow 根只由控制面推进，Worker 只回收不推进。Rationale：把两段混成“B 领取并执行旧执行”会产生重复执行；这是 US-24 语义的部署验收，不是新语义。Alternative：Worker 也跑 `flow.Worker`（范围变更，明确不做）拒绝。
- Decision：测试接管设有限截止（TTL + 回收轮询量级），截止内未完成收尾或回收即失败；报告只记录实测耗时，不写产品 SLA。Rationale：Q-25-06 不发明未测量的指标；但验收必须有通过 / 失败判定，不能以“记录读数”代替。Alternative：设固定 SLA 阈值（无测量依据）或只记录不判卷拒绝。
- Decision：停机顺序为“停止监听与领取 → 排空期间继续续约 → 到点先取消 → 等待执行退出；各执行先完成审计终态、钩子与投递结算再交还执行权 → 关闭观测面 → 释放租约（编排层空操作）→ Worker 下线 → 关闭 MCP → 最后关闭数据库”。Rationale：先释放会让收尾与释放竞争；先关库会让审计终态写不进去。Alternative：先关库再 join（审计终态丢失）拒绝。
- Decision：M1 SQLite v6 → PostgreSQL v12 走九步与 `db verify --handoff`；源库没有的 `flow_*` / 学习审批 / `kb_*` 对象按“源无对象、目标新建空表”逐项登记，知识引用计数为 0 并写明原因；M2 再验单实例 → 多 Worker 的身份保留、计数一致与旧 bundle 可读。Rationale：把“源库没有”写成“已迁移”是可追溯性造假；M2 才能验证非空 Flow 与学习审批。Alternative：M1 一并声称验完 Flow / 知识（空表证据冒充）拒绝。
- Decision：两节点升级停全部旧进程、备份数据库与每个工作区及密钥、先起控制面迁移再起 Worker；跨 schema 用旧制品验证拒绝；同 schema（US-24 与 US-25 均为 v12）**不存在**制品版本门禁，只验停全部旧进程、制品一致、整组回滚。Rationale：US-24 与 US-25 同为 v12，若宣称“被版本门禁拒绝”是伪造证据。Alternative：为本案新增制品版本门禁（超范围）或省略回滚演练拒绝。
- Decision：releasekit 只做最小扩展：把 `basalt.worker.yaml` / `export-master-key.sh` / `seed-workspace.sh` 放进镜像构建上下文，在 `ImageRecord` 记录三者 SHA-256（`omitempty`），构建上下文缺件在 `docker build` 之前报错；`release/support-matrix.json` schema 不动。Rationale：Q-25-13 把 releasekit 边界留给 US-17；`omitempty` 保证 US-18 既有镜像记录断言不变。Alternative：改支持矩阵 schema 或改判卷逻辑拒绝。
- Decision：四个文档面（README / Operations §1.5 + 新增 §8.3 / release 说明 / `basalt.yaml.example`）用同一套九个锚点顺序、容器隔离五要素与多 Worker 五要素；支持矩阵只写 Compose 多 Worker 与 `LocalRunner`，不写 K8s / 数据库 HA / 真实双宿主已验证。Rationale：文档断言（`TestDocs_*`）让口径可机器判定，避免一处改了另一处漂移。Alternative：只写一处再链接（用户明确要求四处同口径）。
- Decision：本 US 零新增 Go / npm 坐标；`go.mod` / `go.sum` 与起点 `3f8d0dc` 空 diff；tar、SHA-256 与随机数全部标准库。Rationale：原则 VIII 依赖最小化，本 US 无必须引入外部库的能力。Alternative：引入归档 / 摘要库拒绝（表外坐标）。
