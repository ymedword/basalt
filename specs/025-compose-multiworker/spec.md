## User Scenarios & Testing

### User Story 1 - 首次安装可 init 优先并支持中断重试 (Priority: P1)

运维在全新目录执行 `basalt init`：工作区先得到配置文件、首次进度标记与实例名册，再建 SQLite 源库；随后 `basalt serve` 首次启动生成主密钥、打印一次管理面密码、完成开箱 Agent 与内置工作流素材安装。若首次 `serve` 因缺入口限流配置或数据库未就绪而退出，工作区保留首次进度与名册，重试时续做安装并补发主密钥，不出现“已有实例但无密钥”的死局。已有业务历史的实例缺钥时一律等待人工初始化，不生成新钥。

**Why this priority**: 首次安装是每一个新用户的第一步；顺序错误会把全新目录判成存量实例，导致主密钥、管理面密码与开箱 Agent 全部跳过——这是本模块所有其它交付的前置。

**Independent Test**: 在临时目录只跑 `init`，断言配置文件、名册与源库同在且准备先于建库；模拟首次 `serve` 缺入口限流退出后重跑，断言密钥被补发；在已有运行历史的库上断言不生成新钥；并发两个首次启动只有一个成功写入。

**Acceptance Scenarios**:

1. **Given** 全新目录，**When** 执行 `init`，**Then** 配置、首次进度、名册与 SQLite 源库全部存在，且首次准备先于源库创建；首次安装能力缺失时命令失败且不建库。
2. **Given** 首次 `serve` 因缺入口限流配置退出，**When** 补齐配置后重试启动，**Then** 续做开箱安装并生成主密钥，管理面可登录。
3. **Given** 共享库已有运行记录但当前工作区无密钥，**When** 启动，**Then** 判定为等待人工初始化，不生成新钥、不覆盖既有状态。
4. **Given** 已有托管密文但缺记录或密钥，**When** 启动，**Then** 进入恢复态，不生成替代密钥。
5. **Given** 两个进程同时对同一全新目录做首次准备，**When** 并发执行，**Then** 恰好一个成功写入，另一个零写入返回。
6. **Given** 名册文件半截或不可解析，**When** 启动，**Then** 失败关闭并提示人工处理，不自动续做、不生成主密钥。

### User Story 2 - 双角色 Compose 编排与 Worker 启动边界 (Priority: P1)

运维用 Compose 双角色启动一个控制面与至少一个 Worker（同机或两机）：控制面跑完整的对外服务，Worker 跑既有后台角色——保留全量装配、调度、租约、回收与心跳，但不监听 HTTP、不生成管理面密码、不做首次安装。两角色共享私有网络的 PostgreSQL 与同一把主密钥；Worker 从种子工作区启动，种子带逐文件校验清单，篡改、截断、越界路径与符号链接一律拒绝。Worker 密钥文件与父目录权限过宽时预检失败并退出，不进入运行。

**Why this priority**: 双角色编排是“多 Worker 可部署”的直接交付；角色边界错一处（Worker 暴露管理端口、自铸主密钥、自建实例）就会破坏身份、凭据与准入。

**Independent Test**: 解析并启动双角色编排，断言控制面有端口、Worker 无端口且以既有后台模式运行；缺种子或缺密钥时 Worker 启动预检退出；构造被篡改种子断言拒绝导入；两个 Worker 同时注册且实例标识不同。

**Acceptance Scenarios**:

1. **Given** 控制面编排档，**When** 启动，**Then** 控制面与数据库就绪，控制面健康检查可用。
2. **Given** Worker 编排档，**When** 启动，**Then** 只启动 Worker；Worker 进程无任何 HTTP 监听、无管理面密码。
3. **Given** Worker 缺少种子工作区或共享主密钥，**When** 启动，**Then** 启动预检失败退出，不产生新实例、不写业务表。
4. **Given** 种子归档被篡改、截断、含越界路径或符号链接，**When** 导入，**Then** 拒绝导入且目标工作区零落盘。
5. **Given** 两个 Worker 启动完成，**When** 查看 Worker 注册，**Then** 各有一行、实例标识互不相同、心跳在有效期内。
6. **Given** 数据库只应由控制面侧暴露，**When** 检查网络配置，**Then** 单宿主不发布或只绑回环、双宿主只绑私网，Worker 容器无本地数据库。

### User Story 3 - 双角色执行权与故障边界 (Priority: P1)

两个 Worker 同时运行时，同一计划触发只执行一次；控制面停机后，存活 Worker 只接管收尾旧执行——执行行置终态、租约释放、旧计划时刻不产生第二个 Run、调用与工具计数不变，旧持有者的回写被拒绝；后续新的计划时刻由存活 Worker 正常领取。Flow 根只由控制面推进，Worker 只回收不推进。数据库短暂中断恢复后，未确认的未知副作用停止待查、不自动重放。资产 bundle 缺失或哈希不符时，新 Run 准入被拒。停机时先完成审计终态与结算，再交还执行权，最后关闭数据库。

**Why this priority**: 多进程同时持有执行权是分布式部署最容易击穿的语义；去重、fencing、接管收尾与停机顺序任何一项错误都会造成重复执行或双终态。

**Independent Test**: 两 Worker 竞争同一计划时刻，断言执行记录恰一条；停控制面后断言旧执行被收尾且零重放、旧持有者回写被拒；中断数据库后断言无自动重放；删除 bundle 后断言新 Run 准入拒绝；执行停机编排断言审计终态先于执行权释放。

**Acceptance Scenarios**:

1. **Given** 两个 Worker 同时到期扫描，**When** 同一任务同一计划时刻被竞争，**Then** 恰好一条执行记录，一个成功、另一个返回已领取。
2. **Given** 控制面停机、其持有执行租约过期，**When** 存活 Worker 回收，**Then** 旧执行被收尾（终态+租约释放），旧计划时刻不产生第二个 Run，调用与工具计数不变。
3. **Given** 接管完成后旧持有者恢复，**When** 其尝试回写终态，**Then** 被拒绝，零行写入。
4. **Given** 控制面停机后出现新的计划时刻，**When** 存活 Worker 扫描，**Then** 由它正常领取执行，租约负责人为该 Worker。
5. **Given** 数据库短暂中断后恢复，**When** 服务继续，**Then** 未确认的未知副作用标记停止或待查，不自动重发；Run 终态与审计一致。
6. **Given** 资产 bundle 缺失或哈希不符，**When** 新 Run 请求准入，**Then** 被拒绝；Worker 不执行资产安装或发布。
7. **Given** 收到停机信号，**When** 执行停机编排，**Then** 先停止领取并继续续约，各执行先完成审计终态、钩子与投递结算再交还执行权，最后关闭观测面、下线 Worker、关闭 MCP、关闭数据库，全程在宽限内完成。

### User Story 4 - Demo 知识库准备命令 (Priority: P2)

首次使用者运行 `basalt demo workflow prepare`：无 `--yes` 时只读预演，列出九个文档、两个 Agent 绑定与向量模型调用费用提示，不产生任何写入；加 `--yes` 后创建两个知识集合、摄取九个文档、为两个 Agent 写入只读知识绑定，并按项输出结果。第二次运行幂等：集合复用、文档去重、绑定不变、不产生新的模型调用。已有不等价绑定时拒绝覆盖；两个 Agent 一个失败一个成功时逐项报告、退出码 3、再次运行只补失败项。

**Why this priority**: Demo 准备把“九个文档手工点 + 两个 Agent 手工勾选”变成一条可预演、可重复的命令，是首次体验与演示可用性的关键，但不影响多 Worker 执行语义。

**Independent Test**: 对桩服务运行预演，断言零写请求且费用提示存在；应用后按服务端读回断言集合、文档与绑定逐项一致；第二次运行断言去重与不变；构造冲突绑定与并发修改断言拒绝与部分成功退出码。

**Acceptance Scenarios**:

1. **Given** 未安装模板或未启用角色，**When** 运行准备命令，**Then** 直接失败并提示先安装并启用，不自动安装。
2. **Given** 无 `--yes`，**When** 运行，**Then** 只发只读请求，零写入，并打印费用提示。
3. **Given** 加上 `--yes`，**When** 运行完成，**Then** 两个集合存在、九个文档为活动状态、两个 Agent 的知识绑定与目标一致；命令逐项报告集合、每个文档与每个 Agent。
4. **Given** 第二次运行，**When** 执行，**Then** 集合复用、文档去重、绑定不变，无新增模型调用。
5. **Given** 已有非空且不等价的绑定，**When** 运行，**Then** 该 Agent 报冲突、内容不变、命令非零退出。
6. **Given** 读取与提交之间他人修改了 Agent，**When** 提交被拒（前提失效），**Then** 视为计划过期、停止该 Agent 并重新计划，不用新版本标记重提旧正文。
7. **Given** 一个 Agent 失败、另一个成功，**When** 运行结束，**Then** 标记部分成功、退出码 3、逐项结果可读；再次运行只补失败项。

### User Story 5 - 迁移与两节点升级 (Priority: P2)

存量用户执行 M1：SQLite 源库经九步迁移到 PostgreSQL 当前版本，按对象级核对运行、审计、资源引用与技能版本；源库没有的 Flow、学习审批与知识对象按“源无对象、目标新建空表”逐项登记，知识引用为零并写明原因。随后执行 M2：单实例 PostgreSQL 扩为多 Worker，生命周期索引与 Agent 身份保留、计数一致、旧资产可读；非空 Flow 与学习审批完整性在 M2 验证。两节点升级停全部旧进程、备份数据库与每个工作区及密钥、先起控制面迁移再起 Worker；跨 schema 用旧制品验证拒绝，同 schema 验整组回滚。

**Why this priority**: 迁移与升级决定存量用户能否安全进入多 Worker 部署；但它是部署后的路径，不阻塞新用户与执行语义验收。

**Independent Test**: 用冻结的 v6 样例库跑九步迁移，断言交接校验通过且对象抽样一致；在单实例库上扩多 Worker，断言身份与计数不变；模拟混合版本与整组回滚，断言拒绝与恢复集完整。

**Acceptance Scenarios**:

1. **Given** v6 样例库，**When** 执行九步迁移，**Then** 交接校验通过，有对应对象的运行、审计、资源引用与技能版本计数及内容抽样一致。
2. **Given** 源库无知识表，**When** 生成迁移报告，**Then** 知识引用计数为零并写明原因，报告与文档不出现“知识已迁移”。
3. **Given** 单实例数据库已完成 M1，**When** 扩为多 Worker，**Then** 生命周期索引与 Agent 身份保留、准入通过、运行/Flow/审计/知识计数一致、旧资产可读。
4. **Given** 非空 Flow 与学习审批对象，**When** 在 M2 阶段核对，**Then** 完整性由 M2 证据判定，不拿 M1 空表证据冒充。
5. **Given** 旧版本制品连接更新 schema 的库，**When** 启动，**Then** 拒绝启动；同 schema 场景不宣称制品版本门禁，只验停全部旧进程、制品一致、整组回滚。

### User Story 6 - 文档与首发支持矩阵口径 (Priority: P3)

四个文档面（根 README、运维手册、发布包说明、配置示例）写同一套首次配置固定顺序与同一套多 Worker 说明：角色、数据库连接复制、主密钥共享、种子、启动顺序；都写清容器隔离为实例级可选项、不在首发支持矩阵、五个日常脚本受影响、四个 Flow 角色只读不受影响、如何回退到本地执行档。发布说明与运维手册的支持矩阵只写 Compose 多 Worker 与本地执行器，不出现 K8s、数据库 HA、真实双宿主的“已验证”表述。

**Why this priority**: 文档口径决定首发用户能否按图索骥、也决定对外声明是否夸大；它不改变运行时行为，但属于首发门槛。

**Independent Test**: 对四个文档面跑断言：九个首配锚点顺序一致、隔离警告五要素齐全、多 Worker 五要素齐全；对发布说明与运维手册断言支持矩阵否定项，并断言支持矩阵 schema 未变。

**Acceptance Scenarios**:

1. **Given** 四个文档面，**When** 按固定顺序搜索九个锚点，**Then** 每面顺序一致、无缺项。
2. **Given** 四个文档面，**When** 检查容器隔离警告，**Then** 五要素齐全且互不矛盾。
3. **Given** 四个文档面，**When** 检查多 Worker 说明，**Then** 角色、连接复制、主密钥共享、种子与启动顺序均出现。
4. **Given** 发布说明与运维手册，**When** 检查支持矩阵，**Then** 只含 Compose 多 Worker 与本地执行器；K8s、数据库 HA、真实双宿主未写入“已验证”。

### Edge Cases

- 首次准备进行到一半崩溃，名册在、配置不在：失败关闭，不把半截状态当“未创建”继续铸钥。
- 并发首次启动：只允许一个写成功；另一个零写入返回。
- 共享数据库已有业务历史但工作区是新的：不得据此生成新主密钥。
- 已有托管密文但无密钥记录，或密钥损坏、身份不符：进入恢复态，不生成替代密钥、不回落环境变量、不删除来源不明文件。
- 种子归档被篡改一个字节、截断、含 `../` 路径或符号链接：全部拒绝导入。
- Worker 密钥文件权限正确但父目录权限过宽：同样拒绝启动（父目录必须私有）。
- 数据库短暂中断：恢复后未确认的未知副作用停止待查，不自动重放。
- 接管过程中旧持有者恢复回写：被拒绝，零行写入。
- Demo 准备读取正文后、提交前他人修改了 Agent：视为计划过期，不用新版本标记重提旧正文。
- Demo 准备部分成功：退出码 3，逐项结果可读；再次运行只补失败项。
- 源库没有 Flow、学习审批与知识对象：按“源无对象、目标新建空表”登记，不冒充已迁移。
- 同 schema 的两节点升级：不存在制品版本门禁，不得宣称被门禁拒绝；只验停全部旧进程、制品一致、整组回滚。
- 真实双宿主、真实模型、真实 webhook、K8s、数据库 HA：未授权，不得写成已验证。

## Requirements

### Functional Requirements

- **FR-25-01**: `init` 后工作区必须同时存在配置文件、实例名册与 SQLite 源库；首次准备必须在源库创建之前执行；首次安装能力缺失时命令必须失败且不建库。
- **FR-25-02**: 首次 `serve` 因缺入口限流配置退出后，工作区必须保留首次进度与名册；第二次启动的主密钥判定必须返回“可创建”并生成密钥。
- **FR-25-03**: 自动建钥必须仅在同时满足“无密钥记录、无密钥文件、零托管密文、零业务历史、允许自动初始化、全新实例或首次进度挂起”时成立；业务历史只计运行记录、任务执行、Agent 生命周期与知识文档四张表，管理操作不计入；创建动作必须先写待定审计。
- **FR-25-04**: 有业务历史时必须等待人工初始化；有密钥记录且有密钥文件时必须就绪；有托管密文但缺记录或密钥时必须进入恢复态；三种情况都不得生成新密钥。
- **FR-25-05**: 首次准备顺序必须固定为“配置 → 首次进度 → 内置安装意图 → 名册”；第二次调用必须零写入；并发首次启动只允许一个成功写入；名册半截或不可解析时必须失败关闭并提示人工处理，不得自动续做。
- **FR-25-06**: Worker 启动不得写实例名册、不得生成管理面密码、不得创建 SQLite 库；从种子工作区启动后名册中的实例标识必须不变。
- **FR-25-07**: Demo 准备命令在无 `--yes` 时必须只发只读请求；计划必须包含九个文档、两个 Agent 绑定与向量模型调用费用提示；服务地址为非回环明文 HTTP 时必须拒绝。
- **FR-25-08**: 应用后两个知识集合必须存在、九个文档必须为活动状态、两个 Agent 的知识绑定必须与目标一致；写 Agent 定义必须使用基础集合的版本标记作为条件且只提交一个文件；命令必须按项输出集合、每个文档与每个 Agent 的结果，不得只凭成功状态码记成功。
- **FR-25-09**: 第二次运行必须复用集合、自动去重文档、保持绑定不变，且不产生新的模型调用。
- **FR-25-10**: 已有非空且不等价的绑定时必须报冲突、内容不变、命令非零退出；读取与写入之间他人修改（前提失效）时必须视为计划过期，停止该 Agent 并重新计划，不得用新版本标记重提旧正文。

### Key Entities

- **实例名册与首次进度**：标识一个自托管实例的身份与首次安装进度；决定首次准备是否已完成、主密钥判定走哪条分支。既有实体，本模块只改变其写入顺序与判定条件。
- **实例密钥记录与托管密文**：主密钥记录、密钥标识与托管密文；决定自动建钥、等待人工初始化或恢复态。既有实体，不新增表。
- **部署角色**：控制面与 Worker 两种运行角色；共享数据库与主密钥，但对外能力不同（控制面有 HTTP 与管理面，Worker 只有后台执行）。
- **种子归档**：工作区的可移植副本与逐文件清单；只含类别白名单内文件，带大小与摘要，可校验可拒绝。
- **Demo 准备计划与逐项结果**：只读预演产出的写入计划，以及应用后的集合、文档与绑定逐项结果（成功、复用、去重、冲突、过期、失败）。
- **迁移核对报告**：M1/M2 的对象计数、抽样结果与“源无对象、目标新建空表”的逐项登记。
