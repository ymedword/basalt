## User Scenarios & Testing *(mandatory)*

**标签口径（`[US1]` / `[US2]` / `[US3]` 不混淆）**：下面三个用户故事在 [tasks.md](./tasks.md) 中以 Spec-Kit 的工具标签 `[US1]` / `[US2]` / `[US3]` 出现——那是**本 feature 内部**用户故事的编号，**不是**项目台账（[docs/us/REGISTRY.md](../../docs/us/REGISTRY.md)）里的 US-1 / US-2 / US-3。本 feature 的三个故事同属项目 **US-1（工程地基）** 一个模块，是它的三个独立可验场景；标签按工具产出保留。

### User Story 1 - 一条命令验证整个工程（Priority: P1）

开发者从干净检出开始，运行一条聚合门禁命令：格式、静态检查、安全扫描、竞态测试、集成测试、覆盖率阈值判卷、发布构建七个目标全部通过；发布产物是一个不依赖 C 工具链的静态单二进制，`--version` 输出包含构建时注入的版本标识。

**Why this priority**: 这是 US-1 的第一可演示物，也是整个递进依赖链（US-1 → US-2 → …）的质量放大器——没有机器可执行的聚合门禁，后续全部 US 的「完成」定义无从判卷。

**Independent Test**: 在有完整前置工具链的机器上直接运行聚合门禁命令，以退出码与关键输出判卷；配合负向对照（故意留未格式化文件与语法错误文件，门禁必须判红）。

**Acceptance Scenarios**:

1. **Given** 干净检出 + 完整前置工具链（Go 1.27.2 / Make / C 编译器 / 四个检查工具固定版本），**When** 运行聚合门禁命令，**Then** 七个目标全绿、退出码 0。
2. **Given** 仓库内有一个未格式化文件，**When** 运行门禁的格式目标，**Then** 非零退出并点名文件；留一个语法错误文件同样非零退出（判卷先查退出码、再判输出）。
3. **Given** 一次完整构建，**When** 运行产物的 `--version`，**Then** 输出包含注入的版本标识（由版本控制状态派生）。
4. **Given** 干净检出仓库，**When** 在 CI 上运行，**Then** 测试与发布两个 job 各自独立、CGO 状态互不混用，全部通过。

### User Story 2 - 一键初始化工作区且二跑幂等（Priority: P2）

开发者 / 运维在目标目录运行初始化命令：得到完整工作区（6 个目录 + 5 个模板文件）与就绪的数据库（11 张表 + 版本记录 = 1）；再次运行不报错、不覆盖任何已有文件（逐字节不动）。初始化的数据库引导在并发与"另一进程已持写锁但尚未提交初始化"的启动窗口下仍然安全：只有实际创建者执行初始化。

**Why this priority**: 工作区是全部业务能力（Agent、技能、记忆、审计）的落点，数据库是整个系统唯一的持久化基座；幂等与并发安全是可重复执行的运维底线。

**Independent Test**: 在临时目录连续运行两次初始化，比对目录 / 文件清单与文件内容；对数据库清点表与版本记录；跑并发初始化用例。

**Acceptance Scenarios**:

1. **Given** 空目录，**When** 运行初始化命令，**Then** 生成 6 目录 + 5 文件 + 数据库文件（11 表 + 版本记录 = 1），并输出"创建 / 保留"清单。
2. **Given** 已初始化的工作区（含被手工修改过的文件），**When** 再次运行初始化命令，**Then** 不报错、无新建、已有文件逐字节未变。
3. **Given** 多个初始化调用并发竞争同一目录，**When** 全部完成，**Then** 恰好一个报告"实际创建"，其余报告"已存在（Kept）"且不报错；数据库终态一致（11 表 + 版本记录 = 1）。

### User Story 3 - 无需配置的诊断报告（Priority: P3）

运维在未准备配置文件的机器上运行诊断命令：得到三节（工作区 / 配置 / 存储）报告，全部通过时成功退出；配置文件缺失只报「未发现配置（路径明示）」、**不计失败**——"还没配好"恰是它最需要工作的时刻。

**Why this priority**: 首日排障的主入口；收敛三节的唯一工作区口径（当前工作目录下的工作区目录），并让全部库异常态以点名原因的文案浮出。

**Independent Test**: 初始化后不准备任何配置直接运行诊断命令；再对未初始化 / 配置无效 / 库四类异常态逐项验证文案与退出码。

**Acceptance Scenarios**:

1. **Given** 初始化后的工作区且无配置文件，**When** 运行诊断命令，**Then** 三节报告齐备、节 2 报「未发现配置（路径明示）」、退出码 0。
2. **Given** 未初始化的目录，**When** 运行诊断命令，**Then** 报「工作区未初始化 + 建议先初始化」、退出码 1，且继续给出其余两节。
3. **Given** 数据库为旧版本 / 过高版本 / 损坏（版本表存在但零行）之任一，**When** 运行诊断命令，**Then** 各自点名原因与建议、退出码 1、**不迁移、不写入**。
4. **Given** 配置文件存在但含明文凭证，**When** 运行诊断命令，**Then** 拒绝并点名配置键路径、退出码 1，且全部输出不含明文值。

### Edge Cases

- 配置文件含未解析的占位残留（畸形模板，如未闭合或未知形态）→ 拒绝并点名配置键路径。
- 凭证键的占位变量**不存在**与**存在但为空**是两类不同拒绝，均须点名（变量名与键路径），且都不得回显值。
- 首次建库中途失败（全量建表与版本记录之间）→ 整体回滚：无版本表残留、无半建表残留；重跑按新库重试成功。
- 增量迁移某版失败 → 该版整体回滚，版本记录不变；修复后可重试到目标版本。
- 库内版本高于当前程序支持的版本 → 一律拒绝（不得让旧程序打开新库）；版本表存在但零行 → 按损坏拒绝（不猜测为新库或旧库）。
- 目标版本缺少对应迁移文件 → 拒绝并点名文件（不跳过、不静默）。
- 只读路径打开库前先校验版本；只读路径**只校验、不迁移**，且不取实例锁、不做恢复、不触碰锁文件。
- 判定库状态不得早于取得数据库写权——"文件在不在"与 "IF NOT EXISTS" 不能替代写权后的重新判定（并发窗口的假安全）。
- 无系统时区数据的环境（裸容器）中，产物内嵌的时区数据仍须让时区名可解析；对照探针必须以"时区加载失败"这一种原因失败，才算隔离成立。

## Requirements *(mandatory)*

### Functional Requirements

#### 工程骨架与门禁

- **FR-001**: 仓库 MUST 具备单模块工程骨架：唯一程序入口 + 内部分包起点（空包以包文档占位，包注释中英并列、中文在前）。模块声明 MUST 区分两种版本语义——「最低语言版本要求 1.27」与「准确构建版本 1.27.2（由工具链指令与 CI 共同固定）」；**不得**表述或实现为"锁定 1.27.2"。
- **FR-002**: 门禁 MUST 为一条聚合命令，含七个目标：格式（两个格式工具各查一遍）、静态检查（显式判定集，含命名与注释规范判卷）、安全扫描（零命中）、测试（启用竞态检测）、集成测试（独立触发、默认不跑）、覆盖率阈值判卷、发布构建。格式判卷 MUST 先查退出码、再判输出（顺序写反会把"文件解析不了"判成通过）。
- **FR-003**: 覆盖率判卷 MUST 可执行、按包判失败：核心包（核心抽象 / 沙箱 / 记忆 / 存储）≥ 70%，其余 ≥ 50%；有可执行语句但无测试文件的包计 0%、**不得豁免**；无可执行语句的包跳过。判卷脚本自身判据六类（低于阈值 / 恰好达标通过 / 无语句跳过 / 有语句无测试计 0 / 测试命令失败传导 / 输入异常报错）MUST 由脚本自检用例逐条覆盖。程序入口包与统计工具包 MUST 同样达标（≥ 50%，可测包装形态 + 用例，无豁免）。
- **FR-004**: CI MUST 为两个互相独立、CGO 状态分离的 job：测试 job 启用 CGO（竞态检测需要）并跑门禁；发布 job 关闭 CGO、四平台交叉编译，且 MUST NOT 运行竞态检测。两 job MUST 钉同一准确构建版本；四个检查工具 MUST 固定版本安装；测试 job 内 MUST 含"时区数据隔离"步骤——先移除系统时区数据与工具链内嵌时区包、**断言移除成功**（移除失败即步骤失败、fail-closed），再运行隔离组用例。

#### 配置与日志

- **FR-005**: 配置装载 MUST 对四类不安全输入 fail-closed 拒绝并点名配置键路径（占位变量另点名变量名）：①占位变量不存在；②凭证键的占位变量存在但值为空；③替换后仍有占位残留（畸形模板）；④凭证字段为明文（非占位形态）。必填缺失与类型非法 MUST 拒绝；**不得**静默取默认值。全部用户可见输出（错误文案、日志、标准输出 / 标准错误）MUST NOT 回显凭证明文值。
- **FR-006**: 日志 MUST 双档可切换（开发：可读文本；生产：结构化 JSON）；失败路径 MUST 落 ERROR / WARN 日志；**不得**以打印函数代替日志。进程退出码 MUST 成功 0 / 失败 1，具体原因由文案区分（不分档非零）。
- **FR-007**: 命令行面 MUST 交付 `init` / `status` 两条命令与全局 `--version` 选项（版本经构建期注入，输出 MUST 包含注入值）；两条命令 MUST 不依赖业务能力装配。

#### 工作区与引导

- **FR-008**: 初始化 MUST 幂等生成工作区骨架：目录六项（agents / skills / memory / logs / archive / sessions）+ 文件五项（AGENTS.md、SOUL.md、USER.md、mcp_servers.yaml、memory/MEMORY.md）；记忆模板 MUST 含「核心记忆 / 归档记忆」两个分区；MCP 配置 MUST 为空表且可被 YAML 解析；记忆的 Agent 层目录 MUST 不预建（写入时落盘）。已存在的文件与目录 MUST 逐字节不覆盖、不报错；输出"创建 / 保留"清单供幂等对账。
- **FR-009**: 初始化的数据库引导 MUST 与骨架联动：缺库 → 创建（全量建表 + 版本记录，**同一事务**）；已存在的库一律零写——当前版本按"已存在"通过，旧版本 / 过高版本 / 损坏态各自拒绝且**不迁移**（升级归持锁重路径，US-4）。

#### 持久化基座（写能力与迁移机制）

- **FR-010**: 写模式打开能力 MUST 在本 feature 交付（US-2 的审计写入即消费）：读写连接分工（写侧上限 1，序列化单写者）；连接级完整性参数（外键约束、忙等待时限）MUST 对**每一条物理连接**生效——**不得**只对第一条设置；日志模式 MUST 为 WAL（库级持久，重开仍有效）。打开 MUST 先取得数据库写权、在写权内**重新判定**库状态再分支：新库 → 创建（全量建表 + 版本记录同一事务）；当前版本 → 正常打开；旧版本 → 正常打开但**不迁移**（升级是调用方的显式动作）；过高 → 拒绝；损坏（版本表零行）→ 拒绝。
- **FR-011**: 引导 MUST 保证只有「实际创建者」执行初始化并写版本记录：两个初始化并发、或初始化与"已持写锁但初始化事务未提交"的启动窗口并发时，竞争方 MUST 在写锁释放后重新判定——见到版本记录即以"已存在"（Kept 语义）成功返回，不报错、不重复初始化；忙等待超时 MUST 如实报错、不得吞错。
- **FR-012**: 只读打开 MUST 只校验库状态、**不迁移**、不写库；打开库前 MUST 校验版本（过高 → 拒绝并提示升级程序；旧版本 → 点名提示需升级、不迁移）；库缺失 → 报"库未就绪"，**不代建**。只读路径 MUST NOT 取实例锁、MUST NOT 做恢复、MUST NOT 触碰锁文件。（实例锁与恢复的实现本身不属本 feature。）
- **FR-013**: 迁移机制 MUST 以「注入的文件集 + 显式目标版本」实现（目标版本显式传参，可测合成版本）：新库 → 全量建表；旧库 → 逐版前向，**每一版**的 SQL 与其版本记录**同一事务**；库版本高于目标 → 拒绝；版本表零行 → 拒绝；目标版本缺迁移文件 → 拒绝并点名文件。该机制的**唯一生产调用方**归 US-4 持锁重路径定案——本 feature 交付能力与测试覆盖，不接通命令。
- **FR-014**: 迁移与建库 MUST fail-closed 原子：首次建库（全量建表 + 版本记录）中途失败 → **整体回滚**（无版本表残留、无半建表残留），重跑 MUST 按新库成功；增量某版失败 → 该版回滚、版本记录不变，修复后重试成功。**判态 MUST NOT 早于写权**——文件存在性检查与"仅用 IF NOT EXISTS"**不得**替代取得写权后的重新判定。
- **FR-015**: 库结构 MUST 幂等建齐 11 张表（会话 / 消息 / 运行 / 模型调用审计 / 工具执行审计 / 配置快照 / 定时任务 / 任务执行历史 / 通知渠道 / 记忆条目 / 版本记录）；列与状态字面量的唯一事实源是契约文件，实现的嵌入副本 MUST 与契约**逐字节一致**（由用例强制，防"第二份字面量"漂移）；本 feature **只建表**、不启用审计写入。

#### 测试基础设施与内嵌数据

- **FR-016**: 测试基础设施 MUST 交付：临时工作区助手（每用例独立目录）+ 本地回环 HTTP 测试服务（不访问真实网络，作为"单元层测试基建"的首个样例）。
- **FR-017**: 产物 MUST 内嵌 IANA 时区数据（无系统时区数据的环境仍可解析时区名，为 US-3 / US-10 的时区前提）。默认测试层 MUST 含可移植的加载检查（**不**判隔离有效性——平台时区源无法用环境变量遮蔽）；隔离组（独立触发标签，**不入**聚合门禁，由 CI 必跑步骤执行）MUST 验证：①内嵌生效（主组通过）；②无内嵌导入的对照探针 MUST 以「时区加载失败」这一种原因失败（进程退出码 3 + 标记文本）——启动失败 / 崩溃 / 任意其他退出码均**不**算对照成立。
- **FR-018**: 契约 YAML 文件（当前 `openapi.yaml`）MUST 被解析用例覆盖：全部解析通过即绿，解析失败即红。

### 自动化验收锚点（关键回归守卫）

自动化验收由颗粒度文档「验收测试（Harness）」§4 的测试套件承载（测试全绿即通过）。本 feature 的关键回归守卫（实现期 MUST 原样落地断言逻辑）：

| 守卫点 | 用例（颗粒度文档 §4.3） |
| --- | --- |
| 二跑幂等、已有文件逐字节未变 | `TestInit_Idempotent` |
| 首次建库失败整体回滚（非空虚断言：先建可观察残留再断言其不存在） | `TestMigrate_NewDatabaseFailureRollsBack` |
| 合成迁移集逐版前向 1→2→3 | `TestMigrate_AppliesIncrementalWithFixtures` |
| 库版本高于目标 → 拒绝 | `TestMigrate_RejectsNewerSchema` |
| 并发初始化：恰好一个创建者、零报错、终态一致 | `TestBootstrap_ConcurrentInitRace` |
| 配置三连 fail-closed（缺失 / 空值 / 明文）且不回显明文 | `TestConfig_RejectsMissingEnvVar` / `_RejectsEmptyCredential` / `_RejectsPlaintextCredential` |
| 实现副本与契约逐字节一致 | `TestSchemaFile_MatchesContract` |
| 时区：默认层可移植 + 隔离组主组 / 对照（对照以 exit 3 + 标记失败） | `TestTZData_LoadLocationPortable` / `TestTZData_Isolated*` |

### Key Entities

- **工作区**：Agent、技能与记忆的落点；含 6 个目录与 5 个模板文件；路径口径固定为「当前工作目录下的工作区目录」（诊断报告三节同源，不从配置取）。
- **数据库**：单文件库，含 11 张表（会话 / 消息 / 运行 / 模型调用审计 / 工具执行审计 / 配置快照 / 定时任务 / 任务执行历史 / 通知渠道 / 记忆条目 / 版本记录）；读写连接分工（写上限 1）。
- **版本记录**：迁移与兼容判定的锚点。状态取值：表不存在 = 新库；等于目标 = 当前；低于目标 = 旧库；高于支持 = 拒绝；表存在零行 = 损坏。
- **配置文件**：六段骨架（服务 / 提供商 / 沙箱 / 记忆 / 预算 / 署名，后四段本 feature 解析保留、语义校验随消费 US 落位）；凭证一律环境变量占位；仓库只含样例文件，实例配置不入库。
- **命令面**：本 feature 两条命令（初始化 / 诊断）+ 全局版本选项；其余命令归对应 US。

### Out of Scope（本 feature 明确不做）

- 五大能力的业务面（Provider / Agent 加载与 profile / ReAct 与工具 / Memory / MCP / 通知 / Web / 调度 / 管理台与热加载 / 动态管理——各归对应 US）。
- 12 条命令中的其余 10 条。
- 实例锁、恢复扫描与持锁调用顺序（归 US-4）——但**写模式打开能力与迁移机制属本 feature**，命令何时可调用归 US-4 定案。
- 实例锁与崩溃恢复的实现（含服务启动恢复）；审计两阶段写（表建齐、写入自 US-2 / US-4 起）。
- 沙箱三档执行、授权矩阵、工具注册、监控指标实装（仅接口 + 空实现）、企业级治理（认证 / 多租户 / 审计查询 / Tool Policy / SSO）、官网与演示素材、发布闸门 e2e、网络文件系统（NFS / SMB）工作区。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 干净检出 + 完整前置工具链，一条聚合门禁命令七个目标全绿（退出码 0）；负向对照（未格式化文件、语法错误文件）100% 被同一命令判红。
- **SC-002**: 工作区一键就绪：单次初始化产出的目录 / 文件 / 表 / 版本记录与清单 100% 一致；二跑对已有文件 0 覆盖（逐字节比对）；4 路并发初始化 → 恰好 1 个"实际创建"、0 报错、终态一致。
- **SC-003**: 无配置诊断可跑通：初始化后未经任何配置准备即诊断 → 退出码 0；四类异常态（未初始化 / 配置无效 / 库异常 / 明文凭证）100% 以点名原因的文案判红（退出码 1）。
- **SC-004**: 建库失败可恢复：构造的首次建库失败现场 0 残留（无版本表、无半建表），重跑 100% 成功；增量失败版本记录不变、修复后重试成功。
- **SC-005**: 凭证红线：四类不安全配置 100% 拒绝；捕获的错误文案 / 日志 / 标准输出 / 标准错误四路 0 明文回显。
- **SC-006**: 单二进制可验证：CGO 关闭的发布构建通过，Linux 产物经静态检查断言无动态依赖；竞态检测在独立测试命令中全绿。
- **SC-007**: 覆盖率按可执行判据达标：全部包（含入口包，无豁免）达阈值，或由判卷脚本显式判红——不存在"看起来绿实际未判"的路径。

## Assumptions

- 开发机环境已就位：Go 工具链 1.27.2、GNU Make、C 编译器（竞态检测需要）、四个检查工具按固定版本安装（实测读数与装法见 `docs/GettingStarted.md` §2）。
- 模块拉取经镜像代理（本机直连上游不可达，已实测；命令一律显式带代理环境变量）。
- US-1 是依赖链起点，无前序模块交付物；外部依赖仅四个已裁决坐标（CLI / YAML / SQLite 驱动 / 测试断言），写入模块声明前逐坐标经模块代理复核（软门禁：与技术方案 §1.2 不一致即停下报告）。
- 运行时契约（schema 契约）在对应链路验证通过前为「待验证设计草案」，不构成开工阻断（宪法·开发工作流）；实测偏差回写契约并交用户确认。
- 本 feature 交付"能力与机制"；重路径的持锁调用顺序、实例锁与恢复归 US-4 定案。
- 工作区不支持网络文件系统（NFS / SMB）挂载场景（v0.1 边界）。
- 工作区路径取颗粒度文档「待决事项」#1 的**默认建议**：CWD 固定口径、本 feature 不引入配置覆盖键（与运维手册 §1.1 / §5.3 同向）；该键是否引入随 US-9 装配面复核。另一项「待决事项」#2（实例锁的 Windows 手段）属 US-4 范围，不在本 feature。
