# Feature Specification: US-15 工程验收基础设施

**Feature Branch**: `015-acceptance-infra`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "第15模块需求：工程验收基础设施——让验收持续执行、可复现、可审计，人审 ② 审证据而非亲手重跑每一项。"

## Clarifications

### Session 2026-10-19

- Q: `--executor` 与 `--run-kind` 的缺省值是什么，会不会影响检查选择？ → A: 缺省 `ai` / `original`；CI 环境非空时执行者缺省 `ci`；显式旗标优先；回填运行必须显式 `--run-kind backfill`，用户复跑必须显式 `--executor user --run-kind rerun`；两者只写记录字段，不得改变检查选择或放宽判据。（AI 依据：模块卡 §4.2 跳过规则段、待决事项 D-08）
- Q: 目录覆盖以哪一种记录为准，运行记录能否算作覆盖？ → A: 目录覆盖只认 `subject.kind = manual_item` 的已发布记录：每个目录项对应一条记录，引用同一次运行的日志与报告并标 `run_kind = backfill`；运行记录不得冒充目录覆盖。（AI 依据：模块卡 §3.3「两类记录的来源」与校验规则 10、§4.3 回填命令说明）
- Q: 人工项记录的标识如何取，记录发布碰撞时怎么办？ → A: 人工项记录由执行者给稳定 ID（`<运行目录名>-<item>` 或 `backfill-<UTC 时间戳>`），全库唯一；同名已存在即停止。运行记录碰撞时只能换新运行目录重跑，人工项记录可另取新 ID，均不得覆盖。（AI 依据：模块卡 §3.3 记录字段表 `record_id` 行）
- Q: 记录、报告与台账的「发布」是否意味着自动提交版本库？ → A: 「发布」指写入仓库工作区的发布目录并纳入版本控制文件面，不触发自动 commit / push；原始运行日志留在运行目录、不入库，保留至人工 review ② 结束。（AI 依据：模块卡待决事项 D-04；项目硬性禁止自动 commit / push）
- Q: 慢速 300s 项与真实外发项在哪里执行，是否进入 CI？ → A: 四个中立项进入现行累计清单；Linux 信号项进入 CI 的 Ubuntu 运行；慢速项只在收口执行；真实项只在用户授权后收口执行；后两者均不进入 CI 与现行累计清单。（AI 依据：模块卡待决事项 D-09、D-10、D-12）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 每次验收运行都留下可复跑的证据 (Priority: P1)

一次验收运行（公共 profile、某个 US 的 stage、回填运行或已授权的真实外发）结束后，运行目录里同时有机器报告与运行记录。记录绑定源码指纹、基线提交、工作区脏标记、平台、Go 版本、被测二进制哈希与本次授权；层级（source / process / external）由 check 声明决定，日志缺失不得降级；报告里的日志路径在发布前投影为仓库相对路径。记录与同次报告成对发布到仓库、台账可索引，旧记录不被覆盖。

**Why this priority**: 人审 ② 审证据的前提是证据确实来自同一次执行、可逐字段核对、可在新目录复跑。没有记录规范时，"AI 说跑过了"无法审计，人工项最终还是得人重跑。

**Independent Test**: 跑一次 stage 运行，检查运行目录的 `record.json` 与 `report.json`：字段齐、`record_id` 等于目录名、记录引用同次报告哈希；对一个声明 process 的 check 删掉全部 `binary_sha256=` 日志行后重跑，得到退出码 2 且无记录；对 external check 不给授权旗标，同样退出 2 且无记录。

**Acceptance Scenarios**:

1. **Given** 一次成功的 stage 运行，**When** 读取该运行目录的记录，**Then** 它包含运行类型、执行者、源码指纹、基线提交、脏标记、平台、Go 版本、报告路径与报告哈希，`record_id` 等于运行目录名，且引用的是同一次运行的报告。
2. **Given** 某 check 声明为 process，**When** 命令成功退出但日志中没有任何 `binary_sha256=` 行，**Then** 判为基础设施错误（退出 2）、不生成可发布记录，且不得把层级降级为 source。
3. **Given** 本次选中的 check 含 external，**When** 未同时给出授权标识与授权范围，**Then** 退出 2 且不生成记录；**Given** 本次未选 external 却给出授权旗标，**Then** 同样退出 2。
4. **Given** 一条记录已发布，**When** 再次发布同名记录，**Then** 拒绝覆盖；运行记录只能以新的运行目录重跑，不得改 ID 冒充新运行。
5. **Given** 运行目录位于仓库之外，**When** 启动验收，**Then** 退出 2 且不生成记录；**Given** 运行目录在仓库内，**When** 写报告，**Then** 每个 check 的日志路径都是仓库相对路径且使用正斜杠，可拼回真实日志。
6. **Given** 运行期间源码发生变化，**When** 运行结束，**Then** 报告与记录如实标为失败（源码已变），不得以通过结束。

### User Story 2 - 现行累计验收持续回归，历史定义零漂移 (Priority: P2)

现行清单聚合 US-8 / US-9 / US-10 三个历史 stage 的全部专属检查，加上 US-15 自己的检查，形成每轮都能跑的现行累计验收。历史 stage 文件一个字节都不许改写；US-8 中已经改名的测试通过显式替代映射登记，而不是删掉或改历史文件。stage lint 在不执行测试的前提下预检 required_tests 是否仍然存在；现行清单失配即失败，历史清单失配只告警。stage-only 模式只跑 stage 自身的检查，不重复跑门禁全量。

**Why this priority**: 历史 US 的专属检查如果不再被执行，回归面会悄悄腐烂；如果允许顺手改写历史 stage 或静默删 check，漂移不可见。它是"持续执行"的骨架。

**Independent Test**: 对现行清单跑 lint 退出 0；跑现行 stage 全部检查通过；从现行清单删掉一个历史 check 或改动历史 stage 任一字节，相应用例变红；把 `-list` 预检指向一个不存在的测试名，lint 能报出缺失。

**Acceptance Scenarios**:

1. **Given** 三个历史 stage 文件未改动，**When** 运行现行 stage，**Then** 历史 check 全部按原定义执行并通过。
2. **Given** 历史清单中的某个测试已不存在（如 US-8 的九个工具检查被十工具检查取代），**When** 构建现行清单，**Then** 以显式替代映射登记新 ID，且替代项只校验"目标存在 + 测试名精确相等"，不逐字段比较已消失的旧测试。
3. **Given** 历史 stage 文件被改写，**When** 运行判据，**Then** 历史钉住用例变红。
4. **Given** 现行清单声明了某个不存在的测试名，**When** 跑 stage lint，**Then** lint 退出非 0 并点名缺失项；**Given** 历史 stage 有同类失配，**Then** 只打印告警、不影响退出码。
5. **Given** 同时给 stage-only 与显式 profile，**When** 启动验收，**Then** 退出 2 并提示二选一，不得静默忽略任一参数。

### User Story 3 - 历史人工项全量回填为进程级证据 (Priority: P3)

US-1~10 中所有可客观判定的进程级人工项，由一套进程级夹具在本轮全部执行：构建真实二进制，使用临时工作区与回环假外部服务，按历史场景逐个断言。冻结的必验全集与回填目录双向相等，目录项与各 stage 的 required_tests 逐字一致；每条记录进入三视图状态：历史是否曾执行、当前代码版本的结论、新旧结论冲突是否显式列出。用户复跑与 AI 记录并列，不得互相遮蔽。

**Why this priority**: 这是本 US 的直接交付价值——历史上"等人有空再跑"的项，现在由 AI 跑完并把记录交给用户抽检。它依赖 P1 的记录规范与 P2 的清单骨架。

**Independent Test**: 跑回填检查，全部具名测试通过；每个目录项都至少有一条已发布记录；删掉一条目录覆盖记录，覆盖用例变红；改动一条已发布报告的字节，绑定用例变红；构造同一目录项在两个版本下结论相反，冲突视图显式列出两条记录 ID 与两个结论。

**Acceptance Scenarios**:

1. **Given** 冻结目录中的每个进程级项，**When** 回填运行结束，**Then** 每项都对应一条通过的具名子测试与一条已发布记录，且记录能在同次报告中找到对应的具名 PASS。
2. **Given** 回填目录与冻结全集，**When** 校验覆盖，**Then** 非外部项与冻结全集双向相等；外部项与已授权外部全集双向相等；同时删掉目录项与其 required_test 仍必须变红。
3. **Given** 同一目录项存在较新的通过记录与较早的失败记录，**When** 计算状态视图，**Then** 两条都保留，历史曾执行视图为是，当前版本视图取该版本的结论，冲突标志显式置位。
4. **Given** 用户对某一项亲自复跑，**When** 运行结束，**Then** 复跑记录以 user / rerun 登记并与 AI 记录并列，不因运行类型被过滤。
5. **Given** 首批记录尚未发布，**When** 运行覆盖用例，**Then** 它处于预期失败状态；不得用跳过、删测试或放宽断言规避。

### User Story 4 - 已授权真实项的执行与留证 (Priority: P4)

在用户明确授权下，收口时执行真实模型对话与真实飞书外发。授权标识与授权范围由命令行显式传入，凭证只经运行时环境变量注入；缺少任一所需环境变量时测试直接失败而不是跳过；模型调用与飞书发送有硬上限；数据只允许合成内容；输出、记录与报告只允许出现接收方的 `scheme://host`，不得出现完整 webhook 或任何凭证。

**Why this priority**: 真实模型与外发是价值最高、风险也最高的人工项。一次性授权必须可追溯、不可复用、不会因为"没配好环境"被冒充为通过；它建立在 P1 的授权绑定与 P3 的夹具之上。

**Independent Test**: 不带授权旗标运行外部 stage，退出 2 且无记录；带齐旗标但缺环境变量，两个外部检查失败（不是跳过）；环境齐备时两个检查通过，记录中的授权与报告逐项相等，且调用次数与发送次数不超上限。

**Acceptance Scenarios**:

1. **Given** 用户已授权真实模型与飞书外发，**When** 以授权标识与范围运行外部 stage，**Then** 两个外部检查通过，记录与报告的授权字段逐项相等。
2. **Given** 环境变量缺失，**When** 运行真实项，**Then** 检查失败并指出缺失变量名，不得 SKIP、不得生成通过记录。
3. **Given** 真实调用成功，**When** 查看输出、记录与报告，**Then** 只出现 `scheme://host`，不出现完整 webhook、查询串或任何 API key。
4. **Given** 授权只覆盖本次运行，**When** 下一次要执行真实项，**Then** 必须重新取得用户明确授权并记录新的授权标识。
5. **Given** 真实服务偶发失败，**When** 重试预算耗尽，**Then** 如实记为失败，不得降级为未验证或跳过，也不得无限重试。

### User Story 5 - CI 接线与仓库不变量 (Priority: P5)

既有 CI 的 test job 内插入三步：lint-stages、现行清单、Linux 信号场景；不新增 job、不改 job 名。所有验收运行目录与日志名带 run id 与 attempt 后缀，跨运行和重试唯一。六个仓库级不变量由测试机器判卷：无 Agent 框架坐标、生产代码不用进程本地时区、发布面零明文凭证、无 ORM、测试专用依赖不进发布二进制、CI 运行目录唯一。

**Why this priority**: 验收要"持续执行"就必须进 CI；目录唯一性决定重试证据是否错位。它属于收尾加固，但漏掉会让前三项的证据在 CI 场景失真。

**Independent Test**: 在 CI 上看到三步依次执行且全绿；把任一 `--out` 改回固定名，CI 目录唯一不变量变红；在 `go.mod` 加入被禁框架坐标或 ORM，相应用例变红。

**Acceptance Scenarios**:

1. **Given** 一次 CI 运行，**When** 查看 test job，**Then** lint-stages、现行清单与 Linux 信号三步都执行并通过，job 名与上传步骤不变。
2. **Given** 同一次 CI 运行被重试，**When** 第二次尝试启动，**Then** 运行目录带新的 attempt 后缀，不复用第一次目录。
3. **Given** 工作流文本中出现固定运行目录，**When** 运行不变量用例，**Then** 变红并指出位置。
4. **Given** 发布面出现明文凭证模式，**When** 运行不变量用例，**Then** 变红。

### Edge Cases

- **运行被取消**：已完成的检查不得让整轮以通过结束；报告标为错误，未执行的检查保持"未运行"，正在运行的报告只表示进度、不得授权推进。
- **源码在运行期间变化**：报告与记录判失败（源码已变），不得声称通过。
- **首批记录发布前**：覆盖用例处于预期失败状态（bootstrap），不得用跳过或删测试规避。
- **测试名有意重复覆盖**：同一测试同时服务两个 check 时（US-8 替代项与 US-10 专属项），两处均保留，不合并、不去重。
- **历史 stage 失配**：只告警，不改变退出码；但现行清单的同类失配必须失败。
- **平台限制**：Linux 信号事件序与真实 Ctrl+C 在 Windows 上无法执行，记未验证并写明平台原因，不得记为通过。
- **缺少环境**：第二主机、分词器、第三方 MCP server 等缺环境项记未验证；不与"未授权"混写。
- **记录发布碰撞**：manifest 记录已存在即停止；运行记录只能换新目录重跑；人工项记录可另取稳定 ID。
- **空匹配与全跳过**：具名测试未执行、拼写不符或父测试下子测试全跳过，均判失败，不得当通过。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 每次验收运行 MUST 在同次运行目录写出机器报告，并为该次运行生成运行记录；记录 MUST 含版本、记录标识、运行标识、运行类型（原始 / 复跑 / 回填）、执行者（ai / user / ci）、被验对象、判据结论、代码绑定（基线提交、源码指纹、脏标记、被测二进制哈希）、环境（平台、架构、Go 版本、是否 CI）、逐检查结果与证据（报告路径与报告哈希）。运行类型缺省为原始、执行者缺省为 ai（CI 环境非空时缺省为 ci），显式旗标优先；回填运行 MUST 显式声明回填类型，用户复跑 MUST 显式声明用户执行者与复跑类型；运行类型与执行者 MUST 只决定记录字段，不得据此改变检查选择或放宽判据。
- **FR-002**: 运行记录的 `record_id` MUST 等于运行目录名；发布目录中同名记录已存在时 MUST 停止且不覆盖。人工项记录 MUST 使用稳定标识（`<运行目录名>-<条目>` 或 `backfill-<UTC 时间戳>`）且全库唯一；运行记录碰撞时 MUST 换新运行目录重跑，人工项记录 MAY 另取新标识。
- **FR-003**: 记录 MUST 通过字段与枚举校验：结论取值限于通过 / 失败 / 跳过 / 未验证 / 不适用；运行记录不得出现跳过、未验证或不适用；未验证记录 MUST 写明缺失条件与条目清单；不适用 MUST 给出书面依据；红态证据 MUST 声明失效范围。
- **FR-004**: 记录、报告与台账 MUST 不含凭证与绝对路径；校验器 MUST 拒绝密钥形态、webhook 的路径 / 查询串 / userinfo、盘符路径与 Unix 家目录路径。
- **FR-005**: 每个检查 MUST 可声明层级 source / process / external（缺省 source）；process 与 external MUST 在本次日志中出现唯一且一致的被测二进制哈希标记；层级 MUST 由声明决定，日志缺失时判基础设施错误，不得降级为 source。
- **FR-006**: external 检查 MUST 绑定运行期授权（标识 + 范围）；选中 external 时两旗标 MUST 同时给出，未选中时 MUST 不得给出；记录的授权 MUST 与同次报告逐项相等。
- **FR-007**: 报告在写入发布面之前 MUST 把每个检查的日志路径投影为仓库相对路径并统一使用正斜杠；运行目录经解析后 MUST 位于仓库根内，否则判基础设施错误且不生成记录。
- **FR-008**: stage lint MUST 只做只读预检：从 Go 测试参数中去掉执行与计数参数、保留 build tag 与包参数、追加或替换成列名模式；required_tests 中的子测试全名 MUST 截断为顶层测试名、去重并保持声明顺序。现行清单失配 MUST 使 lint 失败；历史 stage 失配 MUST 只告警。
- **FR-009**: 现行累计清单 MUST 覆盖 US-8 / US-9 / US-10 三个历史 stage 的全部检查（替代项按 FR-010 处理）并加入 US-15 的四个中立检查；非替代项 MUST 与历史定义逐字段相等。
- **FR-010**: 历史检查的失配 MUST 通过显式替代映射登记：现行清单 MUST 存在替代检查，替代检查的必需测试名 MUST 精确等于冻结值；旧检查的参数、超时与测试名不参与比较；替代目标不得自我替代。
- **FR-011**: 三个历史 stage 文件 MUST 按换行归一后的内容哈希钉住，钉住集合 MUST 固定为这三个文件，不得扫描整个目录。
- **FR-012**: stage-only 模式 MUST 只执行所选 stage 的检查（含未绑定任务的整合断言），不运行公共 profile；与显式 profile 同时出现 MUST 判参数冲突并退出 2。
- **FR-013**: 回填目录 MUST 按现行检查分组记录每个历史项的编号、测试全名与层级；目录 MUST 与冻结的必验全集双向相等（非外部项对非外部全集，外部项对已授权外部全集）；目录项与各 stage 的必需测试名 MUST 逐字一致。目录覆盖 MUST 只以人工项记录为准：每个目录项对应一条已发布记录，引用同一次运行的日志与报告，运行记录 MUST NOT 冒充目录覆盖。
- **FR-014**: 记录状态 MUST 提供三个互不遮蔽的视图：历史是否曾执行（任一记录）、当前代码版本与平台的结论、同键结论冲突的显式列出；用户复跑记录 MUST 进入当前视图并参与冲突判定，不得按运行类型过滤。
- **FR-015**: 记录与同次报告 MUST 成对发布，发布前 MUST 通过执行绑定校验——记录声称通过的检查，其必需测试 MUST 能在同次报告的同检查具名通过列表中找到；发布后 MUST 追加台账一行，台账链接与记录 MUST 一一对应。「发布」MUST 指写入仓库工作区的发布目录并纳入版本控制文件面，MUST NOT 触发自动 commit / push；原始运行日志 MUST 留在运行目录、不入库，保留至人工 review ② 结束。
- **FR-016**: stage 的批准引用 MUST 指向真实人审决定与所审版本；模板占位 MUST 被拒绝；stage MUST NOT 携带凭证或授权值；其输入与保护路径 MUST 位于仓库内且实际存在。
- **FR-017**: 进程级回填夹具 MUST 构建真实二进制（关闭 CGO、裁剪路径、注入测试版本），复用既有假模型、回环 HTTP、MCP helper 与临时工作区夹具；平台中立场景、Linux 信号场景、慢速超时场景与真实外发场景 MUST 以不同构建标签隔离。
- **FR-018**: 真实项在缺少任一所需环境变量时 MUST 直接失败（不得跳过）；只允许合成提示词、临时工作区与固定合成消息；模型调用 MUST 不超过 30 次、飞书发送 MUST 不超过 5 次；MUST NOT 复用 Agent 自身的凭证变量。
- **FR-019**: CI MUST 在既有 test job 内插入 lint-stages、现行清单、Linux 信号三步，MUST NOT 新增 job 或改动 job 名；所有验收运行目录与控制台日志名 MUST 同时含运行标识与尝试序号。慢速 300 秒项与真实外发项 MUST NOT 进入 CI 或现行累计清单——慢速项在收口执行，真实项仅在用户授权后收口执行。
- **FR-020**: 六个仓库不变量 MUST 有机器可判测试：无 Agent 框架坐标、生产代码不用进程本地时区、发布面零明文凭证、无 ORM、测试专用依赖不链接进发布二进制、CI 运行目录唯一。
- **FR-021**: 源码指纹 MUST 排除已发布记录与台账（发布不得扰动自身指纹），其余源码、判据与 stage 变更 MUST 改变指纹。
- **FR-022**: 开发操作正文的收口执行项 MUST 整项替换为「AI 默认执行具备环境、授权且可客观判定的验收项并留证；未授权项保持未验证」；凭证与权限纪律原文 MUST 保持不变。
- **FR-023**: 本功能 MUST 保持判据面零删除、零跳过、零放宽：既有两个测试文件的断言逐条保留（仅签名适配），公共清单的 profile 与七目标门禁不变。
- **FR-024**: 本功能 MUST 零新增第三方坐标、零数据库迁移、零新增配置键、零新增对外端点或 Agent 字段；验收工具的记录校验 MUST 只用标准库。
- **FR-025**: 任何基础设施错误——缺字段、层级缺哈希、外部缺授权、运行目录越界、记录已存在、报告写失败——MUST 以退出码 2 结束且不生成可发布记录。

### Key Entities *(include if feature involves data)*

- **验收运行记录**：一次运行的可审计凭证；标识、运行类型、执行者、被验对象、判据结论、代码绑定、环境、逐检查结果、证据引用、授权、备注、红态失效范围。
- **机器报告**：一次运行的原始结果；运行标识、范围、源码指纹、基线提交、脏标记、环境、被测二进制哈希、授权、起止与状态、逐检查结果（含层级与通过 / 跳过的测试名单）。
- **阶段描述文件**：一轮验收的映射；批准引用、输入、保护路径、检查定义、任务绑定、替代映射。
- **回填目录项**：历史子判据到现行检查与测试全名的映射；编号、检查、测试、层级。
- **发布台账行**：记录索引；记录标识、日期、范围、运行类型、执行者、结论、记录链接。
- **状态视图键值**：目录项 × 源码指纹 × 平台 → 记录标识列表、结论、冲突标志。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 现行累计清单的 33 个检查全部通过，且每个检查的必需测试都是本次运行中的具名通过（空匹配或跳过为 0）。
- **SC-002**: 现行清单与三个历史 stage 的非替代项逐字段差异为 0；历史 stage 文件内容差异为 0；US-8 替代项的必需测试名精确匹配率 100%。
- **SC-003**: 冻结回填目录中的每一项都至少有 1 条已发布记录；每条声称通过的记录都能在 1 份同次报告中找到对应具名通过；发布记录与报告配对数 100%。
- **SC-004**: 历史回填矩阵中每一项都有四态结论之一（通过 / 失败 / 跳过 / 未验证）或书面不适用依据；留空项为 0；未验证项的缺失条件写明率 100%。
- **SC-005**: 外部运行记录与报告的授权字段逐项相等率 100%；模型调用次数 ≤ 30、飞书发送次数 ≤ 5；记录、报告与输出中的凭证与完整 webhook 出现次数为 0。
- **SC-006**: stage lint 对现行清单退出码为 0；对人为删除的必需测试 100% 报出缺失；对历史 stage 的失配只产生告警。
- **SC-007**: 三视图冲突判定：同一目录项存在相反结论时，冲突标志置位率 100%，两条记录标识均保留；用户复跑被过滤的次数为 0。
- **SC-008**: CI 运行目录与日志名全部含运行标识与尝试序号；固定目录复用率为 0；重试时不发生目录碰撞。
- **SC-009**: 六个仓库不变量在逆改（加入被禁坐标、明文凭证、固定目录等）时 100% 变红，在正常仓库上 100% 通过。
- **SC-010**: 公共门禁七目标全绿；判据面既有断言删除数 0、无理由跳过数 0、阈值放宽处 0。
- **SC-011**: 发布记录与报告中的绝对路径出现次数为 0；日志路径 100% 可拼回真实日志。
- **SC-012**: 本 US 收口时，历史人工项的回填执行率（甲类全部 + 已授权乙类）为 100%，未执行项均为未授权、缺环境或平台限制并逐条写明原因。

## Out of Scope

以下项目在本 US 明确不做，各有替代或后续归属：

- 超出回填需要的进程级场景与故障注入扩展——只做回填必需的项；扩展留后续波次。
- fuzz 与属性测试、种子回归、定时探索——后续波次；本 US 只做定向用例。
- 条件式跳过白名单（按 profile / 平台 / build tag / 用例 / 原因细分）——本批先做统一摘要与必跑规则，不新增白名单。
- 改写历史 US 颗粒度文档或历史 stage——冻结；US-8 替代只在新清单中显式登记。
- 改七目标门禁、覆盖率阈值或公共 profile——保持不变。
- 新增生产依赖、配置键、数据库迁移或对外端点——零变更。
- 父目录 fsync——仍属 US-10 的独立待办，本 US 不冒充完成。
- 未授权真实外发、真实天气 API、跨仓对拍、平台授权项（如 GitHub 分支保护）——保持未验证并写明缺失授权。
- 第二主机、Windows 真实 Ctrl+C 事件序、分词器依赖、第三方 MCP server——缺环境或依赖，保持未验证。
- 自动 commit / push / tag / 部署——由用户决定。
- 丙类人工判断项（证据充分性、控制台观感、备份面口径、差异可接受性、文档真实性）——仍由用户裁决。
