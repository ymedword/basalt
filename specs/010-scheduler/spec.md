- Q: 手动补跑是否允许作用于已停用任务？ → A: 允许；启停只控制 cron 注册，手动补跑是运维显式动作（AI 依据：颗粒度文档注 7）。
- Q: 锁失导致 cron 跳过时，是否更新任务的最近运行时间与最近状态？ → A: 不更新；两者只描述"最近一次已开始的执行"，锁失的独立 `skipped` 只写执行历史（AI 依据：颗粒度文档注 2 / 注 6）。
- Q: 最近运行时间在何时写入？ → A: 在 `started` 执行历史写入成功后、发起运行之前；准入失败也算一次已发起的尝试（AI 依据：颗粒度文档注 2）。
- Q: 同一 Agent 的兄弟任务占住会话时，本次执行历史与最近状态如何记？ → A: 状态 `skipped`、固定原因「同一 Agent 的另一任务仍在执行」、关联运行标识置空、最近状态同步为 `skipped`（AI 依据：颗粒度文档失败判据表与注 8）。
- Q: 任务列表与执行历史的排序和窗口是什么？ → A: 列表按任务标识升序；执行历史按开始时间倒序、固定最近 100 条、无分页（AI 依据：颗粒度文档注 11 与 FR-028）。
- Q: 写入后何时生效？ → A: `serve` / `gateway` 下立即对账生效；`chat` / `tool` 下只落盘，下次启动对账生效（AI 依据：颗粒度文档注 13 与 FR-037）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 到点自动运行 (Priority: P1)

企业管理员在各 Agent 的 `AGENT.md` 中声明 `schedules:` 后启动 `serve` 或 `gateway` 进程。到达计划时刻时，系统以该 Agent 的身份发起一次真实运行：消息进入该 Agent 的调度会话，Agent 按既有 ReAct 链路调用模型与工具，执行历史与运行账本各留一条可关联的记录。运行期间同一任务不得重叠；单次失败不得影响其他任务或进程本身。

**Why this priority**: 这是整个模块的存在理由——五个每日 Demo（D1–D5）以"每天固定时刻自动跑一次"为底座。没有真实到点触发，其余管理与自管能力都没有意义。

**Independent Test**: 让某 Agent 声明一个近期的 cron 计划（含 `CRON_TZ=` 时区），启动 `serve` 后等待到点；检查运行账本新增一条 `trigger=cron` 记录、执行历史新增一行、该 Agent 的调度会话新增一轮 user / assistant 消息，且消息内容与计划一致。

**Acceptance Scenarios**:

1. **Given** 一个已注册 Agent 含一条启用的计划，**When** 到达计划时刻，**Then** 恰好发起一次运行，执行历史先写 `started` 再按结果收尾为 `completed` / `failed`，运行账本记录 `trigger=cron`，两者共享同一运行标识。
2. **Given** 同一任务的上一轮仍在运行，**When** cron 再次到点，**Then** 新增一行 `skipped` 执行历史并记录警告，不发起第二次运行、不排队、不返回冲突。
3. **Given** 调度会话已归档，**When** cron 到点，**Then** 新增一行 `skipped` 执行历史（固定原因「会话已归档，本轮跳过」），不发起运行、不自动重建会话。
4. **Given** 某次触发中准入失败、运行失败或执行记录写入失败，**When** 该次触发结束，**Then** 其他任务照常触发，进程不退出，遗留的未收尾执行行在下次启动时被恢复。
5. **Given** 两个不同任务属于同一 Agent，**When** 它们先后触发，**Then** 两者使用同一个调度会话，上下文连续。

### User Story 2 - 重启与停机一致性 (Priority: P2)

运维重启进程或发送停止信号时，任务定义、启停状态与执行历史必须保持一致：文件是定义的唯一来源，库是启停状态的唯一来源；重启不复活人工停用的任务，也不补跑停机期间错过的触发点；在途运行在数据库关闭前收尾。

**Why this priority**: 调度器一旦与文件或库不同步，就会出现"文件改了不生效""重启偷偷开回停用任务""停机后雪崩补跑"这类难以发现的事故；它直接决定系统能否被信任。

**Independent Test**: 停用一个任务并修改其 cron，重启进程后确认：停用状态保持、新 cron 生效、无补跑、无遗留 `started` 执行行；再发送停止信号，确认在途运行收尾、进程在宽限内退出。

**Acceptance Scenarios**:

1. **Given** 某任务在库中被人工停用，**When** 文件中的定义未变而进程重启，**Then** 该任务保持停用、不被注册；文件中的 cron / 时区 / 消息更新则生效。
2. **Given** 同一 Agent 的多条定义在一次对账中更新，**When** 其中任意一条写入失败，**Then** 该 Agent 的全部更新与退休都不生效，旧定义与旧调度继续完整工作；启动路径整体失败并拒绝启动。
3. **Given** 停机期间错过了若干触发点，**When** 进程重新启动，**Then** 只记录一条包含任务、次数与最后错过时刻的警告，不自动补跑。
4. **Given** 上次进程遗留了 `started` 执行行，**When** 进程启动，**Then** 这些行按关联运行的实际终态收尾（达上限视为完成），任务状态同步刷新。
5. **Given** 进程收到停止信号，**When** 存在在途运行，**Then** 调度先停止产生新触发，在宽限内等待在途收尾，超时后取消运行并有界等待。
6. **Given** 一个 Agent 的文件被修改并被保存，**When** 该 Agent 的旧调度回调在切换后仍被派发，**Then** 旧回调不得产生运行、执行行或状态变更。

### User Story 3 - 任务管理与手动补跑 (Priority: P3)

运维通过四个管理端点查看任务、启停任务、查看执行历史，并对某任务手动补跑一次。手动补跑与 cron 到点走完全相同的运行链路，但运行账本记录 `trigger=manual`；停用的任务仍可手动补跑；上一轮未结束时返回冲突而不是产生第二次运行。

**Why this priority**: 没有可见性与人工触发，定时任务只能"盲跑"；排障、补救和 Demo 演示都依赖这四个端点。但它建立在 P1 的真实触发之上。

**Independent Test**: 启动 `serve` 后调用列表端点看到任务与最近状态；停用一个任务并确认它不再按 cron 触发但手动补跑成功；在上一次运行未结束时再次补跑得到冲突响应；查看执行历史按时间倒序且上限固定。

**Acceptance Scenarios**:

1. **Given** 系统中有已注册与已退场的任务，**When** 调用任务列表，**Then** 只返回可见任务，按任务标识升序，包含最近运行时间与最近状态。
2. **Given** 一个任务存在，**When** 提交启停请求且载荷含布尔值，**Then** 返回成功且无数据体；载荷缺失或为空，**Then** 返回 400。
3. **Given** 一个任务存在，**When** 查询执行历史，**Then** 返回最近 100 条、按开始时间倒序，未知或不可见任务返回 404。
4. **Given** 任务上一轮未结束，**When** 手动补跑，**Then** 返回 409 `SESSION_BUSY` 与冻结建议文案，不新增执行记录。
5. **Given** 调度会话已归档，**When** 手动补跑，**Then** 返回 400 与「会话已归档，不可追加消息」，并记录一行 `skipped`。
6. **Given** 某任务已停用，**When** 手动补跑，**Then** 运行照常执行，但 cron 不再自动触发。
7. **Given** 执行历史中存在内部失败原因，**When** 客户端读取历史，**Then** 只看到固定投影文案（失败 / 归档跳过 / 上一轮未结束），原始原因永不出站。

### User Story 4 - Agent 自管任务 (Priority: P4)

Agent 在运行中通过内置工具 `manage_schedule` 查看、新增、修改或删除**自己**的任务。写入经过与页面编辑器、脚手架创建相同的唯一写入门：先按同一套规则校验候选内容，再原子替换文件中的任务段，其余内容逐字节保留；越界修改其他 Agent 的任务一律拒绝且零写入。在 `serve` / `gateway` 下修改立即生效；在 `chat` / `tool` 下只落盘，下次启动生效。

**Why this priority**: 这是"Agent 能管自己的时间表"的差异化能力，但它依赖 P1–P3 的注册、对账与可见性链路，且安全边界（身份与归属）必须最后收口。

**Independent Test**: 在 `serve` 下让某 Agent 调用工具把提醒从 8 点改到 9 点，确认返回任务标识、文件中只有任务段变化、下一次触发按新时间；再尝试修改其他 Agent 的任务，确认被拒且文件未变。

**Acceptance Scenarios**:

1. **Given** 运行环境注入了 Agent 身份，**When** 调用工具新增一个合法任务，**Then** 文件中的任务段被原子替换、其余字节不变，返回含任务标识的确认；在 `serve` 下该任务立即注册。
2. **Given** 当前 Agent 恰有一个任务且标识为自定义值，**When** 省略标识执行修改，**Then** 修改作用于该任务并返回其真实标识；当前为零个或多个任务时省略标识，**Then** 返回 `invalid_input`。
3. **Given** 目标标识属于其他 Agent（含已退场），**When** 尝试修改或删除，**Then** 返回 `invalid_input`，文件零写入、数据库零变更。
4. **Given** 删除一个完全不存在的任务标识，**When** 调用工具，**Then** 返回 `not_found`。
5. **Given** 候选内容不符合装载校验规则，**When** 尝试写入，**Then** 操作失败且原文逐字节不变、无临时文件残留。
6. **Given** 没有 Agent 运行上下文，**When** 调用工具，**Then** 返回 `invalid_input`，零写入。

---

### Edge Cases

- 任务定义在文件中被删除但库中仍有行：该任务置为退休标记（不物理删除），不再注册、不再出现在任何管理端点；同一 Agent 之后重新声明同一标识可复活，启停状态保持库值。
- 另一 Agent 声明已被占用的任务标识：一律拒绝，无论原任务是否已退场；归属不因退场而释放。
- 任务目录仍存在但文件校验失败（整只不注册）：其库中任务不置退休标记、不参与对账，修好文件并重启后按新定义恢复。
- 进程重启时上次运行仍在账本中显示"运行中"：按失败收尾并记录错误，不重复运行。
- 调度器尚未启动时收到停止：静默无操作，不阻塞、不报错；重复停止只生效一次。
- 运行时出现本不应出现的"运行中"终态：按失败收尾并记录错误，不留悬挂记录。
- 同一 Agent 的两个任务同时到点：一个执行，另一个记为 `skipped`（同一会话被占用），两者都不排队。
- 执行历史的原始原因包含路径、服务商错误或堆栈：对外只显示固定文案。
- 大停机后错过触发点极多：枚举有上限，只报告"至少 1000 次"，不无限循环。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 任务定义**必须**只来自各已注册 Agent 的 `AGENT.md` `schedules:` 段；启动时扫描注册，**不得**引入固定任务表或第二份任务清单。
- **FR-002**: 系统**必须**接受 6 段 cron（秒 分 时 日 月 周），每任务时区经 `CRON_TZ=` 前缀表达，缺省 UTC；5 段制式、`L` / `W` / `#`、周字段 7、日与周同时受限等不支持的语法**必须**在装载期拒绝；运行期**不得**另写一套校验。
- **FR-003**: 任务标识**必须**全局唯一：单任务可省略标识并在装载期规范化为「Agent 名-1」；两项及以上每项必须显式；显式撞车时该 Agent 整只不注册。
- **FR-004**: cron 到点与手动补跑**必须**经同一个运行入口（准入、账本、审计、循环、消息落库与既有 CLI / REST 完全一致）；调度器**不得**直接执行工具、调用模型、写消息或写审计。
- **FR-005**: 每个任务**必须**有一把互斥锁：cron 触发时锁不可得 → 记一行 `skipped` 执行历史并记录警告，不排队、不并行、不回冲突；手动补跑时锁不可得 → 返回 409 `SESSION_BUSY` 与冻结文案「该任务上一轮尚未结束，请等待完成或稍后重试」，且不写执行历史。
- **FR-006**: 每次触发成为运行之前，**必须**先成功写入一行 `started` 执行历史，其中运行标识预先生成并同时用于本次运行与执行历史；写入失败**不得**发起本次运行。
- **FR-007**: 执行历史状态**必须**只取 `started` / `completed` / `failed` / `skipped`；终态映射固定：运行完成或达迭代上限 → `completed`；运行失败或取消 → `failed`；返回面出现"运行中"视为实现缺陷，按失败收尾并记录错误。
- **FR-008**: 单次触发的任何错误（准入失败、运行失败、存储失败、panic）**必须**被触发边界吸收：记录错误或警告、尽力收尾执行历史，**不得**让异常逃逸到调度线程或使进程退出。
- **FR-009**: 调度会话身份**必须**固定：同一 Agent 的所有任务与手动补跑共用同一个确定性派生的调度会话（渠道与用户均为 `scheduler`）。
- **FR-010**: 触发源**必须**显式落账，只允许 `cron` / `manual`；运行账本的 `trigger` 必须与之一致；调度发起的运行标识前缀固定为 `scheduler-`。
- **FR-011**: 渠道到触发源的映射**必须**是显式表：仅 `scheduler` 渠道可携带显式 `cron` / `manual`，其余组合拒绝落账；未携带显式值时保持既有四渠道映射不变。
- **FR-012**: 重启对账**必须**以库为启停状态与最近状态的事实源、以文件为定义的事实源：更新 cron / 时区 / 消息 / 定义指纹 / 归属，**不得**覆盖启停状态、最近运行时间、最近状态与创建时间；文件改动不得翻转停用状态。
- **FR-013**: 同一 Agent 的全部定义更新与退休标记**必须**在一次事务中应用（全成或全败），**只有事务提交成功后**才允许停旧调度句柄、注册新句柄；失败时保留完整旧定义与旧句柄，**不得**产生部分更新。
- **FR-014**: 下线**必须**只标记、不物理删除：已标记的任务不再注册、不出现在任何管理端点；同一 Agent 的同标识重新出现时清除标记并保留库中启停状态；其他 Agent 声明同标识**一律**拒绝。
- **FR-015**: 任务标识的归属**必须**绑定首次成功写入的 Agent，跨 Agent 复用**一律**拒绝（与是否已退休无关）；**不得**为此新增列或迁移。
- **FR-016**: 每次注册**必须**携带进程内单调递增的注册代次；切换句柄后，切换前已派发的旧回调**不得**产生执行历史、运行或状态变更。
- **FR-017**: 停机期间错过的触发点**不得**补跑；**必须**按任务记录一条警告（任务、次数、最后错过时刻），枚举上限 1000 次；基线为最近运行时间，从未运行的新任务不告警。
- **FR-018**: 进程启动时**必须**先把上次遗留的 `started` 执行历史按关联运行的实际终态收尾（完成 / 达上限 → 完成；失败 / 取消 / 无关联运行 → 失败；异常"运行中" → 失败并记错误），并同步更新任务的最近状态。
- **FR-019**: 启动注册**必须**分两阶段：先对全部已注册 Agent 完成对账事务，任一失败则**零句柄注册**并拒绝启动；全部提交成功后才统一注册句柄。
- **FR-020**: 启动路径的存储失败、对账失败或句柄注册失败**必须**致命——`serve` / `gateway` 以退出码 1 结束（若停止信号已到达则退出码 0 并记警告），不置启动成功位；运行期单任务注册失败**不得**阻断其余任务，但**必须**返回聚合错误说明"已落库、该任务未注册"。
- **FR-021**: 调度器**必须**只在 `serve` 与 `gateway` 启动；`chat` / `tool` / `profile` / `session` 下即使构造了调度器也**不得**开始触发任务。
- **FR-022**: 启动**必须**只成功一次（成功后再启动返回错误，首次失败不置位、可重试）；停止**必须**幂等，未启动时停止为无操作，并发停止等待同一次完成。
- **FR-023**: 资源释放顺序**必须**固定为「调度器停止 → 外部工具连接 → 数据库 → 实例锁」，在途运行**必须**在数据库关闭前收尾。
- **FR-024**: 停止**必须**有界：先停止产生新触发；在 70 秒宽限内等待在途运行；超时取消在途运行并再等最多 5 秒；仍未退出则记录错误并继续等待（安全优先于退出速度）。
- **FR-025**: `serve` / `gateway` 的停止信号上下文**必须**只有一个来源；调度器监听同一上下文并在收到信号后立即停止，与 HTTP 排空并行；**不得**再建第二个停止监听。
- **FR-026**: 会话归档判定、在途运行登记与归档动作**必须**收敛在运行入口的同一临界区；任何触发源（含 cron）都**不得**绕过；无会话的调用**必须**完全绕过该门禁（不查会话、不登记、不产生会话级冲突）。
- **FR-027**: 归档会话在调度路径的语义固定：cron 触发 → 写 `skipped`（「会话已归档，本轮跳过」），不发起运行、不重建会话；手动补跑 → 400 与「会话已归档，不可追加消息」；两者都同步最近状态为 `skipped`。
- **FR-028**: 系统**必须**提供四个管理操作：任务列表（按任务标识升序、隐藏已退休与未注册 Agent 的任务）、启停（缺失或空载荷 → 400，成功 200 无数据体）、执行历史（按开始时间倒序、上限 100、不可见任务 404）、手动补跑（成功 200 返回运行视图，不存在 404，上一轮未结束 409，归档会话 400）。
- **FR-029**: 执行原因**必须**对外脱敏：`failed` → 「运行失败」；归档 `skipped` → 「会话已归档，本轮跳过」；其余 `skipped` → 「上一轮尚未结束，本轮跳过」；`started` / `completed` → 空串；分支只按固定字面量精确匹配，任何未识别原因落回通用文案，原始原因永不外泄。
- **FR-030**: 内置工具 `manage_schedule` **必须**只从运行环境注入的 Agent 身份取值；入参不承载身份；Agent 上下文缺失 → `invalid_input`。
- **FR-031**: 工具动作**必须**只接受 `set` / `remove` / `list`：`set` 必填 cron 与消息（时区缺省 UTC；省略标识时仅当该 Agent 当前恰有一个任务，定位该任务的**真实标识**，当前为零个或多个 → `invalid_input`）；`remove` 必填标识；`list` 忽略其余参数。
- **FR-032**: 工具失败分类**必须**固定：入参非法或修改他人任务 → `invalid_input`（后者点名归属 Agent）；删除不存在的标识或 Agent 未注册 → `not_found`；`set` 的显式新标识属于新增，不是错误；成功返回含标识的确认。
- **FR-033**: 所有写操作**必须**经唯一的注册写入门；工具**不得**自行写文件或另立解析路径。
- **FR-034**: 写入**必须**先验后写、原子替换：候选内容先经与装载相同的校验（含全局标识占位）；校验失败时原文逐字节不变；成功时写同目录临时文件并原子重命名，任何一步失败都删除临时文件、保留原文。
- **FR-035**: 写入**必须**只替换顶层 `schedules:` 块；块以外的配置键、注释、正文与换行风格逐字节保留；无该键时在配置段收尾前插入。
- **FR-036**: 写入**必须**串行化；进程内的标识占位基线**必须**在每次成功写入后于同一临界区刷新；未注册目录**不得**占位；落盘前的归属预检命中他人任务 → 拒绝且零写入。
- **FR-037**: 写入后的生效时机**必须**固定：`serve` / `gateway` 下立即对账并生效；`chat` / `tool` 下只落盘、不写库不注册，下次启动生效。
- **FR-038**: `manage_schedule` 加入后，重路径注册池与声明名集**必须**恰好十件且逐名一致；轻路径与重路径对同一份 `AGENT.md` 的装载结论**必须**相同。
- **FR-039**: 本模块**必须**零迁移、运行时零新增依赖、零新增配置键；唯一例外是已批准的**测试专用**校验坐标（只允许测试文件导入、不进发布二进制），其必要传递依赖可随依赖整理进入，既有依赖版本**不得**变更。
- **FR-040**: 日志**必须**双轨：失败记录错误；锁跳过、错过触发点、定义变更记录警告或信息；字段固定含任务、Agent、运行标识、触发源；日志**不得**包含凭证或路径，消息正文只记字节长度。
- **FR-041**: 调度业务时间**必须**由显式注入的时钟提供，**不得**散落直接读取系统时间。
- **FR-042**: 审计关联**必须**以运行标识为唯一键，贯穿运行账本、执行历史与工具调用审计，三段可一路追溯。

### Key Entities *(include if feature involves data)*

- **定时任务**：一条来自 `AGENT.md` 的计划，含任务标识、所属 Agent、cron 表达式、时区、消息正文、启停状态、定义指纹、最近运行时间、最近状态与退休标记；任务标识的归属由首次成功写入的 Agent 固定。
- **任务执行**：一次触发尝试的留痕，含所属任务、关联运行标识（未成为运行时为空）、状态（`started` / `completed` / `failed` / `skipped`）、触发源（`cron` / `manual`）、耗时、内部失败原因、开始与结束时刻。
- **运行记录**：既有的运行账本，本模块为其增加显式触发源（`cron` / `manual`），其余字段与语义不变。
- **调度会话**：按 Agent 确定性派生的固定会话，渠道与用户均为 `scheduler`；同一 Agent 的所有触发共享。
- **任务定义段**：`AGENT.md` 中的 `schedules:` 段，是任务定义的唯一事实源；写入只替换该段。
- **管理视图**：任务与执行历史的对外投影，含脱敏后的失败原因，不含内部路径或原始错误。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对任一启用任务，到达计划时刻后 100% 产生一次运行，且运行账本、执行历史与调度会话三者可凭运行标识互相关联。
- **SC-002**: 同一任务在任意并发到点或补跑场景下，重叠运行数为 0；锁冲突 100% 被记录为 `skipped`（cron）或 409（手动），无一排队。
- **SC-003**: 进程重启后，遗留 `started` 执行行的悬挂数为 0；人工停用的任务被重新启用的次数为 0。
- **SC-004**: 同一 Agent 的定义更新与退休在故障注入下 100% 保持全成或全败；无"旧触发时间 + 新任务内容"的混合执行。
- **SC-005**: 跨 Agent 的任务标识复用 100% 被拒，且拒绝路径的文件与数据库变更均为 0。
- **SC-006**: 四个管理操作的响应 100% 符合公开契约（字段、状态码、文案），执行原因不含任何原始内部串。
- **SC-007**: 执行历史窗口稳定为最近 100 条、按开始时间倒序；任务列表顺序在多次读取间稳定。
- **SC-008**: 本模块专属自动验收 13 项全部通过，项目全量门禁（七目标）全绿；关键回归在实现被逆改时按预期变红。
- **SC-009**: 停机期间错过的触发点补跑次数为 0；错过告警在 1000 次枚举上限内收敛。
- **SC-010**: 运行时新增依赖为 0；发布二进制不包含测试专用校验组件。

## Out of Scope

以下项目在本模块明确不做，各有替代路径或归属阶段：

- 停机窗口错过的触发自动补跑——只记录警告，人工手动补跑。
- 失败自动重试与指数退避——下次到点自然再触发，或人工补跑。
- cron 描述符（`@daily` / `@every` 等）与星期 `7` / `L` / `W` / `#`——装载期拒绝。
- 亚秒级精度——6 段 cron 最低 1 秒，扩展阶段另行立项。
- 任务级并发上限与排队——每任务互斥、锁失即跳过；实例级并发上限仍生效。
- 任务依赖、DAG、优先级——扩展阶段。
- 多实例调度、领导者选举、多副本协同——扩展阶段。
- 管理台 UI 与外部编辑文件后的配置热加载——归 US-11；本模块只保留单 Agent 对账入口。
- 任务创建 / 删除 / 改 cron 的 REST 端点——创建与改 cron 走文件与内置工具，删除 = 从文件移除。
- 执行历史分页、过滤、导出与清理留存策略——固定最近 100 条，只增不删，扩展阶段再议。
- 调度端点认证、多租户、RBAC——扩展阶段。
- 调度专用配置键——时限与历史条数为代码常量，不新增配置。
- 每任务预算覆盖——统一使用既有预算段。
- 调度器直接发送通知——通知由 Agent 经既有通知工具自行发起。
- TLS 终止与证书管理——由反向代理承担，扩展阶段。
- IM 入站通道（企微 / 飞书 / 钉钉 / Slack）——扩展阶段；`gateway` 本模块只增加定时调度职责，`chat` 不启动调度器，`serve` 是唯一同时提供 HTTP 与调度的模式。

## Assumptions

- 硬依赖既有运行入口（US-4）与 HTTP 接入面（US-9）：本模块只追加可选的运行标识与触发源字段，既有 CLI / REST / 评测调用行为不变。
- 复用既有装载校验（US-3）、数据库与初始 schema（US-1）、工具注册池（US-5）；每日 Demo 的通知投递由既有 `notify` 工具（US-8）承担，本模块不新增投递逻辑。
- 进程由实例锁保证单实例运行，因此任务调度与写入串行化只需进程内互斥，不需要分布式领导者选举。
- 调度器按系统时钟运行；时区数据由运行环境提供，任务时区显式声明，缺省 UTC。
- 配置热加载与观测端点归 US-11，Agent 动态管理写面与通知渠道增删改归 US-12，IM 入站通道族属扩展阶段；本模块均不实现、不占位测试。
- `gateway` 进程的通道族仍为占位；本模块只为其补上第一个真实后台职责（定时调度）。
- 测试专用校验坐标已获人工 review 批准，其必要传递依赖以实际依赖整理结果为准，运行时零影响。
