- **准入三层词表统一（2026-10-30 校正）**——原「并发名额是调用方级在途请求上限 / 运行名额是 Run 准入槽位」的二分与实现不符：代码与契约只有「按调用方计的在跑 Run 名额」（`RunTicket`，429 `CALLER_CONCURRENCY_LIMITED`）与实例级 Run 上限（429 `TOO_MANY_RUNS`）。现行词表：①**入口速率**——每个已认证业务请求在 HTTP 边界扣一次的令牌桶（`callers.ingress.{run,ingest,read}` 的 `qps` / `burst`，429 `CALLER_RATE_LIMITED`）；②**调用方并发 Run 名额**——按 `CallerID` 计的在跑 Run 数，同调用方多 Key 共享；③**实例并发 Run 上限**——超即 429 `TOO_MANY_RUNS`。FR-034 的四条释放路径对②成立；被拒请求**不得**占用①的令牌或②的名额。`caller_limits.qps` / `burst` 两列是①的**每调用方覆盖**（2026-10-31 裁决第 5 条 T151 接线，原「只存储、不消费」表述撤回）：生效值逐列取 `min(类别预算, 覆盖值)`，**只收紧不放宽**；`0` 表示该列不覆盖（沿用类别预算，不是不限流）；覆盖按 `CallerID` 计，轮换 Key 不重置桶，读覆盖失败回 500 而不是伪装成 429。列清理仍属契约变更，交 review ② 裁决。
- **配额按周期容量计，无独立的「存量容量配额」（2026-10-30 校正）**——权威口径是 `docs/TechnicalDesign.md` §6.2.5「配额按周期容量计（任务数 / Token / 摄取字节）」：三个维度按 `caller_limits.timezone`（IANA 名，缺省 `UTC`）的本地周期边界重置，统一拒绝码 `QUOTA_EXHAUSTED`。原表述另设「知识库条目 / 存储字节存量上限」与「拒绝码不同」，在技术方案、契约与 schema 中均无依据，已撤回。
- **迁移「逐表一致」的可判定口径**（来源：颗粒度文档 §2.11）——逐表行数 + 主键集合全等 + 关键字段（二进制 / 时间 / 大整数）逐值比对；**不**以抽样通过代替逐表核对。
- **「证据缺口」是显式状态而非空表**（来源：颗粒度文档 §2.9 / §3.1.9）——管理台在权威记录 / 结构化诊断 / 采样遥测 / 外部后端四类数据源缺项时显示缺口标记与缺失原因，**不得**把「没有数据」渲染成「一切正常」。
- **诊断契约 v0 随本 US 冻结并交付基础记录**（来源：CLAUDE.local 2026-10-22 OBS 阶段提醒；颗粒度文档 §2.9）——完整观测能力属后续 OBS 模块，本 US 只交付契约与可读取的基础事件，**不**提前把未来模块画成现状。

## User Scenarios & Testing *(mandatory)*

**标签口径**：下面六个用户故事在 `tasks.md` 中以 `[US1]`～`[US6]` 标注，与颗粒度文档的 G1 / G2 验收矩阵对应，不另立编号体系。

### User Story 1 - 企业知识库：摄取、混合检索与引用（Priority: P1）

运维把企业制度文档上传到知识库，系统切分、生成向量并按**文档版本**管理内容（向量写入当前生效的索引代际）；业务 Agent 在一次 Run 中被问到制度问题时，检索返回命中的切块与**可定位**引用，模型据此作答并给出出处；文档被删除或撤权后，后续检索与注入不再出现其正文。

**Why this priority**: 知识库是 B 的核心业务价值，也是 pgvector 统一存储的直接受益面；没有引用闭环，「模型说了什么」无法审计。

**Independent Test**: 用固定小语料（脚本生成的纯文本集合）完成摄取 → 检索 → 引用解析 → 删除 / 撤权后重查，逐项断言检索命中、引用可定位、撤权后正文不出现；不需要真实模型即可验证检索与引用面。

**Acceptance Scenarios**:

1. **Given** 知识库为空，**When** 摄取一份文档，**Then** 生成新的**文档版本**（写入当前生效的索引代际）、切块入库、返回可核对的摄取结果；重复摄取同一内容**不**产生重复版本。
2. **Given** 已摄取多份文档，**When** 以自然语言查询，**Then** 返回按相关度排序的切块，且每条结果带可定位引用（文档 / 版本 / 切块）。
3. **Given** 某文档被删除或调用方失去权限，**When** 再次检索与装配上下文，**Then** 其结果与正文**不再出现**；历史回答中的既有引用标记为失效而不是伪造原文。
4. **Given** 检索结果为空，**When** 组装本次 Run 的上下文，**Then** 注入面保持为空且不产生占位正文；模型仍可正常作答。

### User Story 2 - 语义记忆与历史回查（Priority: P1）

用户在多轮对话里说「以后按这个格式回答」，模型通过既有记忆工具写入；之后的 Run 在开始时就**冻结**注入文本，跨 Run、跨重启保持稳定；用户也可以按关键词或精确引用回查历史消息，命中结果是**指针**（位置 + 归属），正文仍按权限与版本校验读取。

**Why this priority**: 记忆注入语义是既有已验收行为（US-6），本 US 只把**召回**从关键词升级为语义，**不得**改变注入完整性、分区与冻结口径。

**Independent Test**: 以脚本化检索替身驱动真 `AgentService`，断言「核心区由 `Load` 完整注入、归档区不进注入面、Run 开始冻结注入文本、无记忆时提示词与基线逐字节相同」；另用既有消息仓储造历史，验证检索命中为指针、读取受归属与权限约束。

**Acceptance Scenarios**:

1. **Given** 记忆核心区非空，**When** 组装一次 Run 的提示词，**Then** 注入内容与无记忆后端时一致（完整性不变），Run 内多轮读取恒为一次。
2. **Given** 一次 Run 已开始，**When** 期间发生写入或撤权，**Then** 本次 Run 的注入文本不变（冻结），但**读取面权限不冻结**——已撤权内容不得被后续读取返回。
3. **Given** 用户按关键词回查历史，**When** 命中多条，**Then** 返回指针列表并带显式 `truncated` 截断标记（契约只有 `limit`，不提供总数与游标）；按指针精确读取时逐项校验归属、会话与版本，越权或跨调用方返回**找不到**而非内容。
4. **Given** 存量工作区存在 `.basalt/memory/MEMORY.md`，**When** 升级到统一存储，**Then** 该文件**不搬迁、不删除、不双读**，一次性只读导入后原文件保留为回退层。

### User Story 3 - 调用方接入：身份、Key 与配额（Priority: P1）

外部系统以**作用域 API Key** 接入业务端点；系统在准入时确定身份（主体 + 作用域），依次施加入口速率、调用方并发 Run 名额与周期容量配额，超限**拒绝且不占用**后续名额；Key 有明确生命周期（创建 / 轮换 / 吊销），管理面只能看到指纹与状态，**不**回显明文；管理面 admin token 映射内置 `local-admin`，三类凭据（管理凭据 / 调用方 Key / Provider Key）**不得**混用。

**Why this priority**: 没有这一层，知识库与历史端点一开放就无法约束消耗；它是 G2 的前置，也是所有后续模块继承的主体与预算来源。

**Independent Test**: 不依赖真实模型，直接对 HTTP 层与准入路径施压：非法 / 吊销 / 越权 Key、超 QPS、超并发、超周期配额、跨调用方访问，逐项断言拒绝码、**名额不泄漏**（被拒请求不占用并发名额）、以及「准入与限流分开」。

**Acceptance Scenarios**:

1. **Given** 请求未携带凭据或凭据无效，**When** 访问任意业务端点，**Then** 返回未授权，且不产生任何业务写入。
2. **Given** 某 Key 的 QPS 已耗尽，**When** 继续请求，**Then** 返回限流拒绝并给出重试语义；已持有并发名额的请求**不**受影响，被拒请求**不**占用并发名额。
3. **Given** 调用方 A 的 Key，**When** 访问调用方 B 的会话 / 文档 / 记忆资源，**Then** 返回**找不到**（不泄露存在性）。
4. **Given** 管理面请求，**When** 使用调用方 Key 访问管理端点，**Then** 拒绝；管理凭据访问业务端点时身份固定为 `local-admin` 而不是任意调用方。
5. **Given** 配额周期跨日 / 跨月，**When** 周期切换，**Then** 用量按周期重置且历史用量可查；预留核对结果与拒绝原因可审计。

### User Story 4 - 存储迁移与实例交接（Priority: P2）

运维在停机窗口内把既有 SQLite v6 实例迁移到 PostgreSQL：导出 → 校验 → 导入 → 校验 → 实例身份与主密钥交接 → 切换；任一步失败时按**三维判据**（数据库 / 文件 / 外部副作用）决定是否可回退，**不得**只凭「重跑一次」掩盖未知状态。schema 3～5 的合法存量实例走**隔离副本 + 外部锚点**的受控升级路径，**不得**就地迁移。

**Why this priority**: 它是运行期存储切换的必经门槛，但以「不丢数据、可回退、可审计」为前提，优先级低于业务能力本身却必须先于其上线。

**Independent Test**: 用脚本生成的代表性 SQLite v6 库（覆盖 33 张表与边界编码）与 schema 3～5 副本做往返演练：导出 / 导入后逐表行数与关键字段一致、无损编码（二进制 / 时间 / 大整数）；故障注入中途失败，断言三维判据给出**停止**而不是自动回退。

**Acceptance Scenarios**:

1. **Given** 合法 SQLite v6 实例，**When** 完成导出 → 导入 → 校验，**Then** 逐表核对一致、审计与消息顺序保持、ID 关系不变。
2. **Given** 导出包缺少身份或名册，**When** 执行交接校验，**Then** 明确拒绝并给出原因，不进入切换。
3. **Given** 迁移途中失败，**When** 系统判断回退，**Then** 任一维脏或未知即**停止自动回退**并给出人工指引；已发出的外部写（通知等）列出补偿清单。
4. **Given** schema 3～5 存量实例，**When** 直接在原库上尝试迁移或补写身份记录，**Then** 拒绝并零写入；正确路径是隔离副本上的受控升级。
5. **Given** 无 `instance_secrets` 记录但有托管密文，**When** 正常启动，**Then** 进入恢复态（`unprovable_provenance`），**不**自动生成密钥、**不**覆盖旧密钥、**不**改写密文。

### User Story 5 - 会话上下文压缩（Priority: P2）

长会话接近上下文预算时，系统把较早的消息压缩为**派生摘要**，保留最近完整工具组；原始消息仍是唯一权威，摘要可重建、**不写回**消息历史；压缩调用同样走既有 Provider 映射、审计、配额与取消；失败时按判据降级为整组裁剪或明确拒绝，不静默丢内容。

**Why this priority**: 它决定长会话是否可用，但属于体验与成本优化，业务正确性由前四项保证。

**Independent Test**: 用确定性脚本化模型替身产生可控长度的消息序列，断言触发阈值、切点落在完整工具组边界、摘要链与来源引用正确、连续压缩不重复生成、失效内容不重新注入。

**Acceptance Scenarios**:

1. **Given** 会话超过预算，**When** 触发压缩，**Then** 生成摘要条目并记录覆盖区间与策略 / 提示版本；下一轮投影使用摘要而原始消息仍可回查。
2. **Given** 切点落在工具调用组中间，**When** 计算覆盖范围，**Then** 切点后移到完整工具组边界，**不得**产生半截工具组。
3. **Given** 某来源已被撤权或删除，**When** 后续再次压缩，**Then** 该内容不被重新注入摘要。
4. **Given** 摘要调用失败或超时，**When** 处理本轮请求，**Then** 按既定判据降级（整组裁剪或明确拒绝），并向用户与审计给出可判定结果。

### User Story 6 - 诊断事件与运维可见性（Priority: P3）

每次 Run 的关键步骤产生**结构化诊断事件**（`event_id` / `step_id` / `attempt_id` / `parent_step_id` / `seq` 只做局部有序，不设跨节点全局序号）；审计仍是 fail-closed 的权威记录，诊断采样可就地丢弃；管理台区分「权威记录 / 结构化诊断 / 采样遥测 / 外部后端」，缺记录时显示**证据缺口**而不是空白。

**Why this priority**: 它提升排障效率，但不改变业务路径正确性；其字段与枚举随契约冻结。

**Independent Test**: 以故障注入（模型超时 / 工具拒绝 / 空检索）产生事件流，断言事件可关联到 Run 与步骤、敏感信息已脱敏、诊断写失败**不阻塞**业务、审计与诊断的失败语义不同。

**Acceptance Scenarios**:

1. **Given** 一次包含工具调用的 Run，**When** 查看诊断，**Then** 步骤、重试与父子关系可还原，`seq` 在局部范围内单调。
2. **Given** 诊断存储不可用，**When** 业务请求继续，**Then** 业务不被阻塞，管理台显示证据缺口；审计路径仍按 fail-closed 处理。
3. **Given** 诊断无记录，**When** 按 correlation 查询，**Then** 响应区分 `missing`（采样率为 1）与 `sampled_out`（采样率 < 1），管理台显示证据缺口；导出及其断点恢复归 US-16A（拟）OBS，本 US 不承诺。

### Edge Cases

- 摄取过程中进程崩溃：文档版本处于未完成状态，重试**不得**产生半写版本，也不得让后续检索看到不完整内容。
- 同一文档并发摄取 / 并发删除：以版本与作业状态约束串行化，结果可判定（成功 / 冲突），不出现「删除后又出现」。
- 迁移期间仍有在途 Run / 定时任务 / MCP 子进程：停机窗口内必须清点并等待或显式取消，未清点不得开始导出。
- 磁盘满 / 数据库连接中断：诊断采样可丢，审计与业务写入必须给出明确失败，不静默降级。
- 时间与时区：所有时间戳以 UTC 存储；周期配额的**边界**按 `caller_limits.timezone`（IANA 名，缺省 `UTC`）的本地 00:00 计算（月周期取当月 1 日 00:00），进程时区不参与——跨夏令时的一天不得按 24 小时推定。
- 密钥与凭据：任何错误路径、日志、诊断事件均**不得**输出凭据值、Webhook 或数据库连接串。

## Requirements *(mandatory)*

### 知识库（FR-001～FR-009）

- **FR-001**: 系统**必须**支持文档摄取，生成带版本标识的切块集合与向量表示（向量写入当前生效的索引代际）；重复摄取相同内容**不得**产生重复版本。
- **FR-002**: 系统**必须**支持混合检索（语义相似 + 关键词），检索结果**必须**携带可定位引用（文档 / 版本 / 切块）。
- **FR-003**: 引用**必须**区分「可定位」与「被支持」两种语义，不得把「找到了出处」表述为「该出处支持该结论」。
- **FR-004**: 文档删除或权限撤销后，其正文**不得**再出现在检索结果与上下文注入中；历史回答中的既有引用**必须**标记为失效。
- **FR-005**: 系统**必须**提供来源视图，展示每个来源的文档版本、所属索引代际、生效状态与最近变更，供管理面核对。
- **FR-006**: 空检索结果时上下文注入**必须**为空，**不得**插入占位正文。
- **FR-007**: 摄取与检索**必须**记录可审计的操作（谁、何时、对哪个来源、结果如何），失败路径同时落审计与日志。
- **FR-008**: 检索的召回质量判据（索引类型、参数、中文关键词路径）**必须**在实施前以实验冻结；未达标时保持可用基线，**不得**以未达标的默认值上线。
- **FR-009**: 向量维度与 embedding 模型**必须**在实验后冻结；候选值不构成承诺。
- **FR-009A**（D-19）: 知识集合与 Agent 的绑定**必须**由 `AGENT.md` frontmatter 的 `knowledge:` 声明表达——元素为 `{name, access}`，`access` 闭集**只认** `read`；**声明即绑定**，`agent_resource_bindings`（`resource_kind = knowledge_collection`）只是可重建投影，**不得**作为写入口。结构非法或名字解析不到唯一活动集合时该 Agent **整只不注册**；声明**只收窄**检索范围，解析出的集合仍须与调用方自身的 scope 取交集，一个都不可见按越权拒绝（403，**不是**空结果）。

### 记忆（FR-010～FR-019）

- **FR-010**: 记忆召回**必须**支持语义方式，并保留关键词方式（`mode=keyword`）作为可选项。
- **FR-011**: 记忆注入语义**必须**与既有实现一致：核心区由 `Load` 完整注入、归档区不进注入面、Run 开始时冻结注入文本。
- **FR-012**: 记忆**必须**支持六态生命周期（含纠正、删除、冲突处置），状态迁移可审计。
- **FR-013**: 系统**不得**在 Run 结束时自动抽取记忆；候选只由显式提议产生。
- **FR-014**: 撤权或删除后，该内容**不得**经后续读取或摘要重新注入。
- **FR-015**: 记忆读取**必须**在每次读取时校验当前权限（Run 内**冻结注入文本、不冻结读取面权限**）。
- **FR-016**: 存量 `.basalt/memory/MEMORY.md` **必须**保持原样（不搬迁、不删除、不双读）；一次性导入后原文件作为回退层保留。
- **FR-017**: 记忆容量与配额**必须**有明确上限与拒绝语义，超限拒绝时给出可判定原因。
- **FR-018**: 无记忆（空层）时**必须**与基线提示词逐字节一致，不产生额外空段。
- **FR-019**: 记忆后端切换**不得**再以「改一行配置」表述；运行期唯一后端为统一存储。

### 历史回查（FR-020～FR-026）

- **FR-020**: 用户**必须**能按关键词回查历史消息；结果**必须**带 `limit` 与显式 `truncated` 截断标记（缺失按未截断解释），**不得**静默截断。本 US **不**提供总数与游标翻页——`/history/search` 的冻结形状只有 `limit` 与 `hits` / `truncated`，补游标须先走契约评审（2026-10-30 收窄）。
- **FR-021**: 用户**必须**能按消息或引用精确读取；读取**必须**校验归属、会话与版本。
- **FR-022**: 检索命中**必须**是**指针**（位置 + 归属），正文按权限与版本另行读取；不得把正文塞进检索结果。
- **FR-023**: 跨调用方或越权访问**必须**返回「找不到」，不得泄露资源存在性。
- **FR-024**: 历史查询**必须**受运行预算约束（结果条数 / 读取大小），超预算给出明确拒绝或截断语义。
- **FR-025**: 历史读取**必须**覆盖「会话存在」与「无状态 Run」两种形态，后者不得依赖消息表。
- **FR-026**: 历史与引用的时间、顺序与版本字段**必须**可核对（UTC，单调可判定）。

### 调用方身份、Key 与配额（FR-030～FR-039）

- **FR-030**: 业务端点**必须**支持作用域 API Key 鉴权；未携带或无效凭据一律拒绝。
- **FR-031**: 主体（Principal）**必须**显式传递，零值主体**必须**被拒绝；**不得**依赖隐式上下文携带业务状态。
- **FR-032**: Key **必须**支持创建、轮换、吊销与作用域限制；存储只保留指纹，任何界面与日志**不得**回显明文。
- **FR-033**: 准入**必须**按 `docs/contracts/run-and-errors.md` §8 的固定顺序依次施加：**认证 → 入口速率 → 作用域与归属 → 调用方并发 → Run 准入 / 会话串行 → 配额预留**（C-F03，2026-10-31 裁决：先限流、后作用域；其后才是审计预写与真正调用）；**不得**倒置——配额**不得**提到 Run 准入之前，**不得**省略作用域与归属步骤；限流键只由调用方与入口类别决定、与目标资源无关，作用域拒绝**扣自己的桶**，桶空的调用方先得 429、桶未空时才见 403 / 404；三个 429 **不得**合并；**准入与限流分开**表述与实现。
- **FR-034**: 被拒请求**不得**占用并发名额或运行名额；名额生命周期**必须**在成功、失败、取消、超时四条路径上均正确释放。
- **FR-035**: 管理面凭据映射内置 `local-admin`；管理凭据**不得**被当作任意调用方，调用方 Key **不得**访问管理端点；三类凭据（管理 / 调用方 / Provider）**不得**混用。
- **FR-036**: 配额**必须**按周期容量计（任务数 / Token / 摄取字节三个维度），周期（日 / 月）与各维度上限**必须**可配置且按 `caller_limits.timezone` 的本地边界重置；阈值随容量实测冻结；未映射的路由**必须**在启动时失败而不是静默放行。**不得**另立「存量容量配额」语义。
- **FR-037**: 预留与核对**必须**可查、可审计；拒绝原因**必须**返回稳定错误码而非自由文本。
- **FR-038**: 调用方管理的管理入口**必须**随本 US（第二阶段 B，US-16）交付；核心阶段（US-1～US-14）**不**包含调用方身份与配额治理；企业级 SSO / 多租户 / RBAC 仍属扩展阶段，**不得**在本 US 表述为已具备。
- **FR-039**: 身份、Key 与配额的审计**必须**先写 `pending` 再执行，失败路径可查证终态。

### 存储迁移与实例交接（FR-040～FR-049）

- **FR-040**: 运行期存储**必须**为 PostgreSQL + pgvector；连接失败、schema 版本不符或扩展能力不足时**必须**拒绝启动，**不得**回退 SQLite。
- **FR-041**: 既有 SQLite 谱系**必须**冻结在 v6，仅作迁移来源与回退快照；**不得**新增 SQLite 迁移。
- **FR-042**: 迁移**必须**提供导出 → 校验 → 导入 → 校验 → 切换的完整链路，任一步失败给可判定原因。
- **FR-043**: 迁移**必须**无损：二进制、时间、大整数、审计与消息顺序均**不得**失真；ID 关系保持不变。
- **FR-044**: 回退判定**必须**按三维（数据库 / 文件 / 外部副作用）进行；任一维脏或未知**必须**停止自动回退并给人工指引。
- **FR-045**: 首次成功业务写入后**必须**只前滚；重启旧 SQLite **不得**被表述为无损回退。
- **FR-046**: 实例身份与主密钥交接**必须**在迁移之外单独完成并校验；缺身份 / 缺名册的导出包**必须**被拒绝。
- **FR-047**: schema 3～5 存量实例**必须**走隔离副本 + 外部锚点的受控升级路径；**不得**就地迁移、**不得**在原库上运行、**不得**在部分迁移的副本上重试。
- **FR-048**: 无 `instance_secrets` 记录但有托管密文时，启动**必须**进入恢复态（`unprovable_provenance`）；自动生成密钥、覆盖旧密钥、改写密文一律**禁止**。
- **FR-049**: 迁移与交接的每一步**必须**留审计与可核对清单（哈希 / 行数 / 责任人与时间），并**不得**把主密钥材料写入数据库备份包、普通导出包或日志。

### 会话压缩（FR-050～FR-057）

- **FR-050**: 原始消息**必须**为唯一权威；摘要**必须**是可重建的派生视图，**不得**写回消息历史。
- **FR-051**: 压缩覆盖范围**必须**按会话与消息顺序定义，`run_id` 只用于记录触发与审计关联。
- **FR-052**: 切点**必须**落在完整工具组边界，**不得**产生半截工具调用 / 结果。
- **FR-053**: 压缩调用**必须**复用既有 Provider 映射、审计、配额、取消与未知结果核查路径。
- **FR-054**: 连续压缩**必须**保留来源引用与失效信息；已撤权 / 删除内容**不得**经后续摘要重新注入。
- **FR-055**: 压缩失败时**必须**按既定判据降级（整组裁剪或明确拒绝），**不得**静默丢内容。
- **FR-056**: 触发比例、保留组数与摘要预算**必须**先定判据再实验冻结；**不得**预填数值。
- **FR-057**: 摘要投影**必须**可从 committed 链与保留窗口确定性重建（同一输入重复装配结果逐字相同）；覆盖区间**必须**与原始消息顺序一致且相邻条目首尾衔接（无缺口、无重叠）；断链、缺口、陈旧或不可注入时**必须**给固定 `reason_code` 并降级，**不得**注入半成品。**不**要求摘要正文与原始消息「一致率 100%」——摘要是派生压缩，该表述已撤回（2026-10-30）。

### 诊断事件（FR-060～FR-067）

- **FR-060**: 系统**必须**产生结构化诊断事件，字段位包含 `event_id` / `occurred_at` / `kind` / `correlation` / `step_id` / `attempt_id` / `parent_step_id` / `seq` / `attrs`；**必填**以契约 `required` 列表为准（`event_id` / `schema_version` / `kind` / `occurred_at` / `seq` / `correlation`），`step_id` / `attempt_id` / `parent_step_id` 只在适用事件上必填。`correlation` **必须**至少含一个主锚点（`request_id` / `run_id` / `operation_id` / `ingest_job_id`），**不得**为凑锚点伪造 Run。`seq` **只保证局部有序**，不设跨节点全局序号。
- **FR-061**: 诊断采样**必须**可丢弃且**不得**阻塞业务；审计**必须**保持 fail-closed，两者失败语义**不得**混同。
- **FR-062**: 管理台**必须**区分权威记录、结构化诊断、采样遥测与外部后端四类数据源，并在缺记录时显示**证据缺口**。
- **FR-063**: 诊断的存储与查询**必须**全程脱敏；**不得**包含凭据值、Webhook 或数据库连接串。导出归 US-16A（拟）OBS，本 US **不**交付导出端点。
- **FR-064**: 诊断查询**必须**给出明确的缺失 / 采样语义——无记录时区分 `missing=true`（采样率为 1）与 `sampled_out=true`（采样率 < 1），**不得**用空集冒充「一切正常」；导出及其断点恢复归 US-16A（拟）OBS，本 US **不**承诺。
- **FR-065**: 诊断保留期与采样率**必须**可配置，数值随容量实测冻结。
- **FR-066**: 诊断契约（字段、枚举、丢弃规则）**必须**在实施前随契约冻结，**不得**在代码里另立字面量。
- **FR-067**: US-11 的管理认证**不**等于企业 RBAC；管理凭据与调用方 Key **必须**分离。

### 横切（FR-070～FR-078）

- **FR-070**: 所有新增持久化**必须**手写 SQL、幂等建表、受控前向迁移；**不得**引入 ORM。
- **FR-071**: 两套 schema 谱系**必须**各自持有版本常量：SQLite 为 6（冻结）、PostgreSQL 自 1 起；**不得**混用。
- **FR-072**: 领域包**不得**反向依赖适配层；消费方窄端口由各包声明、由存储适配层实现。
- **FR-073**: 发布产物**必须** `CGO_ENABLED=0` 构建；`-race` 与发布构建**必须**分属不同命令 / job。
- **FR-074**: 新增依赖仅限已批准坐标（`pgx/v5` v5.11.0、`pgvector-go` v0.4.1）；表外新增坐标或版本变更**必须**先经确认。两个坐标是**允许上界**，不是必须使用：`pgvector-go` 经 A6 决定不引入（向量以字面量 `$1::vector` 传入），`go.mod` 只含 `pgx/v5`。
- **FR-075**: 配置中的凭据一律 `${ENV_VAR}` 占位，未解析残留即拒绝启动；DSN 不得出现在 `/info`、日志或诊断中。
- **FR-076**: 时间戳一律以 UTC 存储；周期**边界**按 `caller_limits.timezone`（IANA 名，缺省 `UTC`）的本地 00:00 计算；**不得**依赖进程本地时区。
- **FR-077**: 判据面变更（新增 / 等价重构可，删断言、跳过、放宽阈值不可）**必须**披露；分析未清零 CRITICAL 时**不得**实施。
- **FR-078**: 外部真实服务验证仅在已授权范围内进行（ref `user-2026-10-27-us16-external`）；凭据存在不代表有效，未运行项**必须**标未验证。

### Key Entities

- **知识集合（Collection）**：`kb_collections` 的逻辑身份，按 `project` 归属；与 Agent 的绑定由 `AGENT.md` 的 `knowledge:` 声明表达（FR-009A）。
- **知识来源（Source）**：企业文档的逻辑身份，**按 `project` 归属**并带状态；schema 无独立的调用方 / ACL 列，可见性由绑定派生的集合 ACL 与调用方 scope 交集决定（见 Clarifications 2026-10-30）。
- **文档版本（Document Version）**：一次摄取产生的不可变切块集合（`kb_document_versions`），同一 `content_hash` **不**产生新版本；它**不是**索引代际。
- **索引代际（Index Generation）**：`kb_index_generations` 定义的 embedding 模型 / 维度 / 距离组；同一时刻至多一个 `active`，检索按生效代际进行；本 US 只有代际 1（精确扫描）。
- **切块（Chunk）**：检索与引用的最小单位，带向量表示与定位信息。
- **引用（Citation）**：指向切块的定位（文档 / 版本 / 切块），区分「可定位」与「被支持」。
- **记忆条目（Memory Entry）**：带六态生命周期、作用域、生效层与有效头的记录。
- **历史消息（Message）**：会话内按顺序的权威原文；检索命中只返回其指针。
- **调用方（Caller）/ API Key / 配额周期**：身份主体、作用域凭据（仅存指纹）与用量窗口。
- **迁移包（Migration Package）/ 清单（Manifest）**：导出载体及其哈希、行数与责任记录。
- **实例身份（Instance Identity）/ 主密钥记录**：实例可启动性的权威凭据，与数据库迁移分离交接。
- **压缩摘要（Compaction Entry）**：覆盖区间、切点、策略与提示版本、来源引用与失效标记。
- **诊断事件（Diagnostic Event）**：步骤级结构化记录，局部有序，可采样丢弃。

## Success Criteria *(mandatory)*

- **SC-001**：新实例在无 SQLite 的情况下可完成启动、对话、工具调用与知识检索全流程；缺少数据库或扩展能力时启动**拒绝**并给出原因（可机器判定）。
- **SC-002**：迁移演练在代表性数据集上**逐表**行数 + 主键集合全等、关键字段（二进制 / 时间 / 大整数）**逐值**比对一致率 100%；**不**以抽样通过代替逐表核对，不设抽样放行。
- **SC-003**：被拒绝的准入请求**零**占用并发名额与运行名额（压力脚本可判定，重复 3 轮结果一致）。
- **SC-004**：跨调用方越权访问 100% 返回「找不到」，且响应体不泄露目标存在性。
- **SC-005**：撤权 / 删除后，检索、注入与后续摘要中出现该正文的次数为 0（固定语料回放可判定）。
- **SC-006**：长会话触发压缩后，原始消息仍可逐条回查；每个 committed 摘要条目的覆盖区间与原始消息顺序一致、相邻条目首尾衔接（无缺口 / 无重叠），同一输入重复装配的投影逐字相同，断链 / 缺口时给出固定 `reason_code` 而不是静默注入（具名用例可判定）。
- **SC-007**：诊断查询在无记录时 100% 区分 `missing` 与 `sampled_out`；存储与查询投影零凭据泄漏（模式扫描判定）。导出及其断点恢复不在本 US 范围（归 US-16A（拟）OBS），本 US 不承诺。
- **SC-008**：全部新增与既有判据在 `make check` 七目标上全绿；**`make check` 依赖 PostgreSQL**——`test-integration` 与 `make cover` 在缺 `BASALT_TEST_PG_DSN` 时**失败而非跳过**（D-01 已批准判据面，见颗粒度文档 §4.7），PG 专项 stage 同样全绿。无库环境**不得**以跳过、tag 隔离或降级为 SQLite 换取绿态。

### 迁移资产与静止窗口（FR-090～FR-094，来源 §2.11.5 / §2.11.6 / §2.13）

- **FR-090**: 迁移**必须**产出与数据库清单**配对**的文件资产清单（`assets.json`）：以 `<WorkDir>/.basalt` 为工作区根，逐文件登记 `RelPath` / `Class` / `Kind` / `Size` / 平台权限字段 / SHA-256 / `RequiredFor`；路径**必须**是相对正斜杠路径，拒绝绝对路径、盘符、UNC 与 `..` 段，逐段 `Lstat` 拒绝符号链接、联接点与硬链接；数据库文件、运行期状态（锁 / 名册 / 日志）、密钥与令牌、通用敏感项（`.env*` / `*.clixml` / `dev-env/secrets/` / `.git/`）**必须**排除。**不得**拿仓库 `examples/**` 代替已安装实例的实际工作区。
- **FR-091**: 未命中业务白名单也不命中排除清单的普通文件**必须**标 `class=unclassified` 先入受限核查区（`review/`）；存在未归类文件时**不得**产出可交付包；操作者逐条 `include` / `exclude` / `handoff`（后两者必填原因）并 `--seal` 后才生成，`exclude` / `handoff` 条目**必须**留在最终清单可对账（缺条目 / 摘要不符 / 决定非法 → `unclassified_unreviewed` 拒绝）。
- **FR-092**: 导出**必须**在静止窗口内完成：`serve` 已停且进程退出、无残留 MCP 子进程与在途 Run、持 `<ws>/basalt.lock`（取不到 → `workspace_busy`）；同一窗口内盘点 A1 → `VACUUM INTO` 快照 → 盘点 A2，逐项相等才产出清单，否则 `assets_changed_during_capture`（**不得**取较新的一份）；源库身份以 `basalt.db` 尺寸 + SHA-256 为必需，`-wal` 同窗口记录，`-shm` 只记存在性；切换前**必须**重盘 A_cut 与源库身份，不符 → `source_changed_since_snapshot`；打包后**必须**对打包产物重算哈希，不符 → `packaged_digest_mismatch`。**限度必须写明**：两次盘点一致不证明窗口内「改后又改回」，也不覆盖锁外写者。
- **FR-093**: 两份清单**必须**共用绑定字段（`migration_batch_id` / `source_instance_id` / `source_instance_id_origin` / `source_snapshot_sha256`）；导入 / 切换前三元组逐字比对，任一不等即拒绝（`batch_mismatch` / `instance_mismatch` / `snapshot_mismatch`），**不得**取交集或合并；`source_instance_id_origin` 只取 `roster` 或 `adopted_without_roster`，**不得**把采纳说成原生。
- **FR-094**: 迁移验收**必须**按五个内置 Agent 逐项核对（定义与状态 / 模型连接 / MCP 定义与版本 / 技能 / 定时任务 / 会话与历史 / 工作区资产 / 外部依赖 / 凭据 / 业务验证），五层（L1 数据导入 → L2 资产完整 → L3 依赖与凭据就绪 → L4 连接可用 → L5 业务任务成功）缺一层即未完成；未安装 / 已停用的 Agent **必须**在清单写明状态，**不得**从清单消失；组件版本以实读为准，**不得**用「目录存在」代替版本核对；未授权或凭据不可验证时**必须**标「未验证」，**不得**用假成功填充。

### 旧定时任务授权与启动期补齐（FR-097～FR-099，来源 §2.14 / §2.16）

- **FR-097**: 运行期管理姿态只有 `token` 与 `local_trust` 两种合法状态（`unavailable` 仅在测试注入下可达），非法配置**必须**在监听前拒绝启动；`admin-builtin` 任务（`caller_id='local-admin'`、`authorizing_key_id IS NULL`）在两种姿态下**都有权运行**——`local_trust` **不得**被当作「认证关闭」；`caller-key` 任务**必须**按绑定的那一把 Key 重读状态与 scope，Key 撤销 / 过期 / scope 不足 / 调用方禁用即 `owner_unauthorized`（缺 Key 行 → `key_missing`）fail-closed，**不得**借用同调用方另一把 Key，**不得**借用进程的管理能力。迁移**必须**把旧任务填成 `local-admin` + `admin-builtin` + 空 `authorizing_key_id`，**不得**补一个「看起来能用」的 caller key，**不得**改变管理认证模式。
- **FR-098**: 管理台**必须**提供五类视图并接入既有鉴权：知识（集合 / 文档 / 版本 / 失败处理 / 来源与引用）、调用方（Key 一次性明文 / 限额 / 用量与拒绝原因 / pending 预留核对 / `overage` 核对并清零必填理由）、历史（按时间 / Agent / 调用方 / 关键词回查，**列表结果只是指针**，点开走精确读取显示原文与 `version_id`）、压缩（**只读**展示 `compaction_id` / 覆盖区间 / 切点 / 策略与提示模板版本 / 模型与用量 / `decision` 与原因码，**不提供**手动触发）、诊断（按 `run_id` / `session_id` / 时间窗查看，缺记录显示 `missing` 证据缺口）。权限**必须**由服务端判定，**不得**靠隐藏按钮实现。
- **FR-099**: 启动期 `BackfillEnvSources` **必须**保留为每次启动的幂等补齐：只补「已发布槽位无来源行」，已迁移来源行**不得** UPDATE / 覆盖；只记 `mode=env` 与变量名，**不得**读取 / 记录 env 值，**不得** managed → env 回落，**不得**改变任何授权；补记**不**设置 `first_write_at`、不产生外部副作用，回退前的行数对照**必须**排除补记行；失败按启动期既有规则处理，**不得**静默跳过整轮。
