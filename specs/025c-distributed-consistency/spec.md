## User Scenarios & Testing

### User Story 1 - 发布即分发：已发布资产在所有 Worker 自动生效 (Priority: P1)

运维在 A 控制台修改某个 Agent 的正文与一项配置（如通知渠道绑定）并发布。数据库写入一次载荷与指针后，各 Worker 在下一次发现检查中有界拉取、校验并安装到本机资产目录，技能同步物化到本机发布版本目录；新 Run 使用新版本，且 Entry、定义与技能来自同一份固定 bundle。此前已启动的在途 Run 继续用旧版本跑完。同步失败时旧版本继续服务，新版本准入被拒并给出可见原因；恢复后自动补齐，不需要手工重导种子，也不需要重启进程。

**Why this priority**: 这是本模块的存在理由——今天的「数据库权威」只在控制面成立，Worker 仍靠旧副本，五组缺口都由此暴露。没有自动分发，其余修复只是局部补丁。

**Independent Test**: 在两端进程共用一个数据库的夹具中发布一个 Agent 新版本，断言两端安装哈希与指针一致、后续 Run 的资源清单记录同一哈希、在途 Run 仍记录旧哈希；破坏载荷后断言新 Run 被拒而旧版本在跑任务完成，恢复后未安装实例重新尝试；断言同步前后种子与运行数据哈希不变。

**Acceptance Scenarios**:

1. **Given** 一个已发布且两端已同步的 Agent，**When** 控制面修改正文与一项配置并发布，**Then** 载荷先于指针写入；各 Worker 安装新版本并在下一次完整处理轮次后就绪；两端后续 Run 使用同一新哈希且实际生效的配置值与本次发布一致。
2. **Given** 某 Agent 的长任务在发布前启动，**When** 发布并同步新版本，**Then** 该 Run 始终按旧 bundle 的 Entry、定义与技能执行到结束。
3. **Given** 某哈希的载荷缺失或损坏，**When** Worker 尝试同步，**Then** 该条目保持旧已安装版本、标记阻塞原因，新 Run 准入被拒；恢复后尚未安装该哈希的实例在后续轮次重新尝试。
4. **Given** Worker 工作区含种子业务状态与运行数据，**When** 多轮同步完成，**Then** `state/`、`runs/`、`agents/`、工作副本技能目录的哈希不变。
5. **Given** 存量库在升级前已有发布指针但无载荷，**When** 控制面启动执行回填，**Then** 目录自洽的存量指针补齐载荷；缺失或损坏项逐条报告为 `payload_missing` / `corrupt`，不伪造、不写空载荷、不移指针。

### User Story 2 - 管理台已改、Worker 生效：五组一致性缺口收口 (Priority: P1)

运维发现四类策略（允许域、拒绝域、网络例外、执行档位）、Agent 启用状态、新发布的技能、新增模型连接与 MCP 在管理台改完后，Worker 上要么不生效、要么要重启才生效、要么被旧进程回写覆盖。交付后：策略按数据库一致快照刷新；生命周期以数据库索引为准；技能发布联动重发依赖 Agent，并物化到各 Worker；资源准备先于注册，版本与凭据未变化时不发生周期性断连；Worker 不再执行任何共享初始化写入。

**Why this priority**: 五组缺口是「管理台已改、Worker 不生效」的直接原因，与自动分发共同构成一致性闭环；任何一组遗漏都会让用户重新回到「重导种子」的老路。

**Independent Test**: 逐组构造管理台变更并在 Worker 侧观察：策略删除例外在下一轮被发现；停用 Agent 后调度门与准入同时拒绝；技能发布后依赖 Agent 在运行期下一轮修复且 L1/L2 可读；新增 Provider / 已 applied MCP 不重启即可用于后续 Run，未 applied 的 MCP 不被隐式应用；Worker 启动不写共享定义列、不重建绑定投影、不建知识代际但保留知识检索能力。

**Acceptance Scenarios**:

1. **Given** 四类策略在管理台被修改或删除，**When** 下一刷新周期执行，**Then** 各服务只按本轮实际应用的快照计算摘要，新增、修改、删除、同内容不同版本号与同毫秒变化都被发现；长期无变化不误判过期；读失败时准入返回 `POLICY_STALE`（503）。
2. **Given** 某 Agent 在管理台被停用，**When** Worker 的调度门与 Run 准入判定，**Then** 两者都以数据库生命周期索引为准，无索引行才回退本地状态文件。
3. **Given** 一个被多个 Agent 引用的技能发布新版本，**When** 技能发布成功，**Then** 依赖 Agent 被联动重发；锁内复核的当前技能版本在发布前再次确认，晚到的旧版本结果为 `superseded` 且不覆盖新版本；失败项由控制面技能修复器在后续轮次有界重试，连续失败转 `blocked` 并由下一轮全量扫描复位；Worker 不发起重发。
4. **Given** 新增模型连接或已 applied 的 MCP，**When** Worker 完成下一轮资源准备，**Then** Agent 不重启即可注册并在后续 Run 中使用；版本与凭据代次均未变化时不发生 `seal` / `Close` / `Connect` / `epoch++`；凭据轮换触发一次受控重建；未 applied 的 MCP 不被隐式应用。
5. **Given** Worker 以旧种子启动，**When** 启动链执行，**Then** 共享定义列不倒退、绑定投影不被重写、MCP applied 指针不被改写、知识代际不被创建；领取推进 `next_fire_at`、`last_run_at` / `last_status`、执行行、租约与心跳等协调写入照常保留。
6. **Given** Worker 上的知识绑定 Agent 执行，**When** 检索、来源校验、embedding 与 `recall_memory` 被调用，**Then** 能力可用；控制面尚未创建 active 代际时失败关闭并点名先由控制面初始化。

### User Story 3 - 领取与准入：固定版本贯穿整条执行链 (Priority: P1)

调度扫描在持续高频到期、前 N 条任务长期未就绪、整页任务尚未初始化、同步刷新穿插扫描等情况下，仍能在一圈有界扫描内考察到后续健康任务并重新发现恢复任务与新增行。触发被领取的那一刻在事务内钉住 bundle 版本；Run 准入凭领取记录与执行租约复核，Entry、定义与技能都取自同一固定 bundle；领取后暂停、租约被接管或自然过期的旧 Worker 恢复后不能创建新 Run。

**Why this priority**: 这是「旧版本继续可用」与「新版本不会丢触发」的正确性根基；扫描公平与执行权判定任何一处错误都会造成永久饥饿、触发丢失或双版本混用。

**Independent Test**: 构造前 N 条不可领取、整页 NULL 初始化失败、持续高频到期、同步刷新穿插长扫描与圈中途到期五类场景，断言健康任务与恢复任务在有限拍数内被考察或领取；构造领取后发布同步、伪造领取记录、租约被接管与自然过期四类场景，断言 Run 用钉住版本跑完或被拒且零写入。

**Acceptance Scenarios**:

1. **Given** 前 N 条任务持续未就绪或持续返回版本已移动，**When** 调度扫描推进，**Then** 同一圈边界内已到期的第 N+1 条健康任务被考察并领取，不因前缀占满批次而饥饿。
2. **Given** 一整页任务的初始化持续失败或整页 `next_fire_at` 为空，**When** 扫描推进，**Then** NULL 段游标照常前进，同拍剩余容量取非 NULL 段，后续健康任务不被挡住。
3. **Given** 持续有任务每秒到期，**When** 扫描运行固定拍数，**Then** 冻结边界内的行被走完、一圈结束并开新圈；期间恢复的任务与新增 NULL 行被下一圈重新考察；圈中途到期的行归下一圈，不延长本圈。
4. **Given** 扫描进行中发生同步刷新或注册集合替换，**When** 集合被替换，**Then** 扫描游标与本圈边界不被清空，只有调度启动清空。
5. **Given** 到期触发在查就绪与领取之间被新发布抢先，**When** 领取事务执行，**Then** 指针缺失 / 移动导致零写入：不写执行行、不推进 `next_fire_at`；越过宽限的未就绪触发如实记 missed 并推进，不延长宽限、不补跑。
6. **Given** 一次触发已被领取并钉住旧版本，**When** 发布并同步新版本后 Run 准入，**Then** Entry、定义与技能均来自旧固定 bundle，Run 用旧版本跑完。
7. **Given** 伪造的领取记录、租约被回收器接管（epoch+1）或租约自然过期，**When** 旧 Worker 尝试准入，**Then** 返回 `ASSET_UNAVAILABLE`（503）、零新 Run、零业务调用；`Pin == nil` 的普通 Run 仍按当前指针判定，不被放宽。

### User Story 4 - 概览节点状态：按进程实例的只读三态读数 (Priority: P2)

运维打开概览「分布式执行」面板，看到的不再是几十行历史登记和「N 个 Worker」。面板按进程实例显示服务端计算的心跳正常 / 心跳超时待确认 / 已停止三类计数（全库聚合），明细有界、排序为正常→超时→停止，超出显示「当前展示 X 条，共 Y 条」；名称、宿主、构建版本、schema 版本、心跳年龄与租约数进详情折叠区。读取失败显示「状态不可用」并标注上次读数已过期，不渲染成 0。心跳与状态只作显示，不参与准入、调度或租约接管。

**Why this priority**: 这是用户直接提出「37 个 worker 我看不懂」的可用性缺陷；它是只读诊断，不改变执行语义，但决定运维能否正确判断集群状态。

**Independent Test**: 造 250 行登记含同名不同实例、三种状态混排与 limit=200，断言计数来自全库、明细恰 200、排序与截断正确、同名不合并；注入偏差时钟与读取失败，断言状态仍按服务端字段渲染、失败显示不可用；断言页面无管理动作与禁语。

**Acceptance Scenarios**:

1. **Given** 同一 `worker_name` 的两个 `instance_id`，**When** 读取概览，**Then** 返回两行、不合并不推断服务器数量。
2. **Given** 一行心跳超时但 `stopped_at` 为空，**When** 渲染，**Then** 状态为 `stale`（待确认），不出现在已停止组，也不显示成 0。
3. **Given** 库中 250 行登记、明细上限 200，**When** 读取概览，**Then** 三类计数按全库聚合、明细 200 行、`truncated` 为真、`total` 为 250，且计数与明细来自同一条语句的同一快照。
4. **Given** 明细上限截断或读取失败，**When** 面板渲染，**Then** 截断文案如实；失败显示「状态不可用」并标注过期，不补 0。
5. **Given** 两行心跳间隔分别为 10 秒与 60 秒，**When** 同一时刻收到心跳，**Then** 各行按 `max(3 × 心跳间隔, 30 秒)` 独立判定状态；迁移前旧行用部署默认并在详情标注。

### Edge Cases

- 两件发布在同一毫秒提交：增量发现必须让每行只读一次，游标在服务端严格前进；迟到提交与撤回由下一次完整全量扫描覆盖。
- 全量扫描中途进程退出：不删除任何缺席项；下一轮从保留的进度继续，整趟完成后才逐项回读确认移除。
- 载荷超限、路径穿越、符号链接、非普通文件：解码零落盘并返回明确错误；发布失败时载荷表零行、指针不变。
- 同步中途崩溃在安装与注册之间：下一轮发现目录已存在后重做物化与 Entry 构建并注册，不永久漏注册。
- 集合替换成功但调度替换失败：条目退回已安装状态下一轮重做两步替换，不需要重启。
- 管理面在扫描圈内直接重写 `next_fire_at`：有限次回写只在下一圈收敛；持续回拨使终止性不成立，属于超界场景而不是正常输入。
- 数据库时钟回拨：圈长上界不成立，按运行环境故障处理，不宣称仍然有界。
- 通知渠道定义、Demo 本地业务状态、Flow 推进：属于产品边界，不冒充本模块已修复。
- 概览读取失败：显示不可用并保留过期标注，不显示成 0 或全部已停止。

## Requirements

### Functional Requirements

- **FR-25C-01**: 发布必须先写入载荷再移动指针；载荷写入失败时指针不变、操作终态为失败并可见。
- **FR-25C-02**: 同哈希发布也必须核对载荷存在；缺失时补写载荷而不移动指针，实现真正的幂等。
- **FR-25C-03**: 迁移 0013 必须幂等且只追加：建立载荷表；为 Worker 登记加可空心跳间隔列并带正数约束；为资源指针加 `(kind, updated_at, resource_id)` 索引；为执行行加可空固定版本哈希列；支持 schema 版本改为 13；时间列由应用写入毫秒值，不使用数据库默认值。
- **FR-25C-04**: 载荷编解码必须确定性且可拒绝：路径排序、固定权限、零修改时间、不跟随符号链接；解码拒绝绝对路径、`..`、符号链接、非普通文件与超限；解码后复算哈希必须与期望一致。
- **FR-25C-05**: 升级必须为存量已发布指针回填载荷；只接受目录自洽（哈希与记录逐字相等）的来源，先验证目录再编码；缺失或损坏逐条报告为 `payload_missing` / `corrupt`，不伪造、不写空载荷、不移指针、不因回填发布新版本。
- **FR-25C-06**: 同步工作集必须有界、可恢复、轮转公平：四态 `pending` / `installed` / `ready` / `blocked`；已安装不等于就绪；失败项留在工作集并按尝试序号退到队尾；单轮有总量超时；上一轮未完成不叠加；停机等待在关闭数据库之前完成。运维通过只读 `basalt assets status` 逐 Agent 观察指针哈希、已安装哈希、载荷存在性、技能物化与阻塞原因；同步由后台循环自动重试，不新增手动触发命令。
- **FR-25C-07**: 技能必须物化到本机发布版本目录并逐文件核对哈希，每轮无条件执行（含安装复用分支）；不得回落到工作副本；失败即该 Agent 未就绪，不静默降级。
- **FR-25C-08**: 运行期必须固定已安装版本：领取事务内钉住 bundle 哈希并写入执行行；Run 准入按领取记录与执行租约（owner / epoch / 未释放 / 未过期）在同一事务、固定锁序内复核；Entry、定义与技能都取自同一固定 bundle；在途 Run 不因同步切版本；伪造领取记录一律拒绝，且不新增契约错误码——普通与手动 Run 仍返回 `ASSET_VERSION_MISMATCH`（409），钉住路径的领取记录或租约不符返回 `ASSET_UNAVAILABLE`（503）。
- **FR-25C-09**: 同步不得覆盖种子工作区与运行数据；写入面白名单只有资产目录的 bundle 子树与工作区的发布版本目录；`state/`、`runs/`、`agents/`、工作副本技能目录在同步前后哈希不变。
- **FR-25C-10**: 注册表与调度集合必须同轮、固定顺序刷新：运行期新增 Agent 不重启即可被下一轮扫描领取；缺失项只从本进程内存移除，不退休或删除共享库任务行；发现游标必须是能前进的复合键集（`updated_at, resource_id`），同毫秒多行每行只读一次；全量兜底扫描只在整趟完成后经回读确认移除缺席者，中断不删除任何项。
- **FR-25C-11**: 到期触发必须有就绪门与扫描公平：未就绪不领取、不推进 `next_fire_at`、不写执行行；越过宽限的未就绪如实记 missed 并推进；领取事务内钉住版本，指针缺失或移动作零写入结局；到期扫描必须两段键集轮转且每圈有冻结的有限边界（开圈一次只读取数据库时间与 NULL 段上界），NULL 段与非 NULL 段各自前进，首屏不得拿 NULL 做元组下界，两段都到达本圈边界才算一圈，只有调度启动清空游标与边界；持续高频到期仍能结束一圈并重新发现恢复任务与新增 NULL 行。
- **FR-25C-12**: Worker 不得执行共享初始化写入：逐项跳过基线回填、管理操作回填、定义协调、启动绑定重建、MCP applied 写、密钥初始化、策略种子写、开箱安装、本地资产补建、调度定义列写、MCP 来源补记、学习回填与知识代际初始化；只保留只读装配，缺策略行或缺少 active 代际时失败关闭并点名先由控制面初始化；Worker 的知识绑定 Agent 仍须能检索、校验来源、使用 embedding 客户端与 `recall_memory`。
- **FR-25C-13**: 合法执行协调写入必须保留：领取推进 `next_fire_at`、`last_run_at` / `last_status`、执行行、租约与心跳、Run 与审计行照常写；旧 Worker 重启不得让共享定义列倒退。
- **FR-25C-14**: 生命周期判定必须索引优先：读数据库生命周期索引，无索引行才回退本地状态文件；停用后不再执行。
- **FR-25C-15**: 四类运行期策略必须一致快照刷新：各服务持自己的锁读表、应用，并只用这份实际应用的行计算子摘要，组合成应用摘要；不得使用 `max(updated_at)` 或发现阶段另一次读的摘要；新增、修改、删除、同内容不同版本号与同毫秒变化都必须被发现；刷新单飞。
- **FR-25C-16**: 策略过期判定必须使用最近一次成功核对时间，与内容版本分开：内容长期不变不得误判过期；读失败才推进过期并在准入返回 `POLICY_STALE`（503）。
- **FR-25C-17**: 技能发布必须联动重发直接依赖的 Agent：锁内复核 Agent 指针与技能当前已发布版本，发布前再次确认；晚到的旧版本不得覆盖新版本（`superseded`）；不得从工作副本重建；发布请求内不重试，逐 Agent 结果可见；`failed` / `missing` / `superseded` 由控制面技能修复器在后续轮次有界重试，连续失败转 `blocked` 并由下一轮全量扫描复位；Worker 不得发起重发。
- **FR-25C-18**: 资源准备必须先于 Entry 构建与注册：逐条构建已发布 Provider（失败隔离、点名），MCP 只对已 applied 的连接做只读凭据解析与准备；已连接且版本与凭据代次相符且连接仍 live 时零副作用复用，版本或凭据代次不符才受控重建；重建按三段锁序，换入前在同一临界区复核目标版本与凭据仍有效，复核失败则 `superseded` 不换入；既有管理 apply 保持事务校验及 CAS 成功后立即换入、不插入提交后复核；Entry 判定只读本轮资源快照，不读实时目录；未 applied 的 MCP 不隐式应用。
- **FR-25C-19**: 新增模型连接与 MCP 必须在 Worker 日常链路生效（不重启），以真实链路验收承载。
- **FR-25C-20**: 变更到数据库再到 Worker 生效路径的判据表中，每个修复行都必须有具名测试，边界行必须有守护断言或明确不测理由。
- **FR-25C-21**: A+B 真实链路验收必须覆盖：管理台修改并发布、两端分别执行后续定时任务、两端版本哈希与实际配置值一致，不能只看文件复制成功。
- **FR-25C-22**: 失败与恢复必须分两个场景验证：载荷读取故障（只破坏载荷、不动数据库）与数据库中断；恢复后未安装该哈希的实例重新尝试，已就绪条目不读载荷；不得把「重导种子」当恢复手段，只能靠它恢复即计为未通过。
- **FR-25C-23**: 未知业务调用不得自动重放：恢复后未确认副作用的调用计数不翻倍。
- **FR-25C-24**: 网站文案必须更新到 US-25 内容：能力与范围注列出未交付项（K8s、数据库 HA、跨节点业务状态共享），不得宣称未交付能力，不得出现未验证声明。
- **FR-25C-25**: 网站系统架构与部署图必须重绘（双语 SVG、PNG 渲染件与可编辑源），页数保持 12，检查器通过。
- **FR-25C-26**: CLI 演示动画必须改用真实的定时触发演示命令，并与站点断言同源。
- **FR-25C-27**: 官网导航 Demo 必须指向部署实例的 `/console/`，链接检查器允许清单只放行该地址。
- **FR-25C-28**: 产品简介与六项能力文案必须与已交付内容一致，能力项证据指向存在的文件。
- **FR-25C-29**: 必须交付四个 US 专属 stage（base / sync / fault / docs）与配置解析：`assets` 的同步间隔、单轮超时、批量、载荷上限、全量扫描周期与 `policy` 的刷新间隔、过期阈值均可被严格解析；默认值为 `30s` / `20s` / `50` / `16777216` / `20` 与 `30s` / `300s`，同步间隔 `0` 表示只在启动时同步一次；定向 stage 全绿后冻结代码，再运行一次全量门禁。

### Key Entities

- **已发布 bundle 载荷**: 内容寻址的不可变归档，代表一次已发布的 Agent 定义与配置；同一哈希只存一份；没有自动清理入口。
- **已发布 bundle 指针**: 数据库中的权威版本指针，决定 Worker 应安装哪一份载荷；发布先写载荷后移指针。
- **技能版本记录**: 已发布技能的不可变文件清单与存储位置，供物化与联动重发使用。
- **同步工作项与就绪记录**: 每个 Agent 的目标哈希、已安装哈希、四态、尝试序号、失败计数与阻塞原因，是领取前就绪门的输入。
- **执行行与执行租约**: 领取事务写入的执行载体与执行权凭证；固定版本哈希写在执行行上，执行权由租约 owner、epoch、释放状态与过期时间判定。
- **策略快照摘要**: 四类策略在本轮实际应用后的内容摘要，用于发现变化并判定过期。
- **Worker 登记行**: 进程实例的登记日志，记录名称、宿主、构建版本、schema 版本、心跳间隔、最近心跳与停机时间；统计对象是实例而不是服务器。
- **节点状态读数**: 三类全库计数、活跃租约数、有界明细与 `as_of`，由同一次查询同快照返回。

## Success Criteria

### Measurable Outcomes

- **SC-25C-01**: 在双实例夹具中发布一个 Agent 新版本后，两端安装哈希均等于指针哈希，两端后续 Run 记录同一版本哈希且实际配置值与发布一致；在途 Run 始终记录旧哈希。
- **SC-25C-02**: 载荷故障或数据库中断恢复后，系统可在不重导种子、不重启进程的条件下自行收敛；已就绪条目不因载荷故障被降级。
- **SC-25C-03**: 技能发布后，直接依赖它的 Agent 全部在运行期后续轮次修复完成并可读取 L1 / L2，无需重启控制面；乱序发布不产生版本倒退。
- **SC-25C-04**: 概览面板显示的三类计数与真实进程实例一致，历史登记行不冒充运行实例；明细超过上限时如实给出「当前展示 X 条，共 Y 条」；读取失败不显示 0。
- **SC-25C-05**: 判据表中每个修复行都有具名测试或明确边界守护；前 N 条持续不可领取或持续失败时，第 N+1 条健康任务在有限圈或下一轮内被执行。
- **SC-25C-06**: 四类策略的新增、修改、删除与同毫秒变化在下一刷新周期被检出；内容长期不变连续十个周期不误判过期。
- **SC-25C-07**: 未确认副作用的业务调用在恢复后计数不翻倍；伪造领取记录与接管后的旧 Worker 均零新 Run、零业务调用。
- **SC-25C-08**: 四个专属 stage 与一次全量门禁全部通过，证据绑定当前源码指纹；无新增依赖坐标。

## Assumptions

- A / B 两宿主运行含本模块的候选构建；PostgreSQL 是共享运行时权威；分发介质为数据库载荷表，不引入对象存储。
- `sync_interval` 只定义发现检查频率，不就绪时限；实际就绪受批量轮转、扫描续跑与失败退避影响。
- SQLite 源库不参与调度，不实现带钉住的领取。
- 五组缺口目前是静态复核结论；A+B 复现结果写入 run-state，未复现前不写成「已验证故障」。
- 真实模型调用与真实 webhook 未授权；自动 CI 一律不得调用真实模型。
- 网站构建按 `.nvmrc` 声明版本；本机不可用时登记未验证，不降引擎声明。
- 载荷按内容哈希去重但不会自动清理，存储增长是登记在案的已知缺口；文档与报告不得宣称存储有界。
- `worker_nodes` 历史登记行不在本模块清理。

## Dependencies

- US-25 已交付的 Compose 多 Worker、数据库权威与停机 join。
- US-24 已交付的执行租约与 fencing。
- 既有资产构建 / 安装 / 解析 / 校验、PostgreSQL 仓储、生命周期索引、MCP 监督器、Provider 目录与 Run 准入。
- 既有契约文件与运维文档；本模块只追加，不改写历史结论。
