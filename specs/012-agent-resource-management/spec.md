## User Scenarios & Testing *(mandatory)*

### User Story 1 - Agent 创建、作者草稿与多文件提交 (Priority: P1)

运维在管理台新建 Agent：输入名字与一句描述，作者模型起草 `AGENT.md`，页面内能看到并修改正文；提交创建后目录落盘、默认停用、代次为 1、定时任务为空；显式启用后通过 HTTP 立即跑通。创建过程任一步失败都不留 staging 残骸或半截目录；同名再创建与非法名被明确拒绝。页面上看到的文件集合与磁盘一致——每次写入后重新读取，不做乐观更新。

**Why priority**: 这是"页面上三分钟上新一个 Agent"的核心链路，也是本模块全部写面的第一条端到端验证。创建失败若残留目录，加载器会把半成品当成真 Agent，后续故障难排。

**Independent Test**: 在管理台用模板与一句话草稿各创建一个 Agent，检查目录、状态文件与注册结果；用同名、含 `/` 与 `..` 的名字重复创建，确认 400 且零残余；提交一组受管文件并检查未列出文件被保留；注入作者模型未配置与预写失败两种故障，确认 503 / 500 且磁盘零变化。

**Acceptance Scenarios**:

1. **Given** 已发布 Provider 与已配置作者模型，**When** 在新建页输入名字与描述并请求草稿，**Then** 返回草稿正文与文件集合视图，页面可编辑；草稿不落盘、不注册。
2. **Given** 编辑完成的 `AGENT.md` 与受管文件集合，**When** 提交创建，**Then** 返回 200，目录出现且内容与提交一致，生命周期为 `disabled`、`generation=1`、`schedules` 为空。
3. **Given** 已存在的 Agent 名或非法名，**When** 创建，**Then** 返回 400 并点名冲突原因，磁盘与生命周期状态零变化。
4. **Given** 作者模型未配置，**When** 请求草稿，**Then** 返回 503 `NOT_CONFIGURED`，不写模型调用审计之外的内容。
5. **Given** 管理操作预写失败，**When** 创建，**Then** 返回 500 且不出现目录、暂存目录或临时文件。

### User Story 2 - 公共资源版本化发布与失败保旧 (Priority: P1)

运维在资源页新增或修改模型连接：填写名称、`base_url`、默认模型与 `${ENV_VAR}` 凭证占位，保存并发布。发布成功后新 Run 立即使用新映射；若 `base_url` 非法或环境变量缺失，保存被拒，定义文件与发布指针零变化，在跑 Run 继续用旧映射。撤回旧版本不是回滚指针，而是用旧内容创建一个新版本再发布，历史版本永不改写。两个人同时保存时，后写者带陈旧 ETag 会被 412 拒绝，磁盘零写入。

**Why priority**: 公共资源的版本账是本模块的第二条价值主线；没有它，"配置改坏了能不能退回去"无法回答，发布失败还会把在跑业务切断。

**Independent Test**: 新增模型连接并发布，检查版本列表与发布指针；用非法 `base_url` 与缺失环境变量各发布一次，确认 400 且文件哈希与指针不变；发布旧版本 ID，确认新版本号递增且来源版本正确；用陈旧与缺失 `If-Match` 保存，确认 412 且零操作行。

**Acceptance Scenarios**:

1. **Given** 有效的候选定义，**When** 发布不带版本号，**Then** 发布最新版本；若该版本已发布则幂等返回，不产生新版本。
2. **Given** 未发布的候选定义，**When** 保存并发布，**Then** 生成不可变版本、原子替换发布指针，并返回新版本视图。
3. **Given** 已发布版本 A 与 B，**When** 带 A 的版本号发布（撤回），**Then** 用 A 的内容创建新版本 C 并发布，返回 C 与来源版本 A，历史版本不被改写。
4. **Given** 候选校验或运行时构建失败，**When** 发布，**Then** 操作置 `failed` 并返回错误，旧定义文件与旧发布指针保留，新 Run 仍用旧映射。
5. **Given** 缺失、弱比较、`*` 或与当前发布版本不匹配的 `If-Match`，**When** 修改 / 删除 / 发布，**Then** 返回 412 并给出当前 ETag，磁盘零写入且不产生操作行。
6. **Given** 两个并发保存携带同一 ETag，**When** 同时提交，**Then** 恰好一个成功，另一个 412。

### User Story 3 - 发布—准入一致、启动对账与目录构建 (Priority: P1)

发布成功后，只有下一次准入的新 Run 使用新映射；已开始的 Run 继续使用准入时固定的旧映射。服务重启时，先对账定义文件与已发布版本：一致则直接构建，文件更新则按固定策略处理，版本更新或文件无效则明确记录，不静默覆盖。启动完成后，Provider 目录、MCP 集合与 Agent 注册表都来自已发布事实，MCP 连接在注册表之后、服务开放之前建立。

**Why priority**: 如果运行对象直接读配置文件，管理台的发布就只是"看起来生效"；如果启动顺序错乱，Agent 会在 MCP 未连接时被注册，运行期才炸。

**Independent Test**: 发布新版本后检查在跑 Run 与新建 Run 的映射差异；重启进程，核对对账日志与构建来源；让一个 MCP 发布成功但未重启，确认注册表与页面一致标"待重启"；重启后确认连接建立且应用版本追平。

**Acceptance Scenarios**:

1. **Given** 已发布映射 A 与在跑 Run，**When** 发布映射 B，**Then** 新 Run 用 B，在跑 Run 继续用 A，A 在最后一个引用释放前不回收。
2. **Given** 定义文件与已发布版本不一致，**When** 启动，**Then** 按"文件更新 / 版本更新 / 文件无效"固定分支处理并记录，不静默覆盖任何一侧。
3. **Given** 启动流程，**When** 开放服务，**Then** Provider 目录与 MCP 集合均由已发布版本构建，MCP supervisor 在注册表之后、服务开放之前启动。
4. **Given** 映射构建失败，**When** 发布，**Then** 旧映射保留且旧 Run 不受影响。

### User Story 4 - Agent 复制、归档与恢复 (Priority: P2)

运维把一个 Agent 复制成新名字：完整复制文件、改写名字与身份、清空定时任务、默认停用；失败零残余。归档一个空闲 Agent：目录移入工作区归档区，状态文件保留 `archived` 并递增代次，会话 / 记忆 / 审计不动；归档有长跑 Run 的 Agent 时等待有界，超时返回 409 点名运行并完整回滚注册表与定时。从归档恢复分原名与异名两条路径：原名恢复校验归档身份、状态与清单哈希，条件迁移并递增代次；异名恢复按新 Agent 引导为停用、代次 1。

**Why priority**: 归档是"下线但不删数据"的唯一安全出口；顺序或回滚做错会把 Agent 卡在注册表与目录不一致的状态。

**Independent Test**: 复制一个 Agent 并检查新名字、停用与空定时；归档空闲与长跑两个 Agent，检查目录、状态、归档记录与超时回滚；分别用原名与异名恢复，检查代次、状态与名字改写；注入 rename 失败，确认状态回退且归档行仍在。

**Acceptance Scenarios**:

1. **Given** 活动区 Agent，**When** 复制到新名字，**Then** 新目录完整、`name` 与 `identity.agent_name` 均改写、`schedules` 为空、状态 `disabled`。
2. **Given** 空闲 Agent，**When** 归档，**Then** 目录移入归档区且标识为 Agent 名加 UTC 时间戳，状态文件 `archived` 且代次递增，归档记录写入。
3. **Given** 有长跑 Run 的 Agent，**When** 归档等待超时，**Then** 返回 409 `AGENT_BUSY` 并点名运行；注册表与定时还原，状态与目录未动。
4. **Given** 归档身份与清单哈希有效，**When** 原名恢复，**Then** 回到原目录、状态由 `archived` 条件迁移到 `disabled` 且代次加一，`schedules` 清空。
5. **Given** 异名恢复，**When** 目标名合法，**Then** 新目录按停用、代次 1 引导；原归档 Agent 状态保持 `archived`。
6. **Given** 归档目标已存在，**When** 归档，**Then** 返回 409 且源目录原样保留，不自动换名。

### User Story 5 - 引用视图与受控删除 (Priority: P2)

运维想删除一个技能，但某个 Agent 的 `AGENT.md` 仍在 `skills:` 中声明它：请求返回 400 并点名引用者；若有未释放的运行引用，返回 400 并点名运行；解除引用后删除成功。版本历史仍可查询；同名重建后版本号继续递增。公共资源不提供强制删除开关；通知渠道保留显式的强制删除，但只在请求明确要求时生效。

**Why priority**: 没有删除闸门，删一个技能会让多个 Agent 在下一次运行时才失败；没有版本历史，排障时无法回答"当时用的是哪一版"。

**Independent Test**: 让一个 Agent 声明某技能后删除，确认 400 与点名；制造未释放的运行引用再删，确认 400 与运行标识；解除后删除并检查版本历史；重建同名资源并检查版本号。

**Acceptance Scenarios**:

1. **Given** Agent 定义引用某技能，**When** 删除该技能，**Then** 返回 400 并列出引用 Agent，文件与发布指针不变。
2. **Given** 有未释放运行引用，**When** 删除该资源版本，**Then** 返回 400 并点名运行。
3. **Given** 定义解析失败，**When** 删除，**Then** 按"可能引用"处理并拒绝，不静默放行。
4. **Given** 无引用，**When** 删除，**Then** 删除成功，版本历史仍可查；同名重建后版本号继续递增。
5. **Given** 通知渠道被任一 Agent 正文整词引用，**When** 删除且未带强制参数，**Then** 400 点名；带强制参数才删除。

### User Story 6 - MCP 双传输、授权与待重启 (Priority: P2)

运维登记一个 stdio MCP server 并发布：发布成功但页面明确标"待重启"、未连接；重启后若命令在允许清单内且策略放行，连接建立、应用版本追平。登记一个 HTTP MCP server 时按 HTTP 授权路径判定，不启动任何进程。两种传输的条件必填不同：stdio 必须有命令与参数，HTTP 必须有合法 URL 且不带凭证信息。测试端点先写管理操作，再发起一次有超时的连接与工具发现，不产生 Run、不写模型调用审计。

**Why priority**: MCP 是工具能力的入口；如果发布等于生效，运维会误以为连接已可用，运行期才暴露策略拒绝或地址不合法。

**Independent Test**: 分别发布 stdio 与 HTTP 两个 MCP server，检查"待重启"与连接状态；不重启的情况下测试两个端点，确认工具发现结果与无 Run；重启后检查应用版本与注册；让命令被策略拒绝，确认不启动进程且页面点名原因。

**Acceptance Scenarios**:

1. **Given** 新建 stdio MCP server，**When** 发布，**Then** 返回成功且 `pending_restart=true`、未连接。
2. **Given** 已发布未重启，**When** 重启服务，**Then** 策略放行则连接成功、应用版本追平；拒绝则保留旧应用版本并点名原因。
3. **Given** 已连接的 MCP server，**When** 调用测试端点，**Then** 返回延迟与工具列表，不产生 Run、不写模型调用审计。
4. **Given** HTTP 传输，**When** 测试或连接，**Then** 走 HTTP 请求授权与域名白名单，零进程；地址被既有规则拒绝时点名 IP 字面量或非默认端口，不放宽策略。
5. **Given** 发布版本与应用版本不一致，**When** 查看详情或注册 Agent，**Then** 明确标"待重启"；未应用或未连接的 MCP 不得被 Agent 引用注册。

### User Story 7 - 技能导入边界与不可变版本 (Priority: P3)

运维导入一个技能包：越界路径、绝对路径、隐藏目录、软链接、非普通文件、非 UTF-8、超限大小或文件数、大小写重复路径一律拒绝并点名，不执行任何脚本。合法导入后工作副本落盘，每次发布把完整文件清单复制到不可变版本目录；更新是全量替换，构建暂存后两次改名完成，失败回滚。校验端点与创建 / 导入 / 更新共用同一校验逻辑，只校验、不落盘、不写操作行。

**Why priority**: 技能包是外部输入，边界不严会把任意路径写进工作区；版本不可变是运行期冻结的前提。

**Independent Test**: 逐个构造越界、软链接、超限与大小写重复的导入，确认 400 且零落盘；合法导入后发布并检查不可变目录；调用校验端点检查零落盘；注入更新失败确认回滚。

**Acceptance Scenarios**:

1. **Given** 含 `../` 或绝对路径的导入，**When** 提交，**Then** 返回 400 `IMPORT_REJECTED` 并点名，不写任何文件。
2. **Given** 含软链接或非普通文件的导入，**When** 提交，**Then** 拒绝且不跟随链接。
3. **Given** 单文件超 256 KiB、总量超上限或文件数超限，**When** 导入，**Then** 拒绝并点名超限项。
4. **Given** 合法技能包，**When** 发布，**Then** 完整文件清单复制到不可变版本目录，工作副本继续可编辑。
5. **Given** 更新失败，**When** 全量替换回滚，**Then** 旧工作副本与旧发布版本保持原样。

### User Story 8 - 通知渠道 CRUD 与引用闸门 (Priority: P3)

运维新增通知渠道：可以只填名称与类型，地址先留空（暂不可发送），也可以填 `${ENV_VAR}` 占位；填明文地址被拒绝。列表只显示地址的主机名。更新时地址留空表示保留原值。删除前扫描全部 Agent（含归档）正文中的整词引用，被引用时返回 400 并点名，只有显式强制才删除。通知类型列表在所有读面与写面来自同一份有序定义。

**Why priority**: 通知渠道是凭证载体，明文地址落盘即泄密；引用扫描缺失则会静默打断已有 Agent 的告警。

**Independent Test**: 创建空地址与占位地址两个渠道，检查列表只回主机名；填明文地址确认 400；让 Agent 正文提到渠道名后删除，确认 400 与强制参数；更新地址留空确认旧值保留。

**Acceptance Scenarios**:

1. **Given** `url` 为 `${ENV_VAR}`，**When** 创建，**Then** 成功，列表只返回主机名。
2. **Given** `url` 为明文，**When** 创建或更新，**Then** 返回 400 且不写入。
3. **Given** 同名渠道已存在，**When** 创建，**Then** 返回 400。
4. **Given** Agent 正文整词引用渠道名，**When** 删除，**Then** 返回 400 并点名；带强制参数才删除。
5. **Given** 更新时 `url` 留空，**When** 保存，**Then** 原地址保留。类型列表在读写面完全一致。

### User Story 9 - 只读工作区浏览与管理台写面 (Priority: P3)

运维在管理台只读浏览 Agent 目录：不跟随软链接、不越出根目录、超过 256 KiB 的文件明确拒绝而不是返回半截内容，暂存与备份残留不可见。资源详情页显示版本列表、发布指针与引用，提供发布、撤回、删除入口；条件写返回 412 后页面重新读取 ETag 并保留输入。所有写操作完成后重新读取，不做乐观更新；认证过期、冲突与未配置三种失败有明确交互。新建页与资源详情页支持深链接刷新。

**Why priority**: 管理台是交付形态的一半；浏览器端若做乐观更新或危险渲染，会把服务端的条件写保证在界面上抹掉。

**Independent Test**: 用软链接与超限文件构造浏览请求，确认拒绝且无内容泄漏；在页面执行一次 412 冲突，确认重新取 ETag 且输入保留；直接打开新建页与资源详情深链接并刷新；检查构建产物与 Go 门禁不依赖 Node。

**Acceptance Scenarios**:

1. **Given** Agent 目录下的普通文件，**When** 浏览，**Then** 返回文件树与内容；隐藏暂存与备份残留。
2. **Given** 软链接或越界路径，**When** 浏览，**Then** 拒绝，不跟随链接。
3. **Given** 超过 256 KiB 的文件，**When** 浏览，**Then** 返回错误而非截断内容。
4. **Given** 陈旧 ETag，**When** 页面保存，**Then** 412 后重新读取并保留输入。
5. **Given** 四条新路由的深链接，**When** 刷新，**Then** 页面正常渲染；静态段排在动态段之前。

### Edge Cases

- 管理操作预写成功但目标写入前进程崩溃：启动恢复按动作查证，结果三分（已应用 / 未应用 / 不确定）；不确定标 `unknown`，不盲目重做。
- 定义文件在读取与提交之间被手工修改：提交锁内重读并比较已发布版本，不一致返回 409 且零写入。
- 发布过程中文件已换而指针未换：条件写与启动对账共同兜住，不把半发布状态当成成功。
- 归档等待期间运行结束：按当前状态继续；超时后回滚注册与定时，状态文件与目录未动。
- 归档目标标识已存在：409 且源目录原样保留，不自动改名。
- 原名恢复时归档清单哈希不符或身份不符：409，不做部分迁移。
- 复制的目标名与既有 Agent 或归档冲突：400 / 409 并点名。
- 技能工作副本内出现软链接：校验与发布均拒绝，快照不跟随。
- 两个 Agent 同时引用同一资源删除：引用闸门逐个点名，不因其一失败而放行。
- 通知渠道地址环境变量缺失：发送失败记 ERROR，不回落明文。
- 发布指针查询失败：失败关闭，启动拒绝或保留旧注册表，不放行空集合。
- 数据库事务中途失败：版本、指针与操作终态同事务回滚，不留下孤立版本。
- 管理台构建产物与完整性清单不一致：Go 门禁变红，二进制不发布空壳页面。
- 同一定义文件的块编辑无法安全保留注释：400 `EDIT_UNSUPPORTED`，磁盘逐字节不变。

## Requirements *(mandatory)*

### Functional Requirements

#### 管理写审计、条件写与恢复

- **FR-001**: 任何写端点**必须**在第一次目标区域写入之前成功插入一条 `pending` 管理操作；预写失败 → 500 `INTERNAL`，**零写入**（含暂存目录、临时文件与归档目录）；测试端点同样先写操作行再发起外部调用。
- **FR-002**: `POST /agents/{name}/generate-files` 是唯一例外：契约规定其唯一写入是 LLM 调用审计，**不得**补管理操作行，**不得**用伪操作让恢复表看起来完整。
- **FR-003**: 纯请求校验（路径参数、`If-Match` 语法与匹配、资源存在性、候选草稿解析）**必须**在写操作行之前完成；412 / 404 / 400 响应**不得**含操作标识；一旦写入 `pending`，后续任何失败**必须**置 `failed` 并返回操作标识。
- **FR-004**: 模型连接、MCP、技能的修改 / 删除 / 发布**必须**要求强 `If-Match`，值等于当前发布版本的 ETag；缺失、语法非法、弱比较、`*` 或不匹配 → 412 `PRECONDITION_FAILED`，`data.current_etag` 给出当前值，**不得**回显定义正文；412 零写入且零操作行。
- **FR-005**: Agent 多文件提交**必须**使用受管文件集合 ETag；单文件内容条件写沿用 US-11；归档、复制、恢复**不要求** `If-Match`，生命周期启停沿用期望状态与期望代次。
- **FR-006**: ETag **必须**按固定字节定义——资源 ETag 为当前发布版本内容的强哈希，技能为完整文件清单的规整哈希；**不得**重新序列化后求值；格式固定为 `"sha256:<64 位小写十六进制>"`。
- **FR-007**: 动作字面量**必须**逐字取契约集合：`agent.create` / `agent.files.update` / `agent.archive` / `agent.copy` / `agent.restore` / `model_connection.create|update|delete|test|publish` / `mcp_server.create|update|delete|test|publish` / `skill.create|import|update|delete|publish` / `notify_channel.create|update|delete`；`target_kind` 取 `agent` / `model_connection` / `mcp_server` / `skill` / `notify_channel`；**不得**自造动词、**不得**改写动作语义。
- **FR-008**: 操作标识**必须**为 `op-<unix_millis>-<6 位小写字母数字>`；资源版本的创建操作标识、归档索引的归档操作标识**必须**指向对应操作；`detail_json` 只存哈希、版本号、文件路径与脱敏测试结果；管理操作**不得**挂运行标识，作者模型调用的调用审计**不得**伪装成管理操作。
- **FR-009**: 启动恢复**必须**扩展到新增动作组：按动作类型查证实际结果（已应用 / 未应用 / 不确定），不确定标 `unknown` 并保留原行，**不得**盲目重做或自动补偿。

#### Agent 创建与文件提交

- **FR-010**: 创建（模板与提交）**必须**默认停用、代次 1、定时任务为空；任一步失败**必须**回滚生命周期状态与目录，零残余。
- **FR-011**: 模板创建**必须**确定性选择 Provider：取已发布列表的配置顺序第一项；没有已发布 Provider 时写可见占位符；**不得**遍历映射随机选择。
- **FR-012**: 作者草稿**必须**是单次生成调用，写入模型调用审计（调用标识 `<agent>-author-<name>` 形态不为运行、不为管理操作）；未配置作者模型返回 503 `NOT_CONFIGURED`；草稿不落盘、不注册、不产生生命周期状态。
- **FR-013**: Agent 多文件提交**必须**是完整副本加两次改名；未列出的文件保留；提交锁内重读并与受管文件集合 ETag 比较，不匹配 412 且零写入零操作行。
- **FR-014**: Agent 写面路径**必须**逐段校验：只接受相对路径，拒绝 NUL 与控制字符、越界段、`staging` / `backup` 后缀与大小写重复；内容必须是 UTF-8；请求体大小受限。
- **FR-015**: 管理写**必须**在文件提交锁内重读定义文件并与已发布版本比较；不一致返回 409 `CONFLICT` 且零写入（分歧闸门）。
- **FR-016**: 并发控制**必须**是每资源串行加每定义文件提交锁；锁顺序固定，**不得**出现第二套互斥；不同定义文件可并行。

#### Agent 复制、归档与恢复

- **FR-017**: 复制**必须**以活动区 Agent 为源，校验目标名与目录；完整复制、改写 `name` 与 `identity.agent_name`、清空定时任务、按停用与代次 1 引导；失败零残余。
- **FR-018**: 归档顺序**必须**固定：注销定时 → 移出注册 → 有界等待运行退出（超时 409 `AGENT_BUSY` 并点名运行，回滚注册与定时）→ 生命周期迁移 `archived` 并递增代次 → 目录移入归档区 → 写归档记录。
- **FR-019**: 归档回滚**必须**按三档矩阵执行；补偿动作失败**必须**标 `unknown` 并记录，**不得**假装成功。
- **FR-020**: 归档标识**必须**为 `<agent>-YYYYMMDD-HHMMSS`（UTC）；目标已存在返回 409 且源目录原样保留，**不得**自动换名。
- **FR-021**: 恢复**必须**分两条路径：原名恢复校验归档身份、`archived` 状态、清单哈希与条件代次，成功后 `archived → disabled` 且代次加一，**不得**重新引导；异名恢复按新 Agent 引导为停用、代次 1，并改写 `name` 与 `identity.agent_name`；两条路径均清空定时任务；rename 失败回退状态并保留归档记录。
- **FR-022**: 生命周期状态文件**必须**只有一个写者：创建 / 复制 / 恢复 / 归档只经既有生命周期端口，**不得**出现第二套写路径；数据库内索引可重建，不参与事务。

#### 公共资源定义、版本与发布

- **FR-023**: 定义内容**必须**以文件为期望载体，已发布版本与发布指针在数据库；运行对象**必须**只由已发布版本构建；手工编辑同样走启动对账，**不得**绕过。
- **FR-024**: 发布语义**必须**固定：不带版本号 → 发布最新版本，已发布则幂等；带旧版本号 → 用旧版本内容创建新版本再发布，返回新版本与来源版本；发布前把定义文件块改写为该版本字节。
- **FR-025**: 发布失败**必须**保旧：校验、运行时构建、文件写入、数据库事务任一步失败，旧定义文件与旧发布指针保留，操作置 `failed`；**不得**先换指针后校验。
- **FR-026**: 版本**必须**只追加：只插入、不更新、不删除；版本号逐资源递增；撤回只创建新版本；来源版本从创建操作派生。
- **FR-027**: 定义块编辑**必须**具备可安全保留的前提，否则 400 `EDIT_UNSUPPORTED` 且磁盘逐字节不变；块外字节逐字保留；注释丢失必须可记录、可解释。
- **FR-028**: 模型连接候选校验**必须**覆盖必填字段、唯一名称、`base_url` 协议与凭证信息、`api_key` 只接受环境变量占位；候选校验**不得**解析无关段的环境变量。
- **FR-029**: MCP 候选校验**必须**按传输分支：stdio 要求命令与参数，HTTP 要求合法 URL 且无凭证信息；`args` 与命令分离；环境变量只接受精确占位；既有文件的多词命令按兼容规则拆分并提示迁移；候选严格拒绝。
- **FR-030**: 技能创建 / 导入 / 更新的校验**必须**与校验端点共用同一逻辑；校验端点不落盘、不写操作行、不执行脚本。

#### 显式映射、准入与启动

- **FR-031**: 每次受控发布**必须**构建一份不可变映射表并原子替换；键来自已发布版本条目自身，**不得**遍历推断或取唯一值当默认；构建失败保留旧表。
- **FR-032**: 新运行**必须**在准入时固定已发布映射与资源版本；发布持写锁、准入持读锁，两者共用同一道闸；**不得**存在第二套互斥或旁路。
- **FR-033**: 启动**必须**先对账定义文件与已发布版本（一致 / 文件新 / 版本新 / 文件无效），按固定分支处理并记录，**不得**静默覆盖任何一侧。
- **FR-034**: 启动**必须**由已发布版本构建 Provider 目录与 MCP 集合；顺序固定为对账 → 目录构建 → 注册表 → MCP supervisor → 开放服务；**不得**直接用配置文件解析结果构建运行目录。

#### MCP 执行与待重启

- **FR-035**: MCP 连接生命周期**必须**由 supervisor 负责，命令执行器只执行单次命令；启动连接**必须**先经策略判定并审计；**不得**形成第二条未审计执行路径。
- **FR-036**: MCP 授权**必须**按传输分支：stdio 走命令授权与进程树回收；HTTP 走 HTTP 请求授权与域名白名单、零进程；拒绝即不连接；两条路径**不得**合并成一条。
- **FR-037**: 应用版本**必须**只在成功连接并接管后写入；连接失败保留旧应用版本并标未连接；待重启 = 发布版本不等于应用版本；Agent 引用的 MCP **必须**已应用且已连接才允许注册。
- **FR-038**: MCP 测试端点**必须**按传输分支、先写操作行再外部调用、固定 15 秒超时、不产生运行、返回工具发现结果；视图与错误**必须**脱敏：只回可执行名与环境变量键名，不回值；错误只含固定短语与协议加主机。

#### 技能导入与不可变版本

- **FR-039**: 技能导入**必须**拒绝越界路径、绝对路径、隐藏目录、软链接、非普通文件、非 UTF-8、单文件超 256 KiB、总量超 `min(2 MiB, 请求体上限)`、文件数超 200 与大小写重复路径；**不得**执行任何脚本；拒绝返回 400 `IMPORT_REJECTED` 并点名。
- **FR-040**: 技能**必须**有工作副本与不可变版本库：每次发布把完整文件清单复制到不可变版本目录；更新是全量替换，暂存构建后两次改名；失败回滚。
- **FR-041**: 技能删除**必须**删除工作副本与定义，版本历史保留可查；同名重建后版本号继续递增。

#### 引用视图与受控删除

- **FR-042**: 引用视图**必须**合并两类来源：Agent 定义（注册表与归档扫描）与未释放的运行引用；**不得**用"当前没有运行"推断无引用；定义解析失败**必须**按可能引用处理。
- **FR-043**: 删除闸门**必须**：被 Agent 引用或存在未释放运行引用时返回 400 并点名引用者，公共资源**不提供**强制删除；通知渠道保留显式强制参数，且只在请求明确要求时生效。
- **FR-044**: 删除的崩溃窗口**必须**由启动恢复查证：文件块与工作副本删除后按已应用 / 未应用 / 不确定三分，不确定标 `unknown` 且不自动补做。

##### 托管凭据

- **FR-074**: 凭据**必须**两种显式模式：`env`（模型连接 `api_key` / 通知渠道 `url` 只接受精确 `${VAR}`）与 `managed`（服务端写入，密文存 SQLite）；`credential_mode` 不按值形态推断；创建未声明时精确 `${VAR}` → env、普通非空值 → 400 `CREDENTIAL_MODE_REQUIRED`；同一资源**不得**同时给 `api_key` 与 `credential_ref`。
- **FR-075**: `credential_ref` **必须**只读（请求体出现 → 400 `CREDENTIAL_REF_READ_ONLY`）；凭据 owner **必须**绑定到本资源 UID（不符 → 409 `CREDENTIAL_OWNER_MISMATCH`）；`api_key` / `url` 为 write-only，响应只回 `credential_state` / `last4` / 版本号；空白值 **400**（不当作保留、不当作清除），省略字段才表示保留。
- **FR-076**: `managed` 密文**必须** AES-256-GCM，key **必须** 32 字节；AAD **必须**为 `basalt/v1|owner_kind|owner_uid|credential_id|version_no|target_binding`（模型连接按 `canonical(base_url)`、通知渠道按 `canonical(full_url)` 求 `target_binding`）；主密钥文件**必须**在工作区外，格式 `{"version":1,"key_id":"k_...","key":"<base64 32 bytes>"}`，Linux 目录 0700 / 文件 0600、Windows DACL 最小权限，拒绝符号链接 / junction / 硬链接。
- **FR-077**: 凭据状态机**必须**：身份 `active` / `revoked` / `retired`；版本 `active` / `superseded` / `revoked` / `retired`。撤销**必须**把该身份全部版本置 `revoked`、活动密文置 NULL、`revocation_epoch + 1`，**不得**复活旧版本、**不得**把「保存其他字段」当撤销；撤销**不得**读取主密钥。
- **FR-078**: 模型调用**必须**在每次 `Chat` 前经 `CredentialGuard` 查固定版本的权威状态与 epoch；`revoked` / 身份 `revoked` / epoch 变化 → 固定错误并终止该 Run。通知**必须**每次发送重新解析当前 `active` 版本；准入**不得**固定通知凭据版本。
- **FR-079**: 主密钥**必须**按需加载：启动只判定「当前托管模型连接」（当前指针 `managed` 且被活动区已注册 Agent 绑定），有则校验路径 / 权限 / 格式 / `key_id` 并解密，失败拒绝启动并点名；无则跳过。纯 env 或仅通知托管**不得**因缺主密钥阻断启动；运行期解析失败 → 503 `CREDENTIAL_UNAVAILABLE`，**不得**回落 env、**不得**自动生成新密钥。
- **FR-080**: 四场景**必须**由测试证明：① 全 env 模型 + 托管通知 → 启动不读密钥、发送时按需读取成功；② 无托管资源 + 密钥已初始化 → 可创建第一条托管连接；③ 无密钥 → env 正常、托管写入 / 测试 / 发送 503、启动正常；④ 当前必需托管凭据不可解密 → 拒绝启动并点名。

### Key Entities *(include if feature involves data)*

- **管理操作（扩展动作组）**：一次写面的留痕，含操作标识、动作字面量、actor、目标类型与标识、状态、恢复查证、开始与结束时刻；不挂运行标识；作者模型调用不在其中。
- **资源版本**：模型连接 / MCP / 技能的一次不可变发布，含资源类型与名称、版本号、内容哈希、逻辑清单、来源版本与创建操作标识；只追加。
- **资源指针**：每类资源的当前发布版本与已应用版本；发布失败保留旧指针；待重启由两者差异派生。
- **Agent 草稿视图**：一次作者模型生成结果的投影，含草稿正文与受管文件集合，不落盘、不注册。
- **归档索引**：Agent 归档目录的登记行，含归档标识、原名称、归档操作标识与恢复状态。
- **技能工作副本与不可变版本目录**：工作副本可编辑；每次发布生成只读版本目录，运行期按发布版本读取。
- **MCP 应用状态**：发布版本、应用版本、连接状态与待重启标记；应用版本只在连接接管后写入。
- **工作区浏览条目**：Agent 目录下经真实路径投影的文件树与文件内容，含大小与截断判定；不跟随链接。
- **通知渠道**：名称、类型、`${ENV_VAR}` 地址占位与主机名投影；列表只回主机名。
- **引用视图**：资源被哪些 Agent（含归档）与哪些未释放运行引用；删除闸门的唯一依据。
- **资源身份（R4）**：每个资源 UID 一行（`resource_identities`），记录创建时名称、`active` / `deleted` 状态与删除时刻；删除只置状态，不物理删除。
- **资源绑定（R4）**：`AGENT.md` 的 `resource_bindings` 为权威；数据库投影记录 `{agent_uid, resource_kind, ref_name, resource_uid}` 与投影时刻，可随时全量重建。
- **凭据身份与版本（R4）**：身份（`cred_`）持有状态；版本持有密文、`key_id`、`target_binding` 与状态；撤销清空活动密文并递增 `revocation_epoch`。
- **Run 凭据引用与通知引用（R4）**：准入时固定的凭据版本与具体通知渠道 UID 集合；释放前阻止资源回收与范围收缩。
- **主密钥（R4）**：工作区外的 32 字节 AES-256-GCM 密钥文件，含 `key_id` 与版本；只在按需加载点读取，不进配置、不进日志、不进工作区。
- **作者问答（R6）**：一次草稿请求携带的问题与答案；问题由模型在信息不足时给出（≤ 3），答案只在页面内存，不落盘。
- **定时任务候选（R6）**：模型生成、服务端校验并计算未来三次触发的候选；保存前不改变 Agent 定义、调度器或注册表。

## Out of Scope

以下项目在本模块明确不做，各有替代路径或归属阶段：

- 企业 SSO、RBAC、多租户与按人追责——扩展阶段。
- 调用方 API Key、QPS、配额——第二阶段。
- TLS 终止与证书管理——反向代理承担，扩展阶段。
- 指标导出、日志聚合、告警与分布式节点监控——扩展阶段。
- `AGENT.md` 内容编辑、启停、运行观测与取消——US-11 已交付。
- 技能市场、远程仓库、签名与来源校验——后续阶段。
- 作者模型多轮对话与自动修复——本模块只做单次草稿。
- 通知发送重试、投递保证与 outbox——不实现；R7 的系统代投只做「成功才发、三值记录、未知不重发」，不承诺到达。
- MCP 资源订阅、prompts 与远程 OAuth——v1 只做工具发现与调用。
- 工作区文件编辑、上传与下载——只读浏览。
- 归档物理清除与保留策略——不实现。
- 资源写面的 CLI 子命令——契约只定义 HTTP 面；CLI 仅保留创建与删除。
- `basalt.yaml` / `mcp_servers.yaml` 运行期热加载——明确提示"需重启"。
- 修改 `shell.allowed_commands`、`http.admin_auth` 与沙箱配置——部署者权限，不属管理台。

R4 范围修订新增的不做项（2026-10-23）：

- 企业 SSO / RBAC / 多租户 / 按人追责——仍是扩展阶段。
- 入站消息接入与路由——只保留范围转换的「消息路由」检查端口，当前返回空。
- KMS / HSM、自动轮换、密钥托管服务——`secrets revoke-managed` 是销毁性恢复，不是轮换。
- 按人保密——`exclusive` 只是运行时使用范围，不是管理员可见性，也不是对同机同权进程的隔离。
- 无目标的任务结束自动投递 / 广播——`notify_mode` 只表达授权；R7 的系统代投必须由任务 `deliver_to` 显式声明，不产生默认发送。
- MCP 服务器与技能的 `scope` / 托管凭据——本轮只覆盖模型连接与通知渠道。
- Agent 之间的凭据借用、共享密钥池、跨资源 `credential_ref` 复用。
- 把依赖图并入 Agent ETag——Agent ETag 只覆盖 Agent 自身内容。
- 重新加密历史密文或自动迁移旧密钥——主密钥丢失按销毁性恢复处理。
