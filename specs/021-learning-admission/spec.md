# Feature Specification: 学习准入

**Feature Branch**: `021-learning-admission`

**Created**: 2026-11-04

**Status**: 已审范围的实施规格（review ① 已通过）

**Input**: US21 已审颗粒度文档 R2（SHA-256 `14a1b4f7a19c9d8fbf4232fd385db7520ad312372933a39a05a84fe7d4fe5e78`）与用户持续开发授权；US20 已收口合入 main。

## User Scenarios & Testing

### User Story 1 - 提议、冻结与确定性评估 (Priority: P1)

管理员把一个技能目录和来源声明提交为准入候选；系统冻结内容与来源，生成不可变证据，并给出七维确定性评估。

**Why this priority**: 没有冻结与复算，后续批准与发布只是口头信任；这是整条通道的证据起点。

**Independent Test**: 临时工作区提交候选后可读回逐字一致的目录与哈希；重复提议同名活跃候选被拒；软链接 / 穿越 / 超限目录被拒。

**Acceptance Scenarios**:

1. **Given** 合法技能目录与来源声明，**When** 提议，**Then** 生成候选目录并置只读，内容哈希与来源哈希可复算。
2. **Given** 同名活跃候选已存在，**When** 再次提议，**Then** 拒绝且不写磁盘、不写数据库。
3. **Given** 目录含软链接、路径穿越或超限文件，**When** 提议，**Then** 拒绝且错误不回显凭证。
4. **Given** 已冻结候选，**When** 评估，**Then** 七维状态、聚合结论、风险档、策略哈希与基线一并落库，评估不执行脚本、不访问网络、不调用模型。

### User Story 2 - 本机批准与受控发布 (Priority: P1)

管理员在本机 CLI 用严格 JSON 决策文件批准或拒绝；高风险候选要求提出者与批准者分离；发布复用既有技能发布事务，新 Run 绑定新版本。

**Why this priority**: 没有可信身份与绑定决策，准入退化为任意文件复制；没有原子发布，审计与版本会分裂。

**Independent Test**: 评估后篡改内容或来源、基线或策略漂移、过期批准、不可信身份、自批高风险均被拒绝；合法发布后指针移动且版本可读。

**Acceptance Scenarios**:

1. **Given** 已评估候选，**When** 本机管理员以 ≤24 小时有效的决策批准，**Then** 只能有一条活跃批准。
2. **Given** 高风险候选，**When** 提出者本人批准，**Then** 拒绝且无决策行。
3. **Given** 已批准候选，**When** 发布，**Then** 版本行、指针、发布记录、候选状态与操作终态在同一事务提交；任一步失败全部回滚。
4. **Given** 评估后内容或来源被改，**When** 批准或发布，**Then** 返回哈希不匹配且不写决策 / 发布记录。
5. **Given** 空主体、非 cli 主体、`cli:unknown` 或非 cli 方法 / 来源，**When** 执行任一写动作，**Then** 在读取候选前拒绝。

### User Story 3 - 撤回与运行版本冻结 (Priority: P2)

发布后发现问题时，管理员撤回：上一版内容作为新版本重新发布，新 Run 绑定上一版，运行中的 Run 保留其冻结版本。

**Why this priority**: 没有可撤回的通道无法在生产使用；但撤回必须复用版本机制，不能删除历史。

**Independent Test**: v1 已发布 → 准入发布 v2 → 撤回后指针内容回到 v1；首版撤回被拒；被后续发布超越或技能已删时只记录撤回、不移动指针。

**Acceptance Scenarios**:

1. **Given** 指针仍指向本次发布版本且存在上一版，**When** 撤回，**Then** 上一版内容作为新版本发布，发布记录为 `restored_previous`。
2. **Given** 本次发布是首版，**When** 撤回，**Then** 拒绝并引导技能删除或新候选。
3. **Given** 指针已被后续发布超越或技能已删除，**When** 撤回，**Then** 只标记撤回，不移动指针，不删除历史证据。

### User Story 4 - 审计、恢复与只读观测 (Priority: P2)

每个写动作先写 `pending` 管理审计；崩溃后只查证不重放；运维在只读管理台查看候选、评估、批准与发布状态。

**Why this priority**: 严监管场景要求可追责与可恢复；只读观测不给管理面增加第二套写路径。

**Independent Test**: 审计预写失败时七个写动作都无任何变更；人为制造 `pending` 后恢复为 `failed` 且不重放；管理台 POST / PUT / PATCH / DELETE 均非成功。

**Acceptance Scenarios**:

1. **Given** 管理审计不可用，**When** 执行任一写动作，**Then** 拒绝且磁盘与数据库均无变更。
2. **Given** 发布 `pending` 行但无发布记录，**When** 启动恢复，**Then** 回填 `failed`，不重放发布。
3. **Given** 候选已发布且发起撤回，**When** 恢复，**Then** 只按 `withdraw_operation_id` 查证，不重复撤回。
4. **Given** 管理台带合法 admin token 请求准入路径，**When** 使用写方法，**Then** 没有写端点返回成功；页面无批准 / 发布 / 撤回控件。

### Edge Cases

- 候选目录被外部清理：评估 / 批准 / 发布返回候选缺失，不静默重建。
- 提议磁盘成功、数据库失败且补偿删除失败：操作记 `unknown`，目录成为可人工检查的孤儿，不自动删除。
- 发布事务失败：版本、指针、发布记录、候选状态全部回滚，候选保持 `approved`；重试重新复核。
- 撤回快照失败：恢复工作副本、删除本次快照，操作记 `failed` / `unknown`，候选保持 `published`。
- 域名策略内容不变但管理台修订号递增：策略哈希必须变化，旧评估不得复活。
- 来源保留期恰好到期：按「可用期限已过」拒绝，不按进程时区取日期。
- 含脚本候选只勾选 `permissions`：不视为完成审查，必须逐条提交静态审查证据。

## Requirements

### Functional Requirements

- **FR-21-01**: 候选必须以内容哈希与来源哈希冻结在只读目录；读取时复算哈希，目录 / 清单缺失或哈希不符必须拒绝。
- **FR-21-02**: 评估必须固定七维（content / source / permissions / safety / regression / effect / cost）、评分器版本、聚合结论与风险档；相同输入与时钟必须得到相同评估。
- **FR-21-03**: `not_evaluable` 不得视为通过；只有 `{effect, cost, regression}` 的未知可逐项确认；阻止维度与聚合失败不得批准。
- **FR-21-04**: 七个写动作必须只接受 `cli:<OS user>` + `Method=cli` + `Source=cli` 的可信本机主体，并在任何状态读取前校验；不得提供 HTTP 批准 / 发布端点。
- **FR-21-05**: 高风险候选（更新已绑定技能或含脚本）必须要求提出者与批准者不同；凭据命中直接阻止批准，不得靠换人解除。
- **FR-21-06**: 评估、批准、发布必须绑定同一基线、策略哈希与风险档；批准与发布必须重读磁盘复算内容 / 来源哈希并校验保留期，漂移必须拒绝。
- **FR-21-07**: 批准有效期必须在当前时刻之后且不超过 24 小时；过期只作派生展示态，发布必须拒绝，不得后台改写数据库状态。
- **FR-21-08**: 发布必须在同一事务写版本行、发布指针、发布记录、候选状态与操作终态；指针条件写与发布闸门必须阻止并发双赢。
- **FR-21-09**: 撤回必须把上一版内容作为新版本重新发布；首版撤回到空必须拒绝；指针被超越或已删除时只记录撤回，不得移动指针或删除证据。
- **FR-21-10**: 每个写动作必须先写 `pending` 管理审计再变更；预写失败必须拒绝；恢复只查证不重放，证据不足记 `unknown`。
- **FR-21-11**: 必须复用既有技能草稿校验、工作副本、快照与发布事务原语；不得新增第二套发布 / 审计 / 执行路径；`.basalt/admissions` 不得进入任何 Agent 读写白名单。
- **FR-21-12**: 管理面只提供只读准入列表与详情，并支持按 `target_kind=skill_admission` 查询操作；不得有写控件或写端点，admin token 不得落盘。
- **FR-21-13**: 评估与验收不得调用真实模型、发起外部网络请求或执行候选脚本；含脚本候选必须逐条提交非空人工静态审查证据。
- **FR-21-14**: 来源与决策文件必须是严格 JSON（未知键拒绝、体积上限、普通文件、不跟随软链接），文本字段必须做凭证扫描且错误不回显。
- **FR-21-15**: 同名活跃候选必须唯一；一个候选最多一次成功发布、最多一条活跃批准；重复批准 / 发布不得改变已有记录。

### Key Entities

- **候选（Admission Candidate）**: 一次准入提议的冻结快照，含技能名、文件集、内容哈希、来源哈希、来源声明、提议时基线、提议者、状态与修订号。
- **评估（Admission Evaluation）**: 固定评分器对候选的七维判定、脚本清单、聚合结论、风险档、基线、策略哈希与操作号。
- **决策（Admission Decision）**: 本机管理员提交的批准或拒绝，绑定候选 / 评估 / 哈希 / 批准范围 / 基线 / 有效期 / 脚本审查。
- **发布记录（Admission Publication）**: 候选版本进入既有技能版本与发布指针的那次事务；记录版本、撤回状态与撤回原因分类。
- **基线（Baseline）**: 评估时冻结的技能指针状态与引用该技能的 Agent 名单。
- **管理操作（Management Operation）**: `skill.admission.*` 的预写审计、终态与恢复查证依据。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 合法提议 → 评估 → 批准 → 发布 → 撤回全链路在临时工作区与测试数据库中可重复通过，且每一步都有对应的成功审计行。
- **SC-002**: 关键拒绝路径（内容 / 来源篡改、基线 / 策略漂移、过期、自批、不可信身份、阻止维度、脚本未审查）逐条返回稳定错误，且不留下决策 / 发布 / 版本残留。
- **SC-003**: 七个写动作在审计预写失败时零磁盘、零数据库变更；恢复对 `pending` 行只给 `success` / `failed` / `unknown`，从不重放。
- **SC-004**: 并发发布同一候选恰好一个成功、一个被拒；数据库中恰好一条发布记录、一个版本。
- **SC-005**: 管理面准入路径的 POST / PUT / PATCH / DELETE 均不返回成功；控制台准入页没有写控件。
- **SC-006**: 全量门禁与验收全绿，且 `go.mod` / `go.sum` 无新增坐标、无新增配置键、SQLite 谱系不受影响。

## Assumptions

- 运行期唯一存储为 PostgreSQL；本 US 追加迁移到 schema v10，不修改 `schema.pg.sql`。
- 写命令要求服务停止（工作区实例锁）；读命令可在服务运行时执行。
- 高风险双人分离在单用户主机上无法人工执行，由测试覆盖并保留人工未验证项。
- 真实模型、真实网络、脚本执行与隔离容器均未授权；效果与成本维度固定 `not_evaluable`。
- 既有技能发布、版本与指针语义保持不变；准入只增加发布前基线 CAS 与发布记录。
