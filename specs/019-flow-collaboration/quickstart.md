# US-19 人工验收准备

以下用于最终 review ②。先以 run-state 和交接材料核对自动验收是否完成；本清单不代表自动门禁已通过。使用独立走查实例及本轮构建，保留原 8080 实例；访问地址和测试身份以最终交接为准。

1. 登录后从左侧“工作流”进入，确认页内有“工作流定义”和“执行任务”，定义展示固定版本、目标、节点与退役状态。基础走查实例只连接本地脚本模型，不调用付费模型。
2. 在“工作流定义”选择“新建工作流”，填写名称与目标，新增一个字符串任务参数，再从已就绪 Agent 中添加两个步骤。给第一步定义字符串输出，将该输出接到第二步输入。拖动或用上／下移交换顺序，原上游引用应提示失效并阻止发布；恢复顺序后应恢复原引用，不自动改接其他步骤。点击在线校验，检查目标与步骤差异；“核对发布”应出现页内影响说明，“返回修改”不会发布，“确认发布”才保存新版本。无需先编写 JSON。
3. 在“执行任务”选择这条已发布定义，通过参数表单填写“人工走查”并启动。先观察已受理／执行中，随后应“已通过验收”；打开任务查看固定版本、硬约束、剩余预算、产物版本及验证依据。展开有权读取的产物，核对内容；格式通过不代表业务结论正确。
4. 从节点打开“运行详情”及“运行排障”，查看原 Run、模型次数和耗时；再从任务入口按“流程任务 ID”查询全部原记录。节点跨度包含执行和暂停核对，不是模型调用耗时；父子阶段和调度／运行有重叠，不能相加。
5. 启动“缺少证据”路线，应暂停并明确展示未满足的槽位／独立来源数量不足，不能显示成功。填写理由，点“核对并恢复”，先检查页内说明再确认；若资料未补齐仍暂停。恢复前后应复用原 Run，模型调用次数不增加；已记录产物不等于整个任务已验收。
6. 对这条隔离测试任务填写停止理由，点“取消并关闭”，核对影响后确认。先保存关闭意图并等待真实执行退出，随后才关闭；已发生副作用不会被撤回，未知结果与预算预留仍需人工核对。退役定义同样先页内核对，确认后禁止新任务，保留历史和在途任务。
7. 在任务页面刷新、切到后台再返回，检查状态和最近刷新时间；终态停止轮询。确认面板打开后若任务版本变化，应要求返回重新核对，不能悄悄用新版本提交。网络失败应保留上次数据；显式失去权限应清除私有正文；不确定写结果应保留原操作标识并禁止换键重发。

以下由自动验收覆盖，不要求用户在人工走查中破坏实例：同键重试／语义冲突／切版退役的原事实回读；真实 kill 窗口及未知零重放；原 Key 撤销和跨 caller 隔离；服务 CLI 不另取写锁；200 次容量、公平预留、32 open 恢复，以及真实 30／35 秒取消排空和 join 后关库。实际结果及限制以对应报告为准。

高级 JSON 导入仍可使用交接提供的当前 Agent UID／资源版本 bundle。`testdata/flow` 含夹具占位符，不能直接作为线上导入；自有定义可用 `basalt flow validate <流程目录> --bundle` 导出再在线校验。

自动命令及 exact 用例以 harness/stages/us19-base.json、us19-process.json、us19-experience.json 和 acceptance-map.json 为准。Q5 真模型业务演示在单独隔离实例执行，和基础 UI 走查分开交接。已发生的用量、原始失败、独立评分与剩余授权见 run-state；不能把脚本模型、结构检查或本清单视作真实业务验收已通过。
