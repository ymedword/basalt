# Feature Specification: US-19 持久流程与有界协作

**Feature Branch**: `019-flow-collaboration`

**Created**: 2026-11-03

**Status**: Derived from approved R3; implementation and review ② pending

**Input**: 用户批准版本化顺序长任务、有界协作、证据与验证、取消／安全恢复及宪法 VII 全文，自动推进至最终人工验收。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 发布并完成可验证流程 (Priority: P1)

作者发布有界流程，调用方提交合格输入，系统持久接受、顺序推进并展示验收产物。

**Why this priority**: 先形成有持久事实和可验收结果的闭环。

**Independent Test**: 单节点定义发布→同键提交两次→唯一任务／唯一调用→适用验证→产物可读。

**Acceptance Scenarios**:

1. **Given** 有效定义，**When** 同键同输入重复提交，**Then** 回原任务且不重复预留／执行。
2. **Given** 已切版／退役定义，**When** 原键重试或旧版新键，**Then** 前者回原事实、后者拒绝。
3. **Given** 成功工具但证据不足，**When** 验收，**Then** 不宣布任务成功。

### User Story 2 - 中断、取消与安全恢复 (Priority: P1)

用户能区分失败、未知和停止，中断后只按可证明事实恢复，不重复业务副作用。

**Why this priority**: 防止重复写与取消后继续执行。

**Independent Test**: 真进程中断覆盖派发及提交窗口；取消与完成竞态；重启后核对调用次数不增长。

**Acceptance Scenarios**:

1. **Given** 动作已发而结果未知，**When** 重启或显式恢复，**Then** 阻断且零重放。
2. **Given** 取消意图先提交，**When** 跨截止／重启，**Then** 永不重新排队；实际退出后关闭，unknown 保留。
3. **Given** 已完成节点证据完整，**When** 恢复，**Then** 重查后复用而不重做。

### User Story 3 - 有界协作与证据修订 (Priority: P2)

多个 Agent 顺序分工，保持原归属、权限、祖先预算与证据依赖；无进展及时停止。

**Why this priority**: 复杂任务分工不能扩大能力或消耗上限。

**Independent Test**: 双 Agent／子流程完成、跨层预算耗尽拒绝、依赖闭包失效、重复／交替／无进展停止。

**Acceptance Scenarios**:

1. **Given** 受限授权和父预算，**When** 委托，**Then** 权限只收紧、未知用量不释放、子会话独立。
2. **Given** 来源撤权或换版，**When** 复用／修订，**Then** 相关结论及产物传递失效，无关结果保留。
3. **Given** 重复调用而无已验证进展，**When** 到达阈值，**Then** 在下一外部调用前停止并展示未解项。

### User Story 4 - 管理与运维 (Priority: P2)

操作者从控制台或服务客户端查看／关闭任务，诊断关联真实运行，容量与停机不会破坏恢复依据。

**Why this priority**: 长任务须可解释、可操作并保护交互容量。

**Independent Test**: UI／CLI 全操作，容量满载预留、停机 join、迁移及历史清理保护。

**Acceptance Scenarios**:

1. **Given** 满载流程，**When** 普通请求到达，**Then** 流程未吃掉实例和同调用方的预留名额。
2. **Given** 停机仍有叶子，**When** 排空尝试超时，**Then** 如实失败且存储仍保持可用到实际退出。
3. **Given** 跨调用方任务，**When** 读详情／产物，**Then** 404 且不泄露存在性或正文。

### Edge Cases

定义未知／非法／退役／旧版；重复键冲突；提交回执丢失；pending 失败；部分消息组；旧代次回调；取消／完成／deadline 竞态；撤销原 Key；同名新 UID；未知检查点；超大／重复键／大整数 JSON；关系环／超限；预算未知；无可用交互槽；嵌套子流程；缺必需人工判断；网络错误及过期 UI 响应。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 版本化定义**：系统必须作者能校验、发布及退役不可变流程定义；新任务只使用当前有效版本，在途任务固定原版本。
- **FR-002 契约与终止性**：系统必须定义只允许顺序、择一分支、有界返工及显式子流程；每条路线有界终止，每个必需证据槽位有适用验证规则。
- **FR-003 持久受理**：系统必须确认接受前保存归属、版本、请求键、语义输入、有效预算和初态；同调用方同键同请求只产生一个任务，切版退役后仍回读原事实。
- **FR-004 只读查询**：系统必须用户可分页查询自己的任务、节点、验证与产物；读取不推进／恢复任务，跨调用方不存在性一致。
- **FR-005 条件推进**：系统必须推进、结果接受、修订及关闭须验证旧状态、修订及执行代次；竞争只允许一个真实尝试，旧结果不能覆盖新状态。
- **FR-006 唯一路径**：系统必须每个叶子沿统一运行、消息与审计路径；调用预写或动作许可失败不发调用，不能凭运行完成推断任务验收。
- **FR-007 稳定动作**：系统必须业务动作发出前固定逻辑身份、输入及来源版本；未知副作用不得自动重放，不以新修订／尝试改名绕过。
- **FR-008 取消与收束**：系统必须取消意图持久单调，先于恢复和截止；实际执行退出后才关闭／归还名额；关闭保留未知动作、预留与依据。
- **FR-009 有界委托**：系统必须只允许固定身份／版本的获准 Agent 与子流程，单任务顺序、有界深度及累计子数，独立子会话避免自锁。
- **FR-010 权限交集**：系统必须叶子使用原执行授权的当前资格与接受上限、目标自有权限及委托上限的交集；同名新身份不能顶替，管理身份不能代原 Key 续跑。
- **FR-011 祖先预算**：系统必须父预算跨尝试、子任务和修订累计；未知用量保留，FixedTool 也计真实 Run／工具次数和调用方配额，没有模型调用不伪造 Token。
- **FR-012 版本化证据**：系统必须观察、证据、结论及产物均带版本与原始定位；重复来源不算独立证据，复用前重查当前来源权限／内容。
- **FR-013 闭包失效**：系统必须来源或结论变化时失效全部直接／间接依赖，保留无关仍有效结果；环、跨作用域和超限关系拒绝。
- **FR-014 独立验收**：系统必须成功要求必需规则对确切目标版本通过；结构、证据、判断分责，inconclusive 不通过，未提供人工能力时停止。
- **FR-015 安全恢复**：系统必须中断后按终态、关闭意图、截止、检查点及调用事实核对；已完成证据完整可复用，未知格式保留并阻断，不猜未执行。
- **FR-016 循环检测**：系统必须在发出前拦截第三次相同或第六次交替调用；第六次无验证进展观察后停止下一调用；合法单调分页不误杀，返工／修订不清计数。
- **FR-017 有限修订**：系统必须只在发布路线与次数内修订输入／补查／返工，不改验收或抬高预算；修订与依赖闭包原子接受，最多一个当前头。
- **FR-018 强参数校验**：系统必须新流程输入／输出／所用工具参数执行完整已批准子集校验，拒绝重复键／未知关键字／深大非有限输入；发出前失败关闭，旧非流程入口兼容。
- **FR-019 上下文**：系统必须版本化任务摘要携目标、硬约束、未解项、进度及引用；摘要不改任务权威／替代来源，不可裁剪约束超限则零模型调用。
- **FR-020 原子事实**：系统必须状态、转移、结果、关系和预算短事务一致；提交回执未知按原身份查证，关闭意图四种合法配对由持久约束强制。
- **FR-021 交互与隐私**：系统必须API、CLI、管理台和诊断可关联真实任务／节点／运行／动作；读写权限分离，正文与凭证不进日志／指标／未授权投影。
- **FR-022 容量及停机**：系统必须持久容量、墙钟截止、交互预留、轮转公平及 Worker 上限受限；总名额共享原子检查，停机实际 join 后才关库。
- **FR-023 迁移与保留**：系统必须新建与升级结构一致，只追加迁移；保留定义／契约及任务恢复引用，终态 unknown 仍保护；普通消息同步、忙即拒和审计不退化。
- **FR-024 管理台闭环**：系统必须定义导入校验发布／退役及任务启动、详情、产物、取消／恢复／放弃可操作；重复点击、过期响应、隐藏轮询和错误态正确。
- **FR-025 评测及交付**：系统必须冻结 12 项固定任务与单 Agent 基线，含成功和应停止样例；mock 仅证明控制协议，真模型单独授权；提供容量／恢复测量和人工验收步骤。

### Key Entities *(include if feature involves data)*

- 定义／契约版本：作者固定流程与验收，上线后不可变。
- 任务／修订／节点尝试：跨运行工作单元、唯一当前头、独立每次尝试。
- 逻辑动作／发送尝试：稳定意图与冻结输入，独立尝试与未知结果。
- 观察／证据／结论／产物／验证：可追溯版本、依赖、验收及失效。
- 祖先预算／分配票据：预留、实际及未知占用不重置。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：冻结 12 项本地控制样例，预期正确 12/12，错误成功 0、非法调用 0；停止样例不要求业务成功。
- **SC-002**：200 次独立任务、4 active／32 open／每任务 20 节点／固定 50ms mock：受理 p95≤2s、读 p95≤1s、无容量排队时 ready 到 start p95≤1s；报告 p50／95／99、失败率、内存、连接／锁与排队等待。
- **SC-003**：32 open、依赖健康、有界历史，重启核对≤30s；unknown 阻断只算核对完成，不算业务恢复成功。
- **SC-004**：取消有界等待 30s、审计独立收尾 5s、Worker 排空尝试 35s；超时如实报告且不提前归还名额／关闭共享存储。
- **SC-005**：所有故障窗口保留命中证明、调用集合与次数、版本、预算和结果；未知写恢复零重放，取消后零新许可，普通 Run 回归保持。
- **SC-006**：控制台真实操作与构建嵌入通过，CLI 不产生第二写实例；公共七目标、完整阶段、竞态与真实中断验收均通过。

## Assumptions

- 单机单工作区实例，已有认证、知识、运行、审计与 PostgreSQL 设施复用。
- 普通消息与 Run 同步；仅新流程面享有经批准的持久任务例外。
- 不做并行图、分布式接管、A2A、代码执行、通用审批、自动补偿或凭据管理。
- 本地 mock／临时 PG 可自主执行；真实模型／外部业务写须独立授权，当前未授权，不以 mock 宣称质量优势。

## Clarifications

### Session 2026-11-03

- 执行模型：按已批准 R3 Q1-A 与宪法 v6.0.0 VII；普通 Run 同步，有界 Worker 仅推进独立持久任务。
- 写路径：按 Q2-A，Agent 只读；受控 Tool 经 G-FT 设计／行为两关，unknown 不重放。尚未通过 G-FT 不开启写分支。
- 校验作用域：Q3-A，只强化 Flow 契约及所用工具，不顺手切换旧工具协议。
- 默认硬限及规模：Q4-A 按正式 Flow 契约，不能放宽阈值换绿。
- 真模型：Q5 保持未授权／未验证；缺少该结果与本地控制协议证据分别报告。

## R4 受控范围增量（2026-11-03）

用户明确要求工作流页面优化、可视化编排和业务演示在 US19 完成，最后人工 review ②。具体设计与验收边界以 [experience-design.md](experience-design.md) 为本次加性补充，不更改原 FR-001–025 与 SC-001–006。

- FR-026：左侧统一“工作流”；已有路由兼容，内部工作流定义／执行任务导航。
- FR-027：从已注册启用且就绪的 Agent 可视化编排现有顺序节点，配置目标、输入输出与验收范围，不要求 JSON；主动作不编辑 Agent 或 prompt。
- FR-028：admin-only Agent 引用目录及指定 UID／版本的完整作者定义读取；零执行、零外发、无 prompt／凭据，发布／执行继续严格固定版本。
- FR-029：本机草稿下载／导入继续编辑；高级原文不因可视化转换丢失未知语义或精确数值；所有变更重置在线校验与确认。
- FR-030：四专业业务 Agent 完成长材料调查准备演示，联动原知识库与受确认记忆，区分事实、经验、未证实建议及正式审批。
- FR-031：真实模型授权按 experience-design §5 有界执行；三组对照分离持久编排和专业分工价值，结果如实记录，不预设胜负或造时长。

新增验收 F20–F24 进入体验 stage；旧测试不降级。真实模型现已授权，原 Q5 未授权仅为历史时点记录。

### 用户追加默认示例（2026-11-04）

- FR-032：采购准备默认示例随二进制携带，四角色、17顺序节点、48需求；安装不带模型/凭据、不计费、不创建任务。新实例禁用准备，升级保留用户内容和删除/归档语义，旧未接管实例显式安装。
- FR-033：管理台从当前已就绪Agent目录生成默认模板草稿，固定身份/版本/资源哈希；缺失点名，发布和执行仍由原权限、审计及人工动作触发。
- FR-031 验收安排更新：三组对照和历史失败保留，最后真实模型业务结果由用户手动运行验收；AI只完成离线验证、服务和操作单，不把人工待验记绿。
