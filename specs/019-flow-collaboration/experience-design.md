# US19 R4：工作流编排与业务演示补充设计

2026-11-03。用户已明确将管理台“工作流”优化、可视化编排、演示 Agent 与工作流纳入 US19，并保留最后人工 review ②。本文是该授权的具体化；不覆盖 R3 的批准文本、失败历史或验收证据，不改变执行模型。

## 1. 产品边界

管理台左侧只有“工作流”，内部区分“工作流定义”和“执行任务”。原 `/console/flows`、`/console/flow-tasks` 与任务深链继续有效。

主要创建路径为：填写目标／约束与任务输入 → 从已注册、已启用、配置就绪的 Agent 中选择节点 → 排列顺序 → 配置输入来源与输出字段 → 在线校验 → 核对并发布。画布展示开始、Agent、结束与连接线；支持拖动排序和键盘／按钮调整，不要求用户写 JSON。只编辑现有顺序 Agent 语义，不定义 Agent、不编辑 prompt、不增加并行或表达式。

JSON 导入／导出保留为高级入口。复杂 branch／subflow／固定工具图及含精确大数／小数的内容保留原始字节，不因切换界面损失字段或数值；无法安全编辑时明确改走高级模式，不能静默转成简化图。

导入草稿在未编辑时逐字保留；服务端已发布内容仅保证保存的规范化 JSON 语义，不恢复原排版。草稿通过用户主动下载到本机保存，上传可继续编辑；不把内容自动写入 localStorage，不把草稿伪称为已发布版本。本轮不新增草稿表、通用文件写 API 或第二套发布事务。编辑已发布版本先读取该版本完整正文，原不可变版本及在途任务不变。

## 2. 加性管理读取契约

仅增加两个 admin-only 只读端点，沿原认证／Host／Origin 闸门；无调用审计、配额消耗、模型调用、MCP 连接创建或节点推进：

| 方法／路径 | 消费端类型与结果 | 边界 |
| --- | --- | --- |
| `GET /api/v1/admin/flow-agents` | `FlowAuthoringBackend.AuthoringAgents(ctx, actor, cursor, limit)` → `FlowAgentPage` | 当前注册快照、有界分页；每项只含名称、显示名、描述、就绪原因、当前 AgentRef、知识库与记忆能力提示；无 prompt、路径或凭据 |
| `GET /api/v1/admin/flows/{uid}/versions/{version}` | `FlowAuthoringBackend.AuthoringDefinition(ctx, actor, ref)` → `FlowAuthoringVersion` | 只按明确 UID／版本读原记录，不追随当前指针；`bundle_json` 字符串承载完整规范化作者定义，避免共享 response.json() 将精确数字转成 JS Number；不混入任务输入／产物 |

`FlowAuthoringBackend` 为可选消费端口，由同一 `flowHTTP` 实现；保留现有 `FlowBackend` 方法，避免为兼容旧测试夹具加入无关桩。未装配端口失败关闭，不退回业务面读取完整内容。

目录只生成当前引用，不授予权限。发布及执行仍核对同一 UID、generation、config_hash、manifest_hash；同名重建或目录读取后的变化仍拒绝。不可选项显示具体就绪类别，不能因列表可见而放行。Agent 节点只读工具限制保持 R3；MCP／DBHub 的声明不作为可信只读证明。

## 3. 编辑器状态与校验

编辑器使用 Vue／TypeScript／SVG 与现有依赖。纯转换函数与组件分离。新建表单只生成封闭、现有格式版本 1 的 bundle。节点 ID 稳定；重排不重新命名。输入只选任务参数／已验证的上游字段或明确常量，不允许运行 JavaScript、模板表达式或引用下游。删除／重排使引用失效时指出字段，不静默重绑。

输入／输出字段基础表单支持字符串、整数、布尔及说明、必填；复杂 Schema 走高级原文。目标、硬约束、产物、验收范围、tokens／工具／1800 秒以内时限可核对。默认结构验收只证明所声明 JSON 结构，不宣称事实／商业结论正确；页面解释此界限。高级验收规则原样保留，不能随改输出字段被悄悄替换。

在线校验成功仅绑定当时的原始 bundle；任一修改清除校验及发布确认。发布复用原 operation_id、版本 CAS、pending 管理审计、未知写锁和页内二次确认。未知发布结果不自动换键。目录读失败不清空已有草稿；身份失效清除可读内容。画布不发 Run，测试任务由原任务受理入口创建。

## 5. 真模型与三组对照
