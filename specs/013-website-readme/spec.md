## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访客读懂 Basalt 并在中英文之间切换 (Priority: P1)

一位第一次接触 Basalt 的企业技术决策者打开站点：默认英文首页用一句话讲清"面向企业自托管的 Agent OS，统一托管多个独立业务 Agent"，并用六项平台能力说明产品层价值；进入架构页能看到五项核心能力、完整项目全景与六类图，并从接入层、应用层、执行引擎层、基础服务层、存储层理解执行、接入、调度、存储与审计如何共享；进入文档索引页能按任务找到已有内容。切换到中文后仍停在当前页面与锚点，导航、页脚、按钮和正文完整中文。首版没有站内搜索，也不暗示存在搜索。

**Why this priority**: 对外门面首先要"说得清、找得到、切得动"。四页双语与默认英文是用户已确认的基线；讲不清定位或多语言断链，后续快速开始再真实也无法建立可信度。

**Independent Test**: 从站点根路径开始，逐一打开四页英文与四页中文；在架构页某锚点切换到另一种语言，确认页面、查询串与锚点保持；检查首页六卡、架构页五项能力、完整全景与六类图；确认页面不存在搜索框；只用键盘完成导航与语言切换。

**Acceptance Scenarios**:

1. **Given** 访客首次访问站点根路径，**When** 页面加载完成，**Then** 显示英文首页、定位句与六项平台能力卡片，每张卡片有本地插图与说明。
2. **Given** 访客位于架构页某个锚点，**When** 切换到中文，**Then** 落在对应中文架构页的同一锚点，语言切换不回到首页。
3. **Given** 访客位于带查询串的快速开始页，**When** 切换语言，**Then** 查询串与锚点保留，页面内容为对应语言。
4. **Given** 访客浏览任一页，**When** 查找站内搜索入口，**Then** 页面没有搜索框，也没有"搜索"能力的暗示。
5. **Given** 访客只用键盘，**When** 按 Tab 遍历，**Then** 能到达全部主导航、语言切换与页脚链接，焦点可见。
6. **Given** 访客阅读架构页，**When** 查看项目全景与专题图，**Then** 能区分当前单节点实现与未来规划，并看到五层职责、调度所属层与贯穿各层的安全 / 审计。

### User Story 2 - 新用户按 README 从干净环境跑通首次对话 (Priority: P1)

一位新用户拿到仓库或发布包，只按 README 操作：写最小 `basalt.yaml`，依次执行 `basalt init`、创建示例 Agent、启动服务，在管理台实际完成"配置模型连接 → 启用 Agent"，停止服务后执行 `basalt chat --agent demo --message "Hello"`，再用 `basalt session list` 看到这次会话。两版 README 结构一致，每版只嵌入一张本地化简化架构图；完整项目全景与专题图由架构文档承接。文档明确 `registered=true` 不等于已配置或可运行，不诱导手改生命周期文件，不虚构不存在的命令；中文 README 与英文 README 使用同一条命令链。

**Why this priority**: 快速开始是对外可信度的核心证据。只要有一条命令、状态或前置条件与真实实现不符，读者会卡在第一步，后续架构说明也失去意义。

**Independent Test**: 在干净临时目录按 README 逐条执行到 `session list` 看到会话；核对命令序列与站点快速开始页一致；确认公开材料中不出现不存在的命令；确认模型占位文本与 `registered=true` 说明存在；确认两版 README 各只嵌一张简图。

**Acceptance Scenarios**:

1. **Given** 干净工作目录与预构建二进制，**When** 按 README 写最小配置并执行初始化与创建示例 Agent，**Then** 工作区与 Agent 目录按文档所述产生，命令无报错。
2. **Given** 服务已启动，**When** 在管理台完成模型连接配置并启用 Agent，**Then** 页面显示已启用状态；README 明确这一步是启用前的必要条件。
3. **Given** Agent 已启用，**When** 停止服务并按 README 执行对话命令，**Then** 得到一次成功回复；随后 `session list` 能看到该会话。
4. **Given** 读者只看到 `registered=true`，**When** 阅读 README 的相关说明，**Then** 文档明确它不代表已配置模型或可运行，并给出下一步。
5. **Given** 读者使用 Windows，**When** 需要管理 token，**Then** 文档同时给出可用的跨平台与 Windows 生成方式，不假设 `openssl` 存在。
6. **Given** 读者比较两版 README，**When** 查看架构图，**Then** 每版只有一张本地化简化图，完整全景与专题图链接到架构文档且结构一致。

### User Story 3 - 首页演示可复跑且与命令同源 (Priority: P2)

访客在首页看到一段简短的 CLI 动画，展示一次真实对话与一次 `read_file` 工具调用；终端展示内容全英文，不随站点语言切换，演示区域明确标注模型回复由本地脚本模拟，不代表模型质量。演示中的命令与快速开始页、README 逐字一致。维护者可以在本地重新采集演示内容；采集结果与脚本回复不一致时检查失败。

**Why this priority**: 演示能降低理解成本，但也是最容易"演戏"的地方。把它限定为可复跑、可核对、明确标注的素材，才能既展示链路又不误导。

**Independent Test**: 对比演示命令与快速开始命令的每个字符；本地启动脚本化模型，重跑采集并确认输出一致；修改脚本回复但不更新采集数据，确认检查失败；检查页面上"脚本化"标注可见；切换两种语言确认终端仍全英文而页内说明已本地化。

**Acceptance Scenarios**:

1. **Given** 访客打开首页，**When** 演示播放，**Then** 展示的命令与快速开始页逐字一致，页面上有脚本化说明，终端标签与输出全英文。
2. **Given** 维护者在本地启动脚本化模型并重跑采集，**When** 采集完成，**Then** 记录的最终回复与脚本实际回复逐字一致。
3. **Given** 脚本回复被修改而采集数据未更新，**When** 运行内容检查，**Then** 检查失败并点名不一致字段。
4. **Given** 访客启用"减少动态效果"或使用键盘，**When** 浏览演示区域，**Then** 不依赖动画也能读到完整内容。

### User Story 4 - 维护者更新内容并手动决定是否发布 (Priority: P3)

维护者修改页面、命令或图表后，自动检查能发现缺页、缺图、断链、私有路径、命令漂移与未测量时长；部署是手动触发的独立工作流，不会随提交自动上线；线上地址在真实部署并验证前不写成已可用。公开运维手册只链接公开目标，不再把读者引向未公开文档。

**Why this priority**: 门面内容会随实现变化。没有可执行的漂移检查，官网很快会变成过期宣传页；没有手动发布边界，则容易把"工作流就绪"误写成"网站已上线"。

**Independent Test**: 分别制造缺页、缺中文图、命令改动、私有链接、无依据时长五类漂移，确认检查逐类失败；确认部署工作流只能手动触发；检查公开运维手册不出现私有文档链接。

**Acceptance Scenarios**:

1. **Given** 页面集合缺少任一语言的任一页，**When** 运行内容检查，**Then** 检查失败并点名缺失页面，不静默跳过。
2. **Given** 六类图中缺少任一语言的任一图，**When** 运行图表检查，**Then** 检查失败并点名缺失图与语言。
3. **Given** 快速开始命令被改动而其他材料未同步，**When** 运行同源检查，**Then** 检查失败并指出不一致的两处。
4. **Given** 公开页面、README 或公开运维手册出现私有路径或私有文档链接，**When** 运行边界检查，**Then** 检查失败。
5. **Given** 维护者未主动触发部署，**When** 代码合并或构建成功，**Then** 不产生任何线上部署。
6. **Given** 部署工作流尚未真实执行，**When** 阅读 README 与站点，**Then** 不声称线上地址已验证或可用。

### Edge Cases

- 页面集合缺一页（如只有英文索引页）时，检查必须失败，不能以"页面不存在就跳过"放行。
- 语言切换发生在带查询串、锚点或非首页路径时，目标地址必须保留这些成分；根路径切换不得错误拼接 base 前缀。
- 六类图只有文件、没有可编辑图源或没有源码提交标记时，图表检查必须失败。
- 演示的脚本化回复改变、但采集数据未同步时，演示检查必须失败并点名字段。
- 窗口宽度为 1440×900 / 768×1024 / 390×844 时，六项能力卡片按 3 / 2 / 1 列排布，不横向溢出。
- 用户使用键盘或减少动态效果时，导航、切换与演示内容仍可完整使用。
- 管理台标签为中文时，英文页面需给出英文注释，但不得声称管理台已英文化。
- 公开材料不得出现 `--profile`、`profile enable` 等不存在的入口，也不得引导读者手改生命周期状态文件。
- 管理 token 只以占位符说明，文档不包含真实凭证；Windows 环境不假设 `openssl` 可用。
- 站点在不访问外部 CDN、字体服务或第三方脚本时仍能完整呈现；断网环境不出现空白版式。
- 中文页面的终端演示仍为英文时，页内说明必须解释这是可复跑的 CLI 记录，不能把英文终端误读成未本地化。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 站点 MUST 提供四个页面——首页、快速开始、架构、文档索引——且每个页面 MUST 有完整英文版与中文版，共八个可独立访问的地址。
- **FR-002**: 站点根路径 MUST 为英文；中文 MUST 位于 `/zh/` 前缀下；两种语言的导航、页脚、按钮、演示说明与 404 文案 MUST 对应完整。
- **FR-003**: 语言切换 MUST 保留当前页面、查询串与锚点；在根路径与子路径之间切换时 MUST 正确处理站点 base 前缀。
- **FR-004**: 首页 MUST 用一句话讲清"面向企业自托管的 Agent OS，统一托管多个独立业务 Agent"，并 MUST 以六项平台能力卡片说明产品层价值；每个 Agent 的身份、配置与业务状态独立，执行、接入、调度、存储与审计底座共享。
- **FR-005**: 架构页 MUST 展示五项核心能力（Provider / ReAct / Memory / Tool / Web Service）与完整项目全景，并按接入层、应用层、执行引擎层、基础服务层、存储层说明职责；MUST 提供六类图（项目全景 / 系统架构简图 / 核心执行流 / 模块图 / Go 包依赖 / 部署），每类图 MUST 有英文与中文两个版本；调度 MUST 归入应用层，安全与审计 MUST 贯穿各层；当前单节点实现与未来规划 MUST 明确分开。
- **FR-006**: 核心执行流图 MUST 标出失败、拒绝、取消、恢复分支，并把 `completed` / `limit_reached` / `cancelled` / `failed` 四个终态落到 Run 结果与审计终态；`limit_reached` MUST 说明为部分结果结束，不是错误。
- **FR-007**: 快速开始 MUST 使用真实可执行的链路：最小配置 → 初始化 → 创建示例 Agent → 启动服务 → 管理台配置模型并启用 Agent → 停止服务 → `chat --agent` → `session list`；命令 MUST 与当前实现一致。
- **FR-008**: 快速开始 MUST 明确 `registered=true` 不代表已配置模型或可运行，MUST 给出模型占位文本与下一步；MUST NOT 引导读者手改生命周期状态文件。
- **FR-009**: 公开材料 MUST NOT 出现不存在的命令（含 `--profile`、`profile enable`）；唯一 Agent 选择写法 MUST 为 `--agent`。

### Key Entities *(include if feature involves data)*

- **页面（Page）**：站点中的一个双语页面，具有语言、路径、标题、描述与锚点集合；四类页面 × 两种语言 = 八个可访问地址。
- **能力（Capability）**：首页六项平台能力与架构页五项核心能力；每项有名称、双语说明与证据来源（实现文件或运行机制）。
- **架构层（Architecture Layer）**：接入层、应用层、执行引擎层、基础服务层、存储层；调度属于应用层，安全与审计为贯穿各层的控制面。
- **图（Diagram）**：六类架构图之一，具有固定标识、语言版本、可编辑图源与源码提交标记；英中同标识图必须语义一致；README 只使用系统架构简图。
- **快速开始步骤（Quickstart Step）**：有序命令或管理台操作，具有命令文本、前置条件与预期结果；站点、README 与演示共用一个事实源。
- **演示记录（Demo Transcript）**：一次真实 CLI 执行的命令、输出行、退出码、采集时间与脚本化来源标记；原始记录可为中文 CLI 标签，展示层统一为英文。

## Success Criteria *(mandatory)*

- **SC-001**: 一位没有项目背景的读者，只按公开 README 从干净环境操作，能完成"初始化 → 创建 Agent → 配置并启用 → 首次对话 → 查看会话"，不需要未记录的手工步骤，也不需要手改生命周期状态文件。
- **SC-002**: 四页 × 两种语言共八个地址全部可访问；从任一页面切换语言后停留在同一页面与锚点，成功率为 100%。
