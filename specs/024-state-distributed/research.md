# US24 实施研究

- Decision：执行权统一进一张 `execution_leases`（`kind` / `resource_id` / `owner_worker_id` / `ownership_epoch` / 到期时刻），Run、定时执行行与 Flow 根共用同一续约、回收与 fencing 语义。Rationale：单一表 + 单一端口才能让回收与续约竞争同一行锁，避免三套近似实现漂移；Alternative：每类资源各建租约表或进程内视图拒绝（回收无法用一条 `SKIP LOCKED` 领取、代次语义会分叉）。
- Decision：租约时间一律用数据库时间，SQL 内换算 `(extract(epoch from clock_timestamp())*1000)::bigint` 后与 bigint 毫秒列比较 / 写入。Rationale：多 Worker 的本机时钟不可信，列类型是 bigint、PostgreSQL 无 bigint 与 timestamp 直接比较的运算符；Alternative：应用侧 `time.Now()` 或把列改成 timestamp 拒绝（跨机时钟偏差会伪造过期或掩盖过期）。
- Decision：受归属保护的写入统一经 `FencedTx`：同一事务先从租约行 `SELECT … FOR UPDATE`，再校验 owner + epoch + 未过期，最后执行写函数。Rationale：行锁是唯一与续约、回收、接管串行的互斥面；快照读无法防止"校验后、提交前"的接管；Alternative：`EXISTS` 子查询或先读后判拒绝（并发用例会绿在单进程、红在多进程）。
- Decision：`Renew` 必须是对租约行的行级条件写（`UPDATE … WHERE kind/resource_id/owner/epoch AND expires_at > db_now`），命中 0 行即 `ErrLeaseLost`；`Acquire` 返回 `TookOver` 表示本次领取来自"已过期"的旧持有者。Rationale：续约本身也要与接管互斥，且 `TookOver` 是"这次领取发生了什么"的结论而非提交凭证，刻在不放 `LeaseToken`；Alternative：先读后判或把 `TookOver` 放进 token 拒绝（会把结论混进归属校验）。
- Decision：续约连续失败达到 `ttl - renewInterval` 即以 `ErrLeaseRenewDeadline` 取消执行上下文并停止新动作；取消请求（`runs.cancel_requested`）随成功续约的 `Lease.CancelRequested` 返回。Rationale：无限重试会让已失权的执行继续写；另开取消轮询通道是第二套状态通道；Alternative：固定超时重试或取消轮询拒绝。
- Decision：Run 准入的权威判定全部放进 `StartRun` 单事务：调用方 advisory lock + 三段并发计数、会话 advisory lock + 活跃 run 租约（含恢复未完成的旧 Run）、每 Worker 实例上限、发布 / 生命周期拦障、任务次数记账（pending → committed）、runs / 清单 / 引用 / 租约写入。任何一步失败整笔回滚（零占用）；提交结果未知返回 `ErrAdmissionOutcomeUnknown`，调用方按 `runID` 经 `LookupAdmittedRun` 回查、不退款不重试。Rationale：跨进程口径必须同事务，否则两个 Worker 各发一份额度、同会话并行；Alternative：内存计数 + 事后对账或分段事务拒绝（既有契约会被击穿）。
- Decision：调用方并发按 total Run / Flow Run / 交互预留三段计数，Flow 叶 Run 只算一次，`IsFlow` 标记只对 Flow 节点创建的请求为真；QPS 明确为每 Worker 软限额。Rationale：Q6 改判的原因正是"running runs + 非终态 flow_tasks"重复计数；聚合 QPS 需要共享状态或外部协调，超出本 US 范围；Alternative：以 DB 聚合 QPS 或全局硬上限拒绝（Q5 / Q10 已裁）。
- Decision：调度器删除进程内 cron 定时器，改为 `scheduled_tasks.next_fire_at` 到期扫描；领取事务用 `SKIP LOCKED` + `(task_id, planned_at)` 唯一 + `next_fire_at` CAS 插入 `started` 执行行并写 `schedule_execution` 租约；同一任务用部分唯一索引 `ux_task_executions_active (status='started')` 保证单活跃；错过宽限只写一条 `skipped`。Rationale：多 Worker 下"同一计划只执行一次"只能由数据库唯一约束表达；Alternative：共享内存或分布式锁拒绝（无独立协调服务，Q10 已排除）。
- Decision：6 段表达式、`CRON_TZ` 前缀、跳过语义、定义哈希、退休与错失记录语义逐项保留，US-10 断言等价替换。Rationale：触发源替换不应改变用户可观察语义；Alternative：借机调整表达式制式拒绝（判据面变化且无批准依据）。
- Decision：回收是独立于 cron 的固定有界循环（默认每 5s、每轮 32 条），只领取已过期或已释放租约，用 `SKIP LOCKED` + 代次条件；A 类三域（在跑 Run / 进行中执行行 / 非关闭态根行）与 B 类两域（终态残留、无 Run 的前置投递）分级处理，B 类不领租约、只用幂等条件更新。Rationale：心跳和启动时间不能证明死亡，只有租约过期是合法信号；Alternative：按心跳判死或启动全局扫描拒绝（会误改写活 Worker 的在跑行）。
- Decision：审计 `pending` 归一化（→ `unknown`）与半截工具组修复只在本次合法领取的 `run_id` 集合内执行；执行行状态只能落 `started` / `completed` / `failed` / `skipped` 四值（`limit_reached` → `completed`，`cancelled` → `failed`，无 Run → `failed` + `worker_lost`）。Rationale：作用域外改写会篡改活 Worker 的审计事实；执行行状态域是既有契约；Alternative：全表归一化或把 Run 状态原样写入拒绝（后者写错不报错、只让索引匹配不到）。
- Decision：投递恢复按被领取的 Run 作用域：`completed` / `limit_reached` 的 `pending` 残留 → `unknown`，其余终态 → `skipped`，无 Run 的前置投递只有在 `execution_id` 对应 `schedule_execution` 租约失效时才 → `skipped`；永不自动重发。Rationale：提交未知不等于未发生；重发会产生重复通知；Alternative：加投递幂等头并重发拒绝（Q9 已裁：不增加）。
- Decision：Flow 根推进前领取 `flow_root` 租约；`TookOver=true` 必须先 `Recover` 再 `Advance`，`TookOver=false`（前手主动释放）可直接推进；`Recover` 出错不释放租约（下一轮仍为接管）。接管递增 `execution_epoch` 并与既有条件提交组合。Rationale：正常交棒与接管是两种语义，混用会让"上一轮查证没做完"被当作正常推进；释放租约会让下一轮退化成正常交棒；Alternative：统一先查证或出错即释放拒绝。
- Decision：跨 Worker 用三个独立判据（`SubtreeGate`）：`HasLiveRunLease`（反面 = `Isolated`，只放行 `Recover`）、`HasInFlightNodeAttempt`（反面 = `Joined`，只放行 `Advance`）、`HasUnresolvedAction`（`outcome IN ('dispatching','unknown')` 为真则不得推进且必须 `Abandon`，逼下一轮 `TookOver=true`）。`interrupted` / `unknown` 是查证输入、不算 `Joined`；已完成节点按运行证据复用、不重跑。Rationale：把"还有没有人能提交"与"还有没有在飞尝试"合成一个判据会形成循环依赖——`interrupted` / `unknown` 只能由 `Recover` 清除而 `Recover` 又要求它们先消失；未决动作是第三种独立风险；Alternative：单一 `Joined` 或按子 Run 终态判定拒绝（R3 / R4 / R7 已逐条改判）。
- Decision：关闭类 Flow 写入（`blocked` / `cancelling` / `cancelled` / `abandoned` / 带关闭意图）不要求根租约，但必须携带 `Isolated` 才能收敛 `prepared` / `running` → `interrupted`；推进类写入按 `root_task_id` 校验根租约（子任务写入走父根）；管理面 `resume` / `revise` 零 token 时自取，`ErrLeaseHeld` → 409 `FLOW_ROOT_BUSY`。Rationale：关闭路径在租约被占时仍须可停住，而收敛必须知道旧执行是否已隔离；子任务行按自身 id 查不到根租约；Alternative：关闭也要求租约（节点运行期会 409，把安全机制装反）或省略 `Isolated`（关闭态 attempt 永不收敛）拒绝。
- Decision：跨 Worker 取消写 `runs.cancel_requested`，属主在续约响应 / 检查点观察并自行收敛；非属主只写标志、如实返回当前状态。归档先立准入屏障（`agent_lifecycle.state` 置非 active，原状态落 `management_operations.detail_json`），再发取消、再有界等待，超时才按原状态回滚并 409。Rationale：取消是属主职责，非属主无法保证在途请求停止；归档若先等待再改状态，窗口内新 Run 会继续进入；Alternative：非属主直接写终态或"等待后置 disabled"拒绝（Q7 / Q8 已裁）。
- Decision：停机顺序固定为"停止领取 → 排空期间继续续约 → 等待执行与收尾退出 → 释放租约 → 关闭数据库"；超过 `worker.shutdown_grace` 直接退出（不 Release、不关库）；总在途由 `worker.max_inflight` 池化信号量统一约束（三条执行路径共用），交互 Run 满额立即 `TOO_MANY_RUNS` 不排队；join 使用剩余停机预算而非再等完整 `cancel_wait`。Rationale：先停续约会被他人接管、先释放会让收尾与释放竞争；Alternative：固定预算或交互 Run 等待取槽拒绝（已验证会超停机宽限）。
- Decision：资产以内容寻址 bundle（manifest + 逐文件 SHA-256 + `bundle_hash`）安装到 `<bundle_root>/bundles/<agent>/<bundle_hash>` 不可变目录；`Install` 返回路径、`Resolve` 返回值与执行期读取路径逐字一致；安装新版不改旧目录，旧 Run 固定在原目录。准入在本地 bundle 与共享发布记录（`resource_pointers` → `resource_versions.content_hash`）不一致时 fail-closed（`ASSET_UNAVAILABLE` 503 / `ASSET_VERSION_MISMATCH` 409）。Rationale：跨 Worker 版本漂移是分布式下最隐蔽的语义问题，内容寻址是唯一可验证的固定方式；Alternative：可变 `current` 指针或"能塞就塞 v2"拒绝（旧 Run 会读到新资产；Q11 已选 v3）。
- Decision：生命周期准入加代次守卫：本地代次低于索引拒绝；高于索引**不自动放行**（须走管理操作单调修复）；同代次只接受逐项内容完全一致的幂等写（异内容拒绝）；启动自举只在代次与索引相等、且从共享发布记录构建时发生。Provider 比对 `published_version_id`、MCP 比对 `applied_version_id`，本地实例 `BuiltVersion()` 两段（版本引用 + 凭据 pin）不符时按同一目标版本重建-换入-再比，仍不符 503；准入不隐式 apply。Rationale：自动放行高代次会把"本地比共享新"误当成已发布；MCP 新版本未被 apply 时顺手应用会绕过管理员；Alternative：按最高代次放行或每次准入重建拒绝（Q12 / Q20 / P-21）。
- Decision：迁移 `0012` 停机前向追加，回填三类在途行（`runs.status='running'`、`task_executions.status='started'`、非关闭态 Flow 根）为 `legacy` / 0 / **已过期**（`expires_at = 迁移时刻`），关闭态根（cancelling / 带关闭意图 / 已过 deadline）不回填；时间用同一事务内恒定的 `now()` 表达，不依赖运行器参数。Rationale：停机迁移时旧进程已不在，遗留租约应立即被首轮回收领取；关闭态根由 `sweepClosures` 推进、不领租约；Alternative：`$1` 占位（内存运行器直接报错）或 `now()+ttl`（拉长无人收尾窗口）拒绝。
- Decision：本 US 零新增第三方坐标；`go.mod` / `go.sum` 与起点空 diff；哈希 / 随机 / 时间全部标准库。Rationale：原则 VIII 依赖最小化，且本 US 无必须引入外部库的能力；Alternative：引入租约库 / 内容寻址库拒绝（表外坐标）。
