## User Scenarios & Testing

### User Story 1 - Worker 身份、执行租约与归属保护写入 (Priority: P1)

每个 `serve` / `gateway` 进程启动时生成进程级唯一的实例标识并登记；此后所有运行类执行（交互 / 调度的每次 Run、一条定时执行行、一个 Flow 根）都先取得数据库租约——负责人、单调递增的归属代次、数据库时间计算的到期时刻。续约必须匹配负责人与代次；受归属保护的一切写入（消息追加、工具结果、恢复补齐、状态推进、Run 终态、审计 `pending` 预写、学习抽取的 Begin / Fail / Commit）都在同一事务里先锁租约行、再校验归属与有效期，不匹配即拒绝。续约连续失败达到 `ttl - renewInterval` 即有界停止并取消执行上下文。

**Why this priority**: 没有租约与 fencing，多 Worker 下旧持有者会覆盖新结果——这是本模块全部其它能力的地基。

**Independent Test**: 在隔离 schema 构造两个负责人：接管后旧负责人调用消息追加 / 工具结果回填 / 恢复补齐 / 状态推进 / 审计预写 / 学习三写面，全部返回失权错误且零行写入；keeper 在续约持续失败时于预算内取消上下文。

**Acceptance Scenarios**:

1. **Given** 新起的 `serve` 进程，**When** 启动完成，**Then** 身份已登记且心跳可读；重复的 `Name` 允许、`InstanceID` 互不相同；未知租约类型被拒绝（fail-closed）。
2. **Given** Worker A 持有 Run 租约，**When** 服务端使用另一负责人或另一代次续约，**Then** 续约被拒；用 A 的身份续约则成功且不递增代次。
3. **Given** Worker A 的租约已过期但尚未被接管，**When** A 提交终态或任一受保护写入，**Then** 返回失权错误、零行写入。
4. **Given** B 已接管同一 Run，**When** A 恢复后提交终态，**Then** 返回失权（`applied=false`），B 的结果不被覆盖。
5. **Given** 续约连续失败，**When** 累计达到 `ttl - renewInterval`，**Then** 执行上下文以"续约到期"原因取消，不再发起新动作；未达预算前的瞬时失败不误停。
6. **Given** 旧持有者持租约行锁未提交，**When** 接管方尝试 `FOR UPDATE SKIP LOCKED` 领取，**Then** 领取返回 0 行且不提交任何变更；旧持有者提交后接管才成功。
7. **Given** 同一来源的第二次学习尝试（RunB 持有效租约），**When** 调用 `BeginExtraction`，**Then** 命中重试路径（行回 `pending`、尝试次数递增、`run_id` 不变）而非被判失权。

### User Story 2 - 跨 Worker 准入：会话串行、并发与配额同事务 (Priority: P1)

Run 准入的权威判定全部进入数据库并收进同一个事务：调用方并发按 total Run / Flow Run / 交互预留三段计数、同一会话最多一条未过期 Run 租约（事务 advisory lock 内复查）、实例上限仍按每个 Worker 计、周期配额与任务次数记账同事务提交。错误优先级与既有契约一致：入口 QPS → 调用方 QPS → 调用方并发 → 会话忙 → 实例上限 → 配额耗尽；被拒请求零占用（不产生 Run 行、不扣配额、不建租约）。调用方 QPS 明确是每 Worker 软限额，不承诺集群聚合硬上限。

**Why this priority**: 会话串行与配额是多 Worker 下最先被击穿的契约；没有同事务准入，两个进程会各发一份完整额度、同一会话并行。

**Independent Test**: 两个 Scheduler / App 共享同一隔离 schema，并发发起同会话 Run 与同一调用方配额请求；断言恰好一个成功、另一个 409 且零占用；配额在边界两侧各算一次；错误优先级按序返回。

**Acceptance Scenarios**:

1. **Given** 两个 Worker，**When** 同一 `session_id` 同时发起 Run，**Then** 恰好一个进入 `running`，另一个 409 `SESSION_BUSY` 且不排队。
2. **Given** 旧 Run 正被接管、恢复事务持会话锁未提交，**When** 同会话新 Run 准入，**Then** 它在恢复提交前不返回成功；提交后按旧 Run 状态返回 409 或成功。
3. **Given** 每个 Worker 的实例上限为 N，**When** 两个 Worker 各跑 N 个 Run，**Then** 都未被误拒（上限不是全局）。
4. **Given** 配额余量为 1 且准入事务中写 Run 失败，**When** 事务回滚，**Then** 配额余量仍为 1、无 Run 行、无租约。
5. **Given** 入口 QPS、调用方 QPS、并发、会话忙、实例上限、配额耗尽同时成立，**When** 发起准入，**Then** 依次返回约定顺序中的首个错误。
6. **Given** 两个独立限流器实例（同一配置、不共享状态），**When** 各放行 N 个请求，**Then** 各自拒绝后续请求，总放行为 2N（每 Worker 软限额）。
7. **Given** 提交结果未知，**When** 调用方回查，**Then** 按已写入的 Run 行与租约得到确定结论；不退款、不重试。

### User Story 3 - 数据库到期扫描与计划触发去重 (Priority: P1)

定时任务不再依赖进程内 cron 定时器：注册 / 推进时计算下次到期时刻，调度循环按数据库到期扫描领取；领取在单事务内插入 `started` 执行行、以行条件更新推进下次到期时刻、写执行租约。同一计划触发（任务 + 计划时刻）最多一条执行；同一任务同时最多一条 `started` 执行；错过窗口超过宽限只记一条 `skipped` 并推进，不制造补跑风暴。6 段表达式、时区前缀、跳过语义、定义哈希与退休语义保持不变。

**Why this priority**: 触发去重是多 Worker 下"同一计划只执行一次"的直接保证，也是五个每日 Demo 的底座。

**Independent Test**: 两个调度循环并发扫描同一到期任务；每个计划时刻恰一行执行、第二次领取返回已领取错误；错失窗口只产生一条 skipped；手动补跑在已有 started 时返回任务忙。

**Acceptance Scenarios**:

1. **Given** 一条到期任务，**When** 两个 Worker 同时领取同一计划时刻，**Then** 一个成功、一个返回 `ErrTriggerAlreadyClaimed`，执行行只有一条。
2. **Given** 某计划时刻已错过且超出宽限，**When** 扫描推进，**Then** 只写一条 `skipped` 并把下次到期推进到未来。
3. **Given** 同一任务已有 `started` 执行，**When** 另一触发或手动补跑到达，**Then** 被拒（任务忙 / 跳过），不产生第二条 `started`。
4. **Given** 执行租约过期（Worker 崩溃），**When** 回收运行，**Then** 执行行被收尾，不永远停在 `started`。
5. **Given** 下次到期时刻已被他人推进，**When** 本 Worker 用旧期望值更新，**Then** 返回"下次到期已变化"，不覆盖。

### User Story 4 - 作用域回收：只碰合法领取的过期 / 已释放租约 (Priority: P1)

回收是独立于 cron 的固定有界维护循环：用 `SKIP LOCKED` + 代次条件领取已过期或已释放的租约，按作用域收尾 Run、执行行与 Flow 根；审计 `pending` 归一化（`unknown`）与半截工具组修复只作用于本次合法领取的 `run_id` 集合；终态残留（含 `limit_reached`）的引用释放与投递结算按幂等条件更新补齐；无 Run 的前置投递只写 `skipped`、不重发。启动不再做全局恢复扫描。

**Why this priority**: 没有作用域回收，第二个 Worker 启动时会把第一个 Worker 在跑的 Run 标成失败，且活 Worker 的审计事实会被篡改。

**Independent Test**: 构造活租约与过期租约并存、终态残留与无 Run 投递；断言回收只动过期 / 已释放者，活 Run 与其审计行一字未改；执行行状态只落四值。

**Acceptance Scenarios**:

1. **Given** 一个未过期租约覆盖的在跑 Run，**When** 回收运行，**Then** 该 Run 及审计行不被改动。
2. **Given** 一个已过期租约的 Run 带 `pending` 审计，**When** 回收收尾，**Then** 审计归一化为 `unknown`、Run 收尾为 `failed`，且只限该 `run_id`。
3. **Given** 终态 Run 残留引用（资源 / 凭据 / 通知三表任一）或 `pending` 投递，**When** 回收运行，**Then** 残留计数归零：`completed` / `limit_reached` 的投递 → `unknown`，无 Run 的投递 → `skipped`，均不重发。
4. **Given** 前置投递的 `execution_id` 对应租约仍有效，**When** 回收运行，**Then** 该投递不动。
5. **Given** 学习抽取 `pending` 且其最近尝试 Run 的租约已失效，**When** 回收运行（进程不重启），**Then** 该行被查证（`success` / `unknown`）并推进游标，不重放；若扫描后发生合法重试，本轮零写入跳过。
6. **Given** 回收循环与 cron 无关，**When** 只看固定间隔运行，**Then** 每轮条数与总时长有界，且全程零模型 / 工具调用。

### User Story 5 - Flow 根租约、接管恢复与两判据推进 (Priority: P1)

Flow 根在推进前领取根租约；正常交棒（前手主动释放）可直接推进，接管（前手过期）必须先查证再推进。跨 Worker 用两个独立判据：`Isolated`（根子树无仍有效 Run 租约）只放行查证（并把整棵子树的进行中尝试收敛为 `interrupted`），`Joined`（根子树无 `prepared` / `running` 尝试）只放行推进；`interrupted` / `unknown` 是复用 / 查证输入而非障碍。子树存在未决动作（已派发未定 / 未知结果）时不得推进，且必须放弃本轮租约把下一轮逼成接管后先查证。子 Run 创建校验父根租约、父根归属与尝试代次；管理面要求推进但根租约被他人持有时返回 409 `FLOW_ROOT_BUSY`。

**Why this priority**: Flow 是最容易永久卡死或重复派发的路径——判据合并会形成"查证等推进、推进等查证"的死循环。

**Independent Test**: 构造子 Run 仍 running 而租约已过期、`prepared` 无 Run、`interrupted` / `unknown` 尝试等状态；断言两判据独立取值、收敛只按 `Isolated`、终态不伪造。

**Acceptance Scenarios**:

1. **Given** 根租约被 A 持有，**When** B 尝试领取，**Then** B 不推进（领取不成功）。
2. **Given** 根租约已过期、B 接管成功，**When** B 开始本轮，**Then** 先查证再推进；查证遇到瞬态错误时不释放租约，下一轮仍为接管并再次查证。
3. **Given** 子 Run 仍 `running` 但租约过期，**When** 读取判据，**Then** `Isolated=true`（可查证）且 `Joined=false`（不得推进）；查证收敛后 `Joined` 才为真。
4. **Given** 子树存在 `dispatching` / `unknown` 动作且根处于可领取状态，**When** 普通 Worker 以正常交棒领取，**Then** 不派发任何新 Run / 动作、两张审计表零新行、根租约不被释放；下一轮过期接管后进入查证，仍未决则再次放弃租约。
5. **Given** 已完成节点在接管后，**When** 推进，**Then** 复用既有运行证据，不重新执行。
6. **Given** 管理面要求推进而根租约被 Worker 持有，**When** 提交，**Then** 返回 409 `FLOW_ROOT_BUSY`、Flow 一行未改；租约释放后同一请求成功。
7. **Given** 跨根尝试或旧任务修订的尝试，**When** 创建子 Run，**Then** 被拒（尝试过期），不建 Run。

### User Story 6 - 跨 Worker 取消、归档屏障与停机顺序 (Priority: P2)

取消请求写数据库标志，由属主在续约 / 检查点观察并自行收敛；非属主只写标志、如实返回当前状态。归档先立准入屏障（生命周期状态置非 active 并记录原状态），再发取消、再有界等待，超时按原状态回滚并 409。停机按"停止领取 → 排空期间继续续约 → 等待执行与收尾退出 → 释放租约 → 关闭数据库"执行；总在途 goroutine 受统一上限约束，交互 Run 与后台共享同一池、满额立即拒绝不排队；超过停机宽限直接退出（不释放、不关库）。

**Why this priority**: 取消与归档决定"多 Worker 下用户操作是否诚实"；停机顺序决定升级窗口内是否会被接管或死等。

**Independent Test**: 非属主取消后属主在续约响应中观察到标志并收敛；归档等待窗口内新 Run 被拒；停机全程断言续约持续、释放晚于收尾、连接最后关闭。

**Acceptance Scenarios**:

1. **Given** Run 由另一 Worker 执行，**When** 本 Worker 收到取消，**Then** 写取消标志并返回当前状态，不声称已取消；属主在下一次续约 / 检查点观察到并收敛。
2. **Given** 归档开始，**When** 等待窗口内到达新 Run，**Then** 立即被拒（屏障生效）且不产生 Run 行；超时回滚后恢复准入。
3. **Given** 远端 Run 仍在跑，**When** 归档，**Then** 不移动目录、不宣称完成。
4. **Given** 停机信号，**When** 排空，**Then** 停止领取新任务、期间继续续约、待执行与收尾退出后才释放租约、最后关闭数据库；另一 Worker 在释放后即可接管而无需等租约到期。
5. **Given** 总在途数已达上限，**When** 交互 Run 到达，**Then** 立即返回 `TOO_MANY_RUNS`（不等待）；后台任务阻塞且可被停机取消。
6. **Given** 停机宽限耗尽仍有未退出执行，**When** 进程退出，**Then** 不做释放、不关数据库，由租约到期后接管。

### User Story 7 - 内容寻址资产、生命周期代次与准入 fail-closed (Priority: P2)

Agent 配置与技能版本可导出为内容寻址 bundle（manifest + 逐文件哈希 + 总哈希），安装到按哈希寻址的不可变目录，执行只消费 manifest 固定的目录；截断 / 损坏被拒收且不破坏已装内容，旧 Run 在安装新版后仍读原目录。准入同时校验本地 bundle 与共享发布记录、生命周期代次（低于索引拒绝；高于索引不自动放行；同代次只接受内容一致的幂等写）、本地 Provider / MCP 实例的版本引用与凭据绑定（Provider 对已发布版本、MCP 对已应用版本，不一致按同一目标版本重建再比，仍不符即 503）。安装、解析与执行期读取三处路径逐字一致。

**Why this priority**: 不同 Worker 用不同版本的 Agent / 技能接同一任务是分布式下最隐蔽的语义漂移；准入是唯一拦截点。

**Independent Test**: bundle 往返与截断拒收；bundle 缺失 / 不符、代次回退、同代次异内容、供应商实例版本不符、MCP 未应用版本、凭据换代的六个准入拒绝 / 重建路径；旧 Run 目录不漂移。

**Acceptance Scenarios**:

1. **Given** 一份有效 bundle，**When** 导出、安装、校验往返，**Then** manifest 与逐文件哈希一致；截断后安装失败且原目录不变。
2. **Given** 本地 bundle 与共享发布记录不一致或缺失，**When** 新 Run 准入，**Then** 503 `ASSET_UNAVAILABLE` / 409 `ASSET_VERSION_MISMATCH`，不产生 Run 行。
3. **Given** 本地代次低于索引，**When** 准入或写索引，**Then** 拒绝、索引不回退；本地代次高于索引时准入拒绝且启动不自举索引。
4. **Given** 同代次但内容不同，**When** 写索引，**Then** 拒绝（`AGENT_LIFECYCLE_MISMATCH`）；内容逐项一致则幂等成功。
5. **Given** MCP 已发布新版本但未应用，**When** 准入，**Then** 按已应用版本放行且清单记录该版本，不隐式应用新版本。
6. **Given** 版本不变但托管凭据换代，**When** 准入，**Then** 以凭据绑定不符判定并按新凭据重建后才放行；重建失败则 503。
7. **Given** 旧 Run 固定在哈希 H1，**When** 安装 H2，**Then** 旧 Run 仍读 H1 目录。
8. **Given** 安装结果、解析与执行期读取，**When** 比较路径，**Then** 三者逐字相等且都含不可变根段。

### User Story 8 - 停机迁移、升级兼容与依赖纪律 (Priority: P3)

新增数据库结构以前向迁移追加：为在途的 Run、执行行与非终态 Flow 根回填"遗留负责人、代次 0、已过期"的租约，关闭态根不回填；数据库版本递增，迁移幂等。升级采用停机迁移：v11 库执行迁移后启动新 Worker，三类回填租约在首轮回收中被领取并收尾。不新增任何第三方坐标，发布构建保持单二进制；诊断只增加 Worker 实例与归属代次关联属性，不引入跨节点全局序号。

**Why this priority**: 迁移与升级规则决定老库能否安全升到新版本；依赖与诊断纪律是收口判据而非功能增量。

**Independent Test**: v11 隔离 schema 构造三类在途行与两类关闭态根，执行迁移后断言回填与不回填各就位、版本为 12；首轮回收收尾三类行；`go.mod` / `go.sum` 空 diff。

**Acceptance Scenarios**:

1. **Given** v11 库含在途 Run / 执行 / 非终态 Flow 根，**When** 执行迁移，**Then** 三类各得一条遗留租约且已过期，关闭态根不产生租约，版本为 12。
2. **Given** 迁移完成，**When** 首个新 Worker 回收，**Then** 三类回填租约都被领取并收尾。
3. **Given** 迁移重复执行，**When** 再次运行，**Then** 幂等无报错、无重复租约。
4. **Given** 本 US 全部改动，**When** 核对依赖，**Then** `go.mod` / `go.sum` 与起点空 diff，发布构建 `CGO_ENABLED=0` 可产单二进制。
5. **Given** 诊断事件，**When** 检查关联字段，**Then** 只含既有事件 / 步骤标识加 Worker 实例与归属代次，无全局序号。

### Edge Cases

- 租约行不存在（该 Run 从未领取过租约）时，恢复写入跳过而不是把"无租约"当"已失权"误报。
- 续约与回收并发：回收写入必须等续约事务提交或回滚后再用数据库时间重判；不得把"等待中的行锁"当超时失败。
- 学习抽取的 fence 对象是**触发 Run**（本次尝试），不是首次创建行的 Run，也不是上次尝试的 Run；合法重试不得被误判失权。
- 学习抽取窗口已消失的受控收尾：必须同时满足当前租约有效、来源一致、预期旧尝试一致；任一不符不写。
- `limit_reached` 的 Run 收尾时执行行只能写 `completed`（四值域），不得把 Run 状态原样写进执行行。
- 关闭类 Flow 写入（blocked / cancelling / cancelled / abandoned）不要求租约，但必须携带 `Isolated` 才能收敛尝试；推进类写入必须按根 `root_task_id` 检查父根租约。
- deadline 关闭的终态是 `stopped`，不得写成 `cancelled`。
- 管理面 resume / revise 在零租约时需要自取；`ErrLeaseHeld` 映射 409 `FLOW_ROOT_BUSY`，不得漏成 500。
- 归档超时回滚依赖持久化的原状态；进程崩溃后不得让 Agent 永久停在 disabled。
- 收到停机信号后新领取为 0 条；`shutdown_grace` 内未完成的执行不释放租约。
- 本机时钟前后拨动不影响续约 / 回收判定（只用数据库时间）。
- Worker `Name` 重复、`InstanceID` 不同：两个身份并存，互不覆盖。
- 未知租约类型（数据库行或调用方传入）：解析错误、fail-closed。

## Requirements

### Functional Requirements

- **FR-24-01**: 每个进程必须生成唯一实例标识并登记（名称、主机、版本、装载的数据库结构版本、启动时刻、心跳）；心跳只作诊断、不构成占有权证明；注册 / 心跳 / 停止必须可读。
- **FR-24-02**: 启动不得做全局恢复扫描；恢复只作用于合法领取的过期 / 已释放租约，不得改写其他活实例的在跑行。
- **FR-24-03**: 每次 Run 的 Run 行、资源清单、引用、Run 租约创建，以及任务次数记账、发布与生命周期复查，必须在同一事务内完成；任一步失败整笔回滚（零占用、不扣配额、不留租约）。
- **FR-24-04**: 续约必须同时匹配负责人、归属代次且租约未过期；过期后即使尚未被接管，原负责人也不得继续提交。
- **FR-24-05**: 续约连续失败达到 `ttl - renewInterval` 时，执行上下文必须以"续约到期"原因取消，停止发起新动作；不得无限重试，不得声称在途外部请求被撤销。
- **FR-24-06**: Run 终态提交必须带归属凭证做 fencing，只写终态列；不得在终态写入中释放引用、结算投递或释放租约；0 行必须区分"已终态"（幂等成功）与"失权"。
- **FR-24-07**: 同一会话跨 Worker 同时最多一条未过期 Run 租约；准入必须在事务 advisory lock 内复查并插入，忙碌即拒绝不排队（409）；恢复未完成期间租约不释放，旧会话在新 Run 准入时仍为忙碌。
- **FR-24-08**: 实例并发上限必须按每个 Worker 独立计算，不得当作全局上限。
- **FR-24-09**: 调用方周期配额必须数据库记账、跨 Worker 生效；硬配额状态无法核实时必须拒绝新增受控消耗。
- **FR-24-10**: 定时触发必须以（任务、计划时刻）唯一约束去重，下次到期推进必须是行条件更新；一次计划触发只能产生一条执行。
- **FR-24-11**: 重复领取同一计划触发必须返回"已被领取"错误，不得产生第二条执行。
- **FR-24-12**: 错过窗口超过宽限时必须只记一条 `skipped` 并推进到未来，不得逐点补跑。
- **FR-24-13**: 同一任务同时最多一条 `started` 执行；手动补跑冲突必须返回既有"任务忙"错误。
- **FR-24-14**: 执行租约过期后必须由回收收尾执行行，不得永远停在进行中。
- **FR-24-15**: 回收必须只处理已过期或已释放的租约，并用 `SKIP LOCKED` + 代次条件领取；不得按心跳、启动时间或"看起来很久"推断旧节点已死；不得触碰未过期租约覆盖的在跑工作。
- **FR-24-16**: 审计 `pending` 归一化与半截工具组修复必须限定在本次合法领取的 Run 集合内；无租约的 `pending` 行只报告、不得静默改写。
- **FR-24-17**: 回收循环必须独立于定时调度、固定有界（条数上限 + 超时），不得执行业务推进或模型 / 工具调用。
- **FR-24-18**: Flow 根推进前必须持有根租约；领取结果为"接管"时必须先查证再推进，"正常交棒"才可直接推进。
- **FR-24-19**: 接管必须递增 Flow 执行代次并拒绝旧代次提交；既有代次条件提交必须保留并与租约代次组合。
- **FR-24-20**: 必须区分两个跨 Worker 判据：`Isolated`（根子树无仍有效 Run 租约）只放行查证；`Joined`（根子树无 `prepared` / `running` 尝试）只放行推进；`interrupted` / `unknown` 不得计入 `Joined`；不得用租约到期推断子 Run 已退出；已完成节点必须按运行证据复用而非重跑。
- **FR-24-21**: 投递 `pending` 恢复必须按被领取的 Run 作用域：`completed` / `limit_reached` 的残留 → `unknown`，无 Run 或其余终态 → `skipped`，永不自动重发。
- **FR-24-22**: 跨 Worker 取消必须写数据库标志并由属主在续约 / 检查点观察；非属主只写标志、如实返回当前状态，不得假装取消成功。
- **FR-24-23**: 归档必须拒绝远端在跑；准入屏障必须覆盖所有 Worker，不得只查本地忙碌即移动目录或宣称完成。
- **FR-24-24**: 资产 bundle 必须支持构建 / 导出 / 安装 / 校验往返并带逐文件哈希；截断或损坏必须拒收且不破坏已安装内容。
- **FR-24-25**: 资产与生命周期准入必须 fail-closed：bundle 缺失 / 哈希不符 / 技能版本不符拒绝新 Run；本地代次低于索引拒绝；高于索引不得自动放行；同代次只接受逐项内容完全一致的幂等写；本地 Provider / MCP 实例的版本引用与凭据绑定必须与目标版本一致（Provider 对已发布版本、MCP 对已应用版本），不一致时按同一目标版本重建再比，仍不符返回 503；准入不得隐式应用 MCP 新版本。
- **FR-24-26**: 诊断关联必须使用 Worker 实例标识 + 归属代次 + 既有事件 / 步骤 / 父步骤标识；不得引入跨节点全局序号，不得把接收顺序当执行顺序。
- **FR-24-27**: 停机必须按"停止领取 → 排空期间继续续约 → 等待执行与收尾退出 → 释放租约 → 关闭数据库"执行；超过停机宽限仍未退出必须直接退出进程，不释放、不关库；审计终态写必须使用不随取消中止的独立短超时。
- **FR-24-28**: 迁移必须前向追加：为在途 Run、执行行与非终态 Flow 根回填"遗留负责人、代次 0、已过期"的租约，关闭态 / 带关闭意图 / 过期 deadline 的根不回填；数据库版本递增，迁移幂等；不得改写已发布迁移或冻结基线。
- **FR-24-29**: 不得新增第三方依赖坐标；发布构建必须 `CGO_ENABLED=0` 且与竞态检测分属不同命令；`go.mod` / `go.sum` 与本 US 起点必须空 diff。
- **FR-24-30**: 未知租约类型必须拒绝（fail-closed）；重复 Worker 名称必须允许、身份由实例标识决定。
- **FR-24-31**: 升级兼容判据必须是：v11 库执行停机迁移后，三类回填租约在首轮回收中被领取并收尾；不得模拟在线混跑；停机迁移期间旧、新二进制不得并存运行（Q15）。
- **FR-24-32**: 调用方 QPS 必须明确为每 Worker 软限额；集群聚合总量不得承诺硬上限。
- **FR-24-33**: 任务次数记账必须与权威准入、Run 写入、租约创建同事务；提交结果未知必须按幂等键回查，不得直接退款或重试。
- **FR-24-34**: 准入错误优先级必须为：入口 QPS → 调用方 QPS → 调用方并发 → 会话忙 → 实例上限 → 配额耗尽；被拒请求零占用。
- **FR-24-35**: 续约失败的有界停止必须有独立单元用例覆盖（与 FR-24-05 同一语义，层次在 keeper）。
- **FR-24-36**: 受归属保护的写入必须统一经同一事务内的"先锁租约行、再校验负责人 + 代次 + 未过期"路径（不得退化为快照存在性检查）：覆盖消息追加、工具结果、恢复补齐、状态推进、审计 `pending` 预写、学习抽取三写面；两种获锁顺序都必须成立（旧持有者持锁时接管等待；接管后旧写入被拒且零行）；合法重试不得被误拒；窗口消失的受控收尾必须校验当前租约 + 同来源 + 预期旧尝试。
- **FR-24-37**: 接管必须先查证再推进；查证出错不得释放租约（下一轮仍为接管并重试查证）；回收对阻塞根按原因分路（租约过期由回收自己重入排队，返工要求不动，子 Run 租约仍有效则不动）；子 Run 创建必须校验父根租约、父根归属与尝试代次 / 任务修订，旧尝试拒绝；管理面要求推进而根租约被持有时返回 409 `FLOW_ROOT_BUSY`，不重试、不降级为无租约写入；子树存在未决动作（已派发 / 未知结果）时不得推进且必须放弃本轮租约（不释放），下一轮逼成接管后查证；普通 Worker 以正常交棒领取含未决动作的根时同样不得派发新 Run / 动作、不得写审计新行。
- **FR-24-38**: 判据必须分开使用（FR-24-20）：查证在 `Isolated=true` 时必须把整棵子树的 `prepared` / `running` 尝试收敛为 `interrupted`，`Isolated=false` 时尝试一字不动；关闭路径（根自身、后代、deadline 三处）的收敛必须改按 `Isolated`，范围覆盖整棵子树；关闭状态推进仍按 `Joined`；deadline 终态必须是 `stopped`。
- **FR-24-39**: 回收必须覆盖 A 类三域（在跑 Run / 进行中执行行 / 非关闭态的根行）与 B 类两域（终态残留、无 Run 的前置投递）：终态残留（含 `limit_reached`）的引用释放必须覆盖资源 / 凭据 / 通知三表；终态 Run + `pending` 投递 → `unknown`，无 Run 的前置投递 → `skipped`（仅当其执行租约已失效）；B 类不得领租约、必须用幂等条件更新；执行行状态只能落 `started` / `completed` / `failed` / `skipped` 四值（`limit_reached` → `completed`，`cancelled` → `failed`，无 Run → `failed` + 原因 `worker_lost`）；孤儿学习抽取只查证不重放，进程不重启也能解阻，写入事务必须带预期值重检（扫描后合法重试则本轮跳过），重检必须按"Agent 锁 → 租约行 → 抽取行"顺序加锁并与续约串行。
- **FR-24-40**: 停机顺序（FR-24-27）之外，总在途数必须受统一上限约束（交互 Run / 调度执行组 / Flow 节点共用同一信号量）；满额时后台阻塞且可被停机取消，交互 Run 立即拒绝不排队；等待执行退出必须使用剩余停机宽限而非再等完整取消窗口。
- **FR-24-41**: 归档必须先立准入屏障（生命周期状态置非 active、原状态持久化），再发取消、再有界等待；屏障与准入复查必须是同一行的行锁互斥；超时才按原状态回滚并 409；两种真实获锁顺序都必须成立。
- **FR-24-42**: 资产必须按内容哈希存于不可变目录，执行只消费 manifest 固定目录，安装新版不得改动旧目录；生命周期同代次异内容必须拒绝；本地代次超前不得写索引且该 Agent 不可准入；准入必须比对期望代次与状态文件哈希。
- **FR-24-43**: 会话准入与接管恢复必须共享同一互斥边界：恢复事务持会话锁未提交时，并发同会话准入不得在恢复提交前返回成功。
- **FR-24-44**: 资产安装返回路径、解析返回值与执行期读取路径必须逐字一致且都含不可变根段。

### Key Entities

- **Worker 实例（Worker Instance）**: 进程级身份——实例标识、人读名称、主机、构建版本、装载的数据库结构版本、启动时刻、最近心跳、停止时刻。
- **执行租约（Execution Lease）**: 一条资源的执行权——类型（Run / 定时执行 / Flow 根）、资源标识、负责人、归属代次、取得 / 续约 / 到期 / 释放时刻；到期只表示可被接管，不表示已经接管。
- **租约事件（Lease Event）**: 状态转换记录——领取 / 接管 / 释放 / 续约失败 / 回收；运维记录，不是审计结论。
- **计划触发（Planned Trigger）**: 一次逻辑触发时刻，身份为（任务、计划时刻）；与执行尝试（执行行）是不同层次。
- **执行行（Task Execution）**: 一次执行尝试——触发方式、计划时刻、负责人、归属代次、状态、耗时、错误。
- **资产 bundle（Asset Bundle）**: 内容寻址的 Agent 配置 + 技能版本集合，带逐文件哈希与总哈希、格式版本、Agent 身份。
- **生命周期期望（Lifecycle Expectation）**: 准入携带的期望代次与状态文件哈希，用于事务内比对索引与归档屏障。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 两个 Worker 共享同一数据库时，同一计划时刻的执行行恰好一条、同一会话同时只有一条未过期 Run 租约、同一任务同时只有一条 `started` 执行——三者在自动化用例中可重复断言。
- **SC-002**: 接管后旧持有者的终态提交、消息追加、工具结果、状态推进、审计预写与学习三写面全部被拒且零行写入；旧持有者不覆盖新结果、不重放已判定动作。
- **SC-003**: 续约持续失败时执行在 `ttl - renewInterval` 内停止且取消原因可判定；活租约覆盖的 Run 在回收中零改动。
- **SC-004**: 故障矩阵（领取竞争、崩溃接管、暂停恢复、同会话冲突、取消路由、投递未知、资产缺失、旧代次启动、停机、升级、数据库中断、时钟变化、响应丢失、网络分区）在本机双进程 / 集成层逐项有可复现记录；真实双宿主标 `未测量`。
- **SC-005**: 资产 bundle 往返可复现：截断 / 哈希不符被拒收、旧 Run 不随新安装漂移、安装 / 解析 / 执行读取三处路径逐字一致。
- **SC-006**: 迁移可前向升级：v11 库执行迁移后版本为 12、三类回填与两类不回填各就位，首轮回收收尾三类在途行；重复执行幂等。
- **SC-007**: 依赖零新增：`go.mod` / `go.sum` 与本 US 起点空 diff；发布构建 `CGO_ENABLED=0` 成功。
- **SC-008**: 并发正确性在本 US 完成前保持 `未验证`——只用静态约定不算证据；由真实 PostgreSQL 并发用例（续约交错、接管与写入交错、合法重试）取得红→绿读数后方可标已验证。
- **SC-009**: 真实双宿主、S3、数据库 HA、正式升级工具链、真实模型 / webhook 在收口证据中逐项标 `未测量` / `未授权`，不得用本地桩通过冒充。

## Assumptions

- 前序模块事实成立：US-16 已交付 PostgreSQL、调用方身份 / 配额与诊断写入；US-19 已交付同步 Flow、`execution_epoch` 条件提交与未知动作阻断；US-22 已交付学习抽取与启动查证；US-10 已交付 6 段 cron 调度语义；US-11 已交付生命周期索引；US-20 / US-21 已交付沙箱产物与技能版本清单。
- 运行后端为 PostgreSQL（v11 起步，本 US 升到 v12）；SQLite 不参与多 Worker 协调，只随既有接口签名适配。
- 多 Worker 部署在本 US 只做本机双进程自动化与本机双进程人工验证；真实 Compose / K8s 拓扑、跨机资产分发归 US-25 / US-25A。
