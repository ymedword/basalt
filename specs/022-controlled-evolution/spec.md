## User Scenarios & Testing

### User Story 1 - 默认关闭的候选生成与人工确认晋升 (Priority: P1)

本机管理员在配置中为指定 Agent 显式打开自动抽取（出厂默认关闭）。此后该 Agent 的 Web / CLI 会话正常结束时，系统在同一次请求内读取有界的新消息窗口与必要前文，经唯一模型调用入口做一次抽取，把模型返回的可信度未知的输出逐项校验为「带逐字证据的候选」落库。候选在确认前不参与召回、不进入注入；管理员在管理台「记忆 → 待确认」查看证据并选择「保留双方」或「替代旧条」确认，确认后新 Run 可召回该条。

**Why this priority**: 这是本模块的全部价值闭环——没有候选生成就没有输入，没有人工确认就没有受控晋升；两者合起来才构成「成功轨迹蒸馏为记忆草案，人在环上入库」的第一切片。

**Independent Test**: 用本地协议桩与冻结夹具完成一次 Run，断言生成 `candidate / auto_extract / archive` 候选、元数据与来源关系各一行、新 Run 召回为空；确认后条目转 `active` 且新 Run 的 keyword 与 semantic 召回均命中；整条链路不调用真实模型。

**Acceptance Scenarios**:

1. **Given** 空配置完成一次 Run，**When** 运行结束，**Then** 无抽取行、无 `memory_extract` 调用、无草案文件，Run 的输出与副作用与启用前相同。
2. **Given** 为 Agent 启用自动抽取且桩模型返回一条带合法证据的事实，**When** Run 结束，**Then** 候选以 `candidate / auto_extract / archive` 落库并带来源消息、逐字引文、形成时间、有效期与建议取代目标。
3. **Given** 一条候选，**When** 未确认时执行召回，**Then** 不返回该候选，也不进入系统提示。
4. **Given** 一条候选，**When** 管理员以「保留双方」确认，**Then** 条目转 `active`、旧条目保持不变、新 Run 可召回，回执 `superseded_id` 为空。
5. **Given** 一条带建议目标的候选，**When** 管理员以「替代」确认且目标与建议一致，**Then** 旧目标转 `superseded`、候选转 `active`、回执带 `superseded_id`。
6. **Given** 一条候选，**When** 管理员不确认或直接删除，**Then** 后续 Run 不召回，且不产生 `active` 行。

### User Story 2 - 确认门禁与来源失效复核 (Priority: P1)

自动候选的确认是唯一晋升路径：即使请求体为空（= 保留双方），也必须执行全部门禁——候选未过期、来源闭包全部有效且未过期、来源 Key 未撤销未到期、来源调用方未停用、替代目标与建议逐字一致且仍为 `active`。任一不满足返回冲突（409）并保持状态不变。

**Why this priority**: 没有门禁，「人工确认」只是点击按钮，撤权 / 停用 / 到期后的内容仍会被晋升；这是安全边界而非体验优化。

**Independent Test**: 分别制造候选到期、来源条目删除 / 到期、来源 Key 撤销 / 到期、调用方停用、替代目标被纠正等状态，确认全部 409 且候选仍为 `candidate`、目标未被误替代；并发确认恰好一个成功。

**Acceptance Scenarios**:

1. **Given** 自动候选与空请求体，**When** 确认，**Then** 仍按保留双方执行全部检查，不回落到旧确认路径。
2. **Given** 显式提议候选，**When** 确认，**Then** 保持既有确认语义不变。
3. **Given** 候选已过期或来源闭包任一无效，**When** 确认，**Then** 409 且候选状态、目标条目均不变。
4. **Given** 替代请求的目标与候选元数据中的建议不一致，**When** 确认，**Then** 409 且原目标不被替代。
5. **Given** 两个并发确认同一候选，**When** 同时提交，**Then** 恰好一个成功、一个冲突，数据库只产生一条 `active`。
6. **Given** 确认与来源撤销并发，**When** 撤销先完成，**Then** 确认失败关闭并 409。

### User Story 3 - 有界窗口、冻结重试与预算 (Priority: P2)

抽取只读取触发 Run 同来源、游标之后、角色为 `user` / `assistant` 的有界消息窗口（最多 40 条 / 8 KiB），前文最多 6 条 / 2 KiB 只用于指代理解、不得作为证据。窗口在首次尝试后按消息主键冻结；失败在同一冻结窗口上有界重试至多 3 次，第 3 次失败转 `skipped` 并推进游标；每 Agent 每滚动 24 小时最多 200 次抽取尝试，预算与行写入同事务判定，耗尽不建行不调用。

**Why this priority**: 没有窗口与预算，抽取会无界重试、烧钱且跨来源污染身份；没有冻结窗口，重试会用新消息集合产生不一致证据。

**Independent Test**: 窗口超限保留最近并记录丢弃；工具 / 系统消息被剔除；跨来源消息不进入窗口；失败后重试只重读同一冻结窗口；第 3 次失败转 `skipped`；200 次后不建行不调用。

**Acceptance Scenarios**:

1. **Given** 新消息超过 40 条或 8 KiB，**When** 生成窗口，**Then** 保留最近部分并记录丢弃条数。
2. **Given** 会话包含多个来源的 Run，**When** 生成窗口，**Then** 只包含与触发 Run 同来源的消息；前文同样只取同来源。
3. **Given** 一次尝试失败且 attempts 小于 3，**When** 同来源下一次 Run 触发，**Then** 只重试同一冻结窗口，窗口主键不变，尝试身份（触发 Run、时刻、provider / model / config）更新为本次 Run。
4. **Given** 同一冻结窗口第 3 次失败，**When** 写回，**Then** 行转 `skipped` 并推进游标，之后新 Run 从新窗口开始。
5. **Given** 已用满 200 次尝试，**When** 新 Run 触发，**Then** 不建抽取行、不发起调用，状态页显示已耗尽。

### User Story 4 - 两级预写审计与有界时延 (Priority: P2)

抽取先写抽取行的 `pending`，再经唯一模型调用入口发调用；该入口先写 `llm_calls` 的 `pending`（用途 `memory_extract`、轮次 0）。任一预写失败不得发出调用。钩子端到端不超过 20 秒（工作段 13 秒 + 审计回填 5 秒 + 失败回填 2 秒），不得起 goroutine，钩子失败不改变 Run 的终态、返回文本或错误。

**Why this priority**: 审计 fail-closed 与有界时延是宪法级约束；没有它们，抽取会变成不可审计、可拖垮请求的后台路径。

**Independent Test**: 注入抽取行预写失败与 `llm_calls` 预写失败，两种情况调用次数为零；慢模型 8 秒正常返回时审计仍能写成功；工作段耗尽后失败审计仍在总预算内落库；审计预写不得外扩独立 5 秒；钩子 panic 后 Run 结果不变、不泄漏 goroutine。

**Acceptance Scenarios**:

1. **Given** 抽取行预写失败，**When** 触发抽取，**Then** 不发出模型调用、不写 `llm_calls`。
2. **Given** `llm_calls` 预写失败，**When** 发起调用，**Then** 不发出调用，抽取行落 `failed` 并分类为审计不可用。
3. **Given** 桩模型在 8 秒正常返回，**When** 回填审计，**Then** `llm_calls` 与抽取行都写 `success`。
4. **Given** 工作段 13 秒耗尽，**When** 回填失败，**Then** 审计与抽取行都在总预算内落 `failed` / `timeout`。
5. **Given** 抽取过程中发生 panic，**When** 恢复，**Then** Run 的终态、返回文本与错误不变，且无 goroutine 泄漏。
6. **Given** Run 终态写失败或幂等未转换，**When** 钩子门禁判断，**Then** 跳过抽取；引用释放仍无条件执行。

### User Story 5 - 召回面派生复核与失效停止召回 (Priority: P2)

来源条目被删除、替代或到期后，由它派生出的候选条目即使自身仍是 `active` 也不得被召回。派生复核在召回时执行，三个 SQL 入口共用同一判据（关键词真实入口、无向量关键词回退、向量路径），沿来源关系递归取闭包；递归深度超过 8 按失效处理（fail-closed）；过滤在排序与 top-k 之前；没有来源关系的显式条目不受影响。

**Why this priority**: 只检查条目自身会让已失效来源的内容继续喂给模型；这是删除 / 撤权的下游承诺。

**Independent Test**: 删除来源 A 后，关键词、旧关键词入口、真实工具入口与语义四条链路均不返回派生 B / C；A → B → C 传递链同时退出；深度超限 fail-closed；显式条目不受影响。

**Acceptance Scenarios**:

1. **Given** 来源 A 被删除或到期，**When** 分别经三个 SQL 入口召回，**Then** 派生条目均不返回。
2. **Given** A → B → C 的派生链，**When** 删除 A，**Then** B 与 C 都退出召回。
3. **Given** 显式条目（`save_memory` / 显式提议）没有来源关系，**When** 召回，**Then** 不受派生过滤影响。
4. **Given** 派生深度超过上限，**When** 召回，**Then** 该条目按失效排除，不返回无法证明来源有效的条目。

### User Story 6 - 方法草案与受控转交 (Priority: P3)

模型产出的可复用工作方法不写记忆条目，而是写成固定布局的只读草案文件（`DRAFT.md` + `evidence.json`）。人只能通过 `learning handoff` 薄适配把它提交给既有技能准入：必须取实例锁、主体必须为本机 CLI 用户、来源声明必须为用户确认，程序强制来源字段，随后只调用既有提议入口；评估 / 批准 / 发布 / 撤回仍全部归技能准入。

**Why this priority**: 这是「经验发现」的第二个出口，但不自动成为技能；没有它，方法类输出只能被丢弃。

**Independent Test**: 草案文件固定布局且只读、不含脚本、Agent 文件工具无法读取；handoff 强制取锁与主体校验、拒绝未用户确认的来源、只调用提议入口而不直接评估 / 批准 / 发布。

**Acceptance Scenarios**:

1. **Given** 模型返回 `kind=method`，**When** 提交抽取，**Then** 写固定布局的只读草案文件与草案行，不写记忆条目。
2. **Given** 草案文件已生成，**When** 以 Agent 文件工具读取，**Then** 被拒绝（不在任何 Agent 读写白名单）。
3. **Given** 未取实例锁或主体不是 `cli:<OS user>`，**When** 执行 handoff，**Then** 拒绝。
4. **Given** 来源声明不是用户确认，**When** 执行 handoff，**Then** 拒绝。
5. **Given** 合法 handoff，**When** 提交，**Then** 只调用既有提议入口，来源字段由程序强制。

### User Story 7 - 崩溃恢复、只读学习查询面与迁移 (Priority: P2)

提交结果未知或崩溃重启后，启动恢复只查证不重放：已有候选元数据或草案行判 `success`，否则判 `unknown`；两者都在同一事务推进游标并写查证时间。未查证的 `unknown` 与 `pending` 阻断同来源新窗口，查证后保留历史但不再阻断。学习面只读：状态、抽取列表与详情、草案列表与详情经 HTTP 与 CLI 提供；管理台并入既有「记忆」页三页签（记忆库 / 待确认 / 学习记录），没有独立入口、没有新写端点；确认 / 删除复用既有记忆管理动作。迁移只追加：扩展两个闭集并新增五张表，schema 版本 10 → 11。

**Why this priority**: 未知不等于未发生——不查证就重放会破坏证据与预算；只读查询面是运维与人工复核的入口。

**Independent Test**: 人为制造 `pending` 后恢复为 `unknown` 且不重放、游标推进、`verified_at` 写入；重启后同来源新 Run 正常抽取新窗口；学习只读端点全部无写方法；迁移从 v10 前向升级、表数与版本同步。

**Acceptance Scenarios**:

1. **Given** 提交结果未知且不重启，**When** 同来源新 Run 触发，**Then** 被 `pending` 阻断，零写入零调用。
2. **Given** 提交结果未知后重启，**When** 启动恢复，**Then** 行转 `unknown`、游标推进、`verified_at` 写入，不重放；新 Run 恢复抽取。
3. **Given** 学习只读端点，**When** 使用 POST / PUT / PATCH / DELETE，**Then** 没有写端点返回成功。
4. **Given** v10 数据库，**When** 升级，**Then** 迁移 0011 前向执行，`source` 与 `purpose` 新取值可用，五张表存在，表数 82 → 87。

### Edge Cases

- 冻结窗口的消息被保留策略全部或部分清理：比对实际条数与冻结条数，不等即转 `skipped`（`window_gone`）并推进游标；不得用残缺集合抽取。
- 触发 Run 未在本来源留下任何合格消息：不建抽取行、游标不动。
- 抽取行预写与预算判定并发：同一 Agent 取事务级 advisory lock，两个会话不得同时突破 200 次上限。
- 提交事务失败但草案文件已写：保留文件、行留 `pending`、等恢复查证；不补偿删除、不重做。
- 自动候选的请求体为空：仍然执行全部确认门禁，不回落旧路径。
- 来源 Key 为空（本机 CLI 管理员会话）：不查 Key 行，但仍受候选到期、来源闭包、来源调用方状态与目标复核约束。
- 确认成功后的向量补索引失败：条目仍 `active`，只记 WARN；召回按既有索引未就绪错误显式暴露，不静默返回空。
- 名单内的 Agent 在运行时未找到：记 WARN、不抽取、不阻止启动，状态页列出。
- 配置启用但名单为空 / 重复 / 非法名：启动报错，服务不启动。
- 抽取输出 0 条合法候选：仍记 `success`、推进游标，不产生空候选。
- 单项证据非法或凭证命中：只丢弃该条，其余候选照常提交，整次仍可成功。
- 建议取代目标不在条目快照内：清空建议、保留条目；来源条目 id 不在快照内：丢弃该条。

## Requirements

### Functional Requirements

- **FR-22-01**: 自动抽取必须出厂默认关闭；启用必须显式给出 Agent 名单；名单为空、重复或非法名必须启动失败；名单内不存在的 Agent 必须记 WARN 且不抽取、不阻止启动；未启用时必须零写入、零模型调用、零日志正文。
- **FR-22-02**: 抽取必须只有一个同步触发点——Run 终态真正落库之后；只有 `applied` 且 `completed`、渠道为 `web` / `cli`、非 Flow、非固定工具的 Run 才触发；终态写失败或幂等未转换必须跳过；顺序必须固定为「终态落库 → 抽取 → 引用释放」，释放必须无条件执行并由启动恢复兜底；生产链路的每个客户端装饰器都必须实现抽取入口，路由器不得实现。
- **FR-22-03**: 窗口必须有界且按来源冻结：同来源 Run、角色 `user` / `assistant`、最多 40 条 / 8 KiB，保留最近并记录丢弃；前文最多 6 条 / 2 KiB 且不得作为证据；首次尝试后窗口必须按消息主键冻结；游标必须按（Agent、会话、来源调用方、来源 Key）推进。
- **FR-22-04**: 抽取行与 `llm_calls` 必须两级预写 `pending`；任一预写失败不得发出调用；每次尝试只发一次调用，不重试、不 fallback；provider / model / config 必须取该次尝试的触发 Run 冻结值，重试必须绑定本次 Run 的尝试身份。
- **FR-22-05**: 模型输出必须视为不可信数据：严格 JSON（≤64 KiB、UTF-8、无未知键、无尾随内容）；必须逐项校验类型闭集、内容上限、证据（窗口内、角色、逐字子串）、临时约束的绝对未来有效期、去重、来源子集与建议取代目标；凭证扫描命中必须丢弃该条；确定性必须由程序派生，模型自报置信度不得作为门槛。
- **FR-22-06**: 合格条目必须以 `candidate / auto_extract / archive` 落库并附元数据与来源关系；确认前不得参与召回、不得进入注入；范围必须只写 Agent 层；`save_memory` 的显式保存与既有管理提议语义必须不变。
- **FR-22-07**: 确认必须是唯一晋升路径；自动候选无论请求体是否为空都必须进入统一确认事务并执行全部门禁（候选状态 CAS、候选到期、来源闭包有效且未过期、来源 Key 未撤销未到期、来源调用方未停用、替代目标与建议逐字一致且仍 `active`）；任一不满足必须冲突（409）并回滚；显式提议候选保持既有确认路径；确认必须写管理审计且明细不得包含正文。
- **FR-22-08**: 方法草案必须只写固定布局的只读文件（`DRAFT.md` + `evidence.json`）、不写记忆条目、不执行脚本、不进任何 Agent 读写白名单；handoff 必须取实例锁、主体必须为本机 CLI 用户、来源声明必须为用户确认、来源字段由程序强制，且只调用既有提议入口。
- **FR-22-09**: 恢复必须只查证不重放：启动扫描 `pending`，已有候选元数据或草案行判 `success`，否则判 `unknown`；两者都必须同事务推进游标并写查证时间；未查证的 `unknown` 与 `pending` 必须阻断同来源新窗口，查证后必须解除阻断；提交结果未知时必须保留 `pending`、不得删除草案文件、不得写 `failed` 覆盖可能已成功的结果。
- **FR-22-10**: 预算与失败必须有界：每 Agent 每滚动 24 小时最多 200 次抽取尝试（代码常量）；预算判定与行写入 / 重试递增必须同事务并取 Agent 锁；耗尽不得建行、不得调用；失败必须在同一冻结窗口上至多重试 3 次后转 `skipped` 并推进游标；失败分类（审计不可用、超时、模型错误、非法输出、窗口缺失、装配缺陷）必须分别落库；钩子端到端必须 ≤20 秒（工作 13 秒 + 审计回填 5 秒 + 失败回填 2 秒），不得起 goroutine，钩子失败不得改变 Run 的终态 / 返回 / 错误。
- **FR-22-11**: 学习查询面必须只读：状态、抽取列表与详情、草案列表与详情经 HTTP 与 CLI 提供；管理台必须并入既有「记忆」页三页签（记忆库 / 待确认 / 学习记录），不得新增左侧入口或 `/console/learning*` 路由，不得新增写端点；确认 / 删除必须复用既有记忆管理动作；存储错误必须返回错误，不得用空列表冒充「没有抽取」。
- **FR-22-12**: 迁移必须只追加：扩展 `source` 与 `purpose` 两个闭集并新增抽取 / 元数据 / 来源关系 / 草案 / 游标五张表，schema 版本必须 10 → 11；不得改写冻结基线或已发布迁移；不得新增 Go / npm 依赖；不得新增动作字面量。
- **FR-22-13**: 召回面的派生复核必须在三个 SQL 入口（关键词真实入口、无向量关键词回退、向量路径）共用同一判据：沿来源关系递归取闭包，任一来源非 `active` 或已过期必须排除该派生条目；递归深度上限 8 必须按失效处理（fail-closed）；过滤必须在排序与 top-k 之前；无来源关系的显式条目不得受影响。

### Key Entities

- **学习抽取（Learning Extraction）**: 一次有界抽取尝试的完整记录——触发 Run、Agent、会话、来源身份、冻结窗口首尾消息、窗口条数与丢弃数、前文条数、尝试身份（Run / 时刻 / provider / model / config）、提示词与规则版本、状态（pending / success / failed / skipped / unknown）、尝试次数、失败分类、查证时间。
- **记忆候选（Memory Candidate）**: `state='candidate'` 的条目，来源固定 `auto_extract`、分区固定 `archive`；附类型、确定性、内容、有效期。
- **候选元数据（Candidate Meta）**: 与候选一一对应的证据与建议：证据（消息主键、角色、逐字引文、消息时刻、所属 Run）、来源调用方、类型、确定性、建议取代目标、事件 / 有效期、时间可信度。
- **来源关系（Candidate Source）**: 派生条目 → 来源条目的有向关系；召回面据它递归复核来源闭包。
- **方法草案（Method Draft）**: 固定布局的只读文件集与对应数据库行，不是技能、不是记忆条目、不可执行。
- **抽取游标（Extraction Cursor）**: 每个（Agent、会话、来源调用方、来源 Key）已处理到的消息位置。
- **学习查询视图（Learning Read Models）**: 状态（启用与否、Agent 名单、预算用量与是否耗尽）、抽取视图、草案视图与候选视图（含元数据）。
- **确认处置（Confirm Resolution）**: `keep_both`（默认）或 `supersede`（必须与候选建议一致）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 启用自动抽取后，从一次正常结束的 Web / CLI Run 到「候选可见 → 人工确认 → 新 Run 召回」的完整链路在本地协议桩与冻结夹具下可重复通过，且每个动作都有对应审计行。
- **SC-002**: 拒绝错误候选的行为可复现：不确认或删除候选后，后续 Run 的关键词与语义召回都不命中，数据库不产生 `active` 行。
- **SC-003**: 来源失效后停止召回：删除 / 到期来源条目后，派生条目在三个 SQL 入口与传递链上全部退出召回；显式条目不受影响。
- **SC-004**: 确认门禁可复现：候选到期、来源失效 / 到期、Key 撤销 / 到期、调用方停用、建议不一致任一出现时全部冲突且状态不变；并发确认恰好一个成功。
- **SC-005**: 审计 fail-closed 可复现：两级预写失败时模型调用次数为零；恢复对 `pending` 行只给 `success` / `unknown`，从不重放；未查证 `unknown` 阻断下一窗口、查证后解除。
- **SC-006**: 时延有界可复现：钩子端到端不超过 20 秒；慢模型正常返回仍能写成功审计；工作段耗尽仍在总预算内落失败；审计预写不被独立的 5 秒外扩。
- **SC-007**: 默认关闭无副作用：空配置下完成 Run 后无抽取行、无 `memory_extract` 调用、无草案文件；`go.mod` / `package.json` 无新坐标。
- **SC-008**: 迁移可前向升级：v10 数据库升级到 v11 后新取值与五张表可用，既有迁移测试保持通过；冻结基线与已发布迁移未被改写。
- **SC-009**: 只读面可验证：学习路径与记忆页签没有新增写端点或左侧入口；存储错误显式失败而非空列表。
- **SC-010**: 效果类结论保持 `未测量`：真实模型抽取质量、任务收益与技能绑定收益不在本模块断言，任何自动化绿态都不得转写为效果提升结论。

## Assumptions

- 前序模块事实成立：US-16 已交付记忆六态、召回与注入守点、管理四动作与审计；US-20 已交付隔离与文件白名单（草案不进白名单、不执行）；US-21 已交付技能准入状态机、提议入口与凭证扫描实现（本模块把扫描器下沉到公共层共用，不复制规则）。
- 运行后端为 PostgreSQL（v10 起步，本模块升到 v11）；SQLite 只随 `core.RunStore` 签名与释放拆分适配，不新增学习路径。
- 单实例部署；同会话由既有忙锁串行；跨节点抽取协调不在本模块。
- 管理员启用自动抽取即知情：Agent 层条目对该 Agent 的所有调用方共享；草案与候选纳入既有备份范围，但不承诺无限保留。
- 测试只使用本地协议桩与冻结夹具，不注入真实模型凭据、不访问外网、不执行脚本；本地 PostgreSQL 与 npm 测试构建为既有授权。
- 真实模型效果、固定评测集、隔离对照实验与技能绑定收益归后续 D-2（拟），需另行立项并解除真实模型禁令；本模块的确定性验收不能替代效果结论。
- 时间语义：只接受 RFC3339 绝对时刻；相对日期在无可信时区时不解析并记 `time_confidence='unknown'`；证据时刻是消息记录时刻，不是事实发生时刻。
