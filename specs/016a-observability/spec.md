# Feature Specification: US-16A Agent 可观测与执行诊断

**Feature Branch**: `016a-observability`

**Created**: 2026-11-01

**Status**: 已审范围的 AI 派生规格，待实现与 review ②。

**Input**: 用户已通过模块颗粒度文档 review ①，授权 Codex 自动推进至最终人工走查。用户明确编号为 US-16A，保留 US-17；当前会话编号决定覆盖交接单整数顺延说明。

## User Scenarios & Testing

### User Story 1 - 解释一次任务发生了什么（Priority: P1）

管理员从请求、运行、任务、摄取、管理操作或会话定位执行事实，查看时间线、关联与证据缺口。

**Why this priority**: 统一诊断是上下文解释、指标和导出的公共基础。

**Independent Test**: 正常链路和工具拒绝两个独立场景核对同一请求/运行/审计身份、顺序与禁止副作用。

**Acceptance Scenarios**:

1. Given 带知识和工具的任务，When HTTP 请求完成两轮模型交互，Then 请求关联到运行，时间线显示运行、检索、装配、模型和工具，审计记录独立存在。
2. Given 模型请求未获准工具，When 查看时间线，Then 显示权限拒绝，没有工具执行和工具审计行。
3. Given 诊断不可读、被采样或未记录，When 查询，Then 分别显示读取失败、可能被采样或未记录，不能显示正常。

### User Story 2 - 核对上下文为何入选或丢弃（Priority: P1）

管理员查看检索候选、排名截断、预算裁剪、历史裁剪和压缩，区分“已装配”和“模型确实使用”。

**Independent Test**: 真实检索路径的混合过滤/预算场景与空检索场景独立验收。

**Acceptance Scenarios**:

1. Given 同时存在保留、排名截断和预算丢弃的允许候选，When 查看上下文，Then 每项决定可核对，过滤项不泄露身份，混合计数明确说明单位和原因未统一。
2. Given 无检索命中但装配记录存在，When 查看，Then 显示知识库无结果；装配记录缺失时显示证据缺口。
3. Given 历史记录缺检索阈值，When 查看，Then 显示未记录，不能补成零。

### User Story 3 - 观察健康、告警和恢复（Priority: P2）

管理员查看本进程计数与数据库窗口指标，从异常任务组下钻具体运行，查看告警触发、持续、恢复和未知状态。

**Independent Test**: 模型超时场景、告警状态重启和读取失败测试。

**Acceptance Scenarios**:

1. Given 模型调用已发出后超时，When 查询，Then 审计与诊断标超时，运行失败，超时指标增加。
2. Given 规则达到持续条件，When 评估，Then pending 后 firing；条件恢复后当前状态 inactive，历史保留一次 resolved 转换。
3. Given 读取或状态存储失败，When 查看告警，Then unknown，不能显示正常或恢复。

### User Story 4 - 有界导出并解释不确定结果（Priority: P2）

管理员启用标准遥测导出，查看持久账本、扫描覆盖、尝试、重试、部分成功与可能重复。

**Independent Test**: 故障与恢复场景；真实本地 Collector 对 traces、logs、metrics 分别验证。

**Acceptance Scenarios**:

1. Given 终态记录，When 扫描，Then 按终态时间分页入队、唯一键幂等；所有页完成后才推进覆盖区间。
2. Given 三条记录部分成功拒绝一条，When 响应落账，Then 三条均逐条未确认，批次记录接受二、拒绝一，不自动重试。
3. Given 响应已到但确认前崩溃，When 租约过期，Then 可以重发；首次尝试仍 unknown 且计数为空，页面说明此前结果未知、可能重复。
4. Given 重叠窗口指标快照，When 导出，Then Gauge 快照不跨窗口相加，重复快照不累加。

### User Story 5 - 安全清理且诚实显示缺口（Priority: P2）

管理员按策略清理诊断、装配和 OBS 历史，保留业务与审计，不删除未确认导出的源记录。

**Independent Test**: 隔离数据库短保留期，验证删除、重启、冲突、覆盖、原子性和窗口级缺口文案。

**Acceptance Scenarios**:

1. Given 默认配置，When 启动，Then 清理关闭，数据不会自动删除。
2. Given 导出开启但无覆盖或无行级已确认，When 清理，Then 保留源行并记录跳过原因。
3. Given 删除与清理账本写入中发生失败，When 事务结束，Then 一起回滚。
4. Given 只有窗口清理记录，When 解释缺失，Then 只能说该窗口发生过清理、当前记录是否因此缺失无法确认。

### Edge Cases

- 旧事件、未知原因码、缺轮次/尝试/父关系、恢复未知调用、时钟回拨、同毫秒多来源。
- 较小 ID 晚提交、长任务今天终态、分页中断、覆盖 CAS 失败、发送前源字段变化。
- 部分成功 warning 但拒绝零、非法拒绝计数、发送前尝试写失败、确认落库失败。
- 数据库不可用、采样率零/小于一/等于一、进程重启、清理发生但无逐条墓碑。
- 调用方 Key 访问、未授权资料存在性、未知属性、原始错误和导出配置凭据。

## Requirements

### Functional Requirements

- **FR-001**: 请求与真实产生的运行关联；历史未记录关联不补造。
- **FR-002**: 六类查询锚点均受界限约束；查询时间线必须指定唯一主锚点。
- **FR-003**: 合并权威事实与诊断，冲突并列且以业务/审计为准。
- **FR-004**: 按记录时间、固定来源优先级和来源 ID 局部排序，不推断因果。
- **FR-005**: 派生步骤号在过滤和分页前分配；截断前缀与数据变化边界明确。
- **FR-006**: 读取失败、采样、未记录、未支持、未知和窗口清理缺口可区别。
- **FR-007**: 上下文展示候选、命中、阈值、决定、历史和压缩，不泄露过滤项身份。
- **FR-008**: 混合过滤计数不可误读为文档数量、匹配行数或已分类权限拒绝。
- **FR-009**: 已装配不等于模型使用；每项结论有证据档位。
- **FR-010**: 工具调用关联真实 ID，摄取阶段/索引切换及撤权收窄只记录真实锚点。
- **FR-011**: 提供本进程与数据库窗口指标；标签只用有界枚举。
- **FR-012**: 指标不可用区别于零；无样本比率不显示零百分比。
- **FR-013**: 总览和任务组按有界窗口/Top-N 聚合，不选代表运行冒充全组。
- **FR-014**: 八条内置告警规则持久化状态/转换，候选比率规则默认关闭。
- **FR-015**: 数据不足或状态存储不可用时告警 unknown，不判恢复。
- **FR-016**: 标准导出同时交付 traces、logs、metrics，不能用两类替代三类。
- **FR-017**: 仅终态记录按终态时间扫描，覆盖区间分页完成后 CAS 推进。
- **FR-018**: 首次回填、重叠和有界对账的覆盖/漏扫边界必须可见。
- **FR-019**: 发送前重读源行校验哈希；旧状态不得发送。
- **FR-020**: 批次发送前先持久化结果未知尝试；写入失败不发送。
- **FR-021**: 批次部分成功只能记录批次计数，落账后不自动重试；warning 零拒绝仍为成功。
- **FR-022**: 确认前崩溃允许重复；未知计数保持空，不能补造或显示为零。
- **FR-023**: 传输重试有退避、最大次数和年龄；永久错误不重试。
- **FR-024**: 导出不伪造父关系或结束时间；恢复未知调用只导出日志。
- **FR-025**: 窗口指标使用不可相加的 Gauge 快照；重复和重启语义可核对。
- **FR-026**: 清理默认关闭、分批有界，仅清理已审诊断/OBS 历史，不清业务/审计。
- **FR-027**: 导出启用时清理要求有效覆盖和行级确认，未知/未终态及覆盖外历史保留。
- **FR-028**: 删除和清理账本同事务，缺口只按窗口归因。
- **FR-029**: 所有诊断查询沿用管理认证；调用方 Key 不得成为管理身份。
- **FR-030**: 存储、读取、导出都脱敏，不泄露正文、凭据或原始错误。
- **FR-031**: 诊断/导出/清理失败不改变业务结果；审计预写失败仍阻止调用。
- **FR-032**: worker 资源有界、取消可退出，不执行/恢复/重放业务任务。
- **FR-033**: 迁移只追加、历史数据缺失保留；旧事件可读，枚举一致性自动验证。
- **FR-034**: 提供管理台总览、任务组、运行详情、查询、指标、告警、导出、清理和操作手册。

### Key Entities

- 执行事实：请求、运行、模型/工具/向量调用、调度执行、摄取、管理操作。
- 诊断证据：事件、上下文装配、证据档位、来源级缺口。
- 遥测账本：导出项、批次尝试、扫描覆盖、指标快照。
- 运维状态：告警当前状态与转换、清理批次与窗口。

## Success Criteria

- **SC-001**: 六个独立场景分别通过具名自动验收，关键回归可通过逆改验证判别力。
- **SC-002**: 调用方 Key 拒绝、三处 canary、审计预写零调用、无业务 worker 副作用均通过。
- **SC-003**: 真实 PostgreSQL 的迁移、乱序提交、并发入队、分页/CAS、恢复与清理原子性通过。
- **SC-004**: 真实本地 Collector 三信号发送、接收、字段脱敏以及测试后端窗口 Gauge 语义分别留证；真实外部后端可选且不冒充已验。
- **SC-005**: 完整公共门禁、阶段验收、适用 e2e、前序回归全绿；证据绑定当前稳定源码与候选二进制。
- **SC-006**: 管理台机器测试与构建通过，最终走查包和 Claude 回交包齐备；人工 review ② 仍由用户决定。

## Scope Boundaries

不交付 Prometheus 端点、完整告警平台/DSL/外部通知、企业 SSO/RBAC/多租户、跨节点全局序号、业务重放/恢复、端到端恰好一次、原始正文采集、stderr 持久化、未来 C/A/F/H/E 领域能力或外部后端嵌入。

## Clarifications

### 2026-11-01 自动澄清

- 编号固定 US-16A：当前用户明确指令优先；不占 US-17。
- 两处设计选择已定：独立可空 retrieval 摘要；诊断语义扩展技术方案。
- 查询锚点与聚合区别：时间线要求锚点；总览/指标/告警/导出状态是有界聚合，不是无界列举事件。
- 缺失字段保留 presence，不以整数零代替；技术载体与迁移细节在 plan 冻结。
- 部分成功计数以 span/log_record/data_point 为单位，不能将指标快照 item 数当数据点数。
- 依赖选型按有界 spike 自动裁决，在工作区实现并列入 review ② 追认；中间不等待人工确认。
